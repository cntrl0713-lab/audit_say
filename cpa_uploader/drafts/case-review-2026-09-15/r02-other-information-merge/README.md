# r02: 기타정보 두 사례의 병합과 종합 문제

60·21번 사례를 합치고, 사용자 요청대로 기타정보(KGA 720)에서 물어볼 다른 요소를 더해 옳고 그름을 구분하는 종합 문제로 만들었다. [문제·모범답안·부분점수](questions-and-answers.md)

| 파일 | 내용 |
| --- | --- |
| [sets.json](sets.json) | 병합 초안 1세트(`needs_review`). [build-draft.mjs](build-draft.mjs)가 원 세트와 등록 전문에서 인용을 그대로 복사해 만든다. |
| [design.json](design.json) | 열한 항목의 옳고 그름과 근거, 물음별 대응표·배점 결정, 정답 암시 제거 내역 |
| [lineage.json](lineage.json) | 원 두 세트의 물음·criterion이 함정·옳지 않은 항목·새 요소 중 어디로 갔는지 |
| [qa.json](qa.json) | 실제 채점 전에 정한 대표 부분정답·오답과 보조 사례의 기대 판정 |
| [questions-and-answers.md](questions-and-answers.md) | [render-sheet.mjs](render-sheet.mjs)로 만든 사람용 문제지와 실제 채점 결과 |

[record-docs.mts](record-docs.mts)는 design·lineage·qa를 한 번 기록한 도구이며 기존 파일이 있으면 쓰지 않는다.

## 구성

- 물음 1(감사보고서일 전 ①~⑤): ① 발행 전 최종본 제공 서면진술 요청(옳음), ② 투자설명서를 기타정보로 봄(옳지 않음), ③ 불일치를 경영진과 논의하고 재무제표 쪽도 조사(옳음), ④ 가동중단 정보가 사실이라며 기존 재고 감사계획 유지(옳지 않음), ⑤ 관련 없는 기타정보를 읽지 않음(옳지 않음).
- 물음 2(감사보고서 작성·감사보고서일 후 ⑥~⑪): ⑥ 재무제표 매출 과대계상을 기타정보 단락에만 기술하고 적정의견(옳지 않음), ⑦ 기타정보 수정 거부를 의견 변형 사유로 보지 않고 보고 계획을 지배기구와 커뮤니케이션(옳음), ⑧ 기타정보 단락에 보고할 사항 없음 기재(옳지 않음), ⑨ 감사보고서일 후 입수 예정 연차보고서 식별(옳음), ⑩ 보고서일 후 연차보고서 열람·수정 요구(옳음), ⑪ 수정되지 않은 채 배포되자 종결(옳지 않음).
- 새로 더한 기타정보 요소: 문단 13 서면진술(①), 문단 7(b) 적용 제외(②), 문단 14·15 주의 유지(⑤), 문단 21·22(b) 식별(⑨).

## 배점

물음마다 옳지 않은 항목을 정확히 고른 식별 1점(함정을 고르거나 빠뜨리면 0점)과 옳지 않은 항목마다 이유 또는 보완절차 중 하나를 핵심 원칙 수준으로 쓴 1점을 둔다. 물음 1·2 각 4점, 합계 8점이다. 구체적 후속절차의 나열은 요구하지 않는다.

## 검증과 남은 일

agent 내용 검토, 초안 형상·인용 검사(`validate_draft_v3.ts --against-bank`), 원 세트 포함·제외 두 경우의 전체 은행 검사, 실제 Luna 채점(대표 6답안 모두 기대점수 일치, 이유만·보완절차만 쓴 보조 답안도 만점 일치)을 마쳤다. 정본·공개본·운영 DB 반영, 원 두 세트의 퇴역, coverage 연결 갱신은 하지 않았다. 세부는 [검증 장부](../../../analysis/reviews/case-review-2026-09-15/README.md).
