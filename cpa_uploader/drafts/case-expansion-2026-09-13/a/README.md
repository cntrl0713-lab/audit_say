# A 담당 사례 보강

8개 기존 사례의 사례형 물음만 교체하는 초안이다. 기존 기준서형 물음은 총괄이 별도 묶음으로 원문·정답·배점을 보존한다. 이 폴더의 제외는 삭제 요청이 아니다.

| 세트 | 사실 글자 수 | 물음 수 | 기존 사례 배점 → 보강 배점 |
| --- | ---: | ---: | ---: |
| pilot-04-005 | 595 | 2 | 2 → 7 |
| pilot-04-006 | 626 | 2 | 3 → 7 |
| pilot-04-007 | 597 | 2 | 2 → 5 |
| draft-04-320-freq01 | 616 | 2 | 2 → 4 |
| pilot-03-005 | 645 | 2 | 2 → 4 |
| pilot-03-006 | 619 | 2 | 4 → 6 |
| pilot-02-007 | 616 | 2 | 7 → 7 |
| pilot-07-007 | 623 | 2 | 3 → 5 |

글자 수는 사실 본문을 개행으로 연결한 공백 포함 길이이며 발문은 제외한다. 모두 400자를 여유 있게 넘는다. 세트 배점 합계는 25점에서 45점으로 증가한다.

- `sets.json`: 사례형 16물음, `needs_review` 초안. 새 요구 7물음과 기존 사례 9물음을 포함한다.
- `design.json`: 실제 version 1 계획, 사실-물음 연결, 원자료 단위, 기존 기준서형 분리 계보와 배점 변화.
- `source-evidence.json`: 기출·고급연습의 실제 지문·해설 비교 및 공식 전사 인용. 원파일 전체와 인용의 해시·행·쪽을 구별한다.
- `review.json`: 모든 포함 물음과 criterion의 agent 내용 대조. 사람 승인이나 모델 API 실측으로 표시하지 않는다.
- `qa.json`: 물음별 대표 부분답안과 오답 32개. 모범은 `model_answer`를 그대로 사용한다.
- `qa-superseded.json`: 함축 결론으로 기대점수가 모호해 대표로 채택하지 않은 옛 경계 후보를 보존한다.
- `validation.json`: 메모리 교체 은행의 `validateAuthoringBank`, version 1 계획, 사실 길이·물음 수, QA ID·정수 합계 검증. 오류·경고 0개.
- `root-peer-review.json`: 총괄 작성 신규 2사례를 별도 독립 agent로 내용 대조한 기록. 최초 지적과 수정 후 확인을 구별한다.

총괄 검토에 따라 04-005의 추가·검토자와 시기를 별도로 인정하는 기존 5점 계약에 맞추었고, 04-006의 을·병 판단과 이유도 각각 독립 1점으로 나눴다. 02-007/sub3 대표 부분답안은 양극단 자동 판단을 부정하는 한 명제만 명시해 1점으로 명확히 했다.

실행: `node a/build.mjs`는 저장소 루트에서 이 폴더까지의 전체 상대경로로 실행한다. `node --import tsx .../a/verify.mjs`로 정적 검증한다. 총괄이 채점 입력을 봉인한 뒤에는 생성기를 재실행하거나 산출물을 바꾸지 않는다. 실제 Luna 채점과 최종 정본·공개본·운영 DB 반영은 총괄의 후속 검증 범위이다.
