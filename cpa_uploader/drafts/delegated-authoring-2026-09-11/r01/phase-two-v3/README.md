# R01·N04·N05·S03 실제 검증 v3

담당 16세트의 작성자 QA 746사례를 `final-153-v1` 문항·계획·QA와 `runtime-v3-stable` 고정 환경으로 처음부터 실행 중이다. v1/v2 기록은 이전 폴더에 보존하고 현재 완료 증거와 합산하지 않는다. 모델은 `gpt-5.6-luna`이며, 작성자 QA·의미검수·의미검수 생성사례 채점은 각각 별도 기록한다. 현재 파일을 수정하거나 정본에 편입하지 않는다.

작성자 QA는 [순차 실행기](run-author-queue.mjs)와 [해시 검사 실행기](launch-stage.mjs)를 사용한다. 처음 두 세트는 [author3 실행 장부](author-queue-author3.json)에 완료했고, 총괄의 생성사례 삽입 지시 때문에 다음 세트 직전에 [명시적 일시정지 기록](pause-author-queue-author3.json)을 남겨 종료했다. 이는 전송 장애가 아니다. T09-A 생성사례 채점 이후 남은 14세트는 `author3b`라는 새 실행명으로 이어간다. 두 실행명의 기록은 겹치지 않는다.

[작성자 QA 진행 스냅샷](author-progress-006.json)은 해당 시점에 완료된 R01 6세트·156고유사례·168실행을 집계한다. 155회는 실제 모델 경로, 13회는 production 빈답안 무모델 처리다. 작성자 기대 불일치는 아래 T12-A 1개이며 3회 관측을 보존했다. 이전 [3세트](author-progress-003.json), [4세트](author-progress-004.json) 시점 스냅샷도 보존했다. 경계 사례의 not_met/contradicted 0점 동등 처리는 공통 정책을 따르며 exact 판정 차이도 개별 원시 파일과 집계에 남긴다. [조회 스크립트](summarize-author-progress.mjs)는 완료된 author3 접두 실행만 읽고, 선택한 새 파일에만 스냅샷을 남긴다. 실행 중 부분 로그나 별도 보충 사례를 746개 완료로 셈하지 않는다.

이전 5개 작성자 불일치는 현재 환경에서 각각 3회, 합계 15회 모두 일치했다. [5사례 후속 장부](prior-five-failures-v3-followup.json)는 원 답안·사전 기대·원시 판단·최종 결과와 각 파일 해시를 보존한다. 완전한 작성자 QA의 첫 실행이 일치해도 같은 사례 2회를 별도 경로에서 추가했다. 통과할 때까지 반복하는 절차가 아니며, 이후 새 불일치가 발생하면 원문·발문·전체 답안과 원시 판단부터 최종 점수까지 대조한다.

- [T09-B 방식 비교](../phase-two-case-investigation/t09-b-method-regression/README.md): 원 간결한 표현과 작성·회신 방식을 모두 쓴 동반 표현을 각각 3회, 합계 6회 실제 채점하여 모두 예상 1점과 일치했다. 원 QA를 변경하지 않았다.
- [T09-A 생성사례 채점](t09-a/generated3-01/README.md): 비빈답안 22개와 빈답안 1개를 실행했고, 기대가 다른 두 경계 답안은 각각 3회 확인했다. 적용범위 c4와 평가 측면 c1/c2를 구별하지 않은 생성 기대 오류 가능성을 별도 조사했다. 현재 검증 오류 2개는 유지하며 총괄 판단과 후속 검증을 기다린다.
- [T12-A 최초 일자 함축](t12-a/author3b/omit1-investigation.md): q2/omit-1은 기대 5점이나 3회 모두 c1만 not_met인 4점이었다. 현재 c1.scope가 두 일자의 병존을 함축하는 추가 일자 답안을 명시적으로 허용하므로 기대를 유지한다. 실제 점수 오류로 조사 중이며 원답안을 더 명시적인 답안으로 교체해 없애지 않았다.

의미검수의 큰 입력은 총괄이 한 stream에서 수행한다. 전달받은 receipt에 대한 생성사례 채점은 작성자 QA 세트 경계에 끼워 넣어 같은 grader stream으로 실행한다. `--packet`에 수동 근거 문서를 넣지 않으며, 생성 receipt 원본·입력 해시·모든 반복 관측을 보존한다. 사람 확인·정본 편입·게시·배포는 수행하지 않는다.
