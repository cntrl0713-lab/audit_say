# T09-A v3 생성 답안의 실제 채점과 경계 사례 조사

현재 의미검수에서 생성한 25사례는 답안이 같은 사례를 합치면 비빈답안 22개다. 빈답안 1개를 더한 최초 23개 실행에서 2개 경계 답안이 기대와 달랐고, 같은 입력으로 2회씩 추가 실행했다. [실측 요약](summary.json)의 총 31회는 비빈답안 모델 실행 26회와 production 빈답안 처리 5회다. 추가 실행 도구가 매번 수행한 빈답안도 숨기지 않고 포함했다. 실행 오류는 없으며 실제 채점 검증 오류 2개는 미해결 상태로 보존한다.

| 답안 | 원 생성 기대 | 각 3회 실제 결과 |
|---|---|---|
| 설계 효과성을 계속기록법인 경우에만 고려 | q2.c1 contradicted | q2.c1 met, q2.c4 contradicted, 1점 |
| 실행 효과성을 계속기록법인 경우에만 고려 | q2.c2 contradicted | q2.c2 met, q2.c4 contradicted, 1점 |

[조사 장부](investigation.json)에 원 발문·공통 사례·모범답안·criterion·공식 A9 인용과 생성 사례의 rationale, 원시 판단·전체 답안·최종 점수 및 3회 관측을 함께 기록했다. [초기 채점 receipt](graded-initial.json), [초기 로그](initial.grading.jsonl), [반복 로그](repeat.grading.jsonl)는 바꾸지 않았다.

발문은 통제 효과성의 세 측면을 제시하는 요구와 어느 기록방식에 적용되는지를 설명하는 요구를 분리한다. c1~c3은 각각 설계·실행·유지의 고려이고 c4는 두 기록방식 모두에 적용된다는 명제다. 주어진 사례는 특정 기록방식을 고정하지 않는다. 따라서 설계 또는 실행의 고려를 직접 쓴 답안에 해당 측면 1점을 보존하고, 계속기록법에만 한정한 잘못은 c4에서 0점 처리하는 해석이 현재 독립 배점에 맞는다. 생성 사례의 rationale도 실제로는 두 기록방식의 적용범위를 반박한다. 대상 c1/c2의 조건 경계를 만들면서 c4의 요구를 중복 적용한 기대값 오류 가능성이 높다.

이는 기준서 A9의 ‘어느 경우이든’ 조건을 삭제하거나 모든 조건 오류를 별도 criterion으로만 판단하자는 뜻이 아니다. 현재 발문과 배점 분리의 개별 대조 결과다. 원시 모델 판단과 최종 결과가 같고 보안 플래그도 없어 인용 복원·보안 보정·합산에서 발생한 오류는 확인되지 않았다.

총괄에게는 두 원답안을 그대로 두고 c1/c2의 기대와 c4의 기대를 함께 기록하는 후속 검증을 제안했다. 총괄 판단 전에는 원 문항·계획·QA·의미검수 receipt를 수정하지 않으며, 이 조사 문서를 실제 채점 pass receipt로 취급하지 않는다. 작성자 QA 24사례 및 q1/opposite 3회 일치 여부는 별도 작성자 QA 기록이다.
