# T09-A 전체 수동 의미 대조 후속안 — 확정 전

[manual-input-proposal.json](manual-input-proposal.json)은 전체 7단위·25사례를 대조해 채운 제안이다. **manual-input 확정과 실제 재채점은 아직 수행하지 않았다.** 원 [수동 양식](manual-template.json)의 `execution.method=template`, `verdict=uncertain` 및 receipt hash를 유지하며 임의의 pass receipt를 만들지 않았다. 작성자 에이전트의 대조이므로 사람 검수로 표시하지 않는다.

[전체 대조·계보](full-comparison-and-lineage.json)는 원 모델 receipt, 고정 은행·문항·계획·출처 해시, 각 단위와 각 사례의 독립 판단 근거를 담는다. 원 [v5 생성 사례 실측](../../phase-two-v5/t09-a/generated5-01/failure-evidence.json)은 3개 불일치를 각각 3회 보존한다. 세 답안은 모두 해당 측면 met·적용 범위 c4 contradicted·총 1점으로 일관되었다. 원래 모델이 만든 target contra 기대와 일치했다고 바꾸지 않는다.

| 변경 대상 | 원 기대 → 제안 | 원답안 처리 |
| --- | --- | --- |
| q2.c1 / condition_boundary / 사례 index 9 | contradicted → met | 설계 효과성과 계속기록법 한정 문장을 그대로 보존 |
| q2.c2 / condition_boundary / 사례 index 14 | contradicted → met | 실행 효과성과 계속기록법 제외 문장을 그대로 보존 |
| q2.c3 / condition_boundary / 사례 index 19 | contradicted → met | 유지 효과성과 실사 방식 제외 문장을 그대로 보존 |

세 측면은 발문에서 별도로 요구했고 c1~c3은 각각 그 측면을 평가한다. 기록방식의 적용은 추가 발문과 c4에서 독립 평가한다. 따라서 기록방식에 관한 같은 오류를 측면의 점수에서도 다시 차감하지 않는다. 25개 답안, unit ID, 사례 유형은 모두 원문 그대로다. 적용 범위 오류를 정답으로 바꾸거나 다른 반대 답안을 새로 만들어 원 사례를 대체하지 않았다.

전체 대조에서는 다음도 확인했다.

- q1은 501.5의 다른 실사일에 따른 추가 절차다. 정상 입회 및 입회·최종 기록 절차의 별도 계획이 지문에 있으므로 501.4의 전부를 추가 답안으로 요구하지 않는다. 기간과 그 기간의 변동 기록을 확인하는 조치는 하나의 구체 절차를 완성하는 범위다.
- 501.5의 실제 인용은 등록 파일 L51~54이며 locator L51~57 안에 포함된다. A9 인용은 L58~64로 일치한다. 본문·문단·PDF 쪽수도 함께 확인했다.
- q1의 일반적인 ‘재고변동 검토’ 사례는 적절한 기록의 확인 목적이 없어 not_met을 유지한다. q1 opposite 사례는 부적절한 기록을 이미 참으로 전제하여 그 사실만 입증하려는 닫힌 절차이므로 contradicted를 유지한다. 정상 감사에서 부적절한 기록을 발견하거나 의심하여 조사하는 것까지 이 반대로 확대하지 않는 제한을 사례 근거에 명시했다.
- q2의 설계·실행·유지 누락은 각기 다른 측면을 쓴 것으로 보충되지 않는다. 세 측면만 쓴 답은 기록방식 적용 c4를 자동 충족하지 않는다. c4의 한 방식 제외는 원문 ‘어느 경우이든’에 반대하므로 기존 기대를 유지한다.
- 고정 153세트 은행의 발문·claim을 검색하고 관련 14물음의 실제 요구를 직접 읽었다. 09-002의 입회 중 절차, 09-006의 입회불능, 09-001/010의 기초잔액, 06의 일반 설계·실행 이해 등과 구체 목적·기간·대상을 대조했다. 일반 통제 개념의 공유는 인정하지만 A9의 다른 실사일 적합성 및 두 기록방식 요구와 동일 명제로 취급하지 않는다. 어휘 미일치만으로 무중복을 확정한 기록은 아니다.

총괄이 이 전체 대조를 읽은 뒤 스킬의 정식 `--manual-input ... --description ...` 경로로 확정할지 판단한다. 확정하면 새 `manual_reasoned`/`model=null` receipt와 원 모델 receipt를 모두 유지해야 한다. 현재 모델 전용 `run-generated-qa.ts`에 수동 receipt를 모델 결과처럼 전달하지 않는다. 별도 실제 재채점과 검증 완료 여부는 후속 증거로 구분한다.

후속 상태: 이 제안 작성 뒤 총괄이 `final-153-v3` 은행을 고정했다. 이 폴더는 **v2 은행을 실제 대조한 당시 제안**으로 보존하며 수동 확정은 보류한다. 은행 해시만 v3으로 바꾸지 않는다. 총괄의 v3 은행에 대한 새 실제 의미검수 결과와 생성 사례를 받은 뒤 수동 후속의 필요 여부를 다시 판단한다.
