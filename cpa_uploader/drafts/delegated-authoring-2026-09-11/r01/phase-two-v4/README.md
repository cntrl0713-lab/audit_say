# R01·N04·N05·S03 작성자 QA v4 전수 실행

총괄 지시에 따라 담당 16세트·746개 필수 작성자 QA를 v4 기준으로 순차 완료하는 실행이다. 원 문항은 `final-153-v1/manifest.json`, 코드·모델·출처는 `runtime-v4-stable/runtime-lock.json`에 고정했다. v3 결과를 현행 실측으로 승계하지 않는다. 실행 중 공통 입력을 바꾸지 않으며 한 세트의 grader만 동시에 실행한다.

[재사용 장부](reuse-index.json)는 같은 원문항으로 이미 v4에서 수행한 T12-A 5사례와 T11-A 3사례를 각각 3회, 총 24관측 연결한다. 원 QA 사례 구조·원문항·현재 코드/출처·모델·실제 요청/스키마 해시를 [무호출 검증](build-reuse-index.ts)했다. 이는 새 24회 호출이 아니다. T12-A 원 q2/omit-1의 세 차례 불일치는 미해결 그대로 포함한다. 비활성 실험본 `phase-two-followup/t12-a-v2/`의 관측은 연결하지 않는다.

따라서 새로 실행할 기본 사례는 738개다. T12-A는 원본 28개 중 23개, T11-A는 원본 72개 중 69개를 그대로 추출한 전용 QA로 실행한다. 원 QA는 덮어쓰지 않으며 개별 실행의 `remaining-author-cases.json`과 `per-case-reuse.json`이 원 QA의 어느 사례를 새로 실행하고 연결했는지 보여준다. 다른 세트는 원 QA 전체를 사용한다.

[순차 실행기](run-author-queue.mjs)는 새 사례에서 불일치가 발생하면 공통 실행기의 총 3회 기록을 보존한다. 이전에 불안정했던 T04-A·T09-A·T09-B·T10-A의 5사례도 현재 v4에서 각 3회 확보한다. 알려진 T12-A 원 실패는 이미 동일 v4로 3회 검증했으므로 무근거 추가 호출하지 않는다. [단계 실행기](launch-stage.mjs)는 원 문항·원 QA·고정 출처/코드 및 재사용 증거의 해시를 확인한다.

[진행 집계 스크립트](summarize-author-progress.mjs)는 완료된 신규 author4 실행과 정확하게 연결한 선행 관측을 합치되, 새 모델 실행과 재사용 관측·빈답안 무모델 처리를 분리한다. 실행 중 부분 로그와 과거 버전의 결과를 완료 세트로 셈하지 않는다. 실제 의미검수·그 생성사례 채점·사람 확인과도 구별한다.

의미검수의 전역 비교은행은 총괄 소유다. 후속 은행에 다른 세트가 바뀌더라도 동일한 grader 입력인지 확인한 뒤에만 해당 사례를 재사용한다. 문항 수정·정본 반영·게시·배포는 이 전수 실행에 포함하지 않는다.
