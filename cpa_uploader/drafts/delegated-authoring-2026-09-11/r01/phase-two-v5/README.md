# 의미검수 v5 전환에서 작성자 QA 계속

`runtime-v5-stable/runtime-lock.json`의 의미검수 변경은 `questionSemanticReview.ts`에 한정된다. [무호출 전환 확인](transition-preflight.json)은 v4와 비교하여 담당 16세트의 문항·QA·계획, 출처 파일, 모델 설정 및 다른 보호 코드가 동일함을 확인한다. 비교은행은 `final-153-v2`를 사용한다. 이 담당 세트들의 채점 입력은 바뀌지 않았다.

기존 [v4 중간 증거](../phase-two-v4/author-progress-007-runtime-transition.json)는 7세트 228개 고유 사례, 260개 관측을 보존한다. 실모델 관측은 244회(그중 정확히 대조한 선행 재사용 24회), 빈답안의 무모델 처리 16회이다. T12-A 1개와 T12-B 3개 불일치를 포함하며 모두 각각 3회 기록했다. 실패 기록을 제외한 성공 집계가 아니다.

T11-A 실행 중 변경된 파일은 의미검수 모듈뿐이다. 실제 작성자 QA의 69개 새 사례와 연결한 선행 3개 사례는 전부 일치했고, 채점 입력 guard는 변경 없음이었다. 외곽 공통 guard가 다음 T11-B를 API 시작 전에 차단했다. 이를 전송 장애 또는 T11-B의 채점 실패로 분류하지 않는다.

[계속 실행기](run-remaining-author.mjs)는 미실행 9세트 518사례만 순차 실행한다. 실행 전후 보호 파일 해시를 확인하며, 원 QA·문항을 그대로 공통 `run-author-qa.ts`에 전달한다. 초기 불일치는 공통 실행기에서 총 3회 기록한다. `--execute` 없이 실행하면 로컬 확인만 수행한다. 모델 호출을 시작하면 각 세트의 `phase-two-v5/<plan-id>/author5/`에 원 응답·로그·입력 lock·결과를 새로 남긴다. 기존 v4 증거와 QA 파일은 덮어쓰지 않는다.

이 전환 기록은 의미검수 pass, 생성 사례 채점 또는 게시 승인을 뜻하지 않는다. 의미검수 스트림은 총괄이 따로 수행한다.

## 이후 은행 고정·실행 중단·재개 이력

`final-153-v3`는 다른 담당자의 T08-B만 변경한 비교 은행이며, [채점 입력 동일성 대조](bank-v3-grader-identity.json)는 이 담당 16세트의 문항·QA·계획·모델·출처·채점 코드가 그대로임을 확인한다. v2 은행으로 실행한 4세트 생성 QA의 120관측은 원 증거로 보존하며, 새 v3 의미검수나 그 생성 사례의 완료로 바꾸지 않는다. [생성 요청 동일성 장부](generated-request-identities.json)의 요청·스키마 해시는 실행 후 고정 입력에서 재구성한 값임을 표시했다. 작성자 QA 원시의 직접 캡처 해시와 구별한다.

공통 API 잔액 소진 시점의 [중단 장부](credit-stop-status.json)는 필수 746개 중 유효 483개 고유 사례, 525관측(비빈답안 실모델 497, 빈답안 무모델 28), 실패 전송 1회를 별도로 기록했다. T14-A의 승인된 기대값 정정 후 실제 재확인 6회는 별도다. 중단 당시에는 실행 중인 자체 프로세스가 없었으며, 그 장부는 당시 기록이다.

사용자 충전 및 다른 담당자의 실제 정상 응답 확인 후 총괄이 `runtime-v5-bank-v3-after-refill-01`로 재개했다. [재개 실행기](run-s03-after-refill.mjs)는 T09-C의 성공 11개를 직접 요청·스키마 동일성으로 보존하고 나머지 54개 및 S03 잔여 209개만 `author5d` 경로에서 순차 실행한다. 이전 timeout과 중단 장부를 덮어쓰지 않는다. 공통 채점 오류가 재발하면 그 큐를 멈추며 credit_balance_exhausted/insufficient_quota를 다른 세트의 추가 호출로 우회하지 않는다.

[8개 선행 사례 명시 매핑](eight-case-reuse-map.json)은 현재 QA와 T12-A/T11-A 선행 실제 24관측의 case ID·원파일·직접 요청/스키마 해시를 연결한다. 현재 QA 전체 객체와 verdict 순서도 동일했다. 파일명 padding 차이가 중앙 탐색 누락의 원인이라고 확정한 것은 아니며, 중앙에서는 원시의 세트 ID·inputs 형상 차이도 대조한다. T12-A의 원 실패 세 번은 이 매핑에 그대로 남는다.

[배점 결합 후보](point-allocation-candidates.json)는 담당 16세트의 39물음·171criterion을 읽은 후 독립 요구의 결합 후보를 기록했다. 현재 문항·QA나 배점을 변경하는 파일이 아니다. [새 은행 생성 QA 실행기](run-generated-bank-v3-after-refill.mjs)는 필수 작성자 QA 큐가 끝난 뒤에만 별도 실행되며, `--execute` 없는 실행은 무호출 preflight다. 현재 확보한 v3 의미검수 pass 6세트의 preflight는 통과했고, 나머지 receipt는 총괄의 실제 의미검수 결과를 기다린다.
