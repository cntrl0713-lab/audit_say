[실제 입력·원문·모델 응답 증거](t08-b-crit4-input-source-evidence.json)는 원실행의 input, schema, instructions, content, bank, source_files 해시를 로컬에서 재구성하여 모두 일치함을 확인했다. API 호출은 0회다. 원 chunks와 형상 실패 기록은 수정하지 않았다.

## 근거와 사례의 연결

1. `src-09fd22479bc66ee351`은 KGA315.A190(a)(ii)의 거래 완전성 정의를 포함한다. 기록되어야 하는 모든 거래·사건의 기록이 검증 목적이다. 실제 원문 인용은 `delegated-n02-kga315-2025.txt` L425–464에 문자 그대로 있으며 등록 범위와 일치한다.
2. `src-d17a554e2fd22ebefe`는 KGA500.A31 전체다. 감사절차 목적·경영진주장과의 논리적 연결, 테스트 방향에 따른 관련성을 설명하고, 과소계상 검증에서 이미 장부에 기록된 항목만을 테스트하는 것과 다른 원천의 정보를 테스트하는 것을 구별한다. 실제 인용은 `kga500-2025-review08.txt` L319–326에 문자 그대로 있다. 원문의 구체 예시는 매입채무이며 매출 기초자료 추적의 동일 문장인 것처럼 인용하지 않는다.
3. 지문 fact2는 매출원장과 별도로 관리되는 창고 출고·운송인 인도 자료에 원장 미기록 거래가 있을 가능성을 명시한다. 따라서 원장에 존재하는 거래만 다시 선정하는 방향은 그 미기록 거래를 표본에 포함시키지 못한다. 관련성과 신뢰성이 확인된 독립 기초자료의 거래를 기록으로 연결하여 누락 여부를 확인하는 방향은 위 완전성 목적 및 A31 원칙의 사례 적용이다.
4. 실제 발문은 미기록 매출의 완전성을 보완할 모집단·추적 방향과 자료 이용 전제를 요구한다. crit3은 모집단 선정과 이용 전제, crit4는 그 기초자료에서 회계기록으로 추적하는 행위다. 입력이 요구한 목적과 주어진 자료의 관계를 기준서에 없는 새로운 보편적 의무로 확대하지 않는다. 모든 상황에서 오직 이 증빙명·절차만 허용한다는 주장이 아니다.

KGA500.A30–A35의 주변 문맥도 대조했다. A32는 주장별 증거 관련성을 구별하고 다른 원천·성격의 증거가 같은 주장에 관련될 수 있음을 설명하며, A34는 해당 테스트 목적 및 주장상 왜곡표시를 구성하는 조건의 식별을 실증절차 설계에 포함한다. 이 문맥은 위 적용과 일관된다. A34를 crit4의 새 직접 source_ref로 몰래 추가하지 않았다.

## 유효 판정과 미완료 구분

crit4의 attempt1은 유효한 실제 모델 응답이며 source_support uncertain을 그대로 보존했다. 정해진 source_ref_ids와 실제 위치는 맞고, 응답 자체도 완전성 정의와 방향 원칙의 지지를 인정한다. 원문에 사례 표현이 그대로 있어야 한다는 기준은 원리의 사례 적용을 지나치게 제한한 것으로 수동 판단한다. 이 수동 판단을 새 모델 pass receipt로 표시하지 않는다.

sub2/crit5의 두 응답은 생성 사례 source_ref_ids 누락 때문에 형상 검증에 실패했고, 첫 응답에는 부분점수 계약이 없는 partial도 있다. 이 응답들은 유효한 완료 판정으로 승계하지 않는다. 특히 인수증빙의 날짜와 기록기간을 대조한 답에 지문의 인수=통제 이전=인식 전제를 다시 쓰도록 요구한 omission 사례, sub3의 범위 조정을 sub2/crit5의 partial로 처리한 사례는 후속 유효 응답과 생성 QA에서 별도로 확인할 필요가 있다. 원문·지문 전제와 다른 물음의 독립 범위를 혼동하지 않아야 한다.

이 실행에서 실제 기록된 마지막 단위는 sub2/crit5다. sub3 단위는 아직 모델 검수를 수행하지 않았고, 완성 semantic receipt도 없다. 문항·계획·비교은행·공통 코드 변경은 0건이다.
