## 내용 검토와 배점

담당 agent가 10물음·62개 기준을 원문 줄 범위와 대조했다. 물음마다 최소 충분 답안, 배점 이유, 가까운 기존 물음과의 차이를 [agent 검토 장부](agent-review.json)와 [조사 장부](research.json)에 남겼다. 사람의 직접 검수나 별도 유료 API 의미검수는 아니다.

- 선택관계를 보존했다. 해지와 의견거절은 실행가능성·법규 조건에 따른 대안이고, 법적 조언 등을 모든 경우의 의무로 바꾸지 않았다.
- 원인별 감사범위 제한 예시(705.A10–A12)는 일부를 고르게 하면 모두 작성 원칙과 충돌하므로 원인과 시사점만 채점한다.
- 열거 항목과 결합요건을 구분했다. 감사인선임위원회 승인과 감사의 선정은 1점, 외부감사법 제31조제7항의 금융기관 다섯 호는 한 범주 1점, 600.41의 괄호 설명은 해당 항목의 범위 설명으로 처리한다.

## 실제 채점

운영 채점 함수와 독립 물음 투영으로 물음마다 저장 모범답안·부분정답·0점 오답을 한 건씩 실측했다. 빈 답안은 API 호출 없이 0점임을 확인했다.

- **초회(run-v1) 30건**: 점수 일치 27건, ±1점 이내 29건, 범위 밖 1건(`l01-sub2-partial`, 기대 3·실제 1).
- **원인**: L01/sub2 기준 문장이 발문이 이미 준 선정 대상(회계법인 또는 감사반)의 반복을 요구하는 것처럼 읽혔다. S03/sub2 crit1에는 괄호 설명이 비필수라는 표시가 빠져 있었다(−1). 두 곳 모두 기준 문구와 발문·배점 이유가 어긋나는 내용 결함이다. 판정에 함께 전달되는 설명만 보완했고 발문·모범답안·배점·원답안·기대값은 유지했다. [편차 분석](discrepancy-analysis.json)
- **재채점(run-v2) 6건**: 영향받은 두 물음의 대표답안 모두 일치.
- **최종 30건**: 점수 일치 29건, **30건 모두 ±1점 이내**. `s01-sub1-partial`의 −1점은 “증거를 입수할 수 없고”를 “충분하고 적합한” 수식어가 없다고 본 판정 편차다. 기준에 결함이 없어 수락했고 반복 호출하지 않았다.
- 재사용한 run-v1 24건은 현재 판본과 요청 본문·스키마가 같음을 확인했다. 수정 전 관측 6건도 원 실행 폴더에 보존했다.
- 실제 응답 36건: 입력 132,387토큰, 출력 16,165토큰(추론 3,997 포함), 캐시 입력 0토큰. 요청·응답 ID와 사용량을 보존했다. 사용자 금액 상한은 없었고 비용은 계산하지 않았다(0달러로 표시하지 않음).

## 재현

- `content.mjs`: 수동 제작 입력(원문 줄 범위·부분답안·배점 이유)
- `build.mjs`: 초안·계획·문제지·모범답안·검토 장부·대표답안 생성. 실측한 입력을 바꾸면 새 실행 버전으로 다시 확인한다.
- `verify-and-grade.ts`: 무호출 사전검사. `--run --run-id=<새 ID>`일 때만 실제 API를 호출한다. `--only`로 대상을 제한한다.
- `finalize.ts`: 실제 원응답의 요청·스키마·점수를 현재 판본과 대조해 receipt를 만든다.
- `update-coverage.mjs`: 초안 대상 coverage 관계 추가.
