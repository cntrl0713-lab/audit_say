# 13물음 정본·운영 앱 반영

사용자가 승인한 기준서형 독립 물음 **13개·62점**을 정본과 운영 학습 DB에 게시했다. 현재 정본은 **161세트·377물음**이다. 기존 155세트의 내용·운영 판본·승급 이력과 기존 풀이 기록을 보존했다.

- [운영 학습 화면](https://audit-say.vercel.app/quiz), [커리큘럼](https://audit-say.vercel.app/curriculum): HTTP 200 응답에서 새 독립 학습 ID 13개 모두 확인
- [운영 확인 기록](app-verification.json): 기준서형·한 물음·사례 지문 없음·합계 62점·정답 필드 비노출 확인
- [운영 DB 등록 영수증](db-applied.json): 릴리스 `8209dfd6-fd2c-452e-83ea-b2ffa967f592`, 공개본 및 정본 원바이트 일치
- [정본 편입 기록](install-completion.json), [사용자 승인](authorization.md), [승급 근거](batch.json)

담당 agent 내용 검토와 기존 Luna 실제 응답 39건을 원 요청·스키마·답안·기대값·출처·결과까지 대조하여 새 수락 형상으로 재처리했다. 새 모델 호출은 0건이며, 과거 38건 점수 일치·39건 모두 ±1점 이내라는 결과와 1점 과소채점 반례를 보존했다. 사람의 직접 내용 검수로 표시하지 않았다. 다른 세 배치의 43물음은 이번 게시 대상에 포함하지 않았다.

검수·게시 승급, 공개본·암호화본 생성, 정본 전체 검사, DB 등록 전 전체 검증 및 등록 후 원바이트·공개본 왕복 대조를 수행했다. 새 관계 3개를 동일한 내용의 정본 대상으로 연결하고 분석·wiki 빌드와 검사를 통과했다. [코드 검사](code-checks.json)에 변경 관련 테스트 50개·5개, 타입·lint 확인 및 중단한 광범위 회귀 검사를 구별했다. 전체 테스트 완료로 주장하지 않는다.

검증 도구는 지정되지 않은 예산을 `null`로 기록하도록 보완했다. DB 등록 도구의 검증 한도를 60초에서 300초로 늘리고 실행 시간·종료코드·시간초과를 구별해 남겼다. 최초 준비 실패와 원 보고서는 보존했으며, [재개 검사](stage/db-readiness-v2.json)와 [실등록 검사](db-readiness.json)는 내용 검증을 생략하지 않고 통과했다. 첫 준비의 sidecar 경로 오기는 이전 publication-v1에 실패 기록과 함께 남겼다.

이 작업은 운영 DB 조회 경로에 대한 문항 게시이며 프런트엔드 재배포는 하지 않았다. 브라우저 조작·사용자 답안 제출을 통한 추가 채점은 수행하지 않았다. 기존 wiki의 긴 페이지 경고 10개와 다른 관계의 과거 `stale` 상태는 이번 새 관계와 구별했다.
