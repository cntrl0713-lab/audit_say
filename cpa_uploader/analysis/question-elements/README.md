# 원자료의 출제 요구사항 추출

`03_문제연습`과 `04_기출문제`에 실제로 실린 발문을 구체적인 요구사항으로 정리한 자료다. 요구사항을 고른 뒤 원래 사례·조건을 읽고 새 문제의 학습목표를 설계하는 데 사용한다.

원자료에는 연도별 해설 A의 「관련 주제」 표, OX 교재의 목차, 주제별 해설의 분류가 이미 있었다. 그러나 책 사이의 같은 기출을 연결하고 요구사항별 빈도를 집계하는 별도의 데이터는 없었다. 기존 wiki의 원자료 카탈로그는 페이지·기준서 문단을 찾는 색인이며, 현재 문제은행의 채점기준 목록도 이 여섯 교재에서 추출한 요소 목록과 다르다.

## 먼저 볼 자료

- [요구사항·상위 주제별 빈도](frequency.md): 기출 고유 물음 수, 요소 출현 합계, 출제 연도와 최근 출제.
- [원출제와 재수록 연결](deduplication.md): 같은 원시험을 어느 책의 어느 페이지에서 찾았는지 확인.
- [원문·재수록 확인 항목](review-queue.md): OCR·발문 해석·부분 재수록 범위를 더 확인할 수록 기록.
- `elements/01.md`부터 `19.md`: 구체 요구사항, 요소 ID, 출제 연도와 대표 원문. 빈도 표의 주제 링크로 이동한다.
- [통합 JSON](question-elements.json): 모든 발문 인용·위치·원출제 식별·요소·원자료 단위 ID·보류 사유.
- [wiki의 활용 안내](../../wiki/question-generation/question-elements.md): 새 출제 계획과 연결하는 방법.

합계 6파일·3,027원문 페이지다. 페이지는 Markdown의 `## 원문 페이지 N` 기준이며 인쇄 면수와 다를 수 있다. 원자료는 수정하지 않았고 각 파일의 SHA-256으로 추출본의 근거를 고정했다. 파일별 발문 추출·재검토 현황은 재생성되는 [빈도 보고서](frequency.md)의 검토 범위에서 확인한다.

기출 교재에는 저자가 기준 변화에 맞춰 수정한 `[기출변형]`도 있다. 따라서 이 자료는 **교재에 수록된 기출 요구의 빈도**다. 공식 시험 원본과 모든 발문의 무변형 일치를 확인한 데이터로 해석하지 않는다.

## 요소와 빈도 단위

요소는 「후속사건」 같은 큰 주제보다 좁은 요구사항이다. 예를 들어 「보고서일 후·발행일 전 사실 인지 시 조치」와 「발행 후 사실 인지 시 조치」는 시점이 달라 분리한다. 사례형 판단은 판단을 바꾸는 주체·가족관계·거래·시점 등을 라벨에 보존한다. 하나의 요구에서 열거할 정답 항목 수가 많다고 그 정답 수만큼 출제 횟수를 늘리지 않는다. 오류를 골라 수정하는 문제는 실제로 검토하게 하는 보기의 조건을 추출하며, 라벨이 그 보기의 옳고 그름을 확정하는 것은 아니다.

| 지표 | 계산 |
|---|---|
| 요소별 기출 빈도 | 같은 요소의 고유 `cpa_exam:연도:문제:물음` 수 |
| 출제 연도 수·최근 연도 | 해당 요소가 확인된 서로 다른 연도와 마지막 연도 |
| 주제별 기출 고유 물음 | 해당 주제의 요소가 한 개 이상 있는 원기출 물음 수 |
| 주제별 기출 요소 출현 합계 | 주제 안 요소별 기출 빈도의 합; 한 물음의 여러 요구를 포함 |
| 확인된 모의고사 빈도 | 연도·회차·문제·물음이 확인된 모의고사끼리 중복을 제거한 수 |
| 원문 수록 기록 수 | 재수록을 포함한 추출 증거의 개수; 중요도 빈도와 구분 |

2023년과 2025년에 같은 요구가 나왔으면 2회다. 같은 해의 서로 다른 물음에 나와도 각각 1회다. 같은 물음 안의 여러 세부항목, 저자 요약표, 다른 책에 재수록된 부분은 추가 횟수가 아니다. 여러 주제를 함께 묻는 물음이 있으므로 주제별 고유 물음 수를 모두 더한 값은 전체 고유 물음 수와 다를 수 있다.

## 중복 처리

1. 원시험 연도·문제·물음 또는 모의고사 연도·회차·문제·물음을 우선 연결한다. 모의고사 회차를 생략하여 서로 다른 시험을 합치지 않는다.
2. `고급`과 `주제별`의 같은 문제, 한 책 안 PART 1·PART 2의 재수록, 기출 해설서 사이의 같은 원기출을 한 출제에 연결한다. 원문과 개별 수록 위치는 모두 보존한다.
3. 연도별 해설 A의 실제 발문이 있는 기출은 그 요구를 대표로 집계한다. 주제별 책이 원래 물음 중 일부만 옮겼거나 더 넓은 제목을 붙였더라도 원시험에 없는 추가 요소·횟수를 만들지 않는다.
4. 표현이 다른 동의 요구사항은 [normalization.json](normalization.json)의 검토된 별칭으로 연결한다. 주제가 같거나 단어가 겹친다는 이유만으로 서로 다른 조건을 합치지 않는다.
5. 원출제가 확인되지 않은 연습 기록은 확정 기출·모의고사 빈도에 넣지 않는다. 동일 문장만 있는 경우에도 공통 사례가 다를 수 있으므로 중복 검토 후보로 남긴다. 이것은 새 출제가 확인되었다는 뜻도, 중복이 완전히 해소되었다는 뜻도 아니다.

빈도는 교재에서 확인한 출제 반복을 보여 준다. 출제 연도 분포·최근 연도와 함께 보고, 앞으로의 출제확률이나 공식 중요도 점수로 바꾸어 해석하지 않는다. 원출제 미확정 기록이나 아직 합쳐지지 않은 동의 표현이 있으므로 0회는 미출제를 뜻하지 않는다.

## 저장 구조와 재현

| 파일 | 역할 |
|---|---|
| `extract-past-exam.mjs` / `extract-practice.mjs` / `extract-ox.mjs` | 원문 발문 경계·원출제·연속 인용 추출 |
| `extract-practice-reprints.mjs` / `practice-reprint-missing.json` | 연습서 재수록의 실제 사례·원시험 번호 대조와 보정 overlay 재생성 |
| `past-exam-curated-*.mjs`, `practice-curated.mjs`, `curation-*.json` | 실제 사례와 발문을 대조한 요구사항 보정·비발문 제외; 생성 답안이 아님 |
| `past-exam.json` / `practice.json` / `ox.json` | 재현 가능한 자료군별 추출본과 원문 해시 |
| `normalization.json` | 확인한 동의 표현과 명시적인 재수록 그룹; 자동 키워드 통합 금지 |
| `../../questionElements.mjs` | 인용·해시 검증, 보정 적용, 원자료 단위 연결, 중복 제거·집계·문서 생성 |
| `question-elements.json` | 전체 데이터. `records`, `elements`, `occurrences`, `question_groups`, `excluded_records`, `unresolved` 포함 |

저장소 루트에서 순서대로 실행한다. 이 명령은 외부 모델을 호출하거나 새 문제를 만들지 않는다.

```sh
node cpa_uploader/analysis/question-elements/extract-past-exam.mjs
node cpa_uploader/analysis/question-elements/extract-practice.mjs
node cpa_uploader/analysis/question-elements/extract-practice-reprints.mjs
node cpa_uploader/analysis/question-elements/extract-ox.mjs
node cpa_uploader/questionElements.mjs
node cpa_uploader/questionElements.mjs --check
npx tsx --test tests/questionElements.test.ts
node --test cpa_uploader/analysis/question-elements/extract-past-exam.test.mjs
```

검증기는 원자료 바이트 해시, 실제 인용·줄·페이지, 고유 기록 ID, 보정 대상·해시, 주제 ID, 원자료 단위 연결을 확인한다. `--check`는 입력을 읽어 같은 계산을 수행하며 출력 파일을 쓰지 않는다. 해시나 보정 대상 ID가 바뀌면 원문을 다시 대조해야 한다. 검증 통과 자체가 모든 동의 표현의 통합이나 해석의 완전성을 증명하지는 않는다.

`status: extracted`는 실제 요구를 추출했다는 뜻이다. 원출제 식별 여부와는 별개이며 정답·현행 기준을 승인한 상태도 아니다. `needs_review`는 발문 경계·OCR·조건 해석 등에 확인이 필요하다는 뜻이다. 추출기의 `unresolved`에는 원출제·페이지 경계 점검 메모도 포함되므로 그 배열 길이를 누락 문제 수로 읽지 않는다.

요소의 `catalog_status: extracted`는 적어도 하나의 실제 발문에서 확인한 라벨이다. 저자 요약 또는 미확정 기록에만 있는 `candidate_only` 라벨도 JSON에는 보존하지만 주제별 요소 목록에 넣지 않는다. 출제 요구 자체를 확인한 것과 그 요소가 실제 시험에 몇 번 나왔는지는 별개의 판단이다.

## 새 문제 제작에 사용하기

요소 ID로 `occurrences`를 찾고 연결된 `record_id`의 실제 발문과 공통지문을 읽는다. `source_unit_ids`와 `context_source_unit_ids`는 기존 원자료 카탈로그의 단위 ID이며 [원자료 기반 설계 지침](../../wiki/question-generation/source-authoring-design.md)의 `adapt_existing_question` 계획서에 연결할 수 있다.

그 다음 새 학습목표·조건·예외·필수 답안 범위를 정하고 공식 기준 및 적용 판본을 대조한다. 원자료의 계산 요구와 일부만 작성하는 과거 조건은 역사적 요구로 보존하되, 새 문제에는 현재 wiki의 출제 정책을 적용한다. 해설에만 있는 지식을 원래 발문이 물은 요구로 추가하지 않는다. 이번 산출물은 문제 후보와 빈도 분석 자료이며 신규 문제·모범답안·채점기준은 포함하지 않는다.
