# 출제·검토 분석 자료

추출·보정·연결·검수에 쓰는 기계 판독 자료와 그 자료에서 생성한 조회 문서를 관리한다. 현재 전체 흐름은 [wiki 출제·검토 현황](../wiki/_meta/authoring-dashboard.md), 역할과 갱신 원칙은 [자료 관리](../../docs/출제-검토-자료-관리.md)에서 확인한다.

| 묶음 | 소유 자료 | 사람이 수정하는 부분 |
| --- | --- | --- |
| [question-elements](question-elements/README.md) | 원발문·원출제·재수록 연결과 요구사항별 빈도 | 추출기, 정규화·보정 입력. 통합 JSON과 빈도·요소 Markdown은 생성 |
| [coverage](coverage/README.md) | 기준서 요구·추출 요소·은행 criterion의 관계와 현재 현황 | `links.json`에 관계·근거·검토 상태·입력 해시 기록. `registry.json`·`summary.md`·`topics/*.md`는 생성 |
| [reviews](reviews/) | 주제·은행 단위 검토 장부·채점 사례·실행 증거 | 실행별 입력과 판단 기록. 이전 실행 결과를 보존하고 후속 검토를 추가 |

문항 정본과 원자료는 `../data/`, 개별 제작 배치의 문제·계획·출처 패킷·QA·검수 receipt는 `../drafts/`에 둔다. 사람이 읽는 결정·보고 이력은 `../../docs/`에 둔다. 생성 Markdown은 해당 분석 결과와 함께 유지할 수 있다.

## 갱신과 확인

- 입력·보정 자료·관계 판단의 소유 위치에서 수정한 뒤 생성한다. 상세 파일 계약은 각 묶음 README를 따른다.
- 관계를 새로 확인할 때 실제 발문·답안·criterion·공식 근거와 판본을 읽는다. 자동 연결을 의미상 커버리지 승인으로 바꾸지 않는다.
- 현재 현황은 현재 입력 해시로 확인한다. 과거 검토 장부는 당시 입력 해시와 실행 방법을 유지하고, 변경된 계약의 재검토 결과를 별도로 남긴다.
- 서로 다른 실제 시험 물음은 각각 보존하고 교재 재수록만 동일 원출제로 연결한다. 기출·모의·연습 수록 수, 문항 수, 커버리지와 검수 상태를 섞지 않는다.

저장소 루트에서 실행한다.

```sh
npm run analysis:build
npm run analysis:check
npm run wiki:build
npm run wiki:check
```

이 명령은 현재 연결 분석과 wiki 산출물의 갱신·일치 검사다. 발문 추출을 바꿨다면 [question-elements의 재현·검증 명령](question-elements/README.md#저장-구조와-재현)을 먼저 적용한다. 의미검수·실제 모델 채점·문항 승급은 각 작업의 별도 절차로 수행한다.
