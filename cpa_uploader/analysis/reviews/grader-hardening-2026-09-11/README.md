# 채점기 ID 제한·검수 변경 후속 검토

- `original-regressions.json`: 원자료·발문·전체 답안 문맥에서 정한 수동 회귀 입력. 과거 사례 교체로 빠진 원답안과 교체답안의 기대값을 구분한다.
- `run-live.ts`: 현재 은행의 8세트와 pilot-05-008 별도 초안을 읽어 모범답안 9건, 원/교체 답안 4쌍 각 3회를 실제 채점한다.
- `live-r1/input-snapshot.json`: 준비 중 초안의 배열 형식을 잘못 읽은 시도. 모델 호출 전에 중단했고 검증 결과로 사용하지 않는다.
- `live-r2/`: 실제 요청·응답·정규화 판정·점수·코드 해시 및 입력 snapshot. 33호출의 당시 결과이며 미래 실행의 무오류를 보증하지 않는다.
- `live-r3/`: 추가 개선 후 실제 모델 33회 실행. 「문제 출제」에서 명확화한 판정 지시를 보존한 현재 채점 코드의 표본 검사다.
- `followup-version.json`: 공통 코드 확정 버전·파일별 해시·검증 범위·재개 조건. 과거 실행 잠금을 대신 덮어쓰는 파일이 아니다.
- `followup-policy-snapshot.json`: 확정 버전의 채점 프롬프트 함수·의미검수 지시 스냅샷. 기존 판정 지시의 보존 여부를 대조하기 위한 자료다.
- `followup-tests.log`: 추가 개선 후 전체 테스트 실행 기록.
- `review-context.json`: 원보고서의 길이·SHA-256과 검토 당시 은행/승급 장부 해시. 원보고서에는 후속 링크만 덧붙이고 기존 바이트를 보존했다.

설명·정정과 검증 결과는 [후속 보고서](../../../../docs/reports/채점기-ID-제한-보고서와-관련-변경의-후속-검토-2026-09-11.md)에 기록한다. 이 폴더는 검토 증거이며 신규 승급 receipt나 사람의 승인 기록이 아니다. API 키는 기록하지 않는다.

추가 개선·지침 반영과 실측 재개용 확정 버전은 [추가 후속 보고서](../../../../docs/reports/채점-검수-추가-개선과-공통-코드-확정-2026-09-11.md)에 기록한다.

새 실측은 저장소 루트에서 `npx tsx --env-file=.env.local cpa_uploader/analysis/reviews/grader-hardening-2026-09-11/run-live.ts live-새이름`으로 실행한다. 이름은 영문 소문자·숫자·하이픈만 사용하며 기존 결과를 덮어쓰지 않는다. 원답안·교체답안·기대값을 바꾸면 새 검토 근거를 기록한다.
