# 고정 비교 은행 이후 실제 검증

배정 common.md와 제작·검토 스킬을 이어받는다. 이 파일은 실행 절차이며 통과 증거가 아니다. 사용자가 승인한 범위는2027년 CPA 시험 대비49세트131물음의 초안 제작·보완, 실제 의미검수·채점·불일치 수정이다. 세 담당자를 재사용하며 동시 담당자는 최대3명이다.

## 입력과 쓰기 소유권

총괄이 보내는 최종 manifest의 세트·plan·작성자QA·출처 경로 및 SHA-256을 사용한다. 비교 은행은 총괄이 새 경로에 고정하며 초기111개 조사본이나 과거 중간 은행을 사용하지 않는다. 공통 코드·공식자료·판본 정책은 총괄만 수정한다. 각 담당자는 배정한 전용 폴더에만 쓰고 이전 실행 파일을 덮어쓰지 않는다.

의미검수 모델과 실제 채점 모델은 현재 환경의gpt-5.6-luna, 이번 의미검수 명시 입력 예산은500000자다. 기본CLI160000자는 유지한다. `node --env-file=.env.local --import tsx`로 실행하고 키·환경 원문을 출력하지 않는다. `run-review.ts`가 이번 모델과 예산을 명시한다. 배치 고정 이후 설정을 임의로 바꾸지 않는다.

## 세트별 실행

1. 최종 파일·계획 경로를 manifest에서 선택한다. R02의 계획 파일명은pilot-05-008.authoring-plan.json이다. 작성자가 쓴 수동 근거 패킷을 생성기source-packet인 것처럼 `--packet`에 넣지 않는다. 생성기 자동 패킷 계약이 실제로 있는 파일에만 해당 옵션을 쓴다.
2. 실제 의미검수는 기존CLI를 사용한다. 예: `node --env-file=.env.local --import tsx cpa_uploader/analysis/reviews/delegated-authoring-2026-09-11/run-review.ts --file <문항> --plan <계획> --bank <고정은행> --output <새실행경로/semantic.json>`. chunks원시 로그와 실패를 보존하고, fail/uncertain을형상 성공으로 통과 처리하지 않는다.
3. 의미검수 receipt가 생성되면 생성 사례를 실제 채점한다. 같은 입력에 `--review-input <semantic.json> --grade-cases --output <다른새경로/graded.json>`을 사용한다. 의미검수 실패 항목이 있어도 채점 가능한 사례의 실제 동작은 별개로 조사한다.
4. 모든 작성자 QA는 `node --env-file=.env.local --import tsx cpa_uploader/analysis/reviews/delegated-authoring-2026-09-11/run-author-qa.ts --file <문항> --qa <작성자QA> --output <새전용폴더>`로 실제gradeQuestionSetV3에서 실행한다. 모든 물음·criterion의 사전 사례가 대상이며 같은세트 모범답안이 의미검수 생성사례와 중복되어도 유형별 범위를 숨기지 않는다. 빈답안은 production경로의 무모델0점 실행으로 별도 집계한다.
5. 작성자QA 도구는 불일치 사례를 동일 설정으로 총3회 확인한다. 생성사례 채점의 불일치는 별도로 총3회 확인하고 원시 판정→인용검증→보안보정→최종합산 중 실패 위치를 조사한다. 통과할 때까지 무근거 반복하지 않는다. 서로 독립된 두 세트 작업을 병렬 실행할 수 있으나 실행장애 시 신규 호출을 멈추고 진행 중 호출의 로그를 보존한다.

## 발견과 수정

문항·원문·계획 수정이 필요하면 먼저 전용폴더의 별도 결함 장부에 ID·실제답안·기대값·관측결과·3회 증거·공식 근거와 수정안을 기록하고 총괄에게 전달한다. 동시에 실행 중인 입력을 덮어쓰지 않는다. 총괄이 다른 작업의 호출 상태와 비교은행 영향을 확인한 뒤 수정 시점을 조정한다. 수정 후 새 버전으로 의미·실제 채점을 다시 확인하며 비교은행 변경의 전역중복 영향과receipt 유효성을 다시 판단한다. 옛receipt의 해시만 갈아 끼우지 않는다.

작성자 기대값 오류도 모델 결과에 맞추지 말고 원문·발문·답안 전체로 판단한다. N05의sub3/omit-1은 최초선정 문장을 삭제해도 선택변경 조치가 선정을 함축하므로 실제모델 실행 전 독립검토로7점의함축사례로 정정했다. 이전QA와근거는n05-implied-selection-followup.json에 보존했다.

## 인계와 결과

세트마다 실제 모델 의미검수 단위수·판정, 작성자QA 고유사례/비빈답안모델호출/빈답안/재실행수, 생성사례 실측수, 불일치와원인·수정·재채점, 최종입력해시·증거경로를 남긴다. 미실측·실패는 검증미완료로 정확히 구분하며 비용이나시간이 오래걸린다는 이유로 초안준비만완료하고 멈추지 않는다. 복구할 수 없는 실제환경장애·해결되지 않은판정은 관측근거와재개조건을 남긴다.

초안의needs_review/needs_human_review상태는 유지한다. 사람확인·정본편입·게시·DB·배포는 수행하지 않는다.
