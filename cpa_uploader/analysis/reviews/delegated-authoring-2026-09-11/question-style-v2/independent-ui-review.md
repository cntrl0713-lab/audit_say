# 유형별 초안 탐색 독립 읽기 검토

2026-09-11 · 검토자 `plan_procedures` · 로컬 읽기 및 데이터 대조 · API 0회

현재 선택된 파일에서 수정이 필요한 결함을 발견하지 않았다. 사용자가 정한 “기준서형은 사실관계 없이 독립적으로, 사실관계가 있는 문제에는 사례형 물음만”이라는 표시 구조가 구현되어 있다. 아래 결과는 코드·자료의 독립 대조이며 실제 브라우저 동작, 모델 의미검수·채점 또는 사람 승인을 의미하지 않는다.

## 검토 범위

- `app/quiz/draft-preview/page.tsx`
- `app/quiz/draft-preview/draftPreviewData.ts`
- `app/quiz/draft-preview/catalog/page.tsx`
- 이 폴더의 `index.json`, `learning-groups.json`
- 로더가 선택한 `final-153-style-v2/manifest.json`과 49개 실제 문항 파일; 계보 대조용 `final-153-structure-v2/manifest.json`

두 페이지는 함수 시작 시 development 이외 환경에서 `notFound()`를 실행하며, 로더도 development 확인 뒤에만 파일을 읽는다. import 시점의 파일 읽기는 없다. 검사한 세 코드 파일에는 채점·제출 action, API 요청, DB 접근 또는 원문 쓰기가 없다.

로더는 index가 선언한 manifest SHA-256과 실제 manifest 바이트를 비교한다. learning-groups의 실제 해시 및 그 manifest 해시도 index와 결속하며, 모든 선택 문항의 파일 해시·세트 ID와 물음별 단일 분류를 확인한다. 독립 대조에서도 이 결속과 분류 원본 4파일의 해시가 모두 일치했다.

전체 132물음은 원본 세트·물음 ID를 유지하여 정확히 한 학습 묶음에 나타난다. 각 묶음의 물음은 현재 원문에서 해당 유형만 선택한 결과와 내용·순서가 완전히 같다. 이전 structure-v2 선택본과 대조한 criterion, 모범답안, requirement도 모두 동일하다. 따라서 이번 분류·독립 발문 적용으로 채점 명제가 추가되거나 삭제된 차이는 발견하지 못했다.

## 사용자 정의와 표시

기준서형 64개 발문을 읽었다. 일반 적용조건과 필요한 기준서·판본 범위를 발문에 포함하며, 특정 회사·이전 물음·보고서 초안을 별도로 읽어야 답할 수 있는 미해결 참조는 발견하지 못했다. 각 기준서형 발문은 index의 `standalone_prompt`와 같고 공통 사실관계는 빈 배열이다. 사례형 묶음은 원 세트의 공통 사실관계를 보존하고, 그 묶음에는 `case`로 분류된 물음만 있다. 이 확인은 학습 분류·독립성에 관한 것이며 모든 공식 근거를 새로 의미검수한 결과는 아니다.

상세 화면의 전체 혼합 탭은 제거되었다. 표시할 한 유형의 묶음만 선택하고, 사실관계는 사례형에서만 표시한다. 목록도 같은 유형의 물음만 보여 준다. 세트·물음 ID와 링크 anchor는 보존하고 화면 번호는 각 독립 학습 묶음 안에서 1부터 매긴다. index의 OX 순서는 `02,01,03,04,08,06,07,09,05,11,13,10,12,15,16,14,17,18,19`이며 로더가 이 순서 후 계획 ID 순서로 정렬한다.

T08-C는 기준서형 `sub2/sub4/sub3`의 3물음·19점과 사례형 `sub1`의 1물음·3점으로 분리된다. 기준서형 사실관계는 0개, 사례형은 원래 5개다. 합계는 기존 4물음·22점이며, 원본 물음 ID와 내부 계보를 변경한 것이 아니다.
