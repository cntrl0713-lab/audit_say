# 지시 경계 진단의 한계와 후속 선택

원 T12-A 문항과 `q2/omit-1` 답안, v4의 입력·스키마·모델을 유지하고 SDK의 상위 지시에서 배점계약과 사용자 답안을 구분하는 제안만 바꾸었다. 기대점수나 정답 판정은 모델에 넣지 않았다. 실제 SDK 호출 3회의 원시 결과는 목표 c1에서 `not_met / not_met / met`였다. 이 진단은 `gradeQuestionSetV3`의 생산 실행이나 정식 receipt가 아니다.

입력 지시의 신뢰 경계를 명료화하는 것만으로 관측된 함축 오판을 해결하지 못했으므로 이 제안을 공통 코드에 적용하지 않는다. T12-A의 claim 명료화 실험본도 같은 반례에서 3회 모두 오판이 남았으며, 활성 문항은 기존 문항으로 유지한다. 원문 560.A13 및 기존 명시 허용 범위에 따른 기대 5점은 바꾸지 않는다. v4 생산 실행의 4/4/4점 불일치는 미해결로 남긴다.

관련 원 입력과 코드·자료·요청·스키마 해시는 `inputs.json`, 세 응답은 `response-1.json`부터 `response-3.json`에 보존한다. 최초 실행의 TypeScript top-level await 변환 오류는 API 호출 전에 발생했다. 실행 함수를 감싼 뒤 위 3회 진단을 수행했으며, 이 로컬 도구 수정은 생산 채점 코드 변경이 아니다. 같은 설정을 통과할 때까지 반복하지 않는다.
