# 최소 API 채점의 추가 허용

사용자가 배점 적용 작업 중 “필요하면 최소한으로 api채점해도 돼”라고 허용했다. 앞선 API 중지 상태에서 수행한 제작·로컬 검사 기록은 그대로 보존한다. 이번 허용은 전체 의미검수·작성자 QA·생성 QA 실행 재개로 해석하지 않는다.

총괄만 새로운 입력 선택과 실행 잠금을 만든 뒤 다음 대표 사례를 실제 생산 채점 함수로 확인한다.

1. T19-A 중요성 물음의 판단만 맞는 답안: 1점.
2. T19-A 판단과 중요성의 기초가 맞는 답안: 2점.
3. T19-A 근거가 판단을 함축하고 세 요구를 충족하는 답안: 3점.
4. T08-C 가정·방법의 네 특성은 맞고 자료 검토를 부정한 답안: 독립 부분 4점.
5. T09-C 두 발동조건은 맞고 AND 관계만 틀린 답안: 조건 식별 2점.
6. T18-A 지문의 숫자만 반복하는 답안: 0점.
7. T12-B 가능한 의견 종류 중 한 가지만 제시한 답안: 1점.

최초 계획은 비어 있지 않은 대표 답안 7개다. 각 실행은 `--only`로 하나의 사례를 선택하며 원 QA와 기대값을 먼저 고정한다. 불일치가 생긴 해당 사례만 기존 실행기의 총 3회 확인 규칙을 적용하고, 그 뒤 다른 사례로 넘어가기 전에 원인과 추가 호출 필요성을 판단한다. 연결·잔액·인증 오류 시 추가 실행을 중지한다. 원시 응답과 모든 실패를 보존한다.

새 비교 은행의 전체 실제 의미검수와 전체 QA 채점은 여전히 미실행이다. 대표 사례 통과로 전체 검증 완료를 선언하지 않는다. 공통 채점 코드·정본·공개본·배포는 변경하지 않는다. 서브에이전트는 로컬 검토만 수행한다.
