# 승인된 요소별·서술 부분점수 적용 계약

사용자는 열거 요소별 배점·서술 독립 내용별 부분점수·판단과 근거의 구별 방식을 적용하고 문제별 배점 타당성도 점검하도록 승인했다. API 중지 지시는 유지한다. 실제 모델 호출은 0회로 진행한다. 문항·배점의 로컬 후속 수정과 정적 검증이 이번 단계 범위이며 정본·공개본·운영 DB·배포는 범위 밖이다.

## 입력과 쓰기 소유권

- 활성 49세트는 `../final-153-v3/manifest-plan-followup-02.json`, 작성자 QA는 `../active-qa-overrides-v3-plan-followup-02.json`의 override 우선 선택이다. T11-B/T17-B의 최신 계획을 반드시 이어받는다.
- 기존 배정서와 `docs/plans/question-authoring-by-topic-2026-09-11/assignments/서브에이전트-공통-작업-계약.md`, 검토 스킬, 자기 주제 wiki, 원문과 직전 배점 보고를 읽는다. 사용자 승인과 본 후속 계약이 이전 제안·중지 단계의 문항 수정 금지보다 최신이다. API 중지는 그대로다.
- 각 담당자는 자기 패키지 폴더에만 쓴다. 새 산출물은 `<package>/point-policy-v1/<plan-id-lower>/` 아래에 둔다. 기존 파일·로그·receipt는 덮어쓰지 않는다. 공용 source·wiki·coverage·manifest·채점 코드·정본은 총괄만 관리한다.
- 모든 세트·물음 ID는 유지한다. 기존 criterion ID도 재번호화하지 않는다. 기존 복합 기준의 첫 명제를 기존 ID에 남기고 추가 명제는 세트에서 사용하지 않은 criterion ID를 새로 할당하며 명시적인 전후 대응표를 남긴다. 조건·출처·대안·원래 답안 범위를 보존한다.

## 검토·수정 기준

모든 담당 물음에 대해 발문 → 필수 정답 → 독립 명제 → 정수 배점 → 공식 근거를 읽고 변경 또는 유지 이유를 남긴다. 이전의 11세트·27점 후보만 처리하고 끝내지 않는다. 점수는 결과에서 집계하며 잠정 총점에 맞추지 않는다.

1. 열거형은 요구된 독립 요소를 각각 기본 1점으로 평가한다. 명칭만 묻는 경우 명칭으로 충분하다.
2. 서술형은 실제 요구한 독립 내용·행위·관계·이유를 각각 기본 1점으로 평가하여 0..n 정수 부분합산을 가능하게 한다. 모든 문항에 핵심·방법·이유라는 세 항목을 기계적으로 붙이지 않는다.
3. 판단과 독립된 근거를 모두 요구하면 나누되, 옳은 근거·조치가 판단을 명확히 함축하면 결론 문구 반복을 강제하지 않는다. 명시적 반대는 해당 판단에 적용하고 다른 정확한 독립 명제의 점수는 보존한다.
4. 주어진 사실·조건의 단순 반복, 해설의 부가 지식, 동의 표현·대안·예시·같은 의무의 긍정/부정에는 중복 점수를 만들지 않는다. 단어 수와 접속사 수로 자동 분리하지 않는다. 필수 조건은 해당 명제에 붙인다.
5. 명제를 분리할 때 모범답안과 critical_facts, source_ref_ids, 계획의 요구 범위도 맞춘다. 범위 확대가 필요한 경우 임의 추가 대신 근거를 보고한다. 실제 핵심 요구를 축소해 낮은 점수에 맞추지 않는다.
6. 수정 문항은 needs_review/needs_human_review 유지. 과거 의미검수·실측을 새 문항의 검증 완료로 승계하지 않는다.

## QA와 로컬 검사

- 변경한 세트는 선택된 이전 QA의 모든 ID·원답안을 보존한 후속 QA를 만들고, 바뀐 criterion에 대한 기대값을 원문과 답안 전체에서 다시 판정한다. 복합 기준의 옛 not_met를 새 하위 기준 전부에 자동 전파하지 않는다.
- 새 criterion마다 완전 답안/동의표현/실제 누락/명시적 반대/조건 경계를 추가하고 각 물음의 빈답안·저장답안·한 문장/역순 및 함축 판단을 점검한다. 원답안을 없애고 명시적인 쉬운 답안으로 교체하지 않는다. 범위 변경 없는 QA 정정도 근거와 이전 값을 보존한다.
- 로컬 합산·정적 형상·원문 인용 대조를 실행하고 실제 모델 실측과 명확히 구분한다. `validate_draft_v3.ts`와 메모리 은행 검사는 API 없이 실행할 수 있다. 고정 원본을 쓰는 기존 생성기를 실행하지 않는다.

## 공통 인계 형상

담당 대표 폴더의 `point-policy-v1/handoff.json`에 다음 구조를 쓴다. 각 세트는 변경되지 않아도 반드시 포함한다.

```json
{
  "owner": "담당 이름",
  "api_calls": 0,
  "entries": [{
    "plan_id": "TXX-A",
    "set_id": "실제 ID",
    "changed": true,
    "question_file": "선택할 문항 경로",
    "plan_file": "선택할 계획 경로",
    "qa_file": "선택할 QA 경로",
    "lineage_file": "변경 이력 경로 또는 null",
    "questions": [{
      "id": "실제 물음 ID",
      "old_points": 1,
      "new_points": 2,
      "decision": "split 또는 retain 또는 refine",
      "rationale": "실제 발문과 독립 의미 단위에 근거한 구체 설명",
      "source_ref_ids": ["실제 근거 ID"],
      "criterion_mapping": [{"old_id":"crit1","new_ids":["crit1","crit7"],"reason":"분리 또는 유지 이유"}]
    }]
  }],
  "validation": {"api_calls":0,"checks":[],"model_revalidation":"not_run_user_paused"}
}
```

물음별 유지 이유도 구체적으로 적는다. 변경 QA의 각 원답안 전후 기대표 및 새 회귀 사례의 근거는 세트별 lineage/QA에 둔다. 총괄은 49/131 전수성, 점수 합산, ID·조건·근거·이전 답안 보존을 독립 검사하고 새 활성 선택·검토용 문제집·문제별 배점표를 만든다.
