# r07~r11 운영 반영 승인

2026-09-19 사용자 지시: "두 초안을 그대로 두고 전체 운영DB 대체 및 커밋 푸시 진행해줘", "업무 맡기고 자리 비울 예정이니까 운영DB적용이 어려우면 그 외 작업만 진행해줘"

"두 초안"은 직전 보고에서 새 사례형 기준(같은 기준에서 결론이 갈리는 두 경우를 한 사례에 함께 두지 않음)에 걸릴 수 있다고 물은 r06(이미 게시)과 r07이다. 둘 다 고치지 않고 현재 판본을 유지한다. "전체"는 초안 검증과 실측을 마치고 반영을 기다리는 r07~r11 다섯 회차다. r01~r04는 release `906ca962`, r05·r06은 release `31504e78`로 이미 반영했다.

앞서 사용자는 지정 검토의 운영 반영을 모아서 한 번에 하기로 정했다([배치 범위](../authorization.md)). 이 문서는 세 번째 묶음(r07~r11)의 반영 승인이다. 이전 authorization.md는 실행 manifest가 입력 해시로 고정하므로 고치지 않는다. 이번 반영은 새 authorization.md·plan.json·batches로 따로 실행한다.

- 정본·승급 장부·공개본·암호화본·학습 분류 입력과 카탈로그를 갱신하고, 운영 DB에 새 릴리스를 적용한다. 원 세트의 과거 판본과 풀이 기록은 보존한다.
- 사례형 세트 퇴역을 허용하는 DB 함수는 2026-09-16에 운영에 적용했다. 이번 묶음은 새 마이그레이션 없이 [기존 반영 기록](../publication/db-migration/completion.json)을 읽기만 한다.
- 운영 DB 명령은 로컬 PGlite 증명과 읽기 전용 확인을 먼저 거친다. 사용자가 자리를 비우므로, agent가 운영 명령을 실행할 수 없으면(자동 모드 분류기 차단 등) 운영 적용은 하지 않는다. 그 경우 사용자가 돌아와 실행할 명령과 준비 기록을 남긴다. 적용이 실패하거나 결과가 불명확하면 다시 적용하지 않고 읽기 전용으로 상태를 확인한다.
- 퇴역 세트를 가리키는 은행 대상 coverage 관계는 대체 문항으로 다시 연결하고 관계를 다시 확인한다. 퇴역 세트의 wiki 생성 페이지는 원 바이트를 보존한 뒤 제거한다.
- 게시 stage·기준·후보 사본과 운영 전송 SQL은 커밋하지 않는 `tmp/`에 두고, 기록에는 해시만 남긴다([문항 수정 패치 운영](../../../../../docs/문항-수정-패치-운영.md)). 대체된 판본(r10 v1)의 전체 은행 사본처럼 필요 없는 사본은 삭제하지 않고 저장소 밖 보관 폴더로 옮긴다.
- 반영 기록을 정리한 뒤 커밋·푸시한다.

모델 상향, 별도 유료 API 의미검수, 사람 확인은 이 승인에 포함되지 않는다. agent 검토는 작성·수정한 agent의 내용 대조이며 독립 교차검토로 기록하지 않는다.
