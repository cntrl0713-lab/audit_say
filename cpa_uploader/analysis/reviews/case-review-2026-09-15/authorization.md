# 사례형 지정 검토·수정 범위

2026-09-15 사용자는 사례형 문제를 전수로 검토하면서 수정할 점을 차례로 제시하겠다고 했다. 공통 지적은 다음 세 가지이며 제작·검토·수정 스킬에 반영하도록 요청했다.

- 모든 문제의 사실관계와 물음에 모범답안을 암시하는 요소가 있다.
- 개별 상황의 적합성을 묻기보다 여러 절차 중 잘못된 절차를 고르고 이유를 쓰게 한다.
- 2026년·2027년 대신 20X1년·20X2년으로 쓴다.

사용자는 한꺼번에 모든 문제를 고치지 말고 지정한 사례형 문제만 검토·수정 절차를 거쳐 바꾸라고 했다. 첫 지정은 55·18·19번(`case-14-component-evidence-gap-20260914`, `pilot-14-006`, `pilot-14-007`)을 한 문제로 합치는 것이다. 문제별 지시는 [수정 요청서](../../../../docs/case-question-edit-notes-2026-09-14.md)의 해당 항목에 기록했다.

## 이 배치에서 수행하는 범위

- 지침: 학습 단위 계약의 사례형 기준, 제작·검토 스킬, AGENTS.md.
- 문항: 새 초안 작성, agent 내용검토, 실제 Luna 대표 채점. 기존 프로젝트 정책(Luna 유지, 물음별 ±1점, 대표 답안 95% 목표, 내용 오류 허용 없음)을 이어받는다. 금액 상한은 지정되지 않았고 제공자 한도 오류에서 중단한다. 별도 유료 API 의미검수와 모델 상향은 하지 않는다.
- 이 대화에서는 정본·공개본·운영 DB 반영과 원 세 세트의 활성 릴리스 제외를 아직 승인받지 않았다. 해당 단계는 사용자 결정 뒤 별도 기록으로 진행한다.

## 이후 사용자 결정

- 두 번째 지정: 60·21번(`case-16-other-information-cause-20260914`, `pilot-16-011`)을 합치고 기타정보에 관해 물어볼 다른 요소를 더해 종합 문제로 만든다. 연도는 20X1·20X2로 쓰되 대상 연도는 2027년이다.
- 앞으로도 옳은 것과 옳지 않은 것을 구분하는 물음 위주로 구성하고, 수험생에게 후속절차나 이유를 너무 구체적으로 요구하지 않는다(이유나 보완절차를 간략히).
- r01도 새 기준으로 맞춘다.
- 운영 반영은 지정 검토를 모아서 한 번에 한다. 그때 정본·공개본·운영 DB 반영과 원 세트 퇴역(사례형 퇴역용 DB 변경 포함)을 함께 준비하며, 이 결정 자체가 개별 회차의 즉시 게시 승인은 아니다.

agent 검토는 작성한 agent가 수행한 내용 대조이며 사람의 직접 확인이나 독립 교차검토로 기록하지 않는다.
