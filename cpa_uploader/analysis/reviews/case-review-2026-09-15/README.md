[build-round2.mjs](tools/build-round2.mjs)는 설계 장부의 `classification_note`를 분류 사유에 쓰고(열거형 물음 등), [summarize-round2.mjs](tools/summarize-round2.mjs)는 `--actual`로 대표 실측 폴더를 지정한다. [record-r04-review.mts](tools/record-r04-review.mts)·[record-r04v2-review.mts](tools/record-r04v2-review.mts)는 r04 v1·v2, [record-r03v2-review.mts](tools/record-r03v2-review.mts)는 r03 v2, [record-r05-review.mts](tools/record-r05-review.mts)·[record-r06-review.mts](tools/record-r06-review.mts)·[record-r07-review.mts](tools/record-r07-review.mts)는 r05 v1·r06 v1·r07 v1 내용 검토를 한 번씩 기록한 도구다. r09부터는 [build-round3.mjs](tools/build-round3.mjs)가 전체 후보를 메모리에서만 검증하고 채점 입력에는 초안 세트만 담은 부분 은행과 그 분류 카탈로그를 쓴다(은행 전체의 최소 세트 수 규칙만 부분 은행에서 제외). [record-r09-review.mts](tools/record-r09-review.mts)는 r09 v1 내용 검토를 한 번 기록한 도구다. 같은 날 병행한 r10 v1은 build-round2.mjs로 전체 후보 사본을 만들었고 v2는 build-round3.mjs의 부분 은행을 썼다. [record-r10-review.mts](tools/record-r10-review.mts)·[record-r10v2-review.mts](tools/record-r10v2-review.mts)가 r10 v1·v2 내용 검토를 한 번씩 기록했다. r08도 build-round2.mjs로 전체 후보 사본을 만들었고, [record-r08-review.mts](tools/record-r08-review.mts)가 r08 v1 내용 검토를 한 번 기록했다. r11도 build-round2.mjs로 전체 후보 사본을 만들었고, [record-r11-review.mts](tools/record-r11-review.mts)가 r11 v1 내용 검토를 한 번 기록했다. r10 v3의 내용 검토는 [record-r10v3-review.mts](tools/record-r10v3-review.mts)가 기록했다. 실제 채점과 보조 실측은 `node --env-file=.env.local --import tsx …`로 실행해야 API 키를 불러온다.
