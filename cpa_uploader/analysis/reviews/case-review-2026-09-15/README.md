[build-round.mjs](tools/build-round.mjs)는 회차·판본을 인자로 받아 후보 은행·분류 입력·채점 manifest를 만들고, [summarize-round.mjs](tools/summarize-round.mjs)는 대표·보조 실측을 요약한다. [record-r02-review.mts](tools/record-r02-review.mts)는 r02 내용 검토를 한 번 기록한 도구다. [build-r01.mjs](tools/build-r01.mjs)는 execution-v1의 고정 입력이라 그대로 둔다. [run-supplementary.ts](tools/run-supplementary.ts)는 표적 사례를 운영 채점 경로로 실행한다. r04부터는 기록된 원본 도구의 바이트를 유지하려고 후속판을 따로 두었다. [build-round2.mjs](tools/build-round2.mjs)는 설계 장부의 `classification_note`를 분류 사유에 쓰고(열거형 물음 등), [summarize-round2.mjs](tools/summarize-round2.mjs)는 `--actual`로 대표 실측 폴더를 지정한다. [record-r04-review.mts](tools/record-r04-review.mts)·[record-r04v2-review.mts](tools/record-r04v2-review.mts)는 r04 v1·v2, [record-r03v2-review.mts](tools/record-r03v2-review.mts)는 r03 v2, [record-r05-review.mts](tools/record-r05-review.mts)·[record-r06-review.mts](tools/record-r06-review.mts)·[record-r07-review.mts](tools/record-r07-review.mts)는 r05 v1·r06 v1·r07 v1 내용 검토를 한 번씩 기록한 도구다. r09부터는 [build-round3.mjs](tools/build-round3.mjs)가 전체 후보를 메모리에서만 검증하고 채점 입력에는 초안 세트만 담은 부분 은행과 그 분류 카탈로그를 쓴다(은행 전체의 최소 세트 수 규칙만 부분 은행에서 제외). [record-r09-review.mts](tools/record-r09-review.mts)는 r09 v1 내용 검토를 한 번 기록한 도구다. 같은 날 병행한 r10 v1은 build-round2.mjs로 전체 후보 사본을 만들었고 v2는 build-round3.mjs의 부분 은행을 썼다. [record-r10-review.mts](tools/record-r10-review.mts)·[record-r10v2-review.mts](tools/record-r10v2-review.mts)가 r10 v1·v2 내용 검토를 한 번씩 기록했다. r08도 build-round2.mjs로 전체 후보 사본을 만들었고, [record-r08-review.mts](tools/record-r08-review.mts)가 r08 v1 내용 검토를 한 번 기록했다. r11도 build-round2.mjs로 전체 후보 사본을 만들었고, [record-r11-review.mts](tools/record-r11-review.mts)가 r11 v1 내용 검토를 한 번 기록했다. r10 v3의 내용 검토는 [record-r10v3-review.mts](tools/record-r10v3-review.mts)가 기록했다. 실제 채점과 보조 실측은 `node --env-file=.env.local --import tsx …`로 실행해야 API 키를 불러온다.

```sh
node --import tsx cpa_uploader/analysis/reviews/case-review-2026-09-15/tools/build-round.mjs --round r01 --version v2 --draft-dir cpa_uploader/drafts/case-review-2026-09-15/r01-group-audit-merge/v2 --set-id case-14-group-procedures-20260915 candidate
npx tsx scripts/build-learning-unit-catalog.ts --review cpa_uploader/analysis/reviews/case-review-2026-09-15/r01/classification-v2.json --output cpa_uploader/analysis/reviews/case-review-2026-09-15/r01/catalog-v2.json
node --import tsx cpa_uploader/analysis/reviews/case-review-2026-09-15/tools/build-round.mjs --round r01 --version v2 --draft-dir cpa_uploader/drafts/case-review-2026-09-15/r01-group-audit-merge/v2 --set-id case-14-group-procedures-20260915 execution
```

위 명령은 새 출력 경로에만 쓴다. 실제 채점 명령은 manifest SHA를 지정해야 하며 기존 출력이 있으면 중단한다. 정본·공개본·운영 DB 반영과 승급 receipt 봉인은 사용자 승인 뒤 새 기록으로 진행한다. 운영 퇴역 RPC의 검사 함수(`cpa_assert_reviewed_question_retirements`)는 기준서형 세트만 받았으므로, 모든 물음이 자기 세트의 사례형으로 분류된 세트도 받도록 [20260915090000 마이그레이션](../../../../supabase/migrations/20260915090000_cpa_reviewed_case_question_retirements.sql)을 두었다([PGlite 회귀](../../../../tests/cpaCaseQuestionRetirementsDatabase.test.ts)). 게시 도구는 묶음마다 [publication](publication/)(r01~r04), [publication-r05-r06](publication-r05-r06/), [publication-r07-r11](publication-r07-r11/)에 있다. r07~r11 도구는 r05·r06 도구를 옮기되 게시 stage·기준·후보 사본과 운영 전송 SQL을 커밋하지 않는 `tmp/`에 두고 기록에는 해시만 남긴다.
