[병합 종합문제 설계](../../../../docs/사례형-병합-종합문제-설계.md)의 **D등급**을 제작한 여덟 번째 묶음이다. 이로써 설계서 대상 40개를 모두 처리한다.

## D등급의 성격

설계서는 D등급을 "단독 유지 권장 — 이미 3물음·8~10점이거나 붙일 짝이 없다. **발문 형식만 선택형으로 바꾸는 갱신 대상**"으로 분류했다. 다만 대상 여덟 세트는 선택형 발문이 하나도 없고 사실관계에 번호 항목도 없어, 사실관계·발문·모범답안·criterion·requirements를 함께 다시 쓰는 **전면 재구성**이 되었다.

`cpa_uploader/corrections/` 경로는 게시 세트의 필드만 고치고 **물음 구성은 바꾸지 못한다.** 기준서형 분리가 필요한 회차가 있고 재작성 범위가 넓어 제작 경로를 따랐다: **원 세트를 퇴역시키고 새 세트를 만든다.** 저장소 선례와 같다("29 재구성 → `case-09-initial-audit-20260915`", "10 재구성 → `case-04-audit-documentation-20260917`").

A·B·C와 달리 **총점이 늘었다**(1,730 → 1,753). 합칠 요구가 없고 오히려 원 세트가 쓰지 않던 요구를 항목으로 더했기 때문이다.

## 운영 명령

운영 명령(`--prepare`·`--probe`·`--apply`)은 자동 모드 분류기가 agent 실행을 막으므로 **사용자가 터미널에서 직접 실행**한다. agent는 도구·범위·기록만 준비하고 결과를 장부에 옮긴다. 적용이 실패하거나 결과가 불명확하면 다시 적용하지 않고 읽기 전용으로 상태를 확인한다.

## 이 승인에 없는 것

모델 상향, 별도 유료 API 의미검수, 사람의 내용 확인은 포함되지 않는다. agent 검토는 초안을 만든 agent의 내용 대조이며 독립 교차검토나 사람 확인으로 기록하지 않는다. 게시 stage·기준·후보 사본과 운영 전송 SQL은 커밋하지 않는 `tmp/`에 두고 기록에는 해시만 남긴다.
