# r12 정본 반영 승인

2026-09-20 사용자 지시: "정본에 설치하고 원 두 세트 퇴역까지 진행해줘"

직전 보고에서 r12 초안(`case-10-analytical-procedures-20260920`, 68번과 32번의 병합, 2물음 7점)의 내용 검토와 대표 실측을 마치고 정본 미반영 상태임을 알린 뒤 받은 지시다. 앞선 묶음(r01~r04 release `906ca962`, r05·r06 release `31504e78`, r07~r11 release `2ed1a151`)과 달리 이번에는 회차 하나만 반영한다. 이전 authorization.md는 실행 manifest가 입력 해시로 고정하므로 고치지 않고, 이번 반영은 새 authorization.md·plan.json·batches로 따로 실행한다.

## 반영 범위

| 회차 | 새 세트(반영 판본) | 퇴역하는 원 세트 |
| --- | --- | --- |
| r12 | `case-10-analytical-procedures-20260920`(초안 v1, 실행 v1) | 68 `case-10-completion-analytics-20260914`, 32 `pilot-10-007` |

- 정본·승급 장부·공개본·암호화본·학습 분류 입력과 카탈로그를 갱신한다. 원 세트의 과거 판본과 풀이 기록은 보존한다.
- **운영 DB 반영은 이 승인에 포함되지 않는다.** 사용자 지시는 정본 설치와 원 세트 퇴역까지이며, 운영 active release는 `2ed1a151-547d-4cc1-bd57-0fe2e0d5a8d3` 그대로 둔다. 따라서 이 반영 뒤 정본과 운영 DB의 내용이 달라지며, 운영 반영은 별도 사용자 지시로 진행한다.
- 퇴역 세트를 가리키는 은행 대상 coverage 관계는 대체 문항으로 다시 연결하고 관계를 다시 확인한다. 초안 대상(`target.scope=draft`) 관계는 보존된 초안 파일을 가리키므로 바꾸지 않는다.
- 퇴역 세트의 wiki 생성 페이지는 원 바이트를 보존한 뒤 제거하고 새 세트의 페이지를 생성한다.
- 게시 stage·기준·후보 사본은 커밋하지 않는 `tmp/case-review-publication-r12/`에 두고 기록에는 해시만 남긴다([문항 수정 패치 운영](../../../../../docs/문항-수정-패치-운영.md)).

## 동시 작업 조율

같은 배치에서 다른 세션이 r13·r14·r15를 만들고 있다. 그 세션은 정본 설치 전에 후보 은행 빌드를 시작하지 않기로 했고(2026-09-20 세션 간 합의), 설치가 끝나면 신호를 받아 재개한다. `tools/build-round3.mjs`의 candidate 모드가 현재 카탈로그의 `source_file_sha256`과 정본 해시의 일치를 assert 하므로, 설치 순간에 걸쳐 있는 빌드가 없도록 시점을 맞춘 것이다. 이 반영은 r13~r15의 파일을 쓰지 않는다.

모델 상향, 별도 유료 API 의미검수, 사람 확인은 이 승인에 포함되지 않는다. agent 검토는 작성·수정한 agent의 내용 대조이며 독립 교차검토로 기록하지 않는다.
