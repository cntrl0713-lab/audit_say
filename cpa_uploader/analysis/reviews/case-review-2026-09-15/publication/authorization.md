# 사례형 지정 검토의 운영 반영 승인

2026-09-15 사용자 지시: “불필요한 파일은 아카이브에 넣고 지적했던 문제들 대체해서 운영Db적용해줘”

앞서 사용자는 지정 검토의 운영 반영을 모아서 한 번에 하기로 정했다([배치 범위](../authorization.md)). 이 지시는 그 반영의 실행 승인이다. 배치의 authorization.md는 실행 manifest가 입력 해시로 고정하므로 고치지 않고 이 문서에 기록한다.

## 반영 범위

사용자가 지적한 원 사례형 세트를 활성 릴리스에서 퇴역하고, 검토·실측을 마친 새 세트로 대체한다.

| 회차 | 새 세트(반영 판본) | 퇴역하는 원 세트 |
| --- | --- | --- |
| r01 | `case-14-group-procedures-20260915` (초안 v3, 실행 v4) | 55 `case-14-component-evidence-gap-20260914`, 18 `pilot-14-006`, 19 `pilot-14-007` |
| r02 | `case-16-other-information-20260915` (초안 v1, 실행 v2) | 60 `case-16-other-information-cause-20260914`, 21 `pilot-16-011` |
| r03 | `case-13-payroll-service-20260915` (초안 v2, 실행 v2) | 59 `case-13-type2-period-exceptions-20260914`, 30 `pilot-13-011` |
| r04 | `case-09-initial-audit-20260915` (초안 v2, 실행 v2) | 29 `pilot-09-010` |

- 정본·승급 장부·공개본·암호화본·학습 분류 카탈로그를 갱신하고 운영 DB에 새 릴리스를 적용한다. 원 세트의 과거 판본·풀이 기록은 보존한다.
- 현재 퇴역 함수는 기준서형 세트만 받으므로, 완전히 분류된 사례형 세트도 퇴역할 수 있게 하는 DB 함수 변경을 함께 적용한다.
- 운영 DB 명령은 사용자가 직접 실행한다. 로컬 PGlite 증명과 읽기 전용 확인을 먼저 거친다.
- 퇴역하는 원 세트를 가리키는 은행 대상 coverage 관계는 대체 문항으로 다시 연결하고 관계를 재확인한다. 퇴역 세트의 wiki 생성 페이지는 원 바이트를 보존한 뒤 제거한다.
- 불필요한 파일은 삭제하지 않고 저장소 밖 보관 폴더로 옮긴다. 승급 검증과 게시 기록이 직접 읽는 파일, README·도구·로그·장부는 남긴다.

모델 상향, 별도 유료 API 의미검수, 사람 확인은 이 승인에 포함되지 않는다. agent 검토는 작성·수정한 agent의 내용 대조이며 독립 교차검토로 기록하지 않는다.
