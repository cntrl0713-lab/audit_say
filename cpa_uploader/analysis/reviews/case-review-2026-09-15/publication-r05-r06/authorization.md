# r05·r06 운영 반영 승인

2026-09-18 사용자 지시: "r05, r06 정본·운영 DB에 반영해줘"

앞서 사용자는 지정 검토의 운영 반영을 모아서 한 번에 하기로 정했고([배치 범위](../authorization.md)), 그 첫 묶음(r01~r04)은 release `906ca962-49f3-4155-8c9d-1b3014e6edda`로 이미 반영했다([기록](../README.md#게시와-운영-반영)). 이 문서는 두 번째 묶음(r05·r06)의 반영 승인이다. 이전 authorization.md는 실행 manifest가 입력 해시로 고정하므로 고치지 않고, 이번 반영은 새 authorization.md·plan.json·batches로 별도 실행한다.

## 반영 범위

| 회차 | 새 세트(반영 판본) | 퇴역하는 원 세트 |
| --- | --- | --- |
| r05 | `case-04-audit-documentation-20260917`(초안 v1, 실행 v1) | 10 `pilot-04-006` |
| r06 | `case-04-materiality-20260917`(초안 v1, 실행 v1) | 5 `draft-04-320-freq01`, 25 `pilot-04-007`, 45 `case-04-materiality-reset-20260914` |

- 정본·승급 장부·공개본·암호화본·학습 분류 카탈로그를 갱신하고 운영 DB에 새 릴리스를 적용한다. 원 세트의 과거 판본·풀이 기록은 보존한다.
- 사례형 세트 퇴역을 허용하는 DB 함수 변경(`cpa_assert_reviewed_question_retirements`, 2026-09-16 적용)은 이미 운영에 있으므로 이번 묶음은 새 마이그레이션 없이 [기존 반영](../publication/db-migration/completion.json)을 그대로 읽는다.
- 운영 DB 명령은 사용자가 직접 실행한다. 로컬 PGlite 증명과 읽기 전용 확인을 먼저 거친다.
- 퇴역하는 원 세트를 가리키는 은행 대상 coverage 관계는 대체 문항으로 다시 연결하고 관계를 재확인한다. 퇴역 세트의 wiki 생성 페이지는 원 바이트를 보존한 뒤 제거한다.
- 이번 묶음은 대체된 판본(v2 이상)이 없어 정리할 사본이 r01~r04만큼 크지 않다. 불필요한 사본이 생기면 삭제하지 않고 저장소 밖 보관 폴더로 옮긴다.

모델 상향, 별도 유료 API 의미검수, 사람 확인은 이 승인에 포함되지 않는다. agent 검토는 작성·수정한 agent의 내용 대조이며 독립 교차검토로 기록하지 않는다.
