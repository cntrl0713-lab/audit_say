# 관찰 O1–O6 수정·재채점·정본·운영 반영 — 2026-09-14

[전수 검증](../README.md)의 관찰 O1–O6을 [사용자 지시](authorization.md)에 따라 처리했다. 관찰마다 처리 방식을 따로 정했다. O1–O3은 문항을 고쳐 재채점한 뒤 정본과 운영 DB에 반영했다. O4는 수동 지침에, O5는 coverage 관계 장부에 반영했다. O6은 고칠 결함이 없어 바꾸지 않았다. O3의 한 물음은 실측 결과를 보고 합치지 않기로 바꾸었다([decision-o3-v3.md](decision-o3-v3.md)).

## 실제 채점과 O3 결정 변경

Luna(gpt-5.6-luna)로 세 번 실행했다. v1·v2 준비물과 관측은 삭제하지 않았다.

| 실행 | 범위 | 결과 | 처리 |
| --- | --- | --- | --- |
| [v1](execution-v1/) ([prepare.mjs](prepare.mjs)) | 11세트·13물음 39건(O3 두 물음 병합) | 39건 ±1 안, 38건 일치. `1cae` 새 부분답안(범위만 언급) 기대 2·실제 1 | crit3 핵심 사실이 "성격이나 범위" 둘 다를 요구하는 것으로 읽혔다 |
| [v2](v2/) ([prepare-v2.mjs](prepare-v2.mjs)) | 같은 39건, `1cae` crit3 핵심 사실을 "다른 감사증거를 줄이거나 바꿀 수 없다"로 좁힘 | 39건 ±1 안, 38건 일치. 같은 답안 기대 2·실제 1 | Luna가 성격·범위를 계속 별개 요건으로 읽었다 |
| [v3](v3/) ([prepare-v3.mjs](prepare-v3.mjs)) | `1cae`를 정본 그대로 두고 10세트·12물음 36건 | **36건 모두 일치**, strict 33건 | 채택. [batch.json](v3/batch.json)으로 수락 |

v3의 strict 불일치 3건은 원 오답 3건이다. 점수(0점)는 같고 일부 criterion의 판정 종류(not_met/contradicted)만 다르다. 기대값은 수락 당시 원 대표답안 값을 그대로 썼다.

`1cae`는 발문이 "다른 감사증거의 성격이나 범위"를 직접 든다. "성격에 영향 없음"과 "범위에 영향 없음"은 각각 한쪽만 써도 옳은 서술이다. 합치면 한쪽만 맞게 쓴 답안이 0점이 되고, 채점 모델도 두 번 모두 둘을 별개 요건으로 읽었다. 그래서 공통 배점 계약의 독립 의미 단위로 보고 분할을 유지했다. `4906`의 세 행위는 발문이 따로 묻지 않은 한 열거 항목 안의 행위다. 합친 기준으로 "육성"만 쓴 부분답안도 기대대로 1점을 받았다.

- 호출: v1 39, v2 39, v3 36, 합계 114회. 입력 321,355토큰(캐시 202,700), 출력 31,518토큰(추론 7,273). 실행기의 고정 단가로 계산하면 약 $0.0715이며 청구서 금액이 아니다. 요청·응답 ID는 [v3/acceptance-completion.json](v3/acceptance-completion.json)에 있다.
- 재실행은 은행 판본이 바뀌어 관측 재사용 계약상 필요했다. ±1점 편차를 없애기 위한 반복이 아니다.
- 담당 agent 검토와 v3 관측을 비용 통제 수락 검증으로 묶었다. 사람의 직접 검수는 아니다.
