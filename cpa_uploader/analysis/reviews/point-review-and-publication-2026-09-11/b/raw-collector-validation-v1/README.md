# raw 수집기 독립 기능 검사

검사 대상은 `cpa_uploader/raw/collect.mjs` SHA-256 `6049f45597d3b0764b32dc4f6687105c3ae93bda5d63167b6c673c1a6d83b5d4`이다. 공통 코드·실제 원자료·현재 수집목록을 수정하지 않았으며 API 호출은 0회다. 테스트는 이 폴더 안에 만든 합성 자료와 독립 가상 저장소에만 `collect({repoDir})` / `verify({repoDir})`를 실행했다. 실제 저장소를 대상으로 CLI 수집 명령을 실행하지 않았다.

`validate.mjs` 실행 결과는 `results-fixture-run-fHLYMM.json`에 보존했다. **35개 중 34개 통과, 1개 결함 재현**이다. 해당 파일의 전체 사례별 결과와 관찰 사항을 읽는다. 대상 ESLint 검사는 통과했다.

## 재현한 결함

`material-directory-junction-cannot-escape-archive`: `cpa_uploader/raw/materials` 위치에 Windows junction을 만들고 가상 저장소 밖 합성 디렉터리를 가리키면 수집기는 그곳에 1개 파일을 기록한 뒤 성공한다. `within`은 문자열 경로만 확인하고, `readRegular`의 마지막 파일 `lstat`는 상위 디렉터리 링크를 확인하지 않는다. 기존 파일 덮어쓰기를 재현한 것은 아니지만, 보관소 내부 쓰기 경계를 지키지 못했다.

제안: 기존 경로 구성 요소를 사전검사에서 확인해 symlink/junction을 거절하거나, 실제 경로가 허용된 보관소 내부인지 확인한다. `materials`뿐 아니라 `collections`의 상위 경로에도 같은 계약을 적용한다. 사전검사 이후 외부에서 경로가 바뀌는 경쟁 상황까지 완전히 방지한다고 주장해서는 안 된다. 이번 검사는 고정된 기존 junction 반례다.

모든 junction 및 실제 대상 파일은 이 검토 폴더의 `fixture-run-fHLYMM/` 아래에만 있다. **실제 원자료 수집 대상에서 `fixture-run-*`를 제외**한다. 합성 테스트 파일을 공식 출처나 실제 검증 자료로 집계하지 않는다.

## 확인한 정상 동작

- NUL·비 UTF-8 바이트·CRLF가 섞인 파일과 수집 inventory의 원래 바이트를 유지하고, 원본 해시가 변하지 않는다.
- 한 수집에서 이름·분류·계보가 다른 동일 바이트를 하나의 파일로 연결하며 각 entry의 역할과 출처 정보를 유지한다. 다른 바이트는 분리한다.
- 기존 collection을 거절하고, 동일 material 경로는 다시 쓰지 않는다. 사전검사 단계에서 두 번째 원본 누락·잘못된 SHA·디렉터리 원본·중복 원본·잘못된 입력·기존 다른 바이트를 발견하면 새 출력이 없다.
- archive 바이트·inventory·index·summary 변조와 보관 파일 누락을 검출한다. 시점 보관본 검사와 현재 원본 비교를 구분하여, 후속 원본 변경/삭제는 `againstOriginals`에서만 오류가 된다.
- `missing` 기록을 복사 성공 수에 포함하지 않는다. 명시적 `../` 출력 이탈·중첩 collection·잘못된 archive namespace·archive 재수집을 거절한다.
- 복사 직후 원본이 변하는 합성 경쟁 상황은 collection 완성 전에 거절한다. 이미 복사된 material은 남으므로 원자적 롤백을 보장하는 도구는 아니다.
- 파일명의 괄호·`#`와 역할의 표 구분자를 색인 링크에서 안전하게 표현한다.

## 정책 대조와 한계

raw README, AGENTS, `docs/출제-검토-자료-관리.md`, 제작/검토 스킬의 공통 `source-evidence.md`는 원자료 보관과 출처 권위·원문 완결성·의미검수·모델 채점의 구별에서 충돌하지 않는다. 각주 호출/소유 문단, 페이지 경계 결론, 원문→추출→전사→인용 해시 추적, 입력 예산 초과 시 의존 원문 조사도 일관된다.

두 가지를 문서에서 더 정확히 할 수 있다.

1. 중복 제거는 **한 수집 안**에서 전체 SHA가 같은 entry를 합치는 동작이다. 후속 수집에서 다른 파일명 또는 분류로 같은 바이트를 등록하면 현재 코드는 추가 보관 파일을 만든다. README의 “동일 바이트의 여러 경로는 하나의 파일을 공유”를 이 범위로 한정하거나, 전체 archive 중복 제거가 의도라면 별도 구현이 필요하다. 현재 결과의 `unique_files`는 해당 collection 집계다.
2. `original_path`는 명시된 가상 저장소 밖의 입력도 읽을 수 있다. 이번에는 소유 폴더 안 합성 sibling 파일로만 확인했다. 외부 원자료 입력을 허용할지는 정책 선택이며, 보관 출력의 경로 이탈 결함과 구분한다. 허용한다면 입력 목록을 사람이 검토한 명시적 원본 경로로 취급한다는 설명이 적합하다.

누락/변조 반례는 합성 파일만 변경했다. 비밀값·모델 응답·실제 학습 자료가 fixture에 없으며, 문항·채점·게시 완료를 검사하거나 주장하지 않는다. 보고서는 위 SHA의 당시 결과이며 수집기 수정 후 결과를 대신하지 않는다.
