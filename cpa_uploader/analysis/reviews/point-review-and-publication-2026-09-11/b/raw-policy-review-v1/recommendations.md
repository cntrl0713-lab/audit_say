# 원자료 수집·공식 근거·검증 절차 제안

공통 파일을 수정하지 않은 독립 제안이다. 원자료를 내려받거나 모델을 호출하지 않았다. 현재 제작·검토 스킬은 공식 출처 대조, 판본 구분, 인용 해시와 파일 해시 구분, 과거 증거 보존 및 실제 검증 상태 구분을 이미 요구한다. 보완할 부분은 **원파일부터 실제 인용까지의 수집 계보**, **부분문자열 일치와 문단 완결성의 차이**, **각주 귀속**, **입력 초과의 진단 순서**다.

`docs/data-management.md`는 확인 시점에 없었다. 실제 관리 본문인 `docs/출제-검토-자료-관리.md`를 읽었다. 원 경로를 다시 만들기보다 최종 AGENTS·스킬 링크가 현재 관리 본문으로 연결되는지 확인하는 편이 일관된다. 루트가 동시에 지침을 편집 중이므로 이 제안은 [review.json](review.json)에 기록한 입력 해시 시점의 비교다.

## 관리 규칙에 넣을 문구

> 원자료 수집은 원출처의 원파일 보존과 수집 장부 작성까지 포함한다. 수집한 PDF·문서·공식 웹 본문, 텍스트 추출본, 공식 전사·발췌, wiki 색인을 별개 산출물로 구분한다. 다운로드한 파일을 열거나 형식을 확인하여 실제 요청한 문서인지 대조하고, 오류 페이지·로그인 페이지·빈 파일을 원문 확보로 기록하지 않는다. 수집 실패·미확보 항목도 원래 요청 범위에 남긴다.
>
> 장부에는 발행기관·문서명, 원 안내 페이지와 다운로드 URL, 확인·수집 시각, 로컬 원파일 경로·크기·SHA-256을 남긴다. 확인된 판본·발표일·시행일·적용 보고기간과 시험 적용 근거를 구분하고, 확인하지 못한 날짜나 판본을 파일명에서 추정하지 않는다. 같은 URL의 파일이 바뀌면 이전 원파일과 장부를 보존하고 후속 판본으로 수집한다. 동일 바이트의 사본은 원자료 ID와 실제 경로로 연결할 수 있지만, 새 확인일을 과거 수집일로 바꾸지 않는다.
>
> 추출본은 입력 원파일의 해시, 추출 도구·버전·옵션, 추출본 해시와 실제 페이지 위치를 연결한다. PDF 파일상의 페이지 순서와 인쇄된 쪽번호를 구분한다. 공식 전사·발췌에는 어느 원파일의 어느 페이지·연속 구간인지와 필요한 앞뒤 문맥을 기록하고, 메타데이터 머리말은 원본문과 구분한다. 메타데이터를 붙인 뒤의 줄번호·파일 해시는 옛 값과 다르므로 실제 인용 위치에서 다시 계산한다. 원문 인용 문자열의 해시, 전사 파일 전체 해시, 원파일 해시를 서로 대신 사용하지 않는다.
>
> 원파일·추출본·과거 검수 로그의 바이트를 후속 작업 편의로 바꾸지 않는다. 이동이 필요하면 원본 해시와 이동 전후 경로를 연결한다. `wiki/raw/source-manifest.md`는 이 원자료를 찾는 생성 목록이며 원파일 자체도, 내용 검토나 시험 판본 승인도 아니다. 수집·전사·등록·문항 검수·실제 채점·사람 확인·게시 상태를 각각 보고한다.

필드명·폴더명은 루트가 확정할 수집 manifest와 실제 디렉터리 계약에 맞춘다. 새 문서에 특정 날짜·모델명·파일 개수·입력 한도 수치를 고정하지 않는다. URL의 인증 토큰이나 비밀키를 장부에 넣지 않는 기존 증거 보존 원칙도 그대로 유지한다.

## 제작 스킬 §4에 넣을 문구

> 공식 근거를 사용할 때 원자료 수집 장부에서 원파일·판본과 현재 전사·발췌의 계보를 확인한다. 로컬 학습자료나 과거 분석 발췌를 공식 파일명으로 옮긴 것만으로 공식 원문 대조를 마쳤다고 하지 않는다. 필요한 raw 원문을 확보하고 실제 본문과 대조한 뒤 등록하며, 추출·인용 방식과 위치·해시는 자료 관리 규칙을 따른다.
>
> 직접 인용은 실제 부분문자열 일치와 별도로 의미상 완결성을 확인한다. 인용이 요구한 문단의 시작과 마지막 문장, 하위 항목, 조건·예외·부정을 포함하는지 확인하고 페이지를 넘는 문장은 다음 페이지까지 읽는다. 본문에도 등장하는 소제목 문자열을 종료 경계로 삼지 않는다. 의도적으로 머리말이나 하위 항목만 인용할 때는 그 범위를 표시하고, 해당 정답에 필요한 주체·공통 조건·다른 항목은 실제 함께 전달되는 근거로 보완한다.

수동 초안에 자동 생성 packet이 없는 경우의 현행 계약은 유지한다. 수집한 PDF, 수동 근거 장부, 생성기 source packet은 역할이 다르므로 서로 대신하는 첨부물처럼 표시하지 않는다.

## 검토 스킬 §2에 넣을 문구

> 인용 문자열이 파일에 존재하고 해시가 맞아도 문단·문장이 완전한 것은 아니다. 실제 공식 원문에서 시작·종료 위치와 다음 문장·하위항목을 대조하여 판단을 바꾸는 부분이 잘리지 않았는지 확인한다. 앞뒤 문맥이나 별도 출처가 정답을 지지하더라도 불완전한 직접 인용을 완전하다고 기록하지 않는다. 수정은 원 인용·receipt를 보존한 후속본으로 남긴다.
>
> 쪽말 각주가 추출상 다른 문단 안에 들어 있어도 그 문단의 요구로 자동 귀속하지 않는다. 실제 각주번호·각주본문·본문 호출·소유 문단과 파일 해시를 함께 대조하고 wiki SCHEMA의 각주 귀속 계약을 따른다. 원문은 그대로 보존하며 확인한 귀속에 한해 의존 참조 추론을 교정한다. 실제 소유 문단의 참조를 지우거나 외부 기준서 전체를 일괄 제외하지 않는다. 기준서 번호를 언급한 관계·적용 제목을 새 기준서 선언으로 오인하지 않는지도 확인한다.

## 검토 스킬 §4에 넣을 문구

> 대량 실행 전에는 현재 코드가 허용하는 명시적 입력 예산으로 무호출 준비 검사를 수행하고, 실제 요청 문자 수와 포함한 대상·원문·계획·비교은행을 기록한다. 한도를 넘으면 먼저 원문 분리·제목·각주 귀속과 의존 연결이 맞는지 확인하고, 의도한 문단 ID와 반드시 필요한 문맥을 대조한다. 단순히 입력을 줄이려고 필수 근거·예외·비교 동료를 삭제하거나 학습자료를 공식 원문보다 우선하지 않는다. 필요한 문맥이 확보되지 않거나 여전히 한도를 넘으면 미완료 범위와 원인을 기록하고 해결 전 모델 호출을 시작하지 않는다.
>
> source packet의 `complete`는 현재 파서가 해석한 의존 관계가 채워졌다는 뜻이며 공식 원문의 모든 필요한 문맥을 의미상 확인한 결과와 구분한다. source_refs와 requirements뿐 아니라 criterion에 추가된 직접 근거도 실제 모델 입력에 전달되는지 확인한다. 수동 근거 장부, wiki 탐색, 정적 검사, 독립 원문 대조, 실제 모델 의미검수·채점, 사람 확인을 각각 표시한다.

입력 초과가 정말 필요한 내용량 때문이면 현재 코드의 허용 한도와 작업 범위 안에서 예산 또는 처리 설계를 조정한다. 큰 한도를 항상 기본값으로 올리거나 오류가 날 때마다 원문을 더 넓게 보내는 규칙을 만들지는 않는다. 문항의 요구를 바꾸는 분할·축소는 그 이유와 새 검수 범위를 남긴다.

## 회귀 지침에 남길 작은 반례

| 변경 영역 | 유지할 반례·확인 |
| --- | --- |
| 문단 발췌 | 본문에 다음 절 제목과 같은 문자열이 먼저 등장하는 경우; 문장이 다음 페이지로 이어지는 경우; 마지막 부정·예외 누락을 exact/hash 검사와 별도로 거부 |
| 각주 귀속 | 3개의 각주가 다음 문단 범위에 물리적으로 포함되지만 두 앞 문단이 실제 소유하는 경우; 각주와 존재하는 다른 번호의 호출을 잘못 짝지으면 거부; 소유 문단 참조와 원문/ID/hash 유지 |
| 참조 파서 | foreign 각주를 제거해도 현재 문단 자체의 동일 기준서 직접 참조는 유지; 미배정 각주·예외는 임의 삭제하지 않음; 관계 제목은 기존 기준에 남기고 실제 새 기준서 선언은 인식 |
| 입력 준비 | 필수 criterion 추가 근거가 전체 물음 입력에서도 누락되지 않음; 필요 출처 확장으로 한도를 넘으면 명확히 실패하고 원문·동료를 조용히 자르지 않음 |
| 변경 영향 | parser 변경으로 원quote/hash가 같아도 ID·locator·source metadata가 바뀔 수 있음; 기존 계획·packet·receipt의 실제 영향과 새 수락/과거 읽기 계약을 구분 |

이 반례의 실제 사례 ID·PDF 쪽수·당시 파일 SHA는 날짜별 검토 증거에 남긴다. 공통 스킬에 A49나 특정 파일명만 예외 목록으로 고정하지 않는다. 테스트 대상 코드가 바뀌는 경우 관련 반례를 수행하며, 일반 문항 하나를 작성할 때 모든 파서·전송 장애 시험을 반복하도록 요구하지 않는다.

## 기존 지침과 충돌시키지 않을 사항

- 공식 원문 수집만 요청했으면 문항 제작·모델 API 호출·기존 기준 적용 변경·승급을 시작하지 않는다. 수집에 필요한 읽기·파일 확보를 다시 승인받게 하는 절차도 추가하지 않는다.
- 새 판본을 받았다는 사실만으로 기존 문항의 적용 판본이 바뀌지는 않는다. 내용 차이를 확인하고 실제 적용 시점을 판단해야 하며 기존 작업 가정은 표시해 유지한다.
- 불필요한 재호출을 막기 위해 이미 적법하게 기록한 승인은 현행 과거 기록 검증 계약을 적용한다. 아직 수락하지 않은 receipt의 비교은행 해시가 달라졌으면 과거 수락으로 꾸미지 않는다. 기존 스킬의 ‘변경되면 새 검수’는 영향 범위와 신규 수락/과거 기록의 차이를 대조하도록 해석·명료화한다.
- ‘raw’는 원자료 원파일과 모델의 원시 응답 모두에 쓰일 수 있다. 문서에서는 `원자료 원파일`과 `모델 원시 응답/실행 로그`로 구분한다. 전자는 원출처의 증거, 후자는 실제 검증 실행의 증거이며 어느 하나가 다른 하나를 대신하지 않는다.

이번 제안의 근거는 [원문 교체 peer review](../official-source-remediation-v1/peer-review-a.json), [파서 peer review](../source-parser-peer-review-v1.json), [순차 승급 계약 조사](../publication-sequence-study-v1/README.md)다. 제안 문구를 반영해도 기존 실패가 해결되거나 실제 검증이 완료되는 것은 아니다.
