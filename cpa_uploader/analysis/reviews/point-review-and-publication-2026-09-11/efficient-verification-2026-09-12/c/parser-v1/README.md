# 반복 발췌의 쪽수 계승 보완

이 작업은 원문이나 문항을 바꾸지 않고 등록 카탈로그가 반복 발췌에 앞선 쪽수를 잘못 계승한 문제를 고쳤다. `impact-final.json`은 당시 등록 입력 56개와 7,789개 단위의 전후 대조다. 16개 단위의 쪽수·위치 설명만 달라지고 모든 단위 ID, 인용 바이트·해시, 오프셋, 의존 관계는 그대로였다. 선택 119개 계획의 실제 1,071개 출처 단위 ID도 존재했다.

자체 PAGE 표지가 없는 반복 `직접 문단 발췌`는 같은 파일·기준서·보론 안의 정규화된 동일 문단이 유일하게 확인될 때에만 그 문단 쪽수를 복원한다. 둘 이상으로 충돌하는 경우 쪽수를 추측하지 않는다. 문단 자체의 PAGE 표지는 우선한다.

KGA 505 A23은 원문이 두 쪽에 걸쳐 있어, 등록 입력의 `confirmedPageRanges`로 408–409쪽을 명시했다. 이 보정은 전체 파일 SHA, 단위 ID와 인용 SHA, 실제 순서의 원문 조각·직전 PAGE와 조각 SHA를 모두 대조한다. 근거가 바뀌면 조용히 같은 보정을 적용하지 않고 거부한다. 확인 근거는 `a23-evidence.json`에 있다.

수정 전 세 파일의 원바이트는 `before.json`과 `*.before.txt`에 보존했다. 최종 수정 파일과 SHA는 `impact-final.json`의 `files` 배열이 기준이다. 해당 버전에서 source catalog 테스트 19개, TypeScript 검사, 대상 ESLint가 통과했다. 이것은 코드·정적 검증이며 문항 의미검수, 실제 채점, 사람 확인 또는 게시를 뜻하지 않는다.

API 호출·DB 쓰기·원문 수정·생성 wiki 갱신은 이 작업에서 하지 않았다. 원문을 추가 등록한 후 생성물 갱신과 최종 실행 잠금은 총괄이 관리한다.
