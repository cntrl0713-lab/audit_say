# 답안 근거·행위 시점 및 중립 누락 후속

resume-003 선행 검증에서 A의 생성 사례 39개와 작성자 QA 35개, B의 작성자 QA 35개, C의 작성자 QA 22개가 모두 일치했다. B 생성 사례의 불일치 2개는 같은 원답안으로 각각 총 3회 확인했다. 이 기록은 [원시 결과 조사](../execution-resumes/resume-2026-09-12-v3/canary/grading-b/pilot-05-003/investigation-v1/README.md)에 보존한다.

## 원문에 따른 판단

- “감사인은 감사 중 식별된 유의적 내부통제 미비점을 지배기구에 서면으로 커뮤니케이션해야 한다.”는 상대방과 서면 방식만 충족한다. “감사 중”은 식별을 수식하며 적시 전달을 뜻하지 않는다. KGA 265.9의 전달 적시성은 별도 요구다. 기존 기대 2점을 유지하고, 3회 모두 3점을 준 채점기의 과다 인정으로 분류했다.
- “미비점의 잠재적 영향만 설명하고, 미비점 자체의 내역은 제시하지 않는다.”는 내역 제시를 명시적으로 반대한다. KGA 265.11(a) 및 독립 배점 계약에 따라 해당 criterion은 contradicted이고, 맞힌 잠재 영향은 1점을 인정한다. 생성 사례의 omission/not_met 기대가 잘못되었으므로 원문·원 기대·실측을 보존하고 새 QA에서 기대를 정정했다. 기존 중립 누락 QA도 보존했다.
- `pilot-03-001`의 직접 출처 누락은 별도 [후보 v8](../c/prepared-reviewed-v8/README.md)에서 보강했다. 원문·발문·모범답안·criterion·배점은 유지했다. 새 은행의 과거 의미검수 자동 승계는 허용하지 않는다.

## 변경 범위

[변경 전 파일](before.json)을 API가 모두 종료된 시점에 보존했다. [runtime-v7](../execution-runtime-v7.json)은 이전 16개 실행 파일 중 두 파일만 바뀐 것을 검사하고 고정한다.

1. `lib/questionV3Grading.ts`: 실제 답안 구간에 요구 명제가 있는지 확인하고, 모범답안에서 내용을 옮겨 채우지 않도록 지시했다. 시점·속도·빈도 수식어의 행위 귀속을 구별하는 지시도 추가했다. 정확히 두 지시 줄이며 스키마·파서·합산·전송·보안 코드는 유지했다.
2. `cpa_uploader/questionSemanticReview.ts`: 중립 누락과 명시적 의무 부정·배제를 구별하도록 사례 생성 지시 한 문장을 두 문장으로 교체했다. omission의 엄격한 기대, 반대 판정, 조건 경계 및 정수 부분점수 계약은 유지했다. [독립 제안·원문 대조](../c/resume-review-2026-09-12/semantic-case-contract-proposal-v1/proposal.json)를 연결한다.
3. 검토 스킬의 `references/regression-cases.md`에 답안 근거 확인과 행위별 시점 검토 규칙을 추가했다. 앞선 조건·부정 목적 규칙은 유지했다.

[B 후속 QA·계획](../b/canary-followup-v2/changes.json)은 이전 35개 사례를 그대로 두고 원실패 답안 2개를 추가한다. 전체 작성자 QA는 6,040개, 선행 세트는 35/37/22개다. 기대값을 모델에 맞춰 바꾸거나 기존 반례를 삭제하지 않았다. 이 판단과 코드는 AI가 검토했으며 사람 확인으로 기록하지 않는다.

## 로컬 검증

- 채점·검토 회귀 18/18 및 의미검수 회귀 21/21 통과. 실제 API를 주입하지 않은 합성 전송 시험은 실제 모델 판정의 증거가 아니다.
- 두 실행 코드와 runtime 준비 도구의 대상 lint 통과.
- v9 입력 준비 시 타입 검사 통과. 앞선 중간 검사는 작성 중이던 준비 도구의 타입 오류 2개로 실패했으며 해당 도구 완성 후 재검사로 구분했다.
- runtime 준비 도구는 보존본과 대조해 두 grader 지시 줄과 한 semantic 지시 치환 외 코드 변경을 거절한다. 별도 독립 검사에서도 스키마·채점·전송 계약의 완화가 없음을 확인했다.

이전 runtime-v6의 전체 테스트 473/473 기록은 그대로 보존한다. 현재 버전은 변경 범위에 맞는 위 39개 회귀 및 별도 입력 준비 검사를 수행했으며 전체 테스트를 새로 실행한 것으로 표시하지 않는다. 실제 모델 후속 결과는 완료 후 별도 증거로 연결한다.

## 실제 Luna 후속 결과

현재 코드로 실제 원사례 3개를 각각 3회 확인하려 했으나 5개 관측 후 중단했다. A의 해지 조치 누락은 0점 1회, B의 목적 배제 누락은 5점 1회 일치했다. B의 시점 누락은 기대 2점에 실제 3점이 3회 모두 재현됐다. 따라서 이 코드 보완으로 해당 과다 인정을 해결했다고 기록하지 않는다. A/B 목적 사례의 잔여 각 2회는 미실행이다.

[독립 결과 검사](../c/resume-review-2026-09-12/semantic-case-contract-proposal-v1/early-regression-results.json)는 원답안·기대·요청·스키마·16개 코드 파일, 실제 응답 5개와 근거 구간 복원·재합산을 대조했다. 전송/형상 오류·원시 보안 오탐·프로토콜 재시도는 없었다. 모델의 내용 판정 실패와 실행 실패를 구분한다.

같은 원답안을 현재 지침 그대로 `gpt-5.6-terra`와 `gpt-5.6-sol`로 각 1회 실행하니 둘 다 기대 2점에 일치했다. 이것만으로 전수 적합성을 주장하지 않고 Terra로 선행 QA 94개를 추가 확인한다. 진단 모델 환경값은 각 자식 실행에만 지정했으며 운영 기본 모델과 기존 동결 manifest는 변경하지 않았다.

이후 Terra QA 94개(비빈 실제 응답 88개·빈 답안 6개)가 모두 첫 관측에서 일치했다. 그러나 사용자는 비용 때문에 모델 상향을 거절하고 **Luna 유지**를 명시했다. Terra/Sol 결과는 과거 비교 진단이며 현행 전수 검증·운영 채점 근거로 승계하지 않는다. 추가 모델 상향 호출과 입력 구조 실험은 중단했다.

사용자는 사소한 채점 오차를 수용한다고도 밝혔다. 기대점수·원시 판정·실제 점수를 바꾸지 않고 허용된 편차를 별도 상태로 관리한다. 구체 허용 범위는 사용자 답변과 후속 정책에 기록하며, 문항·정답·직접 출처 오류 및 실행·보안 오류와 구분한다. 전수 실행 준비 v9는 Luna와 기존 엄격 비교를 보존하고 있으며, 실제 오차 수용은 원 기록을 고쳐 pass로 만드는 방식으로 처리하지 않는다.
