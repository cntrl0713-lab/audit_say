# 회귀 사례와 실행 경계

채점에 영향을 주는 검토·수정에 필요한 사례만 선택한다. 아래 점수는 명시한 criterion 계약의 예이며 미래의 모든 물음에 고정된 정답표가 아니다. 새 데이터에서 요구와 배점을 다시 읽는다.

## 물음별 기본 사례

학습 유형과 배점 타당성의 기준은 [공통 배점 계약](../../../../docs/물음별-학습-단위와-분류-계약.md#배점과-물음별-타당성)을 따른다. 기준서형은 사례 없이 완전 답안이 성립하는지, 사례형은 일반 기준서 답안과 사실 적용 답안의 득점 차이가 실제 요구를 반영하는지 확인한다. 사례 적용을 빠뜨렸다는 이유로 별도로 맞힌 일반 원칙까지 일괄 0점 처리하지 않는다.

완전 정답, 의미가 같은 표현, 일부 독립 명제 누락, 반대 의미, 조건 경계, 빈 답안을 기본으로 하고 저장 모범답안도 평가한다. 완전 정답은 모든 criterion을 충족해야 한다. 부분 명제 누락의 기대값은 답안 전체에서 실제 사라진 독립 명제의 점수만큼 감소하며, 결합 criterion의 부분 충족 여부는 그 계약을 따른다. 결론 문장만 지워도 남은 이유가 같은 판단을 함축하면 판단 명제는 누락되지 않았다.

| 경계 | 사례 구성 | 확인할 결과 |
| --- | --- | --- |
| 모두 작성 | 무관한 첫 문장 뒤 모든 정답, 역순·한 문장으로 합친 정답 | 항목 잘림이나 나열 순서 감점 없이 정답 명제 득점 |
| 요소별 부분정답 | 열거 요소 중 하나만 맞음, 여러 요소 중 일부만 맞음 | 실제 충족한 독립 요소의 정수 점수 합계; 전체 목록 미완성이라는 이유로 전부 0점 처리하지 않음 |
| 서술 부분정답 | 두 독립 서술 요건 중 A만 맞음, B만 맞음, 둘 다 맞음 | 각각의 독립 득점과 합계; 필수 조건이 빠져 의미가 성립하지 않는 조각은 정답으로 오인하지 않음 |
| 독립 인용 | 정의와 시점 등 두 독립 명제를 한 문장으로 작성 | 동일 quote라는 이유로 한쪽을 감점하지 않음 |
| 중복 사실 | 같은 사실을 세 번 반복 | 같은 criterion 한 번만 득점; 독립 명제로 위장한 은행 중복 배점도 확인 |
| 명칭과 정의 | 정의+명칭 세 개를 요구하나 명칭만 작성 | 명칭 3개가 각 1점이면 3점, 정의는 0점; salad 일괄 감점 없음 |
| 함축 결론 | 명확한 보고 조치가 독자 처리 불가를 함축 | 해당 판단 criterion 인정; 별도 목적·신속성 점수는 실제 작성 여부로 평가 |
| 모순 | 적절한 조치와 명시적인 반대 결론을 함께 작성 | 관련 판단 criterion 미득점; 무관한 정상 criterion까지 임의로 감점하지 않음 |
| 판단/근거 | 결론만, 근거만, 결론+틀린 근거, 둘 다 맞음 | 발문과 결합/분리 criterion 계약대로 판정 |
| 조건·예외 | 필요시를 무조건으로 변경, 주체 변경, 법규 예외와 다른 예외를 맞바꿈 | 해당 명제의 조건·예외가 훼손되면 미득점 |
| 조건 경계 | 실제 적용을 가르는 시점·주체·전제를 하나 바꾸고 나머지는 유지 | 바뀐 조건에서 기준이 여전히 적용되는지 직접 근거로 판정; 단순 반대 문장을 복사해 경계 사례 수를 늘리지 않음 |
| 허위 인용 | 존재하지 않는 인용, 다른 물음 답안에서 가져온 인용 | 코드가 검증 실패를 감지; 독립 명제의 같은 문장 허용과 혼동하지 않음 |
| 응답 형상 | 동일 criterion ID 반복, 알 수 없는 ID, 판정 누락 | 파서의 오류 계약 준수; 조용히 두 번 합산하지 않음 |
| 보안 | 정상 명칭 목록, 무관한 키워드, 명시적 채점 조작 지시 | 정상 목록은 의미 채점, 무관한 조합은 criterion 판정, 지시 삽입은 현행 보안 계약 적용 |

주제01–03의 과거 초과 항목 사례는 새 모두 작성 정책에 따라 기대값이 달라졌다. `docs/plans/주제-01-03-검토에-따른-수정-결정.md`의 사례 표와 직접 대조한다. 과거 로그에서 낮은 점수를 그대로 복사하지 않는다.

누락·반복 사례는 변경 후 답안 전체의 의미로 기대값을 정한다. 다른 문장에 같은 명칭이나 결론이 남아 있으면 한 줄 삭제가 criterion 미충족을 뜻하지 않는다. 주제08의 표본감사 명칭과 표본→모집단 연결처럼 뒤 명제가 앞 명칭을 함축할 수 있다. 이 경우 명칭만 남기는 반대 방향의 누락 사례로 연결 criterion의 실패 경계를 확인한다.

조건부 일반 절차와 특정 예외 상황의 판단은 발문의 요구 범위에 따라 구별한다. 조건이 성립하지 않아 조치를 취하지 않는다고만 쓴 답은 조건이 성립할 때 어떤 조치를 취해야 하는지까지 설명한 것이 아니다. 반대로 발문이 해당 비적용 상황 자체를 묻는 경우에는 그 상황의 올바른 판단을 인정한다. 일반 규칙과 예외를 요구한 물음에서 예외만 쓴 답, 일반 규칙과 예외를 모두 쓴 답, 배타적 한정으로 일반 판단까지 분명히 함축한 답을 대조한다. 실제로 독립 배점한 명제의 범위를 따르며 조건·예외마다 기계적으로 새 점수를 만들지 않는다.

적극적 목적과 다른 목적의 배제도 독립 명제인지 확인한다. A를 위한 절차라고 쓴 것만으로 B를 위한 절차가 아니라고 설명한 것으로 추정하지 않는다. 두 설명이 각각 요구되면 둘 다 쓴 답·A만 쓴 답·B의 배제만 쓴 답·B를 명시적으로 긍정한 답을 구분한다. 누락은 반대와 다르며, `만` 등 한정어가 다른 요구를 실제로 배제한 답을 중립적 누락 사례로 만들지 않는다. 모델이 만든 사례의 종류·기대판정도 원문과 해당 독립 criterion에 다시 대조하고, 오류 교정 시 원답안·원 기대·실측을 보존한 새 근거와 후속 버전을 남긴다.

결합 기준을 여러 독립 기준으로 나누면 유효한 기존 QA 답안·반례를 보존하고, 기존 ID를 이어받은 첫 기준을 포함해 모든 하위 기준의 완전·동의·누락·반대·조건 경계를 다시 판단한다. 옛 결합 기준의 0점/만점을 새 기준들에 일괄 전파하지 않는다. 기대값의 변경 이유와 기준·ID·점수의 전후 대응을 기록한다.

## 채점 오류와 검수 증거

채점 엔진이나 검수 경로를 수정할 때 아래 경계를 확인한다. 일반 문항 편집에 모든 장애 시험을 일괄 적용하지 않는다.

| 경계 | 처리·검사 |
| --- | --- |
| ID·인용 계약 | 해당 물음의 criterion·답안 구간 ID만 허용한다. 미등록·다른 물음 ID·중복·누락을 거절하고, 인용은 원문 구간에서 복원한다. 잘못된 모델 응답을 학생의 감점으로 처리하거나 임의 ID에 붙이지 않는다. |
| 재시도 | 일시적 전송·SDK 연결/시간초과·빈 응답·JSON/판정 형식 오류는 현행 횟수·전체 시간 예산 안에서 재시도한다. 인증·설정·거절·출력 한도·사용자 중단은 같은 요청을 반복하지 않는다. SDK 오류는 메시지만으로 분류하지 않는다. |
| 기록 콜백 | `onTrace`·`onJudgment`·`onChunk`·`onRun`의 오류는 증거 저장 실패다. 모델 재호출로 복구하지 않는다. 로그용 객체 편집이 입력·판정·점수·receipt를 바꾸지 않도록 독립 스냅샷을 전달하는지 검사한다. |
| 보안 | 정상 사례는 세트·물음의 원시 보안 플래그까지 대조한다. 기대 0점이라도 보안 오탐이면 불일치다. 공격 사례는 별도로 표시하고 해당 물음의 차단과 다른 물음의 정상 점수 보존을 함께 확인한다. 전체 `security_flag`만으로 국소 판정을 추정하지 않는다. |
| 실행 종류 | 의미검수 `execution.transport`와 채점 `grading.transport`를 별개로 확인한다. 신규 모델 검수 수락에는 둘 다 `model`이 필요하다. 주입 응답 또는 transport 미기록 모델 의미검수는 실제 채점만 추가해 수락하지 않는다. 실제 수동 의미검수는 그 방법·실인용·판정 근거를 갖추는 별도 계약이다. |
| 과거 호환 | 당시 transport·해시·판정의 읽기 호환은 현재 새 수락의 증거가 아니다. 누락 필드를 `model`로 덧씌우지 않고 새 검수를 남긴다. AI가 수행한 대리 검토와 실제 사람 확인을 구분한다. |

CLI의 `<output>.chunks.jsonl`은 의미검수 단위별 응답·오류, `<output>.grading.jsonl`은 실제 사례 채점별 성공·불일치·실패를 보존한다. 도중에 중단되면 완료된 실행과 실패 위치를 보고하고 새 출력 경로로 재개한다. 부분 로그·빈 양식·실행하지 않은 사례는 완료 receipt가 아니다. 점수 오류를 조사할 수 있도록 유효하지 않은 raw 응답도 보존하되 비밀정보를 기록하지 않는다.

## 실행 결과 보존

계획·문서화·중요성 문항에서는 필요에 따라 다음 반례를 사용한다. 상세 기준과 기존 답안은 저장소의 `cpa_uploader/analysis/reviews/question-review-2027/04.json` 및 `cpa_uploader/analysis/reviews/question-review-2027/grading-cases/04-cases.json`을 확인하되, 점수를 다른 계약에 고정하지 않는다. 사람이 읽는 당시 판단은 `docs/archive/과거-검토-증거/reports/question-review-2027/주제-04-감사계획과-중요성-검토-수정-결과.md`에 있다.

- 범주 정답에서 기준서 번호만 생략한 답안과, 경영진주장 수준처럼 필요한 범주 조건을 바꾼 답안을 구별한다.
- 전략·계획의 변경내용만 기록한다고 한 답안에서 대상 명칭의 등장만으로 전략·계획 자체 문서화 점수를 주는지 확인한다.
- 금액과 결정 시 고려 요소를 결합한 criterion에서는 금액만 쓴 답안과 고려 요소의 문서화 요구를 여러 금액에 공통으로 적은 답안을 대조한다.
- 숫자만 적은 답안, 요구하지 않은 날짜를 생략한 답안, 관련 금지·허용 조건의 기산점을 명시적으로 바꾼 답안을 구별한다.

계약이 바뀐 사례는 새로 실측한다. 변경 없는 사례의 이전 실측을 재사용하려면 실제 요청의 프롬프트·스키마·instructions·모델과 해당 물음의 계약이 동일한지 확인한다. 코드가 바뀌었다면 저장된 raw 판정을 현재 코드로 재처리하고, 인용·판정·점수·결과 귀속을 비교한다. 이 재처리는 새 모델 호출이 아니다. 은행 전체 해시만으로 같은 계약이라고 가정하거나, 재합산 성공으로 프롬프트 변경 후의 의미 판정을 검증했다고 쓰지 않는다. 병행 수정이 반영되면 현재 파일·검증 결과를 확인하고 과거 미해결 상태와 새 결과를 구분한다.

다른 작업의 대량 실측과 공통 코드를 공유하면 변경 종료 후 파일별 해시와 검증 범위를 전달하고 실측 중 버전을 유지한다. 실행 잠금이 변경을 감지해 중단하면 이전 지시·입력·로그를 보존하고 새 잠금·출력 경로에서 수행한다. 기존 잠금이나 옛 receipt의 해시만 갱신해 중단을 우회하지 않는다.

누락 사례에서 문장 하나를 삭제했다고 그 문장이 표현한 criterion을 자동으로 not_met으로 두지 않는다. 남은 조치가 판단을 분명히 함축하면 판단 명제는 남아 있다. 결론만 쓰고 요구된 설명을 누락한 사례 등으로 실제 누락 경계를 별도로 확인한다. 기대표 자체가 잘못되었으면 원문·확정 계약을 다시 대조한 근거와 교정 사유를 기록하고 새 버전을 만든다. 기존 기대표·실측을 보존하며 단순히 모델 출력에 맞추어 교정하지 않는다.

사례별로 세트/물음/criterion ID, 합성 답안 원문, 기대 판정·근거·총점, 모델 raw 판정·quote·보안 플래그, 코드 보정 후 판정과 점수를 남긴다. 실제 호출/캐시/mock 여부, 실행일, 설정·해시, 실패·재시도 수를 기록한다. 요청한 모델과 실제 응답 모델을 구별할 수 있으면 둘 다 기록한다. 비밀키나 실제 사용자의 비공개 답안을 로그에 넣지 않는다.

은행·주제 단위 실행은 `cpa_uploader/analysis/reviews/`, 개별 제작 배치의 사례·QA·receipt는 해당 `cpa_uploader/drafts/` 배치에 보존한다. 현재 조회 화면은 `cpa_uploader/wiki/_meta/authoring-dashboard.md`에서 찾되 실제 실행 증거와 입력 해시를 대조한다. 자료 이동은 당시 해시·판정의 교체가 아니며, 이동 전 경로는 이동 기록으로 연결한다. 연결 분석의 재생성·최신성 검사가 통과해도 실제 모델 재실측을 수행한 것은 아니다.

작성자의 기대 판정을 `applyQuestionSetJudgment`에 직접 넣은 검사는 합산 회귀이며 실제 모델의 의미 판정을 측정하지 않는다. `qa-*.json` 같은 작성자 QA와 `review_question_draft_v3.ts`의 의미검수 receipt, 실제 채점 결과, 사람 확인을 구분한다. 생성 sidecar와 다른 파일명을 쓰면 검수 명령에 실제 `--plan`·필요한 `--packet` 경로를 명시한다. 정식 검수 형상·승급 증거는 저장소의 `cpa_uploader/wiki/question-generation/source-authoring-design.md`와 현행 코드에서 확인한다.

한 답안에서 다른 물음으로 새는 인용, 모델의 잘못된 판정, 보안 오탐, 점수 코드의 감점, 화면 결과 소실을 서로 다른 원인으로 분류한다. 불안정 사례의 반복 실측은 원본과 재실행을 따로 보존한다.

## 화면·제출·경험치가 변경 범위인 경우

- UI·action·grader의 현행 답안 길이 제한 상수와 전체 요청 시간 예산을 확인하고 제한 전후를 검사한다. 일부 빈 답안은 작성한 나머지를 평가하고, 전체 빈 답안은 모델 호출·모델 키·호출 한도 없이 0점 경로로 처리하는 정책이다.
- 채점 완료 후 프로필 갱신 실패에도 결과를 유지한다. 감점 사유는 코드가 정한 안전한 사용자용 사유로 표시하며 내부 criterion 계약·source quote·모델 자유 형식 진단을 그대로 공개하지 않는다.
- 새 제출 5점 후 새 제출 5점이면 +10, 같은 ID로 5점 요청을 재시도하면 +5만 가산한다. 답안 fingerprint가 같다는 이유로 서로 다른 새 제출을 합치지 않는다.
- 동시에 새 제출 5점과 4점이면 +9다. 현재 경험치 읽기 후 덮어쓰기는 갱신 유실 가능성을 검증한다. 제출 적립 기록 유일성과 원자적 증가를 DB 트랜잭션/RPC로 확인한다.
- 동일 사용자/제출 ID에 다른 답안·세트를 넣는 요청을 거절한다. 인증·세트·물음 ID·길이 검증과 완료된 재시도 확인이 모델 한도 소비보다 앞서는지 확인한다.
- 채점 결과 저장과 경험치 반영 상태를 분리한다. 적립 실패 후 같은 제출로 재시도해 결과가 사라지거나 중복 적립되지 않는지 확인한다. 서버 장애 시 모델 호출까지 항상 한 번이라는 보장과 경험치 중복 방지는 별개다.
- 기존 누적 경험치는 보존하며 과거 제출에 신규 적립을 소급하지 않는다. 0점·게스트 경로를 따로 확인한다. 인증·DB E2E는 격리 환경을 쓰고 실제 실행하지 못했으면 미실행으로 남긴다.

## 수정 자체의 경계

공통 정책 변경은 기존 문제은행 전체의 영향을 조사하되, 제한 필드를 정리했다는 이유로 미검토 주제의 내용·공식 출처도 모두 승인했다고 기록하지 않는다. 해시 전역 엄격 검증 등은 미검토 데이터까지 읽지 못하게 만들 수 있으므로 영향 데이터를 조사한다. 정본·공개본·암호화본·채점 코드가 서로 다른 계약인 상태를 운영 완료로 취급하지 않는다.
