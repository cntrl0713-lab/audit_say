# 기존 정본 배점 검토 A 인계

상태: 로컬 수정 후보 확정. 이 인계 이후 sets.json·audit.json·qa.json·source-evidence.txt 쓰기를 중지한다. 다음 단계는 총괄이 확정할 비교 은행과 실제 검수 입력을 사용한다.

대상은 canonical-before.json의 부모 주제01–06 전체 30세트·60물음이다. 22세트의 27물음을 수정했고 33물음은 요구별 이유를 남겨 유지했다. 총점은 155→189점(+34)이다. 기준서형59·사례형1이라는 기존 분류와 물음별 다주제 대응을 유지한다. pilot-03-001/sub2의 답안 type만 judgment→descriptive로 바로잡았으며 학습 유형의 변경이 아니다.

## 주요 결정

- pilot-04-004/sub2: 3→8. 기준서230.8의 세 상위 구분에 포함된 절차 특성3·결과·증거·유의사항·결론·판단을 각각 독립 인정한다. 원발문이 요구한 내용의 부분점수 복원이다.
- pilot-05-007/sub2: 2→8. 원발문이 명시한 토의 대상2·내용2와 보고 의무 결정·대상·내용2를 구분했다. 한 상황의 토의/보고 절차로 유지했으나, 학습 부담 관점에서 두 물음으로 나누는 후속 선택은 가능하다. 분리 자체로 점수를 더하지 않는다.
- pilot-04-005/sub2: 4→5. 네 금액·수정 항목과 공통 고려요소 문서화를 분리한다. 같은 공통 고려요소 의무를 네 번 반복 가점하지 않는다.
- pilot-01-004/sub1: 목적과 시급성 분리. 목적만 정확한 답=1점, 정확한 조치·목적·시급성=3점. 같은 의무의 긍정·부정은 중복 배점하지 않는다.
- pilot-02-005/sub2: 발문에 있던 제거 가능성 판단 누락과 다른 개념 인용을 바로잡았다. 정의1·판단1, 정의가 맞고 제거 가능 판단이 틀린 답=1점.
- pilot-03-002/sub1: 주어진 의견거절 예상을 복사하여 받던 점수를 제거하고 수임 판단·법규 예외를 각각 평가한다.
- pilot-02-004/sub2의 감사위험 고정 조건·이유 요구, pilot-03-004/sub2의 법규 예외 요구는 기존 정답/선행 수정결정과 발문을 맞춘 명료화이며 audit.json에 전후 발문을 기록했다.

## 근거와 보존

기존 source_refs와 부모 facts·물음 ID·표시 순서는 그대로 보존했다. 추가 인용은 [source-evidence.txt](source-evidence.txt)에 2025 공식 전문의 실제 바이트를 발췌했고 220.14, 200.13(e)/A47/A49, 210.6/8/19, 330.8의 기존 불완전 연결을 보강했다. 새 src-point-a-*는 문항 로컬 출처 ID이며 공용 카탈로그의 source_unit_id를 꾸며 만든 것이 아니다. 이후 계획 연결에는 실제 카탈로그 단위를 별도로 대조해야 한다.

2027 CPA 대비/2026-01-01 개시·종전 품질관리 체계라는 공통 [판본 정책](../../delegated-authoring-2026-09-11/edition-policy.md)을 유지한다. 그 정책에 명시된 시험 당국의 개별 판본 미지정 및 후속 지정 시 재대조 한계도 유지한다. 이번 작업에서 새로운 시행일 판단을 하지 않았다.

과거 01–06 작성자 QA 원본 전체와 이전 실행 증거는 수정하지 않았다. 핵심 과거 원답안7건은 qa.json의 historical_regression에 원문 그대로 가져와 새 기대판정을 별도로 기록했다. 변경한 모든 하위 기준(기존 첫 ID 포함)의 완전·부분·동의·누락·반대 기대를 다시 만들었으며 옛 결합 기준의 0점/만점을 일괄 전파하지 않았다.

## 실제 수행한 로컬 검사

- validate_draft_v3.ts: 담당30세트 형상·source_quote 실존 통과.
- validate-local.ts: 60개 감사 장부와 전후 점수, 원본 refs/facts/order 보존, 609개 QA ID·criterion·기대 정수 합산 및 applyQuestionSetJudgment 재생 오류0·경고0.
- 메모리 정본 대체:104세트·212물음·608criterion·608점, validateAuthoringBank 오류0. 이는 A만 대체한 임시 검산이며 다른 담당 수정 결과를 포함한 최종 총점이 아니다.
- validate-local.ts 대상 ESLint 통과. 전체 npm test·DB·API는 실행하지 않음.
- 모델 의미검수0회·실제 모델 채점0회·사람 확인 미주장. 작성자 기대값 재생은 의미 판정 검증이 아니다. [validation.json](validation.json)의 실행 종류를 따른다.
