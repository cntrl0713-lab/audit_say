# 운영 DB 적용 요청 사전 확인

2026-09-12 사용자 요청: “운영DB적용”. 운영 쓰기를 승인한 요청으로 받았으며, 앞서 사용자가 확정한 “필수 전수검증을 진행하고 통과 후 DB 반영” 조건과 현재 완료 상태를 대조했다. **운영 DB 변경은 아직 실행하지 않았다.** 적용 승인을 다시 받기 위한 검사가 아니라, 미완료 검증을 생략하도록 이전 조건을 변경한 것인지 구분하기 위한 확인이다.

## 실제 대상과 검사

| 항목 | 실제 확인 결과 |
| --- | --- |
| 운영 프로젝트 | `xvifzicrjmbfqaepcfpp.supabase.co` |
| 활성 릴리스 | `f5e24288-933a-4e3b-864a-7ba4394b550a` |
| 운영 은행 | 104세트·212물음·574점 |
| v8 적용 후보 | 153세트·350물음·1,292점 |
| 운영 원문과 후보 비교 | 신규 ID 49개, 기존 JSON 차이 97개, 동일 7개, 삭제 0개 |
| 이번 내용 검증 대상 | 신규 49세트 + 기존 수정 70세트 = 119세트·280물음 |
| 공식 import 사전검사 | `ready:false`, 오류 120개: 검수·게시 상태 미완료 119개와 전체 은행 검증 실패 요약 1개 |
| 실제 모델 호출 / DB 쓰기 | 0 / 0 |

기존 JSON 차이 97개는 문항·메타데이터·출처 등 전체 객체의 차이다. 이를 이번 배점·내용 수정 70세트와 같은 집계로 해석하지 않는다. 운영 원문은 로컬 정본과 바이트가 같지 않으므로 실제 반영 전에는 운영본과 최종 후보의 차이를 기준으로 확인해야 한다.

확인은 [실행 코드](check.mjs), [실제 DB 조회·입력 해시·전후 보존 기록](preflight.json), [공식 import 검사](import-check.json), [검사 출력](import-check.log)에 보존했다. `--apply`와 `--preserve-source`를 사용하지 않았다. DB에서는 활성 공개 은행과 해당 릴리스의 원문 스냅샷만 읽었고 사용자 답안·회원 테이블은 읽지 않았다. 은행·공개본·분류·승급 장부의 입력 바이트는 검사 전후 같다.

전체 은행 검증 오류 요약은 검증기의 여러 검사를 묶은 문구이며 구조·인용·중복 검사가 모두 실패했다는 뜻이 아니다. 현 후보의 미검수 상태와 과거 승급 장부의 미완료 이력이 남아 있다.

## 현재 전수검증 상태

[119세트 현황](../a/resume-review-2026-09-12/r4/quota-stop-01/status-119.json)과 그 이후 실제 출력 존재 여부를 다시 확인했다. 원 실행 입력 3,065개와 기존 증거의 해시가 유지됐고, 잔액 소진 중단 후 추가 완료 기록은 없다.

- 의미검수: 완성 receipt 19세트 중 pass 15, 비통과 4. 부분 3세트와 미착수 97세트를 합쳐 완성 receipt가 없는 대상은 100세트다.
- 신규 49세트는 현행 실행 버전의 의미검수·생성 채점·작성자 QA가 모두 미착수다.
- 정식 생성 사례 채점과 작성자 QA는 선행 3세트만 완료했다. 물음당 ±1점 허용 평가는 원 엄격 판정과 별도로 보존되어 있으며, 생산 승급 경로의 허용 편차 패치는 아직 미적용이다.
- 출처 후속 4세트의 계획은 비활성 상태다. 준비 자료를 실제 후속 의미검수 완료로 취급하지 않는다.
- 학습 단위 249개의 비빈 답안 실측과 실제 사람 내용 확인도 미완료다.

검증 중단의 마지막 확인 원인은 `credit_balance_exhausted / insufficient_quota`다. 이 요청에서는 잔액 확인용 호출이나 채점 재시도를 하지 않았다. 모델은 사용자가 정한 Luna를 유지한다.

## 확인이 필요한 정책

현재 후보를 바로 게시하는 것은 기존의 “전수검증 통과 후 반영” 조건을 변경하는 일이다. 사용자의 짧은 적용 요청만으로 검증 완료나 조건 생략을 기록하지 않았다.

[검토 스킬](../../../../../.agents/skills/audit-question-review/SKILL.md)의 현행 지침은 “정본 반영·승급이 요청 범위이면 통과한 receipt와 실제 사람 검수 근거를 `promote_cpa_v3.ts`에 전달한다.”이다. 사용자가 명시적으로 절차 예외를 결정하면 그 결정을 기존 검수 결과와 구분하여 기록하고 필요한 적용 경로를 준비한다. 미실행 검수·사람 확인을 완료한 것으로 기재하거나 과거 receipt를 변경하지 않는다.

현재 내용은 [119세트 전체 검토 자료](../c/r4-execution-v1/content-review-catalog-v1/review.html)에서 볼 수 있다. 전수검증 조건을 유지하는 경우에는 [현재 재개요구서](../../../../../docs/plans/문항-전수검증-Luna-1점허용-재개요구서-2026-09-12.md)를 따른다.
