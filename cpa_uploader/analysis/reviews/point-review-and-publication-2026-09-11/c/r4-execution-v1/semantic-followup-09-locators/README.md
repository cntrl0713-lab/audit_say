# 주제09 출처 위치 후속 조사 — 비활성 제안

pilot-09-003의 7단위와 pilot-09-005의 1단위에서 나온 source_support uncertain은 실제 등록 메타데이터 충돌을 짚었다. 문항의 인용 본문과 source_span은 맞지만, 같은 공식 발췌 파일 뒤의 반복 문단들이 앞선 PDF 쪽수를 상속했다. 이 조사를 문항 검수 통과나 카탈로그 오류 정정 완료로 해석하지 않는다.

- 505.8 원전은 2025 전문 PDF402쪽이며 등록 본문 L247–254, 뒤의 반복 발췌는 L365–372이다.
- 505.10·11 원전은 PDF403쪽이며 본문은 각각 L265–267·L268–270이다. 뒤에 두 차례 반복된 발췌는 새 PDF 표지 없이 앞선 409쪽을 상속했다.
- 실제 PDF409에는 A23의 계속과 A24–A25가 있다. 2025·2026 보존 전문의 8·10·11을 직접 비교하면 공백 이외 내용이 같다. 시험 최종 판본을 새로 확정한 것은 아니다.

[investigation.json](investigation.json)은 원 모델 응답·원 요청·현 코드 재구성의 21단위 입력/스키마 해시 일치, 인용 실재 행, 판본 발췌와 82개 작성자 QA의 채점 입력 불변을 기록한다. 직접 HTTP 요청을 새로 캡처한 검증이 아니라 당시 chunks의 해시를 재구성하여 맞춘 검증이다.

[changes.json](changes.json)의 두 계획은 **비활성 후속 제안**이다. 원 source_mapping_evidence의 잘못된 page를 원전 쪽수로 명료화하면서 registered_page=409를 따로 보존하고, 실제 쪽수 상속 원인을 metadata에 덧붙였다. 실질 요구·source_unit_ids·은행·인용·답안·criterion·점수는 바꾸지 않았다. 역적용하면 원계획과 정확히 같고 계획 validator 오류는 0이다. 새 계획을 선택하면 두 세트의 의미검수 입력이 달라지므로 별도 잠금과 후속 검수가 필요하다. 원 receipt는 변경하거나 재해시하지 않는다.

[parser-impact.json](parser-impact.json)은 공통 파서의 page 계승 위치와 안전한 보완 방향을 별도로 기록한다. 같은 파일의 반복 단위 20개 가운데 15개는 원본문과 같지만 상속 쪽수가 틀리며, A23 한 개는 408–409의 여러 쪽 범위를 밝혀야 한다. 선택119 계획 중 09-002/003/004/005/007이 해당 ID를 직접 참조한다. 15단위의 메모리상 page/locator 보정은 ID·quote·해시·범위 등 나머지를 보존하지만, 실제 공통 코드·registry는 수정하지 않았다. 파일을 쓰는 세트 범위 및 과거 ledger 검색을 포함하되 전체 과거 receipt 호환 검사 완료로 표현하지 않는다.

[smoke-readiness.json](smoke-readiness.json)은 학습 smoke 준비 상태다. 공통 동결3065개와 smoke 추가 입력816개가 현재 해시와 일치하고 a/b/c의 새 출력은 아직 없다. root의 실제 진단은 HTTP429 `credit_balance_exhausted`/`insufficient_quota`였으며 C는 호출 시작 전에 중지 지시를 받았다. 학습단위249개의 **비빈 모범답안 실측은 0**, C 활성 API 프로세스도 0이다. 기존 정적 빈답안·fixture 검사를 실제 비빈 채점으로 세지 않는다.

이번 작업은 로컬 대조와 제안뿐이다. API·공통/원본 수정·DB 쓰기·게시·사람 확인은 하지 않았다.
