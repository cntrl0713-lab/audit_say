# R3 C 검수 결과와 직접 근거 보완안

`pilot-03-001`의 실제 의미검수 8단위·30생성사례 응답은 완료됐으나, 1개 source_support uncertain과 1개 nonduplication fail로 최종 fail이다. 따라서 생성 사례 채점은 시작하지 않았다. 독립 작성자 QA22는 현 grader에서 모두 첫 관측에 기대값과 일치했다. 비빈답 20개는 실제 모델, 빈답 2개는 무호출 경로다. 원반례 두 답안의 이전 각 3관측은 보존하며, 현 설정 후속 QA는 각각 1관측이다. 실행 세션은 모두 종료했다.

`evidence.json`은 실패 판정과 전체 actual request의 원문 도달 범위를 대조한다. sub1/crit3은 src6(A11)만 요구출처로 연결했고 A11 인접 문맥에 6(b) 본문이 없다. 전체 request에 등장한 추가 정보 문구는 다른 문항의 채점명제일 뿐 공식 직접 근거가 아니다. 같은 등록 공식 파일의 L325–343에 6(b)(i)~(iii)가 존재한다. 이는 새 자료 확보나 원문 변경이 필요한 문제가 아니라 등록된 의존 본문을 문항 검수 입력에 연결하지 않은 문제다. 이전 A11 단독 pass를 반복 호출하여 유지할 이유가 없다.

`proposal.json`은 6(b)의 정확한 부분문자열을 새 source_ref로 추가하고 sub1/crit1~3의 근거 목록에 연결하는 필드별 제안이다. 기존 A11/A14 인용·requirements와 질문·답안·claim·배점·상태는 보존한다. 새 근거는 세 책임 범주를 뒷받침하며 정보 접근의 세 상세 경로를 추가 득점 요건으로 만들지 않는다. 실제 카탈로그 `src-fdfd62f7d764e46a4c`에 포함되고, 메모리 형상·계획 검사 및 sub1/criterion의 요구출처 전달이 통과했다.

03-006/sub1과는 정당성·범위제한 원리의 적용상 부분 관계가 있다. 03-001/sub2는 두 일반 고려사항을 기술하며, 03-006/sub1은 갑과 을의 사실을 해석하여 각각 정당성 및 구체 이유를 판단한다. 동일한 두 일반사항을 다시 묻는 완전 중복으로 보는 것은 지나치다. 기존 계획에 해당 ID의 명시 비교가 없었던 점은 인정하고, 이번 후속 계획에서 일반 원리와 사례 적용 복습의 차이를 추가한다. 과거부터 이 관계가 명시됐다고 소급하지 않는다.

출처 추가는 reviewed content 및 전체 비교은행 해시를 바꾸므로 새 후보·검수 epoch가 필요하다. 제안 상태에서 공통 은행·코드·원문·실제 문항 파일은 변경하지 않았다. QA22 각각의 현행 `buildGradingPrompt`와 schema는 제안 전후 동일함을 해시로 확인했지만, 이전 semantic receipt 해시를 새 은행 값으로 바꾸어 수락하지 않는다. 전체 결과와 경로·해시는 `status.json`에 기록했다.
