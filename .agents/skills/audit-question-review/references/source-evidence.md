# 제작·검증의 원자료 대조

제작 스킬과 검토 스킬이 함께 사용하는 절차다. 경로·소유권은 저장소의 `docs/출제-검토-자료-관리.md`와 `cpa_uploader/raw/README.md`, 카탈로그 형상은 `cpa_uploader/wiki/SCHEMA.md`를 따른다.

## 확보와 계보

- wiki는 탐색의 시작점이다. 실제 발문·기준서 원문·공식 판본·시행 근거까지 추적한다. 학습자료, 공식 원본, OCR·추출본, 공식 전사, 작성자 해설의 권위를 구분한다. 같은 내용을 raw에 복사했다고 공식 출처가 되는 것은 아니다.
- 새로 확보한 PDF·HTML·문서와 검증에 쓴 페이지 이미지·추출 텍스트는 raw에 보존한다. 원 URL·문서 제목·확인일·판본·쪽수/문단·원래 경로·바이트 SHA-256을 실제 확인 범위로 기록한다. 저장하지 못한 원본과 URL만 있는 출처는 명시적으로 미보관으로 남기며 추측한 해시·확인일을 채우지 않는다.
- 내려받은 파일이 요청한 문서인지 열어 확인한다. 오류·로그인 페이지나 빈 파일은 원문 확보로 세지 않는다. 실패 응답을 보존했다면 출처 원본과 구분한다. PDF 파일의 페이지 순서와 인쇄된 쪽번호도 구분한다.
- 원본 → 추출본 → 등록 전사 → 문항 인용의 각 단계 파일·해시·위치·추출 방법을 연결한다. 파일 전체 해시와 인용 문자열 해시를 혼동하지 않는다. 원문과 바이트가 다른 OCR·전사는 별도 파일로 보존한다.
- 기존 인용·실행 증거가 참조하는 원문 경로와 바이트는 유지한다. raw 보존본과 원래 경로를 수집 매니페스트로 연결하고 기존 receipt 안의 경로·해시를 일괄 치환하지 않는다. 원본을 고치지 않고 새 출처와 후속 검수 입력을 만든다.

## 내용과 범위

- 인용이 실제 파일에 포함되는지와 요구 문단이 완결되는지는 별도로 확인한다. 문단의 시작·끝, 페이지 경계를 넘는 결론·하위 목록·예외·적용자료를 원본에서 대조한다. 연속 부분문자열이라는 이유로 잘린 문장을 완전한 공식 근거로 승인하지 않는다.
- PDF 추출 순서가 불분명하거나 표·각주·줄 연결이 판단을 바꾸면 해당 원본 페이지를 직접 확인한다. 쪽말 각주를 현재 페이지 마지막 문단의 요구로 자동 귀속하지 않는다. 실제 호출번호·소유 문단을 대조하고 SCHEMA의 `referenceFootnotes` 계약을 따른다. 원 인용과 페이지·행 위치는 그대로 보존한다.
- 반복 발췌의 페이지가 앞서 나온 다른 문단의 마지막 페이지를 잘못 이어받지 않았는지 확인한다. 동일 파일·기준서·문단의 실제 본문과 대조하고 여러 페이지에 걸친 인용은 각 조각을 확인한다. 위치 교정은 원 인용 바이트·단위 ID를 보존한 후속 메타데이터로 기록한다.
- 제목에 다른 기준서가 인용됐다고 본문 소속 기준서를 바꾸지 않는다. 실제 기준서 시작과 관계 설명용 소제목을 구별한다. 출처 단위 ID가 바뀌면 계획·연결·미완료 실행의 영향을 확인하고 과거 증거를 재작성하지 않는다.
- 문항 `source_refs[].page`의 `KGA NNN` 값은 현행 은행의 기준서 분류 키다. 국내 기준서를 새로 등록할 때 실제 인용 기준서와 `classification.standards`를 일치시킨다. DOCX XML 문단·전사 행·PDF 쪽수는 `title`·`source_span`·출처 장부에 보존하고 분류 키를 대신 넣거나 없는 PDF 쪽수를 추정하지 않는다.
- 발문에서 요구한 범위와 기준서의 전체 요구를 구분한다. 원문에 있는 후속 조치라도 발문이 묻지 않았으면 숨은 채점 요건으로 추가하지 않는다. 범위를 좁혔으면 발문·계획·답안·배점을 함께 대조한다.
- 발표일·시행일·대상 보고기간·시험 적용 연도를 구분한다. 새 적용 판단은 공식 원문·공고로 확인하고 미확정 사항은 작업 가정으로 남긴다.
- 공식 전문에 `202X` 같은 자리표시 문자가 남아 있으면 연도를 추측해 원문을 고치지 않는다. 해당 개정의 승인·시행 공고와 실제 요구 문단을 별도로 대조한다. 국제 기준의 대응 문구나 다른 국내 기준서의 참조만으로 국내 본문·판본을 확인했다고 처리하지 않는다. 검증 완료를 요구받은 적용 범위의 미확인 근거는 해결 전까지 보류한다.

## 패킷과 후속 검증

- 입력 예산 초과 시 먼저 문단·제목·각주 오귀속을 조사하고, 실제 필요한 의존 문단을 확인한다. 의도한 원자료 ID로 범위를 명시한 뒤 모델 호출 없는 사전검사를 한다. 필수 원문·비교 대상을 잘라내거나 예산 때문에 공식 근거를 학습자료로 대체하지 않는다.
- 원자료 보존·해시 검사, 인용 완결성 대조, 의미검수, 실제 채점, 사람 확인을 각각 기록한다. raw 정리만으로 문항이나 관계의 검수 상태를 올리지 않는다.
- 패킷의 `complete`는 파서가 해석한 참조 확보 상태다. 의미상 필요한 문맥 전부를 확인했다는 판정으로 대신하지 않는다. 물음의 requirement뿐 아니라 criterion의 보충 출처도 실제 검수 입력에 포함되는지 확인한다. 모델 원시 응답·실행 로그는 원자료와 역할이 다르므로 기존 실행 증거 위치에 보존한다.
- 내용·출처·계획·비교 은행·공통 코드가 달라졌으면 현행 수락 계약으로 재사용 가능성을 판단한다. 새 실행 잠금과 출력 경로를 사용하고 옛 잠금의 해시만 최신 값으로 바꿔 이어가지 않는다.
