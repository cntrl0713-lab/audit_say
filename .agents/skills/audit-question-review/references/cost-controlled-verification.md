# 비용을 통제하는 내용 검토와 실제 채점

현재 프로젝트는 수익 전 단계이며 비용을 중요한 제약으로 둔다. 공통 원칙은 [AGENTS.md](../../../../AGENTS.md)를 따른다. 사용자 후속 결정이 과거 배치의 실행 횟수·receipt 절차보다 우선한다.

**95%·±1점은 채점의 일관성만을 위한 허용 기준이다.** wiki·기준서 해석·발문·모범답안·배점 기준·시험 답안의 기대값은 정확해야 하며 오류 허용률을 적용하지 않는다. 전수 내용 검토에서 발견한 오류와 미확인 근거를 해결하고, 기반 자료에 미해결 결함이 있으면 채점 통과율이 높아도 게시하지 않는다. 검토 범위·확인한 근거를 남기며, 형식 검사만으로 완전성을 주장하지 않는다.

## 검토와 실행의 구분

1. **내용 의미검수**: 담당 agent가 발문·부모 사실·모범답안·모든 criterion·정수 배점·직접 출처·적용 판본을 실제 읽고 대조한다. 기준서형의 독립성과 사례형의 사실 적용, 물음별 주제·배점 타당성을 확인한다. 대상 ID, 검토자 종류, 내용·출처 해시, 확인한 문단·인용, 판정 이유와 미해결을 기록한다. 형상·해시 검사만으로 의미검수 pass를 만들지 않는다.
2. **별도 API 의미검수**: 다른 모델 요청으로 같은 내용을 다시 검토하는 선택 단계다. 기본 경로에는 필수가 아니다. 시행했다면 실제 호출과 사용량을 별도 기록한다.
3. **실제 채점 확인**: 운영과 같은 Luna 채점 경로에 합성 답안을 넣고 기대점수와 실제 결과를 대조한다. agent의 판단 재생·mock·점수 합산 검사와 구분한다.
4. **사람 확인·게시·DB**: 실제 사람의 내용 확인 여부와 사용자의 게시 승인 범위를 따로 기록한다. agent 검토와 대표 실측 후 게시를 사용자가 승인했다면 해당 증거 경로로 진행할 수 있지만, 이를 사람이 모든 내용을 읽은 것으로 기록하지 않는다.

## 대표 사례와 성공 기준

- 내용 검토는 대상 물음 전수, 실제 채점은 물음별 모범답안·대표 부분정답·대표 오답/조건 경계를 기본으로 한다. 동일한 답안·모델·요청·스키마는 중복 실행하지 않고 여러 점수 기준을 한 응답에서 확인한다. 선정한 사례와 제외·통합 이유를 **결과를 보기 전에** 기록한다.
- 현행 효율 실행의 세 역할은 저장 모범답안 만점, `0 < 기대점수 < 만점`인 부분정답, 0점 오답이다. 조건 경계 답안이라도 맞는 요소가 남아 있으면 부분정답이며 0점 역할로 이름만 바꾸지 않는다. 원 경계 답안·기대값을 보존하고 실행 역할에 맞는 대표를 선택한다. 저장 모범답안 시험은 `model_answer.join('\n')` 바이트 그대로 사용하며 뜻이 비슷한 다른 QA 답안으로 대신하지 않는다.
- API 호출 전에 대표별 원답안·전체 criterion·정수 합계·역할별 점수 범위·전 물음 역할 커버·중복 요청을 검사한다. 검사 함수가 오류 배열을 반환하면 빈 배열임을 확인해야 통과다. 최종 receipt 단계까지 선정 오류를 미루지 않는다.
- 명칭·요소의 열거를 요구한 물음과 적합성 평가·필요성 판단이라는 행위를 요구한 물음을 구별한다. 후자에서 평가 대상 이름만 적었다고 행위 점수를 자동 부여하지 않는다. “확인한다”처럼 여러 뜻으로 읽히는 답안은 발문 문맥과 최소 충분 명제를 대조해 기대값을 정한다. criterion을 분리하거나 ID를 이관했으면 기대판정의 이유도 현재 기준에 맞는지 각각 확인하며, 합계가 같다는 이유로 옛 기준의 설명을 그대로 복사하지 않는다.
- 별도 부분점수가 존재하지 않는 1점 물음은 모범답안과 오답 2종으로 확인한다. 사례 전체를 함께 요청하면서 일부 물음만 검사하는 회차는 평가 대상 ID를 명시하고, 나머지 물음의 빈 답안은 통과율 분모에서 제외한다. 동일한 모범답안을 반복해 분모를 늘리지 않는다.
- 새 유형·복잡한 조건·동일 기준의 결합/분리·실제 오류에 필요한 사례만 추가한다. 모든 criterion마다 5종의 답안을 별도 API로 검사하거나 생성 사례와 작성자 QA를 이중 전수 실측하지 않는다. 기존 반례는 삭제하지 않고 재실측 대상을 선별한다.
- 화면에서 실제 사용하는 기준서형 독립 물음/사례형 전체 물음의 투영으로 모범답안을 채점하여 학습 단위 최종 시험과 통합할 수 있다. 이전 전체 세트 요청을 새 독립 물음 요청과 같다고 가정하지 않는다. 빈 답안·형상·정수 합산·ID·분류·공개본 비밀정보 제외는 가능한 로컬 검사로 수행한다.
- 모델은 Luna를 유지한다. 각 관측의 물음별 기대점수와 실제 점수의 차이가 **±1점 이내**이면 허용한다. 원 기대값·엄격 판정·실제 점수는 보존하고 `accepted_with_grading_deviation` 등 별도 결과로 구분한다. 기대값은 원문과 요구에서 정하며 실제 결과에 맞춰 고치지 않는다.
- 대표 검증 답안의 **95% 이상이 물음별 ±1점 이내**에 드는 것을 품질 목표로 삼는다. 이 수치는 검증한 사례의 관측 통과율이며 모델 자기 신뢰도·통계적 신뢰구간·모든 가능한 답안의 정확도 보장이 아니다. 검증 집합·분모·중복 처리·재검사 결과는 고정하고 최초 결과와 수정 후 결과를 따로 보고한다.
- 허용 범위 밖의 나머지 관측은 원인과 학습 영향을 기록해 수정·표적 재검사·잔여 제한을 결정한다. 출처·정답·발문·배점 결함, 실행·응답 형상·보안·인용 귀속 오류를 5%의 점수 오차로 면제하지 않는다. 특정 유형에 집중된 반복 오류는 전체 비율이 95%여도 조사한다.
- 허용한 편차를 없애기 위해 같은 답안을 3회 반복하지 않는다. 재현이 필요한 오류는 해당 사례만 목적과 한도를 정해 실행한다. 미완료·오류 사례를 분모에서 숨기거나 통과 결과만 골라 목표를 달성했다고 보고하지 않는다.

## 비용과 증거

- 사용자가 정한 배치별 금액 상한·모델·공급자 한도 방식을 기록한다. 제공자 측 한도가 설정되어 있으면 비용 예측용 AI 호출이나 별도 토큰 추정 작업을 필수로 만들지 않는다. 한도·잔액 소진을 확인하면 새 호출과 반복 진단을 멈춘다.
- 실제 응답의 요청/응답 ID, 요청·응답 모델, 입력 토큰·캐시 토큰·출력 토큰·추론 토큰과 서비스 tier를 가능한 범위에서 보존한다. 과금 계산은 공식 단가·시점·캐시/장문/tier 조건을 명시한다. 누락된 사용량은 `unknown`이며 0이 아니다. 출력 토큰에 포함된 추론 토큰을 중복 합산하지 않는다.
- SDK 응답을 JSON으로 저장할 때 헤더에서 붙인 비열거 속성이 빠질 수 있으므로 요청 ID를 별도 명시 메타데이터로 보존한다. 원 응답 본문의 ID·모델·사용량과 기록 콜백의 값을 대조한다. 과거 JSON에 헤더 속성이 없다는 이유만으로 실제 응답을 폐기하거나 유료 채점을 반복하지 않으며, 본문·원 요청·trace의 결속과 SDK 직렬화 동작을 먼저 확인한다.
- 사용량 기록 콜백은 판정·재시도와 분리한다. 기록 실패를 학생 오답이나 모델 재호출로 바꾸지 않는다. 서버 키·실제 사용자 답안을 실행 로그에 넣지 않는다.
- 검증 요청은 필요한 물음·사실·기준·직접 근거를 포함하되 같은 비교 은행을 기준별로 반복 전송하지 않는다. 중복 검토는 agent의 전수 은행 대조에서 근거를 남긴다. 비용을 줄이려고 필수 조건·출처를 생략하지 않는다.

## 재사용과 승급

- 과거 agent 내용 대조는 같은 내용·출처·판본·계획임을 확인하고 직접 판정 근거를 읽어 재사용한다. 단순 작업 완료 메시지나 해시 일치만으로 전수 내용 검토를 주장하지 않는다.
- 과거 실제 채점은 모델·instructions·입력·스키마와 물음 계약의 동일성을 확인한다. 코드가 바뀌면 원 응답을 재처리해 점수·인용·보안·결과 귀속을 대조한다. 재처리는 실제 API 재실행이 아니며 옛 토큰 사용량을 새 호출로 합산하지 않는다.
- 기록기나 수락 코드만 수정한 재개는 원 실행 manifest·입력·코드 보존본·원 응답 경로와 해시를 명시적으로 연결한다. 재사용할 답안·기대표·모델·실제 채점 동작의 동일성을 검사하고 원 응답을 새 수락 계약으로 재처리한다. 기대값을 정정한 사례는 이 동일성 재사용 대상에서 제외하고, 원 기대값과 결과를 보존한 채 필요한 표적 검사만 새로 수행한다. 재사용·새 호출·제외된 과거 호출의 건수와 비용을 각각 기록하여 중복 계산하지 않는다.
- 정책·검수 형상이 달라지면 새 실행 버전·출력과 명시적인 수락 계약을 만든다. 원 receipt·불일치·계획·비교 은행을 보존한다. 기존 엄격한 모델 receipt 검사를 약화해 통과시키거나 과거 잠금 해시를 새 값으로 덮어쓰지 않는다.
- 비용 통제 경로의 승급 증거에는 사용자 정책·승인 범위, 검토 내용과 출처의 신원, 실제 agent 의미검토 장부, 대표 사례 선정 근거, 실제 채점 원응답과 허용율·잔여 차이, 검수 후 입력 불변 확인을 묶는다. 기존 승인 문항의 수정은 새 이력을 추가한다.
- 이 경로는 `promote_cpa_v3.ts --to verified --sets <ID,...> --efficient-review <batch.json> --evidence <검토 기록>`으로 명시한다. 기존 승인 문항은 `--reverify`를 함께 사용한다. `--review`와 혼용하지 않으며, 기존 엄격한 의미검수 receipt의 필수 검사를 이 경로에 맞춰 완화하지 않는다.
- 정본·공개본·운영 DB 반영은 선택한 경로의 검증을 통과한 최종 내용으로 수행한다. 단계별 실제 완료와 미완료를 구분해 보고한다.
