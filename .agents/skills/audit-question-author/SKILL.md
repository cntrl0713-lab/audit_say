# 회계감사 문제·물음 제작

공통 사실관계를 가진 사례형 문제와 단독 풀이하는 기준서형 물음을 제작한다. 학습자가 읽는 요구, 모범답안, 실제 득점 요건을 일치시킨다. 이 파일이 Claude·Codex 공통 본문이다. 아래 코드 경로는 작업 중인 `audit_say` 저장소 루트 기준이며 개인 스킬 폴더를 데이터 루트로 삼지 않는다.

## 유형별 제작 경로

사용자가 스킬 이름을 쓰지 않아도 신규 제작·추가·확장 요청에 적용한다. 유형을 지정하지 않았으면 물음의 목표·득점 요건으로 먼저 판정하고 아래 경로를 선택한다. 기준서형/사례형은 `question_style`, 열거/서술/판단은 답안 `type`이다.

| 경로 | 제작 시 필요한 설계 | 검토 스킬로 넘길 확인점 |
| --- | --- | --- |
| 기준서형 물음 제작 | 기준서의 요구와 일반 적용 조건을 독립 발문에 담고 사례 사실·다른 물음에 의존하지 않도록 작성 | 사실관계 없이 최소 충분 답안으로 만점 가능, 숨은 사례 요구 없음, 요소별 배점·서술 부분점수 |
| 사례형 문제·물음 제작 | 필요한 부모 사실을 먼저 확보하고 각 득점 요건이 어떤 사실의 해석·적용을 요구하는지 대응 | 기준서 일반론만으로 사례 적용 점수를 받지 않음, 부모 사실 충분, 소속 물음 전부 사례형, 다주제·전체 물음 유지 |

기존 물음의 유형만 바꾸거나 배점을 검토·수정하는 요청은 [검토 스킬](../audit-question-review/SKILL.md)로 시작한다. 검토 결과 새 사실관계나 새 요구의 제작이 필요하고 요청 범위에 포함되면 이 제작 경로를 추가한다. 혼합 유형 묶음은 학습 단위 계약에 따라 분리하며 분류 근거와 원문 ID 계보를 남긴다.

## 1. 요청과 현행 지침 확인

- 대화에서 확정된 주제·제작량·난이도·적용 연도·정본 반영 범위를 이어받는다. 사용자가 요청한 전체 설계안을 우선순위만으로 일부 축소하지 않는다. 정답이나 범위를 바꾸는 미확정 사항만 질문하고 독립적인 원문 확보·설계는 계속한다.
- 문제 제작·확장은 기본적으로 초안 작성, 의미검수, 실제 모델 채점, 불일치 원인 조사와 필요한 수정·재채점까지 포함한다. 사용자가 계획·초안만 요청하거나 모델 호출 금지·예산 등으로 범위를 제한한 경우 그 제한을 따른다. ‘실제 채점’이라는 별도 요청이 없다는 이유로 작성자 QA에서 종료하지 않는다. 사람 승인·정본 승급·운영 배포는 별도 상태와 요청 범위로 관리한다.
- `cpa_uploader/wiki/_meta/authoring-dashboard.md`와 `cpa_uploader/analysis/coverage/README.md`에서 현재 은행·초안·연결 레지스트리의 위치와 입력 해시를 확인한다. 자동 연결·집계와 사람이 확인한 의미 관계를 구분하고, 날짜별 보고서의 수치·미편입 주장을 현재 상태로 재사용하지 않는다. 자료를 추가·옮길 때는 `docs/출제-검토-자료-관리.md`의 소유권을 따른다.
- `docs/plans/주제-01-03-검토에-따른-수정-결정.md`, `cpa_uploader/wiki/question-generation/question-design.md`, `question-output-schema.md`, `source-authoring-design.md`를 읽는다. 마지막 세 파일은 모두 같은 `question-generation/` 디렉터리에 있다. 필요한 `topics/topic-XX-design.md`를 함께 읽는다. 주제별 세부 규칙은 공통 문서의 옛 제목을 찾지 말고 해당 파일에서 확인한다.
- 실제 형상은 `lib/questionV3.ts`, 생성 입력은 `cpa_uploader/generate_cpa_v3.ts`와 `cpa_uploader/questionAuthoringPlan.ts`에서 확인한다. 확정 정책과 현재 코드 지원 여부를 구분한다. 모델은 현재 환경 설정을 따르고 스킬에 모델명을 고정하지 않는다.
- [물음별 학습 단위 계약](../../../docs/물음별-학습-단위와-분류-계약.md)을 읽고 사실 의존성에 따른 `question_style`과 실제 요구내용의 `topic_ids`를 물음마다 정한다. 답안 `type`이나 부모 대표 주제로 자동 대체하지 않는다. 자료 계보와 학습 부모, 신규 형상과 과거 판본 이관을 구분한다.
- 기준서의 발표일·시행일·보고기간·시험 적용 판본을 구분하고 새로운 적용 판단은 공식 자료로 확인한다. 기존 2027년 작업의 ‘2026년 시행 기준 동일 적용’은 그 작업의 가정이며 모든 새 출제에 자동 적용하지 않는다. KGA 220의 해당 판본을 다루면 `docs/archive/과거-검토-증거/reports/question-review-2027/개정-감사기준서-220-시행일-별도-기록.md`도 읽는다.

## 2. 원자료·빈도·기존 문제 연결

[공통 출처 검증 지침](../audit-question-review/references/source-evidence.md)을 읽는다. wiki에서 찾은 기반 자료와 공식 대조 자료를 `cpa_uploader/raw/`에서 추적하고, 새 원자료는 먼저 수집·등록한다. 학습자료·공식 원문·추출본을 구분하여 원문 완결성·판본·각주와 의존 문단까지 대조한 뒤 출제 범위를 설계한다. raw 수집·해시 일치를 의미검수나 실제 채점으로 기록하지 않는다.

빈도 또는 미출제 보완에 근거한 제작이면 `cpa_uploader/wiki/question-generation/question-elements.md`와 `cpa_uploader/analysis/question-elements/README.md`, `deduplication.md`, `frequency.md`, `question-elements.json`을 읽는다. 마지막 네 파일은 같은 분석 디렉터리에 있다. 학습 순서는 `cpa_uploader/wiki/_meta/ox-study-order.md`를 따르되 기존 `topic_id`와 문제 ID를 순서에 맞춰 바꾸지 않는다.

- 구체적인 요구사항별 요소 ID에서 원출제 식별자·실제 발문·공통지문·답안까지 추적한다. 기출 빈도와 모의고사 빈도, 연습·OX 수록 수를 구분한다. 서로 다른 연도·실제 물음의 출제는 각각 집계하고 교재 재수록만 제외한다. 같은 원물음의 동일 요소는 한 번 센다.
- `고급_회계감사_연습.md`와 `주제별_회계감사_연습.md`의 재수록 및 기출문제의 교재 재수록을 별도 출제로 더하지 않는다. 요소 문자열이 같다는 이유로 서로 다른 실제 출제까지 제거하지 않는다. 분석의 확인·보류 상태와 원출제 연결을 확인한다.
- 새 물음과 요소의 관계를 직접 대응·일부 대응·상위 요구·인접 요구·제외로 기록한다. 인접 요구의 빈도를 새 요구의 직접 빈도로 전용하지 않는다. 0회, 인용 연결 없음, 문구 겹침이 낮다는 사실만으로 미출제를 확정하지 않는다.
- 과거 공백 보고서는 후보 목록으로 사용한다. 현재 `cpa_uploader/data/cpa_question_sets_v3.authoring.json`의 발문·답안·criterion과 진행 중인 초안을 대조하여 신규 요구, 기존 요구의 심화, 의도된 복습을 구분한다. 의미 검토 전의 후보 요소를 확정된 출제 요소로 표현하지 않는다.
- 재사용할 요소↔기준서 요구↔문항 관계는 `cpa_uploader/analysis/coverage/links.json`의 입력 계약에 따라 기존 ID·관계·근거·검토 상태·확인 당시 해시로 남긴다. 생성 `registry.json`을 직접 고치거나 원문·정답·빈도를 관계 장부에 중복 작성하지 않는다. 배치별 제작 장부·계획·패킷·QA는 해당 `cpa_uploader/drafts/` 배치에 보존한다. `readPendingDrafts`의 기본 탐색 밖인 초안 폴더도 명시적으로 대조한다.
- 은행에 없는 초안을 관계 장부에 연결할 때는 coverage README의 `target.scope: draft`와 실제 파일·세트·물음·criterion ID를 사용한다. 이후 정본 반영 시 대상과 ID를 다시 대조한다. 초안 연결이나 관계의 `reviewed`는 문항의 정본 편입·사람 승인·게시를 뜻하지 않는다.
- `cpa_uploader/questionDraftInventory.ts`의 `readPendingDrafts`는 기본으로 `cpa_uploader/data`만 탐색한다. `cpa_uploader/drafts`와 사용자가 지정한 별도 초안 폴더도 명시적으로 조사하거나 `extraDirectory`로 전달한다. 기본 탐색 결과만으로 진행 중인 초안이 없다고 단정하지 않는다.
- 제작 장부에 요소 ID·빈도 종류·원출제/페이지·비교한 기존 ID·새 요구와 차이·데이터 해시를 남긴다. 상위 주제 합계는 분석의 집계 단위를 유지하고 서로 다른 척도를 임의로 더해 중요도 점수로 만들지 않는다.

## 3. 출제 계획과 답안 범위

`cpa_uploader/wiki/question-generation/source-authoring-design.md`와 `cpa_uploader/questionAuthoringPlan.ts`에 맞춰 `adapt_existing_question` 또는 `new_from_standard` 계획을 작성한다. 목표, 주체·시점·조건·예외, 요구 답안, 제외 범위, 실제 `source_unit_ids`, 기존 문제와의 차이, 판본 가정과 미확인 사항을 기록한다. 계획의 `ready`는 생성 입력 준비 상태이며 문제 검수 완료가 아니다.

생성기를 쓰면 실제 카탈로그 단위와 의존 문단을 확보하고 계획·source packet sidecar를 보존한다. 수동 발췌를 생성기 패킷으로 꾸미거나 존재하지 않는 카탈로그 ID·해시를 만들지 않는다. 자동 탐색 이름은 `draft.json.authoring-plan.json` / `draft.json.source-packet.json`이다. 다른 이름을 쓰면 후속 검수에서 `--plan`, `--packet`을 실제 경로로 지정한다. 생성 당시 계획 해시를 기록한 문항의 패킷 필수 계약은 현행 검수 코드로 확인한다.

물음별로 **학습목표 → 발문 요구 → 조건·예외 → 정답 명제 → criterion·정수 배점 → 공식 근거** 대응표를 만든다. 내부 ID·빈도·채점 구현 설명은 학습자 발문에 넣지 않는다.

[공통 배점 계약](../../../docs/물음별-학습-단위와-분류-계약.md#배점과-물음별-타당성)을 읽고 열거 요소별 배점·서술 의미 단위별 부분점수·판단과 근거의 득점을 설계한다. 모든 물음에 최소 충분 답안, 서술·추론 부담, 비슷한 요구와의 배점 비교, 유지/조정/분리 결정과 이유를 남긴다. 독립성이 없는 언어 조각으로 배점을 늘리거나 요구가 많은 물음을 단순한 만점/0점 기준으로 묶지 않는다.

- 판단에 필요한 사실과 시점을 공통지문에 보존한다. 서로 다른 상황은 독립임을 명시하고, 정답 결론을 이미 주어진 사실로 제공하지 않는다. 제목·주제·태그는 실제 물음 전체를 반영한다. 세트와 물음 수는 요청과 현행 형상에 따른다.
- 새 출력은 같은 학습 유형의 1~4개 물음으로 작성하고 각 물음에 `question_style`·하나 이상의 `topic_ids`를 기록한다. 사례형은 부모 사실과의 연결을 설계하고, 기준서형은 공통사실을 비워 각 물음이 혼자 풀리도록 쓴다. 과거 혼합 세트 확장은 원문 계보를 보존하며 학습 단위 계약의 분리·후속 버전 절차를 따른다.
- 모든 물음은 `selection={type:'all',n:null}`, `constraints={ordered:false,max_entries:null,overflow_policy:'none'}`를 사용한다. 발문이 한정한 범위를 모두 요구하며 ‘앞 N개·최고 N개·일부 선택’으로 답안을 자르지 않는다. 원문의 선택 출제를 바꾸면 범위와 이유를 기록한다. 의미상의 선후관계는 정답과 criterion에 보존한다.
- 상위 항목 수와 하위 채점 명제 수를 구분한다. 기준서가 여러 대안 중 하나 이상을 허용하면 대안 목록의 완전한 서술과 실제 감사에서 모든 대안을 수행할 의무를 혼동하지 않는다.
- 명칭·정의·판단·이유·조치를 구별해 요구한다. 명칭만 묻는 점수에 정의를 요구하지 않는다. 해설에만 있고 발문이 묻지 않은 지식, 주어진 사실의 단순 반복에는 점수를 주지 않는다.
- 독립 명제는 기본 1점(`met=1`, `not_met=0`, `contradicted=0`)이며 소수 partial을 넣지 않는다. 일부 criterion을 충족한 정수 점수는 유지한다. 별도 가중치가 필요하면 정수 배점과 부분 충족 계약을 명시한다. 과거 세트 8점 상한을 재도입하거나 독립 요구를 상한에 맞춰 합치지 않는다.
- 판단·근거의 분리/결합 배점을 대응표에 명시한다. 요구 조치나 이유에서 결론이 분명하면 정해진 결론 문구가 없어도 판단을 인정한다. 명시적 반대 결론은 인정하지 않는다. 별도로 충족한 근거 점수는 그 criterion 계약에 따른다.
- 한 문장이 여러 독립 명제를 충족하면 같은 답안 인용을 허용한다. 같은 사실을 표현만 바꿔 중복 배점하지 않는다. 대상·조건·부정·수치·그리고/또는·법규상 예외·보고 시점을 보존하며 자연스러운 동의 표현을 허용한다.

## 4. 공식 근거와 초안 작성

- 공식 원문의 본문·하위 항목·관련 적용자료·예외를 함께 확보한다. 학습자료 요약·기출 해설·wiki·기존 정답은 공식 근거의 대체물이 아니다. 판본·문단·공식 URL·확인일을 기록하며 로컬 원문이 없으면 부재를 밝히고 실제 자료를 확보한다.
- `source_refs`, `requirements`, `source_ref_ids`가 각 정답 명제를 직접 지지해야 한다. 원문 인용은 윤문하지 않고 실제 변환에 맞춰 `source_fidelity`를 기록한다. 재구성·범위 명료화를 공백 정리만 했다고 표시하지 않는다. 인용 문자열의 SHA-256과 전체 파일의 해시를 구분한다.
- `source_refs[].page`는 KGA 분류에도 쓰인다. `KGA 402` 같은 기준 식별을 보존하고 PDF 쪽수·문단·판본은 `title`, `source_span`, 출처 장부에 기록한다. `classification.standards`와 실제 출처의 `#`~`### KGA NNN:` 제목 구간도 `cpa_uploader/questionBankPublication.ts`의 검증 계약과 맞춘다. 로컬 exact 인용 일치는 공식 판본·내용 정확성 확인과 별개다.
- 독립 신규 초안은 정본·공개본을 덮어쓰지 않는 경로에 `status=needs_review`, `verification.review_status=needs_human_review`로 작성한다. 실제 타입이 바뀌면 현행 형상을 따른다. 검증 통과를 위해 상태를 올리지 않는다.
- 초안 탐색은 `draft`·`checkpoint`가 들어간 JSON 파일명을 문항 후보로 처리할 수 있다. 작성자 QA는 `qa-<ID>.json`처럼 이름을 정하고, 합본 문항 JSON을 개별 초안과 같은 탐색 폴더에 중복 저장하지 않는다. 계획·패킷·receipt는 현행 `readPendingDrafts`의 인식 형상을 확인한다.

## 5. 검증과 전달

현재 기본 검증 강도는 [비용 통제 검증 지침](../audit-question-review/references/cost-controlled-verification.md)을 따른다. agent의 내용 의미검수와 별도 유료 API 재검수를 구분하며, 실제 채점은 물음별 대표 모범·부분·오답 사례를 통합한다. 모든 criterion의 여러 답안을 API로 반복 실행하는 것을 기본 의무로 두지 않는다. 사용자가 승인한 Luna·±1점·95% 실측 목표와 배치 한도를 제작 후 검증에도 이어받는다.

검토 스킬에는 물음별 학습 유형·분류 이유, 해당 유형의 확인 결과, 배점 대응표와 타당성 결정을 함께 넘긴다. 기준서형 독립성과 사례형 사실 적용을 구분해 확인하고 [공통 배점 계약](../../../docs/물음별-학습-단위와-분류-계약.md#배점과-물음별-타당성)의 부분정답·기준 분할 회귀를 적용한다.

각 물음의 저장 모범답안·완전 답안·허용 표현·한 명제 누락·반대 의미·조건 경계·빈 답안의 기대값을 원문과 criterion에서 먼저 정한다. 누락 사례는 남은 답안 전체로 판단한다. 결론 문장만 지워도 이유가 결론을 함축하면 판단 누락이 아니다. 조건 경계 사례와 명시적 반대 사례를 구분한다. 열거형은 역순·한 문장·명칭 나열도 확인한다.

- 신규 ID의 독립 초안은 `npx tsx cpa_uploader/validate_draft_v3.ts --file <draft.json> --against-bank`로 형상·인용·동일 ID/발문 충돌을 확인한다. 배치 내 중복도 확인한다. 정본 편입 예정이면 현재 은행+초안을 메모리에서 `validateAuthoringBank`로 검증해 기준서 제목·분류 계약도 확인한다. 이 확인을 위해 정본을 먼저 덮어쓰지 않는다.
- 학습 단위 계약에 따라 유형·다주제 연결·사례 facts·기준서형 단독 발문의 적합성을 직접 확인한다. 선택 풀이를 검증할 때는 해당 학습 단위의 답안·최대점수·경험치·복습 범위를 대조하며 원 세트의 전체 결과를 대신 쓰지 않는다. 주제 검색으로 사례형 단위에 속한 물음이 잘리지 않는지도 확인한다.
- 작성자가 만든 기대 판정을 `applyQuestionSetJudgment`로 재생하는 검사는 점수 합산 검증이다. 실제 모델의 의미 판정 실측이나 정식 의미검수 receipt·사람 승인으로 보고하지 않는다.
- 제작한 초안은 [audit-question-review](../audit-question-review/SKILL.md)의 실제 채점·회귀 확인 및 초안 의미검수 절차로 이어간다. 계획·패킷·비교 은행의 실제 경로를 전달하고, 물음별 대표 사례와 위험에 따른 추가 사례를 실제 채점 경로로 검증한다. 허용 범위를 벗어난 결과는 근거를 조사하여 필요한 내용을 수정하고 영향을 받는 사례를 재채점한다. 사례를 더 명시적으로 바꿔도 유효한 원답안과 경계 반례를 함께 보존한다. 의미검수·채점 각각의 실행 종류, 부분 기록, 신규 수락 조건은 검토 스킬에서 확인하며 주입 응답의 통과를 실제 검수로 승계하지 않는다.
- 실행 환경·키·호출 한도·사용자 예산 등 실제 장애가 있으면 확인한 오류, 완료 범위, 미실측 사례와 재개 조건을 기록한다. 가능한 로컬 검증은 계속하되 장애가 해소되지 않은 실측을 완료로 처리하지 않는다. 단순히 호출에 비용이 든다는 이유로 기본 검증을 임의 생략하거나 이미 허용된 실행을 다시 승인받지 않는다.
- 정본 편입·승급이 요청 범위이면 검토 스킬에서 선택한 검수 증거·실제 채점·사용자 승인·승급 장부 계약을 따른다. agent 검토를 사람 검수로 기록하지 않는다. `questions:v3:compile`은 공개본·암호화본을 쓰므로 입력·출력을 먼저 확인한다. 공개본에 사설 채점 정보가 없는지 확인한다. 배포 범위는 사용자 요청을 따른다.
- 출제 규칙·분포·출처·절차가 달라지면 wiki의 `SCHEMA.md`와 수동/생성 문서 구분을 확인하고 필요한 문서만 갱신한다. 연결 분석 입력이 달라지면 `npm run analysis:build`와 `npm run analysis:check`, wiki 입력이 달라지면 `npm run wiki:build`와 `npm run wiki:check`를 수행한다. 생성 문서는 생성기와 입력을 수정해 재생성하며 원자료를 빌드 편의로 바꾸지 않는다. 과거 보고·검수의 해시와 결과는 보존하고 `log.md`에 변경 이유·검증 범위를 기록한다.
- 초안 변경에는 초안 형상 검증과 위의 의미검수·실제 채점을 수행하고, 정본·코드를 바꿨으면 `questions:v3:validate:authoring`과 관련 타입 검사·테스트도 수행한다. 컴파일 후 산출물 일치는 `questions:v3:validate`로 확인한다. 새 문제 제작만으로 전체 엔진·UI 개편을 시작하지 않는다.
- 최종 전달에는 파일·세트/물음 수·총점, 빈도와 기존 요구의 관계, 출처·판본 가정, 실제 실행한 검증과 미실행·미해결 사항을 적는다. 현재 데이터에서 집계하고 과거 보고서의 수치를 재사용하지 않는다.
- 기본 제작 범위의 완료를 보고하려면 최종 문항 버전의 의미검수·실제 채점 결과와 허용 편차·불일치 처리 근거가 있어야 한다. 모델명·실측 범위·잔여 실패·증거 경로를 명시하며 미실측이나 미해결 차이를 숨기지 않는다. 상태 전환은 사용자에게 승인된 검증·게시 경로와 검토 스킬의 증거 계약에 따라 수행한다.
