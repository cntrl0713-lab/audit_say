# 기술 스택 쉽게 읽기

이 프로젝트(Audit Say)가 어떤 기술로 만들어졌는지, 각 기술이 **무슨 일을 하고 어디에 쓰이는지**를 비전문가도 읽을 수 있게 정리한 문서입니다. 설치·실행 방법은 [README](../README.md), 화면·기능 계획은 [PLAN_PRD_v2](PLAN_PRD_v2.md)를 보세요.

## 한눈에 보기

| 층 | 무엇을 쓰는가 | 한 줄 설명 |
| --- | --- | --- |
| 화면 | Next.js 16 (App Router), React 19 | 웹 페이지를 만들고 서버에서 미리 그려 보내는 틀 |
| 스타일 | Tailwind CSS v4 | CSS 파일을 따로 쓰지 않고 클래스 이름으로 디자인 |
| 아이콘 | lucide-react | 자물쇠·검색 같은 아이콘 모음 |
| 언어 | TypeScript 5 | 자바스크립트에 "타입" 안전장치를 더한 언어 |
| 데이터 | Supabase (PostgreSQL) | 회원·문제·채점 결과를 저장하는 클라우드 DB |
| 로그인 | Supabase Auth + `@supabase/ssr` | 이메일 로그인과 비회원 익명 세션 |
| AI | OpenAI SDK (Responses API) | 서술형 답안을 criterion 단위로 판정 |
| 배포 | Vercel | 깃 푸시하면 자동으로 빌드·배포 |
| 테스트 | node:test + PGlite | 내장 테스트 러너 + 진짜 Postgres를 메모리에 띄워 검증 |
| 품질 게이트 | ESLint 9, tsc, git pre-commit 훅 | 커밋 전에 타입·테스트를 강제로 통과시킴 |

## 1. 화면을 만드는 부분

### Next.js 16 (App Router)

웹사이트의 뼈대입니다. `app/` 폴더의 **폴더 구조가 곧 주소**가 됩니다.

- `app/quiz/page.tsx` → `/quiz` 주소
- `app/(firm)/firms/page.tsx` → `/firms` 주소 (`(firm)`처럼 괄호로 묶은 폴더는 주소에 안 나오고, 공통 레이아웃만 묶는 용도)

가장 큰 특징은 **서버 컴포넌트**입니다. 예전 방식은 브라우저가 빈 페이지를 받고 나서 데이터를 다시 요청했지만, 여기서는 서버가 DB를 조회해 완성된 화면을 보냅니다. 그래서 채점 기준·모범답안 같은 비공개 데이터가 브라우저로 새어 나가지 않습니다.

> ⚠️ 이 저장소의 Next.js는 학습 자료에 흔한 13~15 버전과 규약이 다릅니다. 대표적으로 예전 `middleware.ts`가 16에서 **`proxy.ts`로 이름이 바뀌었습니다**. 코드를 고치기 전에 `node_modules/next/dist/docs/`의 실제 문서를 확인하세요 ([AGENTS.md](../AGENTS.md)의 규칙).

### React 19

화면을 "컴포넌트"라는 조각으로 나눠 조립하는 라이브러리입니다. `components/Navbar.tsx`(상단 메뉴), `components/GradeResultDetails.tsx`(채점 결과 표) 처럼 한 조각이 한 파일입니다.

**서버 액션(Server Action)**도 React 19 기능입니다. `app/actions.ts`에 있는 함수를 화면에서 그냥 호출하면, 실제 실행은 서버에서 일어납니다. 답안 제출용 API 주소를 따로 만들 필요가 없어집니다.

### Tailwind CSS v4

`className="text-sm text-foreground/60"`처럼 **클래스 이름으로 스타일을 지정**합니다. 색은 `app/globals.css` 맨 위에 CSS 변수로 한 번만 정의해 두고(`--primary: #f54e00` 등) 전체가 그 값을 씁니다. 브랜드 색을 바꾸려면 그 파일 한 곳만 고치면 됩니다.

## 2. 데이터를 담는 부분

### Supabase = PostgreSQL + 로그인 + 권한

Supabase는 "관리형 PostgreSQL 데이터베이스 + 회원 관리 + 접근 권한"을 한 묶음으로 제공하는 서비스입니다. 서버를 직접 운영하지 않아도 됩니다.

이 프로젝트가 쓰는 세 가지 방식:

| 파일 | 누가 쓰나 | 권한 |
| --- | --- | --- |
| `lib/supabase.ts` | 브라우저 | 로그인한 본인 데이터만 |
| `lib/supabaseServer.ts` | 서버 컴포넌트·서버 액션 | 로그인한 본인 데이터만 (쿠키 기준) |
| `lib/supabaseAdmin.ts` | 서버 전용 | **모든 권한 무시하고 전체 접근** |

세 번째가 위험해 보이지만, 파일 맨 위의 `import 'server-only'` 한 줄이 **이 코드가 브라우저 번들에 섞여 들어가면 빌드를 실패시킵니다.** 실수로 관리자 키가 유출되는 것을 도구가 막아 주는 구조입니다.

### RLS (Row Level Security)

"이 행(row)을 누가 볼 수 있는가"를 DB 안에 규칙으로 박아 두는 기능입니다. 앱 코드에 버그가 있어도 DB가 다른 사람의 답안을 내주지 않습니다. 규칙은 [supabase-rls.md](../supabase-rls.md)에 정리돼 있습니다.

### 마이그레이션 (`supabase/migrations/`)

테이블을 만들거나 바꾸는 SQL을 **날짜가 붙은 파일로 순서대로 쌓아 둔 것**입니다. 새 환경에서도 같은 순서로 실행하면 똑같은 DB가 만들어집니다. 현재 13개 파일이 있고, 프로젝트 소유 테이블은 이름 앞에 `cpa_`가 붙습니다(`cpa_users`, `cpa_firm_*`) — 같은 DB를 쓰는 다른 앱과 섞이지 않게 하려는 규칙입니다.

### 로그인 세션과 `proxy.ts`

로그인 토큰은 한 시간쯤 지나면 만료됩니다. 답안을 오래 작성하다 제출하면 그 사이 토큰이 죽어 "로그인 안 됨"으로 튕길 수 있습니다. 저장소 루트의 `proxy.ts`가 **모든 요청마다 토큰을 확인·갱신해 쿠키에 다시 심는 역할**을 합니다. 작성 중이던 답안이 사라지는 사고를 막는 파일입니다.

## 3. AI 채점 부분

### OpenAI Responses API + 구조화 출력

AI에게 그냥 물으면 자유로운 문장이 돌아옵니다. 그러면 코드가 파싱하기 어렵고 형식이 매번 흔들립니다. 그래서 `lib/ai/openaiStructured.ts`에서 **JSON 스키마를 `strict: true`로 지정**해, 정해진 모양의 JSON만 나오게 강제합니다.

기본 모델은 `gpt-5.6-luna`이며 `CPA_GRADING_MODEL` 환경변수로 바꿀 수 있습니다. 모델 이름은 코드에 박지 않고 설정으로 관리합니다.

### 역할 분담이 핵심

이 프로젝트에서 **AI는 점수를 매기지 않습니다.**

| AI가 하는 일 | 코드가 하는 일 |
| --- | --- |
| criterion 하나하나 충족 여부 판정 | 판정을 모아 점수 합산 |
| 답안 원문에서 근거 구절 인용 | 인용이 실제 답안에 있는지 검증 |
| — | 프롬프트 주입·키워드 나열 차단 |

AI는 판단만 하고, **숫자와 보안은 결정론적인 코드가 책임집니다.** 관련 로직은 `lib/questionV3Grading.ts`에 있습니다.

### 남용 방지

`lib/rateLimit.ts`가 사용자별 호출 횟수를 제한합니다(채점 60초에 10회 등). 카운터를 앱 메모리가 아니라 **DB 함수(`consume_rate_limit`)로 세는데**, 서버 인스턴스가 여러 개로 늘어나도 한도가 정확히 지켜지기 때문입니다.

## 4. 데이터 수집 부분

`scripts/firm_collector/`는 금융감독원 **DART 공시** 데이터를 받아 회계법인 정보(감사 계약, 사업보고서, 임원 명부 등)로 정리해 DB에 넣는 수집기입니다. 웹 앱과 분리된 별도 스크립트라 `tsx`로 직접 실행합니다.

```bash
npm run firm:collect:annual
```

`tsx`는 TypeScript 파일을 컴파일 단계 없이 바로 실행해 주는 도구입니다.

## 5. 품질을 지키는 도구

### 타입 검사

```bash
npm run typecheck
```

TypeScript가 "숫자를 넣어야 할 자리에 문자열을 넣었다" 같은 실수를 **실행 전에** 잡아냅니다.

### 테스트

```bash
npm test
```

Node.js에 내장된 `node:test` 러너를 씁니다(별도 테스트 프레임워크 설치 없음). 현재 `tests/`에 26개 파일이 있습니다.

특이한 점은 **PGlite**입니다. DB 로직을 테스트하려면 보통 진짜 DB 서버가 필요한데, PGlite는 PostgreSQL을 통째로 메모리에서 돌립니다. 덕분에 실제 마이그레이션 SQL과 DB 함수를 **운영 DB를 건드리지 않고** 검증할 수 있습니다.

### 커밋 게이트 (`.githooks/pre-commit`)

`git commit`을 하면 자동으로 타입 검사와 테스트가 돌고, **하나라도 실패하면 커밋이 막힙니다.** "다음에 고쳐야지"가 불가능하도록 도구로 강제한 장치입니다.

### 린트

```bash
npm run lint
```

ESLint 9가 문법은 맞지만 문제가 될 수 있는 패턴을 지적합니다.

## 6. 배포와 보안 설정

Vercel에 배포하며, 설정은 `next.config.ts`에 있습니다.

- **보안 헤더**: 다른 사이트가 이 앱을 iframe으로 감싸지 못하게 막고(`frame-ancestors 'none'`), 파일 형식 추측을 금지합니다.
- **`poweredByHeader: false`**: 어떤 프레임워크를 쓰는지 응답 헤더로 알리지 않습니다.
- **`outputFileTracingExcludes`**: 정답·모범답안이 든 평문 파일을 **배포 묶음에서 제외**합니다. 운영 환경에서는 암호화된 파일만 열고, 열쇠는 `CPA_QUESTION_V3_ENCRYPTION_KEY` 환경변수로 받습니다.

## 폴더 지도

```
app/          화면 (폴더 = 주소). (firm)은 회계법인 섹션
components/   여러 화면이 공유하는 UI 조각
contexts/     로그인 상태 등 화면 전역 상태
lib/          핵심 로직 — DB 접근, 채점, AI 호출, 한도 제한
scripts/      웹앱과 분리된 실행 스크립트 (DART 수집, 문제은행 반입)
supabase/     DB 마이그레이션 SQL과 검증 쿼리
tests/        테스트
docs/         설계·계획 문서
proxy.ts      모든 요청을 거쳐 가는 세션 갱신 계층
```

## 자주 나오는 용어

- **App Router**: Next.js에서 폴더 구조로 주소를 정하는 방식.
- **서버 컴포넌트**: 서버에서 실행돼 완성된 HTML로 오는 화면 조각. 비공개 데이터를 다뤄도 안전.
- **서버 액션**: 화면에서 부르지만 서버에서 실행되는 함수. 별도 API 없이 데이터를 저장할 때 씀.
- **RLS**: 행 단위 접근 권한을 DB 자체에 새겨 둔 규칙.
- **마이그레이션**: 테이블 변경 이력을 순서대로 쌓아 둔 SQL 파일들.
- **criterion**: 한 물음을 채점하는 최소 판정 단위. 부분점수의 기준.
- **구조화 출력**: AI 응답을 정해진 JSON 형태로만 받도록 강제하는 것.
- **RPC**: DB 안에 정의해 두고 앱이 호출하는 함수. 여러 작업을 한 트랜잭션으로 묶을 때 씀.
