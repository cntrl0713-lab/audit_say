# 물음별 학습 단위와 분류 계약

기존 정본과 신규 초안의 모든 물음은 학습 유형과 실제 요구내용의 주제를 가진다. 학습자는 사례형 문제 또는 기준서형 독립 물음을 선택해 풀며, 선택한 물음만 채점·최대점수·경험치·복습 기록에 반영한다. 원자료를 보관하는 v3 세트와 화면에서 푸는 학습 단위는 서로 다르다.

이 문서는 학습 분류·제작·DB·제출 경계의 공통 계약이다. 구현은 [v3 형상](../lib/questionV3.ts), [생성기](../cpa_uploader/generate_cpa_v3.ts), [학습 단위 구성](../lib/learningUnits.ts), [DB 마이그레이션](../supabase/migrations/20260911030000_cpa_question_learning_units.sql)을 함께 확인한다. 로컬 구현·검사, 원격 마이그레이션 적용, 자료 이관, 운영 배포의 완료 여부는 각각 실제 증거로 판단한다.

## 물음의 유형과 주제

| 필드 | 의미 | 계약 |
| --- | --- | --- |
| `type` | 답안·채점 형식 | 기존 `descriptive`, `enumeration`, `judgment`를 유지한다. |
| `question_style` | 학습 유형 | `case` 또는 `standard`다. `type`에서 추정하지 않는다. |
| `topic_ids` | 물음이 실제로 요구하는 주제 | [wiki 주제 정의](../cpa_uploader/wiki/scripts/topic-definitions.mjs)의 ID를 하나 이상 연결한다. 중복 ID를 넣지 않으며 여러 주제를 허용한다. |

- **사례형(`case`)**: 주어진 사실과 연계해 적용 기준·판단·잘못된 점·구체 조치를 도출해야 답할 수 있다. 기준서의 이유를 설명하더라도 사실과의 연결이 득점에 필요하면 사례형이다.
- **기준서형(`standard`)**: 일반 적용 조건에서 기준서의 정의·요건·절차·목록·보고 내용을 재현하면 답할 수 있다. 판단형 발문이나 “이 경우”라는 표현만으로 사례형이 되지는 않는다.
- 물음의 공통사실·발문·모범답안·criterion을 직접 대조해 분류한다. 부모의 대표 `classification.topic_id`를 모든 물음에 복제하거나, 배경에 잠깐 등장하는 내용까지 주제로 확장하지 않는다. 학습 순서는 OX 순서를 따르며 기존 ID를 재번호화하지 않는다.
- 기준서 목록과 사례 적용을 한 물음에서 함께 요구하면 사례형이다. 두 요구를 독립적으로 풀 수 있고 범위가 과도하게 묶였다면 별도 물음으로 나누되 발문·답안·criterion·총점·ID의 전후 대응을 기록한다.

## 새 초안과 학습 화면

새 v3 출력은 같은 `question_style`의 **1~4개 물음**으로 구성한다. 각 물음에 `question_style`과 `topic_ids`를 명시한다. `SubquestionV3`의 두 필드가 선택형인 것은 불변인 과거 v3 판본을 읽기 위한 호환이며 새 제작에서 생략해도 된다는 뜻이 아니다.

**사례형**은 필요한 사실을 가진 부모 사례가 있어야 한다. `shared_context.facts`를 채우고 사실과 연결해 답해야 하는 물음만 그 아래에 배치한다. 서로 다른 실제 요구 주제를 한 사례에 연결할 수 있다. 형상 통과를 위해 무관한 안내 문장을 사실로 채우지 않는다.

**기준서형**은 `shared_context.facts=[]`로 작성하고 각각 한 물음만 읽어도 풀 수 있어야 한다. 제작 파일에 여러 기준서형 물음을 담아도 학습 화면·제출 단위는 물음마다 하나씩 분리한다. 특정 회사·자료·보고서 초안·다른 물음의 판단을 해석해야 하는 요구를 발문 안으로 옮겨 기준서형으로 만들지 않는다. 일반적인 적용 조건과 범위·제외사항은 독립 발문에 명시할 수 있다.

기존 혼합 세트도 화면의 사례 지문 아래에는 사례형만 포함한다. 기준서형에는 사례 지문을 전달하지 않으며 `standalone_prompt`로 혼자 풀게 한다. 원발문 자체가 독립적이면 그대로 사용한다. 학습 목록의 유형·주제 필터와 표시 총점은 실제 물음별 분류를 사용한다.

**주제는 검색 필터이며 풀이 범위를 자르는 기준이 아니다.** 특정 주제와 연결된 사례형 물음 때문에 사례가 검색되면, 그 사례형 학습 단위에 속한 모든 물음을 사실관계와 함께 보여 준다. 다른 주제의 사례형 물음도 포함하며 표시 최대점수·제출·채점 범위를 검색 주제에 맞춰 줄이지 않는다. 원문 세트에서 분리된 기준서형은 사례 아래에 다시 붙이지 않는다.

현재 학습 단위 ID는 사례형의 경우 `<source_set_id>--case`, 기준서형의 경우 `<source_set_id>--<subquestion_id>--standard`다. 이 표시·선택 ID를 새 원문 세트 ID로 정본에 삽입하지 않는다.

## 배점과 물음별 타당성

이 절은 제작·검토 스킬의 공통 배점 계약이다. 학습 유형(`standard`/`case`)과 답안 형식(`enumeration`/`descriptive`/`judgment`)은 서로 다른 축이다. 두 학습 유형 모두 아래 원칙을 적용하며, 기준서형이라는 이유로 점수를 낮추거나 사례형이라는 이유만으로 가산하지 않는다.

| 요구 형식 | 배점·부분정답 처리 |
| --- | --- |
| 열거 | 요구한 독립 요소마다 기본 1점. 네 요소 중 두 요소가 맞으면 2/4점이다. 상위 목록 항목과 그 설명에 포함된 하위 득점 요건을 구분하며, 명칭만 요구했으면 정의를 추가 요구하지 않는다. |
| 서술 | 정의·목적·구체 방법·이유 등 실제 요구 중 독립적으로 인정할 수 있는 의미 단위를 분리하고 충족한 점수를 합산한다. 세 독립 요건 중 두 요건이 맞으면 2/3점이다. 한 부분 누락 때문에 서술 전체를 0점 처리하지 않는다. |
| 판단·근거 | 요구한 판단과 근거를 구별하여 각각의 배점과 독립 득점 조건을 정한다. 올바른 근거·조치가 결론을 분명히 함축하면 별도 결론 문구 없이 판단을 인정한다. 명시적 반대 결론은 판단 0점이며 독립적으로 맞는 근거는 그 의미가 성립하는 범위에서 인정한다. |

기본 독립 criterion은 `met=1`, `not_met=0`, `contradicted=0`이다. 부분정답은 충족한 criterion의 **정수 점수 합계**로 표현한다. 소수 partial은 사용하지 않는다. 별도 가중치나 결합 기준이 필요한 경우에는 근거, 완전·부분 충족 조건과 정수 점수를 명시하고 현재 엔진이 지원하는지 확인한다. 독립 요건을 묶어 만점/0점만 주는 방식은 먼저 분리 가능성을 검토한다.

독립 의미 단위는 다른 요건을 빠뜨려도 그 자체로 옳은 답안으로 인정할 수 있는 요구다. 조사·수식어·주체·조건을 단어마다 나누어 1점씩 주지 않는다. 예를 들어 어떤 조치가 특정 조건에서만 타당하다면 조건은 그 조치의 정확성 요건일 수 있다. 조건 없는 조치와 조건 이름을 각각 맞힌 것으로 자동 취급하지 않는다. 반대로 실제로 따로 물은 여러 대상·검토 특성은 같은 문장이나 같은 출처에 있다는 이유로 합치지 않는다.

한 문장으로 여러 독립 요구를 충족하면 각각 득점하고 같은 답안 인용을 허용한다. 같은 의미의 반복·동의 표현은 한 번만 득점한다. 주어진 사실의 단순 복사, 발문에서 묻지 않은 해설, 무관한 키워드는 점수를 늘리지 않는다. 모든 대안을 설명하라는 요구와 실제 업무에서 대안을 모두 수행할 의무도 구별한다.

포괄적인 “영향을 고려한다”와 이를 구체적으로 이행하는 조치가 포함 관계라면, 같은 조치의 설명에 일반 표현을 덧붙였다는 이유만으로 별도 점수를 늘리지 않는다. 원문·발문이 별도의 판단이나 다른 수행 내용을 요구하는지 대조한다. 함축 관계를 억지로 차단해 독립 기준처럼 만들거나, 독립적인 판단과 조치의 부분정답을 한꺼번에 없애지 않는다.

제작과 검토 모두 물음별 대응표에 다음을 남긴다. 새 양식을 별도로 만들 필요 없이 해당 배치의 기존 장부를 확장할 수 있다.

- 학습 유형·답안 형식·주제, 발문에서 요구한 항목, 독립 정답 명제와 criterion, 각 정수 점수 및 합계.
- 만점을 위한 최소 충분 답안과 필요한 설명의 범위. 명칭 나열인지, 이유·방법·조건·사례 적용까지 필요한지 구별하고 대략적인 문장/절의 수는 부담을 비교하는 참고로만 쓴다. 글자 수나 답안 길이에 비례해 점수를 산정하지 않는다.
- 독립 요구 수, 설명·추론 부담, 같은 범위의 비슷한 물음과 비교한 배점의 일관성. 총점이 낮거나 높아 보이는 원인이 숨은 요구, 불필요한 분해·중복, 과도한 묶음, 정당한 독립 요구 중 무엇인지 판단한다. 점수 합계의 산술 일치만으로 타당하다고 결론 내리지 않는다.
- **유지 / 배점·criterion 조정 / 물음 분리** 결정과 이유. 과도한 묶음은 독립적인 하위 요구를 별도 물음으로 나눌지 검토하고, 특히 사례 적용과 독립 기준서 질문은 유형별로 분리한다. 임의의 물음·세트 총점 상한에 맞춰 필요한 요구를 삭제·결합하지 않는다.

기존 물음을 조정하면 발문·정답·기준·배점·ID의 전후 대응을 남긴다. 분리한 물음의 총점은 독립 요구의 실제 변화로 설명하며 분리 자체를 점수 증가 이유로 삼지 않는다. 각 하위 기준을 다시 판정하고 과거 결합 기준의 0점 또는 만점을 하위 기준에 그대로 복사하지 않는다. 유효한 기존 QA 답안·반례와 과거 실행 증거는 보존한다.

검증은 완전 정답·빈 답안 외에 각 독립 요소만 맞은 답안, 일부 누락, 같은 내용을 한 문장으로 합친 답안, 같은 의미 반복을 포함한다. 서술은 결합했던 요구 중 한쪽만 맞은 양방향 부분정답을, 판단·근거는 결론만·근거만·함축 결론·명시적 반대 결론을 확인한다. 사례형은 일반론만 맞은 답안과 사실에 맞게 적용한 답안을 구별하고, 기준서형은 사례를 보지 않은 답안으로 만점을 얻을 수 있는지 확인한다. 기대값은 원문·요구·배점에서 먼저 정한다. 실행 종류와 모델 호출 범위는 [검토 스킬](../.agents/skills/audit-question-review/SKILL.md) 및 사용자의 제한을 따른다.

## 원문 계보와 학습 부모

[마이그레이션](../supabase/migrations/20260911030000_cpa_question_learning_units.sql)은 원문 v3 내용을 고치지 않고 분류 메타데이터를 추가한다.

| DB 필드·관계 | 사례형 | 기준서형 |
| --- | --- | --- |
| `source_set_id`, `source_set_version_id`, `source_subquestion_version_id` | 원문 계보 보존 | 원문 계보 보존 |
| `case_set_id` | 원문 세트 ID와 같으며 부모 사실이 필요 | `NULL` |
| `standalone_prompt` | `NULL` | 공백이 아닌 독립 발문 필수 |
| `case_fact_ids` | 사용하는 실제 부모 fact ID를 기록 | 빈 배열 |
| `topic_ids` | 하나 이상, 다주제 가능 | 하나 이상, 다주제 가능 |

기준서형의 `source_set_id`는 출처와 과거 답안·채점 기록을 따라가기 위한 계보다. 이 값이 남아 있다고 학습 부모 사례가 존재하는 것은 아니다. 화면·채점용으로 만드는 세트 형태의 투영도 기존 엔진에 전달하기 위한 호환 구조이며 새 DB 부모 사례를 만들지 않는다.

DB의 `cpa_learning_questions`는 기존 `cpa_subquestions`와 연결되는 안정적인 물음 식별자다. `cpa_learning_question_versions`가 원문 세트·물음 판본과 연결된 분류 revision을 보관한다. `cpa_learning_topics`는 주제 목록이고 `cpa_learning_question_topics`는 분류 판본과 주제의 다대다 관계다. 한 개 이상의 주제가 연결되어야 분류 판본을 봉인할 수 있다.

봉인된 분류 내용·주제 관계·식별자는 변경하지 않는다. 분류를 정정하면 새 revision으로 남기며 원문 content hash, 원문 판본 ID, 학습 유형, 부모·독립 발문, 주제·fact ID를 결속한 분류 해시를 검증한다. SQL의 봉인 해시는 실제 SQL 직렬화 계약을 사용하고 일반 파일 SHA나 별도 JSON 직렬화 해시와 혼동하지 않는다.

사례형은 부모 사실이 비어 있으면 거절한다. `case_fact_ids`의 항목은 실제 부모에 존재해야 하며 중복할 수 없다. 기존 판본에서 구체 사실이 발문 안에만 있는 경우 분류 장부에 그 위치를 설명한다. 사실 선택 목록은 분류 근거이며, 현재 화면 구성은 사례형에 부모 사실을 전달한다. 일부 사실만 표시하는 필터가 이미 구현되었다고 가정하지 않는다.

## 과거 판본 이관과 후속 변경

메타데이터가 없는 과거 정본·공개·DB 판본은 **분류 sidecar와 봉인된 DB 분류**로 이관한다. 분류를 채우려고 과거 문항·발문·criterion·출처·receipt·공개본 바이트나 과거 입력 해시를 다시 쓰지 않는다.

분류 장부는 실제 `set_id`·`subquestion_id`, 유형·주제, 분류 이유, 사용 fact ID, 독립 발문 제안 및 원문 파일 또는 세트 해시를 보관한다. 장부의 `standalone_prompt: null`이 “원발문 재사용”을 의미하는 경우 DB 입력에서는 실제 원발문을 채운다. DB의 기준서형 `standalone_prompt`는 `NULL`을 허용하지 않는다.

`cpa_import_learning_classifications`는 공개된 active 또는 retired release의 물음을 빠짐없이 받아 원문 content hash와 판본 계보를 대조한다. 현재 정본의 분류를 과거 판본에 적용할 때는 해당 판본의 사실·발문·모범답안·criterion도 대조한다. 같은 ID라는 이유만으로 승계하지 않는다. 한 release의 분류 누락을 부모 주제 복제나 임시 유형으로 메우지 않는다.

분류만 바뀐 것인지 독립 발문을 통해 실제 요구가 바뀐 것인지 구분한다. 후자는 문항 수정으로 검토하고 영향받는 채점 계약과 증거를 새로 확인한다. 이전 의미검수·채점 증거를 새 분류에 연결할 때도 당시 입력과 현재 실제 채점 입력의 동일성을 확인한다. 분류·이관·형상 검사 통과를 의미검수·실제 모델 채점·사람 승인으로 표시하지 않는다.

## 제출·채점·경험치·복습의 경계

[제출 토큰](../lib/learningSubmission.ts)의 v2는 `learning_unit_id`, 순서 있는 `selected_subquestion_ids`, 대응하는 `classification_version_ids`를 원문 release·세트 판본·소유자·회원 상태와 함께 서명한다. 정규화한 답안 해시도 이 선택과 결속한다. 답안, 선택 물음, 순서, 분류 판본 또는 학습 단위를 바꾸어 이전 토큰을 재사용할 수 없다.

[서버 채점 경로](../lib/learningService.ts)는 토큰의 확정 분류 판본으로 물음을 불러오고 선택한 물음만 기존 criterion 엔진에 전달한다. 선택한 물음의 빠진 답안은 빈 답안으로 정규화하되 선택하지 않은 물음은 답안·채점·최대점수에 포함하지 않는다. 기준서형 제출은 한 물음이며 사례형 제출에도 기준서형을 섞을 수 없다.

DB의 `cpa_attempt_learning_selections`와 `cpa_attempt_learning_questions`가 제출의 학습 단위·선택 순서·분류 판본·원문 물음 판본을 결속해 봉인한다. 봉인된 선택 밖 답안을 추가하거나 같은 제출 키의 선택을 바꾸는 요청을 거절한다. 채점 완료 시 선택 답안과 결과 물음의 수·ID·criterion·인용·점수·최대점수를 대조한다.

경험치는 선택 물음의 실제 정수 득점 합계로 한 번만 적립한다. 복습의 오답·최근 결과·실패 기록도 선택 물음만 갱신한다. 중복 완료·저장 재확인은 경험치나 복습 처리를 다시 실행하지 않는다. 목록이 새 분류 판본으로 바뀌어도 과거 결과가 가리키는 원문·답안·분류 판본의 계보를 유지한다.

v1 토큰의 기존 전체 세트 제출·과거 기록은 호환 경로로 보존한다. v1에 v2 선택 필드를 끼워 넣거나 기존 제출을 부분 제출로 소급 해석하지 않는다. 공통 계정의 회원 상태·membership version 검증, 소유권·만료·멱등성, 서명키·이전 키 호환과 비밀정보 비노출을 유지한다. DB 내부 legacy 코어를 직접 호출해 회원 검증 래퍼를 우회하지 않는다.

2026-09-11 전환에서 사용자는 예전 세트 전체 제출 답안의 삭제를 허용했다. 현재 UI는 해당 사용자의 알려진 원본 세트 임시 제출 키만 정리하고, 새 물음 단위의 제출·다른 사용자·다른 저장소 데이터는 유지한다. 원격 DB의 삭제 대상 존재 여부는 적용 전후 기록에서 확인하며 이 허용을 문제 원문·모범답안·과거 검수 증거 삭제로 확대하지 않는다.

새 DB 문제은행 등록 CLI는 `cpa_import_learning_question_bank`를 사용한다. 원본과 전수 분류를 한 트랜잭션에서 등록하므로 분류 누락·원본 또는 신규 작성 메타데이터와 불일치하면 새 릴리스의 활성화까지 롤백한다. 기존 원본의 분류만 이관할 때는 `cpa_import_learning_classifications`를 사용하여 문제은행 릴리스·내용·게시 상태를 바꾸지 않는다.

이 변경은 `type`, criterion의 정답·배점, 모두 작성 원칙, 독립 명제의 정수 부분점수, 보안 판정과 오류 처리 계약을 바꾸지 않는다. 전송·응답·저장 오류를 학생 오답이나 0점으로 바꾸지 않는다. 모델 호출 제한·예산·공통 코드 변경 시 실행 중지와 증거 보존은 [검토 스킬](../.agents/skills/audit-question-review/SKILL.md)의 기존 지침을 따른다.

## 변경 범위별 확인

- 제작·분류: 모든 물음의 사실 의존성·주제·독립 발문을 직접 읽고 새 출력의 같은 유형·1~4물음·facts 조건을 확인한다. 생성 스키마 검사만으로 분류의 의미 적합성을 확정하지 않는다.
- 이관: 각 release의 전수 분류, 원문·판본 해시, 다대다 주제, 봉인 후 불변성 및 분류 누락·잘못된 fact 거절을 확인한다. 과거 원문·receipt 보존을 별도로 검사한다.
- 제출·실제 채점 경로: 기준서형 한 물음과 사례형 단위의 정상 처리, 주제 검색 후에도 사례 소속 물음 전체가 유지되는지, 선택 밖 답안·다른 판본·변경 답안 거절, 선택 최대점수·경험치·복습 범위, v1 전체 세트 호환과 회원·비밀정보 경계를 확인한다. 실제 모델 호출이 금지된 작업에서는 로컬 검사와 미실측 범위를 구분한다.
- wiki·분석: 생성 페이지를 직접 고치지 않고 실제 소유 입력·생성기에서 갱신한다. 관련 빌드·검사는 [자료 관리 규칙](출제-검토-자료-관리.md)과 [wiki SCHEMA](../cpa_uploader/wiki/SCHEMA.md)를 따른다.
