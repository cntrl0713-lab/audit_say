## 운영 검증

- 실제 감사 닉네임 로그인 후 자동 서비스 가입이 발생하지 않음을 확인했다.
- 실제 세법 이메일 로그인·가입 폼을 제출한 뒤, 변경된 공통 닉네임으로 새 세션에서 로그인했다.
- 감사에서 변경한 닉네임이 세법 프로필에 반영됐다.
- 두 서비스 신규 회원의 관리자 권한과 유료 이용권이 자동 부여되지 않았다.
- 감사만 탈퇴하면 세법 가입 상태는 유지됐다. 감사 재가입은 새 가입 회차·무료 이용권·경험치 0으로 시작했다.
- 실제 통합 계정 삭제 API가 양쪽 서비스와 Auth 계정을 정리했다. 검증 계정도 남기지 않았다.
- DB 함수 51개의 실행 권한, 기존 계정 전부 삭제, 보호 콘텐츠 41개 테이블, cron 정의와 활성 상태를 확인했다.
- 두 운영 주소의 공개 화면은 200, 미로그인 계정·결제 API는 401, 세법 프로필은 로그인 화면으로 이동했다.

Auth 콜백은 양쪽 `/auth/callback`을 허용하며 최소 비밀번호 길이는 8이다. 이메일 인증과 안전한 이메일 변경 설정은 유지했다. `disable_signup=false`, `external_anonymous_users_enabled=true`로 복구했고 기존 cron 4개를 원래 일정과 활성 상태로 복원했다. 운영 재개 후 새로 생성되는 계정은 삭제 대상이 아니다.

## 남은 운영 설정

관리자 계정은 사용자 지시에 따라 나중에 지정한다. 새 이메일과 대상 서비스가 정해지기 전에는 관리자 권한을 부여하지 않는다.

기존 환경에 Toss 결제 키가 없으므로 실결제 활성화·승인·환불은 이번 완료 범위에 포함하지 않는다. 결제 worker 코드와 JWT 보호를 배포·확인했으며, 실제 카드 결제나 외부 이메일 발송은 수행하지 않았다. 이메일 배달 및 복구 메일을 통한 전체 흐름은 이번 운영 검증에서 실행하지 않았다.

## 실행 증적과 재실행 주의

이 전환의 `reset` 단계는 완료됐다. 새 가입자를 대상으로 다시 초기화하지 않는다. 상태 점검은 읽기 전용 `scripts/verify-common-account-rollout-state.mjs --stage live`를 사용한다. 배포 실행기 SQL 이력 문자열 처리 오류는 적용 전 롤백 후 수정했으며 정확한 원문 보존 회귀 검사가 통과했다.
