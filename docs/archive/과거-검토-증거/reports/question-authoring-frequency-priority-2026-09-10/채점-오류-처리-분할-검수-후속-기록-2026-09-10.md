# 채점 오류 처리·분할 검수 후속 기록 — 2026-09-10

채점 엔진과 검수 실행 방식을 수정했다. 문항의 정답·배점·작성자 기대값은 이번 엔진 수정에 맞추어 변경하지 않았다. 정본·공개본·운영 DB 수록이나 배포는 수행하지 않았다.

## 수정한 동작

- `lib/questionV3Evidence.ts`가 제출 답안 전체와 문장 구간에 ID·문자 오프셋을 부여한다. 모델은 인용문을 다시 쓰지 않고 ID를 선택하며, 서버가 실제 답안 문자열에서 인용을 복원한다. CRLF·한글 조사·이모지를 포함한 원문 문자열을 임의 교정하지 않는다.
- 잘못된 ID·다른 물음의 근거·누락된 판정·허용하지 않은 부분점수는 모델 응답 오류다. 형식·근거 오류를 두 번까지 요청하고 계속 실패하면 서비스 오류로 종료한다. 학생 점수를 0점으로 대체하지 않는다. 전체 요청의 시간 한도는 120초이며 전송 실패도 점수로 바꾸지 않는다.
- 보안 의심에는 답안의 근거 ID와 독립 재확인을 요구한다. 실제 채점 조작 지시만 해당 물음에 적용하고 불확실하면 채점하지 않는다. 물음별 플래그와 세트 전체 플래그의 기존 DB 계약을 보존했다.
- 의미검수는 물음·criterion별 요청으로 분할한다. 전체 비교 은행·출처 문맥을 유지하고 선택한 필드/출처 ID를 원문으로 연결한다. 필수 필드·출처·5종 사례의 누락과 중복은 개별 응답 및 전체 receipt에서 검사한다. 사례의 pass는 기대 판정의 타당성이다.
- CLI는 `<output>.chunks.jsonl`에 검수 중간 응답·오류와 입력 식별자를 남긴다. 기존 로그는 덮어쓰지 않는다. 새 검수 수락에는 현재 채점 코드·모델을 요구하며, 과거 승인 기록 조회는 당시 해시를 보존하면서 기록 무결성과 점수 재현을 검사한다.

## 실제 채점 결과

요청 모델은 `gpt-5.6-luna`, 실제 `gradeQuestionSetV3` 경로를 사용했다. 현재 코드의 작성자 QA는 **121사례 전수 실측, 120사례 모든 실행 일치, 1사례 변동**이다. 12개 저장 모범답안은 모두 만점이었다.

| 이전 실패 | 최종 동일 설정 실측 | 결과 |
| --- | --- | --- |
| `draft-09-501-freq01/q2/equivalent` — 통제가→통수가 인용 오타 | 3회 | 모두 4/4점, 제출 원문 인용 보존 |
| `draft-12-560-freq01/q1/condition-boundary` — 정상 답안 보안 오탐 | 3회 | 모두 기대 1점, 보안 오탐 없음 |

별도 보안 회귀 5사례는 정상 답안 2건과 실제 조작 지시 3건을 포함한다. 모두 기대대로 처리했고, 공격을 넣지 않은 다른 물음의 정상 점수도 보존했다. 이는 표본 검사이며 모든 공격·표현의 정확성을 보증하지 않는다.

잔여 변동은 `draft-12-570-freq01/q1/omit-5`다. 답안 첫 문장에 “적정의견을 표명한다”가 있지만 한 실행에서 q1.c1을 not_met으로 판정했다. 최종 코드에서 **3점·4점·4점**, 기대값은 4점이다. 인용·보안 오류가 아니라 의미 판정 오류이며 기대값을 낮추거나 실패를 삭제하지 않았다.

초기 엔진 수정 단계에서는 빈 답안의 임시 근거 ID 선택과 다른 조건 경계/생략 판정 차이도 관찰했다. 중간 결과는 별도 실행 폴더에 보존하며, 현재 코드와 다른 실행을 현재 성공률에 섞지 않는다.

의미검수 pass인 3세트는 CLI `--review-input --grade-cases`로 별도 실행했다. 비교 은행은 위 입력 snapshot의 은행과 동일하게 전달하여 다른 초안 5세트도 보존했다. 동일 답안을 묶고 빈 답안을 추가한 총 77실행 중 76개가 기대 판정에 일치했다. 결과는 같은 폴더의 세트별 `.graded.json`에 보존했다.

외부조회 세트의 `criterion:q2:q2.c1/omission`에서 생성된 답안은 “회신이 필요하다고 결정되었지만 대체절차를 수행한다.”였다. 검토 모델의 기대는 not_met이나 채점기는 3회 모두 contradicted로 판단했고 점수는 모두 0점이었다. 대체절차를 수행한다는 표현이 ‘회신을 대체할 수 있다’는 반대 결론까지 함축하는지 구분이 필요하다. 기대값을 채점 결과에 맞춰 바꾸지 않았으며, 이 검수 receipt의 승급은 차단된다. [반복 실행](../../../../../cpa_uploader/drafts/frequency-priority-2026-09-10/semantic-review/engine-final/09-505-grading-repeat.json)에 근거를 남겼다. 후속 검수에서는 다른 독립 요구만 서술한 명확한 누락 사례로 새 의미 대조·채점을 수행해야 한다.

위 중복 주장은 검토 모델의 판정이다. 한 문장이 여러 독립 명제를 충족할 수 있다는 정책과 대조하여 수동으로 판정해야 하며, 확정 결함으로 간주해 요구사항을 삭제하지 않았다. 출처가 미등록이라는 사실도 원문이 틀렸다는 확정이 아니다. 기존 공식 PDF·provenance와 검수 입력을 연결하는 후속 확인이 필요하다. 세트 상태는 모두 초안으로 유지한다.
