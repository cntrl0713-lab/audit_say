# 열거 요소별 배점과 서술 부분점수 검토안

2026-09-11. 사용자의 “일단 API 채점은 멈추고 고려” 지시에 따라 작성한 로컬 검토안이다. API 의미검수·채점과 대기 큐를 중지했으며, 문항·배점·공통 채점 코드에는 적용하지 않았다. 현재 활성 초안은 49세트·131물음·433점이다.

**열거한 요소는 각각 채점하고, 서술은 독립적으로 확인할 수 있는 내용 단위에 점수를 나누는 방식을 권고한다.** 두 유형 모두 실제로 맞힌 내용을 누적한다. 문제 유형 이름만으로 정해진 점수를 일괄 부여하기보다, 한 물음 안에서도 명칭·판단·설명·적용 요구를 구별한다.

## 배점 원칙

| 발문이 요구한 것 | 권고 방식 | 부분답안 처리 |
| --- | --- | --- |
| 요소·종류·명칭의 열거 | 독립 요소마다 기본 1점 | 네 요소 중 두 요소가 맞으면 2/4점. 동의어를 허용하며 동일 요소의 반복은 한 번만 득점한다. |
| 방안·절차·내용의 서술 | 실제 요구한 핵심 행위, 대상과의 관계, 적용 방법, 이유 등 독립 의미 단위에 배점 | 충족한 단위만 누적한다. 모든 서술형에 이 항목들을 자동으로 추가하지 않는다. |
| 판단과 근거 | 발문이 둘 다 요구하면 판단과 독립된 근거를 구별 | 근거가 판단을 분명히 함축하면 정해진 결론 문구를 반복할 필요가 없다. |
| 요소와 설명을 함께 요구 | 명칭 식별과 설명이 각각 별도 학습 요구인지 먼저 확인 | 이름만 묻는데 설명을 숨은 만점 요건으로 추가하지 않는다. 이름과 정의가 사실상 같은 한 의미인 경우 중복 배점하지 않는다. |

‘부분정답’은 정확한 의미를 일부 제시한 답안이다. 단어 몇 개가 등장했다는 이유로 점수를 주는 방식은 권고하지 않는다. 행위·대상·조건·인과관계가 필요한 설명에서는 그 관계가 있어야 해당 단위를 충족한다. 이미 지문에 주어진 사실이나 해설의 부가 정보에는 별도 점수를 붙이지 않는다.

필수 조건을 반대로 쓰면 영향을 받는 명제는 0점이다. 그렇더라도 다른 독립 명제까지 일괄 0점으로 만들지 않는다. 같은 명제를 정답과 반대로 동시에 쓴 경우에는 해당 모순을 해소했는지 확인한다. 허용된 여러 대안 중 하나로 충분한 요구를 모든 대안을 써야 하는 요구로 확대하지 않는다.

## 현재 초안에 적용할 예

**T12-B 물음 2의 의견 종류:** 현재 발문은 가능한 한정의견과 부적정의견을 모두 요구하지만 두 종류를 한 개의 1점 기준으로 묶었다. 한정의견만 정확히 쓴 답안은 현재 계약에서 그 기준을 완전히 충족하지 못한다. 두 종류에 각각 1점을 두면 한 종류 정답은 1/2점, 두 종류 정답은 2/2점으로 평가할 수 있다. 실제 생성 QA에서도 한 종류 답안의 판정 차이를 확인했으나, 아래 새 배점으로 실측한 결과는 아니다.

**T10-C 물음 2의 정보 신뢰성 평가 요소:** 정보의 원천, 비교가능성, 성격·관련성, 작성 통제의 네 범주를 모두 요구한다. 현재 하나의 1점 기준을 네 개의 독립 기준으로 나누면 특정 범주를 빠뜨린 답안에서도 나머지 정답의 점수가 남는다. ‘성격·관련성’을 다시 단어별로 나눌지는 실제 발문과 공식 원문의 요구 단위에 따라 판단한다.

**T19-A 물음 3의 중요성 설명:** 기존 배점 검토의 2점에서 3점으로 나누는 안은 이 정책과 맞는다.

1. 검토의 낮은 확신만으로 중요성 판단기준을 완화할 수 없다는 판단: 1점.
2. 보고하는 정보와 이용자의 요구를 바탕으로 중요성을 판단한다는 근거: 1점.
3. 낮은 확신·높은 미발견위험과 중요성 판단기준을 구별한 설명: 1점.

예를 들어 “부적절하다. 보고 정보와 이용자 요구에 따라 중요성을 판단한다”는 앞의 두 내용을 충족하므로 제안 기준에서 2/3점이다. 세 번째 설명을 추가하면 3/3점이다. 반대로 올바른 구별 설명이 완화 불가를 분명히 함축하면 판단 문구를 따로 요구하지 않는다. 첫 결론의 단순 반복을 세 번째 설명으로 다시 채점하지 않는다. 물음 1·2를 유지하면 주제 19 세트는 5점에서 6점이 되는 안이다.

## 현재 코드와 맞추는 방법

[현행 wiki](../../../../../cpa_uploader/wiki/question-generation/question-design.md:52)와 [검토 스킬](../../../../../.agents/skills/audit-question-review/SKILL.md)은 이미 독립 명제에 기본 1점과 정수 부분 합산을 원칙으로 둔다. 이번 초안에서는 서로 다른 요구를 하나의 1점 기준에 묶은 곳이 있어 그 원칙이 일관되게 구현되지 않았다.

기본 구현은 **독립 내용 단위를 각각 1점 채점기준으로 만들고 합산**하는 것이다. 서술형도 세 개의 독립 기준이면 0·1·2·3점이 모두 가능하다. 모델에게 답안이 ‘대략 절반 맞았다’고 전체 비율을 추정하게 하는 것보다 어떤 내용이 맞고 빠졌는지 설명할 수 있다. 이 방식은 현행 채점 코드가 지원한다.

[현재 데이터 형상](../../../../../lib/questionV3.ts:25)은 2점·3점의 복합 기준에 정수 부분점수 한 값을 지정하는 것도 허용한다. 다만 3점 기준 하나에서 부분 1점과 부분 2점을 동시에 구별하는 형상은 아니다. 분리 가능한 내용은 독립 기준으로 나누는 편이 적절하다. 꼭 결합해야 하는 기준에 가중치를 주려면 무엇이 부분 충족이고 무엇이 완전 충족인지 별도 계약을 먼저 정해야 한다. 현재 고정 채점 입력에는 구체적인 부분 충족 단계표가 별도로 없으므로, 단순히 `partial`을 켜는 것을 충분한 설계로 보지 않는다.

## 후속 적용 범위와 보존

이 원칙을 채택하면 먼저 131개 물음에서 발문과 필수 답안의 대응을 확정하고, 독립 요구를 묶은 기준을 일관되게 분리해야 한다. 기존 물음·주제 ID는 유지하고 새 세부 기준은 기존 기준과의 전후 대응을 기록한다. 이전 QA·원시 응답·receipt는 과거 계약의 증거로 보존한다.

[앞선 배점 검토](./새-문제-49세트의-배점-검토.md)의 11세트·27점 증가는 우선 후보안이다. 이번 정책 검토만으로 460점을 최종 총점으로 확정하지 않는다. 모든 후보에서 독립 요구와 같은 의미의 중복 표현을 다시 대조한 뒤 총점을 계산해야 한다. 서술 길이나 접속사 수만으로 점수를 늘리지 않는다.

현재는 정책 검토 단계다. 배점·문항·공통 코드 수정, 새 비교 은행 생성과 API 재채점은 수행하지 않았다. API는 사용자의 재개 지시 전까지 중지한다. [중지 기록](../../../../../cpa_uploader/analysis/reviews/delegated-authoring-2026-09-11/user-api-pause-point-policy-01.json)에 실행 종료와 보존 범위를 남겼다.
