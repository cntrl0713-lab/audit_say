# 2027년 대비 문제·물음 전수 검토 계획

갱신: 2026-09-08. 검토 결과와 후속 수정은 주제별 계획·보고서에 기록한다. [01 실행 결과](../reports/question-review-2027/01.md) · [02 실행 결과](../reports/question-review-2027/02.md) · [13 검토·수정 결과](../reports/question-review-2027/13.md). 각 주제의 최신 진행 상태는 해당 문서를 따른다.

## 1. 목표와 확정 범위

계획 작성 당시 문제은행 전체 96세트·192개 물음·503개 criterion을 19개 주제로 나누어 검토한다. 수정 후 집계는 주제별 보고서와 manifest를 따른다. 문제 상황, 발문, 모범답안, 요구사항과 채점기준, 출처, 배점, 실제 채점 코드, 문제·답안·결과 화면의 오탈자와 어색한 표현까지 포함한다.

2027년 대비를 목표로 하되, 사용자 의견에 따라 **2026년 시행 기준과 동일하다는 가정**으로 시작한다. 2026년에 발표된 문서라도 시행일이 다를 수 있으므로 발표일과 시행일을 분리한다. 2027년 시험에 적용되는 변경이 공식 확인되면 영향받는 주제와 물음에만 반영한다.

결과물은 물음별 근거 있는 판정, 구체적인 수정 문안, 재현 가능한 채점 사례, 주제별 검토 보고서다. 문제·정답·채점 코드 수정이나 게시·배포는 검토 결과에 따른 후속 작업으로 구분한다.

## 2. 2027년 적용 기준 확인 방법

- 출발점: 해당 문제에 적용되는 2026년 시행 기준서·윤리기준·법규.
- 우선순위: 공식 시험 적용 공고 → 국내 기준의 확정 본문·부칙 → 관련 공식 해석·FAQ. 해설·기출·위키는 탐색 및 비교 자료로 사용한다.
- 기준대장에 문서명, 공식 URL, 판본, 문단, 발표일, 시행일, 시험 적용 여부, 확인일, 영향 주제·물음 ID를 기록한다.
- 내용 상태는 ‘2026 기준 확인 / 2027 동일 적용 가정 / 2027 변경 확인 / 적용 확인 필요’로 구분한다.
- 원출처가 낡았으면 인용 문자열만 고치지 않는다. 발문·정답·criterion·출처 연결을 함께 검토하고 새 근거를 제시한다.
- 해석이 여러 개 가능하거나 적용 시점에 따라 정답이 바뀌면 해당 물음만 확인 대기로 남기고 다른 물음의 검토는 진행한다.
- 보고 완료 시 공식 공고의 추가 변경을 다시 확인한다. 확인되지 않은 미래 개정을 만들어 넣지 않는다.

현재 확인한 공식 탐색 근거:

- 금융위원회에 [2027년도 공인회계사시험 출제범위 사전예고](https://www.fsc.go.kr/no010104/86803)가 게시되어 있다. 이번 계획 단계에서는 게시 본문을 확인했으며 첨부의 세부 적용 범위는 실행 첫 단계에서 확인한다.
- 한국공인회계사회 [감사기준 자료 목록](https://www.kicpa.or.kr/board/list.brd?boardId=acc0102)에 2026년 개정 전문 및 감사기준서 220 개정 안내가 있다. 게시 사실을 확인한 것이며 시행일이나 2027년 시험 적용을 확정한 것은 아니다.

## 4. 주제마다 반복하는 네 단계

### A. 적용 기준·원출처 확인

해당 주제의 모든 세트·물음·criterion을 기준대장에 연결한다. 인용의 실존뿐 아니라 앞뒤 문맥, 주체, 조건, 예외, 시점, 분류, 숫자, 임계값을 확인한다. 출처의 단순 반복인 발문과 사례 적용형 발문을 구분한다.

산출물: 물음별 적용 기준과 근거표. 완료 신호: 전 물음·criterion의 출처 대조 결과 또는 확인 불가 사유가 기록됨.

### B. 문제·물음·문장 전수 검토

정답을 가리고 모든 문제와 물음을 먼저 읽어 ‘답해야 하는 내용’을 요약한다. 이후 모범답안까지 읽고 문장을 교정한다.

- 공통 상황만으로 답할 수 있는지, 필요한 전제·지시어의 대상·주체·시점이 분명한지.
- 독립 물음의 분리와 결론+근거의 결합이 적절한지.
- 제목·공통 사실·다른 물음이 정답을 누설하거나 불필요한 선행 정답을 요구하는지.
- 명령 동사, 답안 개수, 순서, 선택 범위, 초과 답안 처리, 답안 칸이 일치하는지.
- 오탈자, 띄어쓰기, 조사·호응, 중복 표현, 번역투, 지나치게 긴 문장, 전문용어 표기가 자연스러운지.
- 정답·해설·채점 사유·버튼·오류 안내까지 문체와 용어가 일관적인지.
- 문장을 다듬으면서 부정, 조건, 예외, 시점, 요구 개수 또는 정답 범위를 바꾸지 않았는지.

산출물: 현재 문장 / 수정 문안 / 수정 이유 / 의미 변경 여부. 단순 오탈자에 별도 단위 테스트를 남발하지 않고 의미 보존 대조와 화면 확인으로 검증한다.

### C. 모범답안·criterion·실제 채점 대조

발문 요구 → model_answer → requirement → criterion → source_ref를 양방향으로 추적한다. 묻지 않은 내용을 득점요소로 추가했는지, 필수 요구를 누락했는지, 같은 사실을 중복 채점하는지 확인한다. 결론과 근거를 구분하고 부분점수는 criterion 계약에 따른다.

**모든 물음에 최소 5종 답안**을 준비한다.

| 사례 | 확인 목적 |
| --- | --- |
| 완전 정답 | 모든 필요한 요소가 정상 득점하는지 |
| 의미가 같은 표현 변형 | 자연스러운 동의 표현·띄어쓰기·경미한 오탈자로 부당하게 감점하지 않는지 |
| 핵심 요소 누락 | 누락한 criterion과 허용된 부분점수가 일치하는지 |
| 반대 의미·조건 교체 | 부정어·주체·시점·범주를 바꾼 답안이 키워드만으로 득점하지 않는지 |
| 빈 답안 | 0점, 인용 없음, 불필요한 모델 호출 없음 |

기본 960개 물음-답안 조합이며, 세트별 답안 슬롯에 묶어 실행한다. 각 criterion에 정답 및 실패 판정 사례가 연결되도록 누락·반대 사례를 추가하고, partial이 있는 criterion은 허용/비허용 경계를 추가한다. 주제별 문서의 특화 사례도 포함한다.

기대판정은 원출처와 검토한 채점 계약에서 먼저 작성한다. 현재 코드 출력이나 모델 출력을 그대로 정답으로 복사하지 않는다. 모의 모델 응답으로 코드의 합산·인용·보안 처리를 검증하고, 실제 설정 모델을 사용하는 전수 평가로 의미 판정을 확인한다. 빈 답안처럼 모델 호출이 없어야 하는 사례는 실제 무호출을 검증한다. 모델·프롬프트·데이터 해시와 실행 조건을 기록하며 공급자나 모델 이름을 고정하지 않는다.

모델 판정과 코드 보정 후 결과를 따로 기록한다. 불일치·불안정 사례는 같은 설정으로 최소 3회 재측정한다. 실제 호출 실패나 실행 환경 미비는 미검증으로 남기며 오프라인 통과로 대체하지 않는다. 주제 실행 전에 사례 수·예상 호출 수·토큰량을 산출해 실행 기록에 남긴다.

산출물: 답안·기대 criterion 판정·기대점수·실제판정·실제점수·인용·불일치 원인. 점수 총계만 같다고 합격으로 처리하지 않는다.

### D. 주제 내·주제 간 정합성과 결과 확인

전 물음의 화면 표시, 답안 전송, 결과 귀속을 확인한다. 같은 기준의 정의·조건·시점이 다른 주제와 모순되는지, 사실상 같은 물음을 반복하는지 비교한다. 고위험 오류, 채점 오류, 내용 오류, 표현 개선을 구분해 수정안을 정리한다.

산출물: 주제별 보고서와 전수 검토 장부. 완료 신호: 해당 주제 대상 ID 누락 0건, 근거 없는 판정 0건, 미검증·미해결 상태의 명시. ‘검토 기록 완료’와 ‘2027년용 사용 적합’은 별도 판정이다.

| lib/questionV3Store.ts, lib/questionV3Encryption.ts | 게시 상태, 정본/공개본/암호화본 일치, 오류 분류 및 비공개 정보 경계 |
| lib/rateLimit.ts, lib/dbAdmin.ts, contexts/AuthContext.tsx | 호출 제한, 점수에 따른 진도 반영, 실패·중복 요청 후 사용자 표시 일치 |
| 기존 tests/questionV3*.test.ts, tests/openaiStructured.test.ts, tests/v3Cutover.test.ts, tests/rateLimit.test.ts | 현재 커버리지와 누락된 행위 검증을 구분 |

특히 확인할 반례:

- 동일 문장의 인용에 독립된 여러 명제가 들어 있는 경우와 동일 사실을 반복한 경우.
- N개를 요구할 때 N-1/N/N+1개, 중복 열거, 순서 변경, 정답 뒤 모순 추가.
- 학습 권장 순서 learning_order와 채점상 필수 순서 ordered의 혼동.
- 결론만 맞음 / 근거만 맞음 / 결론과 근거가 모순됨.
- 공통 사실 복사, 다른 물음의 답안 복사, 존재하지 않는 인용.
- 개별 물음의 보안 문제와 전체 세트의 보안 문제, 정상 답안의 오탐.
- 서비스 실패·재시도·반복 제출에 따른 중복 진도 반영. 정책이 불명확하면 실제 동작과 제안 정책을 나누어 기록한다.

AI는 criterion 판정과 답안 인용을 반환하고, 점수 합산·인용 검증·보안 반영은 코드가 수행한다는 경계를 검증한다. 데이터에 계약 필드가 있다는 사실을 기능 구현의 증거로 보지 않는다. 옛 v2 정책 문서의 규칙을 현행 v3에 자동 적용하지 않는다.

### C2 — 19개 주제 통합 검증

주제 간 중복·용어·날짜·조건을 재대조한다. 공통 코드 수정이 후속으로 이루어지면 영향받는 주제의 답안 사례를 모두 재실행한다. 배점·형상·검증 규칙 변경 시 호출처, 공개 변환, UI, 저장 및 테스트의 동반 수정 범위를 명시한다.

모든 물음의 문제/결과 화면은 데스크톱·모바일 폭에서 읽기와 줄바꿈을 확인한다. 로그인·오류·한도·암호화 문제 같은 공통 경로는 별도 행위 검사로 확인한다. 운영 사용자 데이터 대신 격리된 시험 환경과 합성 답안을 사용한다.

Next.js 코드 변경이 필요해지면 먼저 설치된 node_modules/next/dist/docs/의 관련 가이드를 읽는다.
