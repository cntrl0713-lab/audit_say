# N02 — 감사증거·업무분장·IT통제

**배정: 4세트·12물음·잠정 32점 / P1·신규 제작.** 현재 문서는 실행 전 작업지시서다. 이 문서 작성만으로 문항 생성·모델 호출·정본 반영을 시작하지 않는다. 실제로 배정받아 실행할 때 [공통 계약](서브에이전트-공통-작업-계약.md)과 [입력 기준선](../계획-수립의-입력-초안-상태와-확인-범위.md)을 함께 따른다.

## 출력 권한

미래 실행에서 쓸 수 있는 위치는 저장소 루트 기준 `cpa_uploader/drafts/delegated-authoring-2026-09-11/n02/` **한 폴더뿐**이다. 이 위치와 파일은 지금 만들지 않는다. 원자료·정본·공개본·coverage 입력·wiki·코드·다른 패키지는 읽기 대상으로 두며, 공통 반영이 필요하면 총괄에게 제안한다.

신규 문항·작성계획·실제 출처 패킷·개별 검수/채점 증거·총괄 전달 요약은 위 폴더 안에만 남긴다. 파일 이름·형상·검증 절차는 [공통 계약](서브에이전트-공통-작업-계약.md)을 따른다. 필요한 공식 출처 신규 확보본도 이 폴더에 보존하고 공용 카탈로그 반영은 총괄에게 전달한다.

QA 사례 파일 이름은 `qa-cases-<계획ID소문자>.json`처럼 정하며 `draft`·`checkpoint` 문자열을 넣지 않는다. 특히 기존 `draft-*` 실제 ID를 붙여 `qa-draft-*` 파일을 만들지 않는다. 자세한 산출물 계약은 [공통 계약](서브에이전트-공통-작업-계약.md)을 따른다.

실제 생성은 [공통 계약](서브에이전트-공통-작업-계약.md)의 **총괄 단일 생성 경로와 직렬 ID 확정**을 이용한다. 각 작업자가 개별 생성 CLI를 실행한 뒤 ID 장부만 기입하는 방식은 금지한다. 총괄이 전역 활성 초안을 `existingDrafts`로 전달하는 생성 흐름에 필요한 준비계획·출처 패킷·설계경계를 제출하고, 반환된 담당 결과의 검수·수정을 이어간다.

## 담당 범위와 고유 경계

- T08-A는 기업생성정보 정확성·완전성과 목적상 정밀도·상세도 구별이다. T08-A-Q2에 요구하지 않는 새 보고서·보완자료 목록을 숨은 배점으로 넣지 않는다.
- T08-B는 매출의 추출 방향과 기간귀속 범위이며 계약상 통제 이전 조건을 명시한다. FOB 명칭만으로 회계 결론을 확정하지 않는다.
- T06-A는 권한 조합→위험→대응 통제, T06-B는 IT환경→IT사용 위험→일반통제의 연결이다. 실행 확인과 기간 전체 운영효과성 테스트를 구별한다.

## 출처 확보 조건

- 공식 500.7~9·11 및 관련성·정밀도 적용자료, 315의 주장 정의·26 본문과 IT 관련 적용자료·부록, 필요한 330.8의 조건을 확보한다.
- 315 공식 전사 단위가 있어도 업무분장·권한·테스트를 지지하는 적용자료가 빠졌다면 패킷을 보강한다. 회사 내 전산 모듈의 전수 대사가 독립된 증거를 자동 대체한다는 전제를 만들지 않는다.

각 상세계획의 실제 `source_unit_ids`·대표 원기출·빈도 관계·기존 criterion 차이를 그대로 추적한다. 출처 본문·하위항목·적용자료·예외가 새 명제를 직접 지지해야 하며, 카탈로그 연결이나 인용 일치만으로 공식 판본·의미검수 완료를 주장하지 않는다.

## 선행 패킷과 전달 사항

선행은 **총괄의 기준선**이다. 총괄이 전달한 현행 은행·기존 초안·소스·코드 해시 및 실제 ID 배정을 확인한다. 다른 패키지의 종료를 기다릴 필요는 없다.

선행은 **발문과 채점요건을 확정하기 위한 의존성**이다. 선행이 미완료여도 원문 확보·기존 은행 대조·출처 공백 조사·경계 사례 후보 준비는 먼저 진행한다. 아직 받지 않은 확정 내용을 임의로 채워 실제 문항의 조건이나 배점을 고정하지 않는다.

N03·N04 및 S02에 최종 학습목표·사례조건·답안명제와 중복 범위를 전달한다. 특히 T08-B-Q3↔T07-C-Q1, T08-A↔T07-C-Q3는 후속의 의도된 적용복습이며 두 번의 신규 공백 보완으로 세지 않도록 명시한다.
