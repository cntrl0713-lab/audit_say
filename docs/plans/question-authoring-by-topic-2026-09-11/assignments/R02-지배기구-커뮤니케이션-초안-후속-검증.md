# R02 — 지배기구 커뮤니케이션 초안 후속 검증

**배정: 1세트·2물음·잠정 12점 / P1·기존 초안 계속.** 현재 문서는 실행 전 작업지시서다. 이 문서 작성만으로 문항 생성·모델 호출·정본 반영을 시작하지 않는다. 실제로 배정받아 실행할 때 [공통 계약](서브에이전트-공통-작업-계약.md)과 [입력 기준선](../계획-수립의-입력-초안-상태와-확인-범위.md)을 함께 따른다.

## 담당 세트와 물음

| 계획 ID | 실제 계획 제목·상세 원문 | 물음 ID와 잠정 배점 | 세트 합계 |
|---|---|---|---:|
| `T05-A` | [유의적 발견사항과 독립성 커뮤니케이션 초안 완성](../topics/주제05-부정-법규-지배기구-커뮤니케이션.md) | `T05-A-Q1` 7점 · `T05-A-Q2` 5점 | 12점 |

표의 ID는 계획용 ID다. 실제 세트·물음·criterion ID는 총괄이 배정한다. 근거 검토 결과 요구·배점을 바꿀 필요가 있으면 변경 이유와 영향 합계를 총괄에 제안하고, 담당 범위를 임의로 늘리거나 다른 패키지의 세트를 가져오지 않는다.

## 출력 권한

미래 실행에서 쓸 수 있는 위치는 저장소 루트 기준 `cpa_uploader/drafts/delegated-authoring-2026-09-11/r02/` **한 폴더뿐**이다. 이 위치와 파일은 지금 만들지 않는다. 원자료·정본·공개본·coverage 입력·wiki·코드·다른 패키지는 읽기 대상으로 두며, 공통 반영이 필요하면 총괄에게 제안한다.

이 패키지는 **기존 초안의 검증용 후속본·후속 증거 보존과 원본 패치 제안**을 담당한다. 기존 배치의 원본 문항·sidecar·content/build·공유 요약·과거 로그·receipt를 쓰거나 덮어쓰지 않는다. 검증용 제안본 문항 JSON·plan·source packet은 원본 ID와 계보를 유지하여 위 전용 폴더에 저장하고, 그 제안본을 대상으로 공통 계약에 따른 실제 검수·채점을 수행할 수 있다. 이는 기존 7세트 중 담당 세트의 후속 버전이며 신규 세트나 별도 활성 초안으로 중복 집계하지 않는다. 어떤 버전을 활성본으로 비교·검수할지는 총괄이 선택한다. 수정이 필요하면 원본 경로·원본 SHA-256·변경 이유를 명시한 패치 제안과 제안본에 대응하는 후속 검증 근거를 함께 남긴다. 원본 패치 적용은 총괄이 수행한다. 과거 파일의 해시를 최신 값으로 치환하거나 검수 실패 기록을 삭제하지 않는다.

QA 사례 파일 이름은 `qa-cases-<계획ID소문자>.json`처럼 정하며 `draft`·`checkpoint` 문자열을 넣지 않는다. 특히 기존 `draft-*` 실제 ID를 붙여 `qa-draft-*` 파일을 만들지 않는다. 자세한 산출물 계약은 [공통 계약](서브에이전트-공통-작업-계약.md)을 따른다.

- KGA 260.16~17 및 의존 적용자료를 fgi 공식 발췌·배치 provenance와 결속한다. 학습자료 카탈로그 src-73fe85bf893193bbc1·src-b0ab9073ba65ae159e와 공식 판본을 구별한다.
- 전원 경영참여 예외는 해당 발견사항에만, 독립성 커뮤니케이션은 상장기업 범위와 보수·네트워크·안전장치의 주체를 보존한다. 보고기간 총보수와 서비스유형별 배분을 다른 명제로 유지한다.

각 상세계획의 실제 `source_unit_ids`·대표 원기출·빈도 관계·기존 criterion 차이를 그대로 추적한다. 출처 본문·하위항목·적용자료·예외가 새 명제를 직접 지지해야 하며, 카탈로그 연결이나 인용 일치만으로 공식 판본·의미검수 완료를 주장하지 않는다.

## 선행 패킷과 전달 사항

선행은 **총괄의 기준선**이다. 총괄이 전달한 현행 은행·기존 초안·소스·코드 해시 및 실제 ID 배정을 확인한다. 다른 패키지의 종료를 기다릴 필요는 없다.

선행은 **발문과 채점요건을 확정하기 위한 의존성**이다. 선행이 미완료여도 원문 확보·기존 은행 대조·출처 공백 조사·경계 사례 후보 준비는 먼저 진행한다. 아직 받지 않은 확정 내용을 임의로 채워 실제 문항의 조건이나 배점을 고정하지 않는다.

S03에 일반 커뮤니케이션의 범위·주체와 기존 요구의 경계를 전달한다. 게시·정본 편입은 root의 별도 작업이며 이 패키지가 완료하지 않는다.
