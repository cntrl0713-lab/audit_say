# 서브에이전트 배정표와 실행 순서

**49세트·131물음을 14개 작업으로 나눴다.** 각 작업 이름을 열면 그대로 전달할 수 있는 지시서가 있다. [주제별 상세 계획](../README.md)의 실제 물음 ID를 기준으로 중복 없이 배정했으며, 이번에는 작업지시서만 작성했다.

| 작업 구분 | 작업 수 | 세트 | 물음 | 잠정점수 |
|---|---:|---:|---:|---:|
| R: 기존 초안 후속 검토·보완 | 2 | 7 | 14 | 49 |
| N: 새 작성 P1 | 6 | 19 | 54 | 159 |

새 작성 42세트에는 심화·의도된 복습이 포함된다. 기존 초안 7세트는 새로 중복 제작하지 않는다. 모든 작업은 [공통 계약](서브에이전트-공통-작업-계약.md)과 지정된 주제 계획을 함께 읽는다.

## 최대 3개 병렬 작업의 권장 순서

총괄 1명과 서브에이전트 최대 3명으로 진행한다. 14명을 한꺼번에 띄우는 방식이 아니라, 작업을 마친 에이전트에 다음 지시서를 배정한다. 아래는 선행 설계의 인계를 확보하는 간단한 일정이며 소요 시간 추정이 아니다.

| 차례 | 담당자 A | 담당자 B | 담당자 C | 다음 차례에 넘길 내용 |
|---|---|---|---|---|
| 0 | 총괄 준비 | 총괄 준비 | 총괄 준비 | 현재 버전·판본 정책·ID·활성 초안 목록·쓰기 범위 |
| 1 | R01 | R02 | N01 | 기존 초안의 실제 잔여 작업과 기본개념·계약의 확정 범위 |
| 2 | N02 | N05 | N06 | 증거·통제·그룹 업무·보고 요구의 확정 범위 |
| 3 | N03 | N04 | S01 | 위험대응·추정·전문가의 범위와 중요성 심화 |
| 4 | S02 | S03 | S04 | 복습 관계와 추가 증거·감사완료의 경계 |
| 5 | S05 | S06 | 통합 대조 지원 | 보고 문안과 특수 업무의 적용 조건 |

**먼저 각 작업의 초안까지 준비하고, 비교 은행을 고정한 뒤 같은 작업을 재개해 검수·실제 채점한다.** 중간 인계 `draft_ready`를 제작 완료로 보고하지 않는다. 준비된 묶음부터 검수할 수 있으나 나중에 합류한 문항과도 전역 중복을 대조하고, 비교 은행 변경이 최종 receipt에 미치는 영향을 확인해야 한다. R02처럼 최신 통과 증거가 있는 작업은 재사용 가능 범위부터 확인한다.

P1의 원문 미확정이 장기화되면 준비된 P2의 독립 조사를 먼저 진행할 수 있다. 우선순위가 적용 판본·완전열거의 검증을 대신하지 않는다. 후속 작업의 학습상 경계가 확정될 때까지 그 경계에 의존하는 발문·criterion만 유보한다.

## 총괄이 맡을 일

| 단계 | 총괄 산출물과 판단 |
|---|---|
| 배정 전 | 현재 은행·활성 초안·과거 사본의 목록과 해시를 다시 확인. 적용 연도·판본의 확정/미확정 범위 및 현재 설정을 전달. [이 계획의 기준선](../계획-수립의-입력-초안-상태와-확인-범위.md)을 현재 데이터로 오인하지 않음 |
| ID·출처 확정 | `TXX-A[-Qn]`와 실제 문항 ID의 단일 대응 장부. 생성기는 총괄의 단일 경로에서 전역 활성 초안을 `existingDrafts`로 전달하고 새 결과를 누적해 ID 확정. 공용 공식 출처를 통합하고 실제 카탈로그 ID 전달 |
| 초안 수집 | 14개 전용 폴더의 활성 문항과 계보를 확인. 기존7+신규42를 중복 없이 집계. 공용 원본 변경은 패치와 생성 범위를 검토한 뒤 후속 경로에 반영 |
| 검수 전 | 은행·활성 보존 초안·검수 묶음의 동료 문항을 합친 비교 은행과 해시 고정. 비교용 사본은 자동 초안 탐색 폴더 밖에 보존. 검수기 `--bank`의 경로를 전달 |
| 검수 중 | 공통 코드·출처·모델 설정 고정. 공통 결함의 재현과 수정은 한 담당자가 처리하고 영향 작업에 새 버전 전달. 작업자는 전용 로그 경로 사용 |
| 최종 인수 | 세트/물음 처리 목록, 실제 검수·채점 범위, 잔여 실패, 판본 미확정, 의도된 복습, 최종 해시와 증거를 합침. 원문·관계 입력 변경 시에만 해당 분석/wiki 생성·검사를 수행 |

편집 정본·공개본·DB·운영 배포는 서브에이전트의 쓰기 범위에 들어가지 않는다. 향후 요청 범위에 포함되면 총괄이 사람 확인과 현행 승급 계약을 충족한 뒤 수행한다.

## 바로 전달하는 방법

첫 실행에는 아래 지시를 총괄에게 전달한다. 실제로 작업을 시작할 때 적용할 문구이며 현재 문서 작성 중 실행한 명령은 아니다.

```text
docs/plans/question-authoring-by-topic-2026-09-11/assignments/README.md에 따라
49세트·131물음의 제작·보완을 진행해줘.
먼저 현재 입력과 활성 초안, 적용 판본·ID·공통 파일 소유권을 확정하고,
R01, R02, N01을 각각 서브에이전트에게 맡겨줘. 동시에 최대 3개만 실행해줘.
각 담당자는 자기 배정서와 서브에이전트-공통-작업-계약.md를 읽고 지정 폴더만 수정해야 해.
초안 준비 후에는 비교 은행을 고정하고 실제 의미검수·채점 및 불일치 수정까지 이어가줘.
중간 인계와 검증 완료를 구분하고, 정본 편입·게시·배포는 하지 마.
```

한 작업만 맡길 때는 해당 배정서 끝의 지시문을 사용한다. 총괄은 필요한 선행 패킷·실제 ID·검수 단계 정보를 함께 전달한다. 배정서의 원문 링크를 새 메시지에 전부 복사할 필요는 없다.
