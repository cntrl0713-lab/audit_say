# 서브에이전트 공통 작업 계약

이 문서는 [배정표](README.md)의 작업을 **나중에 실제 제작·보완하도록 맡길 때** 사용하는 지시서다. 2026-09-11의 현재 요청에서는 계획과 작업 분할까지만 수행했다. 실제 실행 시에는 그때까지의 사용자 지시와 현재 저장소 상태를 우선한다.

## 먼저 읽을 자료

1. 저장소 [AGENTS.md](../../../../AGENTS.md), [제작 스킬](../../../../.agents/skills/audit-question-author/SKILL.md), [검토 스킬](../../../../.agents/skills/audit-question-review/SKILL.md), [자료 관리 규칙](../../../출제-검토-자료-관리.md).
2. [전체 계획](../README.md), [작성 당시 기준선](../계획-수립의-입력-초안-상태와-확인-범위.md), 자신의 배정 파일과 지정한 주제 상세 계획. 상세 계획에 이미 있는 물음별 명제·빈도·source ID·비교 criterion·제외 범위를 이어받는다.
3. [wiki 통합 현황](../../../../cpa_uploader/wiki/_meta/authoring-dashboard.md) → 담당 주제 설계 지침 → 원자료 카탈로그 → 실제 원발문·공식 본문. [요소 활용](../../../../cpa_uploader/wiki/question-generation/question-elements.md)과 [coverage 계약](../../../../cpa_uploader/analysis/coverage/README.md)도 확인한다.
4. [원자료 기반 설계](../../../../cpa_uploader/wiki/question-generation/source-authoring-design.md), [출력 스키마](../../../../cpa_uploader/wiki/question-generation/question-output-schema.md), [기존 01–03 보완 정책](../../주제-01-03-검토에-따른-수정-결정.md). 실행 명령·타입은 현행 코드와 package.json에서 확인한다.

## 담당 범위와 파일 소유권

- 자신에게 배정된 계획 ID만 처리한다. 계획 ID `TXX-A`는 실제 세트 ID가 아니다. 실제 세트·물음 ID는 총괄이 현재 은행과 모든 진행 초안을 대조해 배정한 값으로 확정한다. 기존 ID를 재번호화하지 않는다.
- 쓰기 범위는 각 배정서에 지정한 **전용 출력 폴더**다. 공용 원자료·공식 발췌·정본·공개본·분석 입력·coverage·wiki·채점 엔진은 총괄이 관리한다. 필요한 공통 변경은 전용 폴더에 제안과 근거로 제출한다.
- 과거 초안·로그·receipt·보고서를 덮어쓰지 않는다. R01/R02는 기존 문항의 후속 버전이며 신규 세트로 세지 않는다. 후속 문항 파일과 계보를 전용 폴더에 보존하고, 원본 반영이 필요하면 패치를 제출한다.
- 특히 R01의 원본 `frequency-priority-2026-09-10/content.mjs`와 `build-batch.mjs`를 직접 수정·실행하지 않는다. 전체 6세트와 과거 보고서까지 쓰는 생성기이므로 총괄이 출력 범위를 확인해 후속 배치로 재현해야 한다. 생성 JSON만 고쳐 원본과 어긋나게 만들지 않는다.
- 다른 에이전트의 변경을 되돌리지 않는다. 공통 코드 결함을 발견하면 재현 입력·기대값·실제 결과를 제출하고, 총괄이 정한 수정 버전을 받아 영향 사례를 다시 확인한다.

## 두 차례로 실행하기

**1차: 출처·범위 확정과 초안 준비.** 위키와 실제 원문을 대조하고 선행 담당자로부터 겹치는 요구의 범위를 받는다. 선행 작업이 끝나지 않아도 독립적인 원문 조사는 계속한다. 적용 판본·답안의 완전열거·필수 예외가 불확실하면 해당 물음은 `source_pending`으로 보고하고 다른 준비된 물음을 진행한다. 기존 2027년 가정을 자동 채택하지 않는다. 총괄은 필요한 적용 연도·판본을 기존 사용자 지시와 공식 자료로 확정하며, 정답을 바꾸는 미지정 사항만 사용자에게 묻는다.

총괄이 실제 source ID와 문항 ID를 확정하면 해당 세트의 version 1 계획, 사례·물음·모범답안·criterion, 작성자 QA를 만든다. `source_pending`, `design_ready`, `draft_ready`는 **작업 장부의 진행 표시**이며 문항 JSON의 status 값으로 추가하지 않는다. `draft_ready`는 형상·근거·명제 대응을 확인한 중간 인계이며 제작 완료가 아니다.

**2차: 고정된 입력으로 의미검수·실제 채점.** 총괄이 동료 초안을 합친 비교 은행의 경로·해시와 검수 대상 버전을 전달한 뒤 진행한다. 검수 CLI에 `--bank`, 필요하면 `--plan`, `--packet`을 실제 경로로 지정한다. 준비된 묶음별로 진행할 수 있지만 이후 합류 문항과도 최종 중복 검사를 해야 한다. 원문·문항·계획·패킷·비교 은행·코드·모델 설정이 변하면 receipt의 재사용 가능 범위를 다시 판단한다. 이전 통과 숫자만 옮기지 않는다.

## 설계·자료·ID 계약

| 항목 | 반드시 남길 내용 |
|---|---|
| 요구와 근거 | 계획 ID → 학습목표 → 발문 → 조건·예외 → 정답 명제 → criterion·정수 배점 → 공식 문단·인용의 대응 |
| 빈도 | 실제 요소 ID·원출제·페이지, 기출/모의/연습/OX의 별도 수치. 재수록만 제외하며 인접 요소의 횟수를 직접 빈도로 옮기지 않음 |
| 기존 요구와 차이 | 현재 은행과 다른 작업의 세트/물음/criterion 대조. 신규 요구·심화·의도된 복습 구분. T07-C-Q1/Q3는 새 커버리지로 계산하지 않음 |
| 공식 출처 | 발표·시행·보고기간·시험 적용 판본, 공식 URL·확인일·문단·의존 문맥·파일 및 인용 해시. 학습자료 요약을 공식 원문으로 표시하지 않음 |
| 실제 ID | 총괄 배정 값과 `TXX-A[-Qn]` 대응표. 새 source ID는 공용 카탈로그에 실제 등록된 뒤 사용 |
| 배점 | 모두 작성, 순서 제한 없음, 개수 상한 없음. 독립 명제 기본 1점, 소수 partial·숨은 채점요건·주어진 사실 재득점 없음. 계산 문제 제외 |

`readPendingDrafts()`는 기본으로 data만 읽는다. 총괄은 drafts 및 별도 출력 경로를 명시적으로 포함하고, **활성 버전·역사본·합본·개별본의 선택 목록**을 정해 중복을 대조한다. 같은 문항의 사본을 여러 번 비교 은행에 넣지 않는다.

자동 ID 할당에는 중앙 잠금이 없으며, 생성 CLI는 다른 작업의 출력 폴더를 자동으로 모두 읽지 않는다. **단순히 실행 순서를 직렬화하거나 장부에 예약하는 것만으로 충돌을 막을 수 없다.** 생성기를 쓰면 총괄의 단일 생성 경로에서 전역 활성 초안을 `existingDrafts`에 전달하고, 생성 직후 새 결과를 그 목록에 추가한 뒤 다음 ID를 확정한다. 계획의 `set_id`가 자동 할당을 강제한다고 가정하지 않는다. 수동 작성도 총괄이 배정한 ID로만 진행하고 전역 충돌을 다시 검사한다. 검수 시작 뒤 임의로 ID를 바꾸지 않는다.

## 산출물과 인계 형식

전용 폴더에 다음 자료를 남긴다. 아래 이름은 작업 파일 예시이며, 문항·계획·패킷의 형상은 현행 스키마에 맞춘다. 같은 문항의 합본 JSON과 개별 JSON을 탐색 폴더에 함께 보관하지 않는다.

| 파일 또는 묶음 | 내용 |
|---|---|
| `README.md` | 담당 계획/실제 ID, 현행 상태, 변경 이유, 출처 확보·설계·정적검사·의미검수·실측 각각의 진행 상태 |
| `scope-and-sources.md` | 요구·빈도·원출제·공식 근거·기존/동료 차이·제외 범위·판본 확인 및 남은 쟁점 |
| 세트별 문항·version 1 계획·source packet | 생성 입력과 최종 내용의 연결. 자동 sidecar 이름 또는 검수 CLI의 명시 경로 사용 |
| `qa-cases-<계획ID소문자>.json` | 원문에 따라 미리 정한 입력 답안과 명제별 기대판정·점수. 예: `qa-cases-t04-a.json`. 기존 실제 ID의 `draft` 접두사를 파일명에 옮기지 않음 |
| 실행별 증거 폴더 | 원본 모델 응답, 실제 설정, 코드/문항/계획/패킷/비교 은행 해시, 의미검수 receipt와 실제 채점 로그. 재실행은 새 경로 |
| `handoff.md` | 아래 인계 표와 공통 파일 변경 제안. 실패와 보류를 삭제하지 않고 재개 조건 명시 |

인계 표의 열은 `계획 ID / 실제 ID / 출처·판본 / 초안 버전·해시 / 정적검사 / 의미검수 / 실제 채점 사례 수·불일치 / 남은 일 / 증거 경로`로 한다. 선행·후속 담당자에게는 확정한 답안 범위·겹침 방지 사항·공식 근거 위치를 함께 전달한다.

## 제작 완료 판정

1. 모든 배정 물음의 발문·명제·정수 배점·공식 근거가 대응하며 범위 변경은 근거와 함께 보고되어야 한다. 계획의 377점은 잠정치여서 근거에 따라 바뀔 수 있지만, 아무 설명 없이 세트·물음을 생략하지 않는다.
2. 형상·인용·현재 은행 및 동료 초안의 ID/발문·의미 중복을 검사한다. 정본 편입을 가정한 검증은 메모리에서 수행한다.
3. 최종 버전의 실제 모델 의미검수와 `gradeQuestionSetV3`를 통한 채점 증거가 있어야 한다. 저장 모범답안만 만점, 기대판정 합산, 주입 응답을 실제 전수검증으로 보고하지 않는다.
4. 전 물음·criterion의 완전 답안·동의 표현·한 명제 누락·명시적 반대·조건 경계·빈 답안을 확인한다. 열거 역순·한 문장의 복수 명제·조치에 함축된 판단·무관한 문장 뒤 정답을 포함한다. 불일치·변동은 같은 설정으로 총 3회 이상 확인하고 원인 조사·수정 후 영향 사례를 최종 버전으로 다시 채점한다.
5. 실패·미실측이 남으면 `검증 미완료`로 보고한다. 정상 실행된 실제 사례 수와 남은 사례를 분리한다. 과거 실패 및 후속 결과를 함께 보존한다.
6. 검증을 통과해도 문항은 현행 `needs_review / needs_human_review` 상태를 유지한다. 사람 확인·정본 승급·공개본 생성·DB 반영·배포는 별도 요청 범위와 현행 계약에 따라 총괄이 처리한다.

총괄은 위 조건을 확인하고 49개 계획의 처리 결과를 합친다. 이 문서나 배정서 작성 자체는 실제 문항 제작·검증 완료의 증거가 아니다.
