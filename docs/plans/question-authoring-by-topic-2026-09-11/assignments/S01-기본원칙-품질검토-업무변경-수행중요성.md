# S01 — 기본원칙·품질검토·업무변경·수행중요성

**배정: 4세트·12물음·잠정 31점 / P2·후속 신규 제작.** 현재 문서는 실행 전 작업지시서다. 이 문서 작성만으로 문항 생성·모델 호출·정본 반영을 시작하지 않는다. 실제로 배정받아 실행할 때 [공통 계약](서브에이전트-공통-작업-계약.md)과 [입력 기준선](../계획-수립의-입력-초안-상태와-확인-범위.md)을 함께 따른다.

## 출력 권한

미래 실행에서 쓸 수 있는 위치는 저장소 루트 기준 `cpa_uploader/drafts/delegated-authoring-2026-09-11/s01/` **한 폴더뿐**이다. 이 위치와 파일은 지금 만들지 않는다. 원자료·정본·공개본·coverage 입력·wiki·코드·다른 패키지는 읽기 대상으로 두며, 공통 반영이 필요하면 총괄에게 제안한다.

신규 문항·작성계획·실제 출처 패킷·개별 검수/채점 증거·총괄 전달 요약은 위 폴더 안에만 남긴다. 파일 이름·형상·검증 절차는 [공통 계약](서브에이전트-공통-작업-계약.md)을 따른다. 필요한 공식 출처 신규 확보본도 이 폴더에 보존하고 공용 카탈로그 반영은 총괄에게 전달한다.

QA 사례 파일 이름은 `qa-cases-<계획ID소문자>.json`처럼 정하며 `draft`·`checkpoint` 문자열을 넣지 않는다. 특히 기존 `draft-*` 실제 ID를 붙여 `qa-draft-*` 파일을 만들지 않는다. 자세한 산출물 계약은 [공통 계약](서브에이전트-공통-작업-계약.md)을 따른다.

실제 생성은 [공통 계약](서브에이전트-공통-작업-계약.md)의 **총괄 단일 생성 경로와 직렬 ID 확정**을 이용한다. 각 작업자가 개별 생성 CLI를 실행한 뒤 ID 장부만 기입하는 방식은 금지한다. 총괄이 전역 활성 초안을 `existingDrafts`로 전달하는 생성 흐름에 필요한 준비계획·출처 패킷·설계경계를 제출하고, 반환된 담당 결과의 검수·수정을 이어간다.

## 담당 범위와 고유 경계

- 고유한계가 절차 생략·법적 면책을 뜻하지 않음을 구별한다. 사후 왜곡표시 발견만으로 수행 부적절성을 자동 확정하지 않는다.
- 품질검토자의 절차·문서화와 업무수행이사 책임, 보고서일과 종료일을 분리한다. 감사→검토 변경은 합리적 이유·계속업무 차단·관련서비스 보고 예외를 구별한다.
- 수행중요성은 재무제표 전체 중요성 기준의 정의·기계적 비율 비판·인하 후 재평가 범위다. 특정 계정 등의 별도 중요성 정의를 숨은 요건으로 추가하지 않는다.

## 출처 확보 조건

- N01 패킷에 공식200 고유한계·사후 수행평가 문맥, 기존 선택판220.19·20·25, 210.14~17·A31~A35, 320.9·11·13·A12~A13을 보강한다.
- 220 발표일·시행 보고기간·시험 적용판본은 각각 확인한다. N01의 공통 기준을 재사용하더라도 윤리·품질 관련 새 공식 문단의 확인은 별도로 필요하다.

각 상세계획의 실제 `source_unit_ids`·대표 원기출·빈도 관계·기존 criterion 차이를 그대로 추적한다. 출처 본문·하위항목·적용자료·예외가 새 명제를 직접 지지해야 하며, 카탈로그 연결이나 인용 일치만으로 공식 판본·의미검수 완료를 주장하지 않는다.

## 선행 패킷과 전달 사항

선행 패킷: **[N01](N01-기초-독립성-계약-감사문서.md)**. 해당 담당자의 최종 학습목표·조건/예외·답안명제·공식 판본/출처 결속·중복 검토 결과를 전달받는다.

선행은 **발문과 채점요건을 확정하기 위한 의존성**이다. 선행이 미완료여도 원문 확보·기존 은행 대조·출처 공백 조사·경계 사례 후보 준비는 먼저 진행한다. 아직 받지 않은 확정 내용을 임의로 채워 실제 문항의 조건이나 배점을 고정하지 않는다.

업무변경·확신 수준 구분은 S06의 중간검토와 비교할 수 있게 총괄에 전달한다. N01과 같은 정의를 재출제한 부분은 의도된 복습 여부를 유지한다.
