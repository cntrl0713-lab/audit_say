## 역할과 변경 소유권

| 담당 | 책임 | 허용 수정 |
| --- | --- | --- |
| 총괄 | 해시 확인, 시작·중단 조율, 불일치 분류, 통합 후보·실행 잠금·최종 집계, 승급/DB 절차 | 새 통합 후속 파일. 실측 중 공통 코드·비교 은행·원자료는 고정 |
| a | manifest의 worker a 작업 | 해당 wave의 `semantic-a`, `grading-a`, `author-qa-a` 및 지정된 후속 수정 제안 폴더 |

| c | manifest의 worker c 작업 | 같은 방식의 c 전용 출력·제안 폴더 |

각 담당자는 이 문서·자기 manifest 작업·공통 스킬을 읽고 자기 출력만 수정한다. 세트/물음/criterion ID를 재번호화하지 않는다. 동시에 최대 3개 실제 작업자만 실행하며 의미검수·채점·작성자 QA·학습 단위 검증을 각각 3개씩 겹쳐 총 6개 이상 실행하지 않는다.

## 1. 선행 3세트 확인

선행 대상은 `pilot-01-002`, `pilot-03-001`, `pilot-05-003`의 30단위다. 공식 원문 보완·발문 범위 수정의 영향을 실제 모델로 먼저 확인한다. 아래는 a 예시이며 b/c는 worker와 출력 끝글자를 함께 바꾼다. 환경 변수는 키 값을 출력하지 않고 현재 `.env.local`에서 읽는다.

```powershell
$batch = 'cpa_uploader/analysis/reviews/point-review-and-publication-2026-09-11'
$run = "$batch/execution-resumes/handoff-001"
$wave = "$run/canary"
$env:CPA_GRADING_MODEL = 'gpt-5.6-luna'
$env:CPA_REVIEW_MODEL = 'gpt-5.6-luna'
$env:CPA_REVIEW_INPUT_MAX_CHARS = '500000'
node --env-file=.env.local "$batch/b/validation-worker-v3.mjs" --manifest "$wave/manifest.json" --worker a --phase semantic --output "$wave/semantic-a" --stop-file "$wave/STOP"
```

첫 실행 전에 같은 명령에 `--dry-run`을 붙여 입력을 확인할 수 있다. dry-run이 실제 모델 검수를 수행했다고 표시하지 않는다. 실제 완료 receipt에서 모든 단위 pass·실인용·현재 파일 결속과 `execution.transport=model`을 확인한다. fail/uncertain이 있으면 원인을 먼저 해결한다.

같은 worker의 의미검수 결과를 연결해 실제 정식 채점을 실행한다.

```powershell
node --env-file=.env.local "$batch/b/validation-worker-v3.mjs" --manifest "$wave/manifest.json" --worker a --phase grading --semantic-directory "$wave/semantic-a" --output "$wave/grading-a" --stop-file "$wave/STOP"
```

`grading.status=completed`, `grading.transport=model`, 모든 사례의 기대 판정·인용·점수 재현을 확인한다. 빈 답안의 함수 경로와 비어 있지 않은 실제 API 호출 수를 분리한다. 일부 단위/사례만 끝났거나 CLI가 정상 종료했어도 summary의 `results`, `not_started_set_ids`, 실제 receipt가 미완료면 통과가 아니다.

## 2. 나머지 116세트와 작성자 QA

선행 단계의 문제를 해결한 뒤 `$wave = "$run/remaining"`으로 바꾸고 같은 방식으로 1,363단위 의미검수 → 정식 채점을 진행한다. 비교 은행은 전체 153세트 파일을 그대로 사용한다. 먼저 통과한 세트의 승급으로 비교 은행을 중간 변경하지 않는다.

작성자 QA는 정식 검수 사례와 별개다. 두 wave 모두 실행하며 전부 합쳐 고유 6,029개를 대조한다. `run-author-qa.ts`의 출력은 지정 draft 루트 아래여야 한다. 실제 root와 worker 소유를 유지한다.

```powershell
$qaRoot = 'cpa_uploader/drafts/delegated-authoring-2026-09-11/validation-resumes/handoff-001'
# 각 wave에서 a/b/c별로 실행. canary/remaining을 정확히 대응시킨다.
node --env-file=.env.local "$batch/b/validation-worker-v3.mjs" --manifest "$run/canary/manifest.json" --worker a --phase author-qa --output "$qaRoot/canary/author-qa-a" --stop-file "$run/canary/STOP"
node --env-file=.env.local "$batch/b/validation-worker-v3.mjs" --manifest "$run/remaining/manifest.json" --worker a --phase author-qa --output "$qaRoot/remaining/author-qa-a" --stop-file "$run/remaining/STOP"
```

답안·기대 판정은 원문·발문·정책으로 결정한다. 점수가 맞지 않는다고 기대값부터 바꾸지 않는다. 유효한 기존 답안은 수정 후에도 회귀 사례에 남긴다. 표본 검사로 전수 QA를 대신하지 않는다.

## 3. 실제 학습 단위 채점

기준서형 독립 물음, 사례형 부모 사실과 소속 물음 전체를 실제 앱 투영으로 채점한다. 249개 빈 답안 검사는 이미 완료됐고 아래는 비어 있지 않은 모범답안 249개에 대한 실측이다. a/b/c 각 83개이며 다른 단계 작업자와 합쳐 최대 3개를 유지한다.

```powershell
node --env-file=.env.local --import tsx "$batch/a/run-learning-unit-smoke-v3.ts" --manifest "$batch/a/learning-unit-smoke-v3/manifest.json" --worker a --output "$run/learning-smoke-a" --stop-file "$run/learning-smoke-STOP"
```

모범답안의 전체·물음·criterion 만점, 실제 요청/응답 모델, 원시 및 최종 보안 오탐, 클래스/선택 범위·입력 해시를 확인한다. 실행기는 불일치를 최대 3회 관측하므로 마지막 성공으로 앞선 불일치를 지우지 않는다. 실제 모델 호출·예상값 합산·빈 답안 무호출을 구분한다.

학습 단위 실행기의 `--dry-run`은 모델을 호출하지 않지만 preflight/summary 폴더를 만든다. dry-run을 추가하면 `learning-smoke-dry-a`처럼 별도 출력 경로를 쓰고 실제 실행의 `learning-smoke-a`와 공유하지 않는다. worker-v3의 읽기 전용 dry-run과 다르다.

## 4. 오류·불일치와 변경 시 처리

- 잔액/쿼터 부족, 전송·응답 형상 오류, 기록 실패, 의미 비통과, 채점 불일치를 구분한다. 쿼터 부족은 전체 새 호출을 중지하고 로그를 보존한다. 실행 오류를 학생의 감점으로 바꾸지 않는다.
- STOP은 작업 경계에서 확인한다. 이미 실행 중인 세트/요청과 중지 이후 미착수를 구분해 기록하고 완료로 올리지 않는다. 중단 후에는 새 출력 경로를 사용한다.
- 원자료·발문·답안·criterion·배점·분류가 달라지면 후속 초안과 근거를 작성한다. 총괄은 공통 코드와 실행 시점을 조율한 뒤 필요한 의미검수·채점을 새 잠금으로 수행한다.
- 새 공식 자료는 raw에 먼저 보존한다. 기존 원자료·receipt·판정·로그의 경로·바이트·해시를 재작성하지 않는다.
- 미수락 receipt의 비교 은행 결속과 이미 장부에 수락된 과거 증거의 읽기 계약을 구분한다. [승급 순서 검토](../../cpa_uploader/analysis/reviews/point-review-and-publication-2026-09-11/b/publication-sequence-study-v1/README.md)를 읽는다. 현재 후보는 기존 70개 상태/장부 문제 때문에 일부만 임의 승급하는 방식으로 해결되지 않는다.

## 5. 사람 확인·승급·운영 반영

모든 실측과 불일치 수정이 끝난 구체적인 결과를 모은 뒤 실제 사람 검수 근거를 확보한다. 사용자가 DB 반영을 승인한 것과 사람이 각 정답·판본·조건·예외를 확인했다는 증거는 구분한다. 새 승인 절차를 임의로 추가하지 말고 현행 스킬·승급 코드가 요구하는 실제 근거를 확인한다.

기존 70개는 후속 판본의 재검수, 신규 49개는 신규 승급 경로로 처리한다. 정본·승급 장부의 전체 일관성을 확인하고, 최종 상태 변경 후 분류 카탈로그를 다시 컴파일한다. 상태가 바뀌기 전 카탈로그 해시를 최종값으로 재사용하지 않는다. 공개본·암호화본·정본 검증도 수행한다.

현재 정본에는 별도 문서 정리 작업의 `verification.notes` 경로 변경이 있다. 최종 통합 때 현재 정본과 `canonical-before.json`, 검증된 후보를 대조해 독립 변경을 보존한다. 예전 후보 파일 전체를 현재 정본에 그대로 덮어쓰지 않는다. 합친 결과가 검증 대상이나 해시 계약에 영향을 주면 필요한 새 검증을 거친다.

실제 DB 쓰기 전 `scripts/import-question-bank-v3.ts`의 현행 `--apply`, `--evidence`, `--expected-hash`, `--project-host`, `--learning-catalog`, `--applicability-file` 계약과 환경 경로를 확인한다. 미검수 상태를 우회하는 보존 옵션으로 게시하지 않는다. 최종 파일·해시가 아직 없으므로 운영 쓰기 명령의 값을 지금 추정해 고정하지 않는다.

검증 후의 실제 적용 결과는 `$batch/c/verify-final-learning-rollout.ts`와 대응 handoff 문서의 입력 계약으로 읽기 대조한다. DB에는 기준서형 단독 풀이, 사례형 부모와 모든 소속 물음, 물음별 다주제, 비공개 답안 보호가 일치해야 한다. 과거 v1 답안 삭제는 허용됐지만 이 작업에서 새로 삭제할 필요가 있는지 먼저 확인하고 불필요하게 삭제하지 않는다.

완료 보고에는 119세트·280물음·1,113 criterion 전수 상태, 실제 API/무호출 수, 정식 채점·작성자 QA·학습 단위 실측 결과, 불일치 수정과 미해결 항목, 사람 확인·정본·게시·DB 각각의 상태 및 최종 해시를 기록한다. 준비 완료나 중간 인계를 검증 완료로 보고하지 않는다.
