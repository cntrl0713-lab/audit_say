# 주제 16 — 감사보고의 특수사항

[전체 계획으로](../question-content-review-plan.md) · 상태: 검토·수정 및 로컬 검증 완료 / 2027 최종 시험 판본·운영 DB 검증 별도

2026-09-08 실행 결과: [16.md 보고서](../../reports/question-review-2027/16.md) · [14물음·38criterion 장부](../../reports/question-review-2027/16.json). 7세트·14물음·38점 유지. 기본 70개 답안 조합과 최종 141개 모의 사례, 실제 모델 174회, 두 폭의 28개 화면 확인. 최초 경계 오채점은 계약 보강 및 재실측으로 수정했다. 아래 대상표의 발문·유형은 계획 당시 스냅샷이며 최종 문구·유형은 보고서의 전후 장부를 따른다.

## 목표와 대상

7세트·14개 물음·38개 criterion을 전수 검토한다. 문제 상황, 모든 발문·정답·채점기준·출처, 오탈자·어색한 표현 및 실제 채점·화면 동작을 포함한다. 2027년 대비이며 **2026년 시행 기준과 동일하다는 가정으로 시작하고 공식 확인된 변경만 반영**한다.

현재 데이터의 기준 태그: KGA 710 · KGA 701 · KGA 720 · KGA 706. 이 태그는 검토 출발점이며 현행성·완전성을 보증하지 않는다.

## 이 주제의 중점 검토

- 비교정보 유형과 그에 따른 보고책임을 확인한다.
- 핵심감사사항의 선정·기술·도입 문구 및 변형의견 관련 사항과의 관계를 확인한다.
- 강조사항·기타사항·기타정보의 목적과 적용 조건을 구분한다.
- 문제 제목·상황·물음·모범답안의 용어, 조사·호응, 띄어쓰기, 부정어와 수식 범위를 함께 교정한다. 세트 간 유사 발문도 대조한다.
- 연계 주제: [12](12.md), [15](15.md), [17](17.md). 적용 조건·전문용어·배점 계약의 모순 또는 중복을 확인한다.

## C — 정답·채점기준·코드 검증

- 목표: 발문 요구와 모범답안·criterion·실제 득점이 일치한다.
- 범위: 정본의 이 주제 항목, 공통 계획 C1의 채점 경로, 해당 주제의 평가 답안.
- 절차: 양방향 요구사항 연결 → 기대판정 독립 작성 → 모의 응답으로 코드 검증 → 실제 설정 모델 평가 → 불일치 원인 분류.
- 기본 사례: 물음마다 완전 정답 / 의미가 같은 표현·경미한 오탈자 / 핵심 누락 / 반대 의미·조건 교체 / 빈 답안. 이 주제는 최소 70개 물음-답안 조합이며 criterion별 정답·실패 및 허용된 partial 경계를 추가한다.
- 빈 답안의 모델 무호출, 물음 간 인용 격리, 점수 합산·상한·보안 처리는 코드에서 검증한다.
- 실제 모델의 답안 인용과 criterion 판정, 코드 보정 후 판정·점수를 따로 기록한다. 불일치·불안정 사례는 동일 설정으로 최소 3회 재측정한다.

주제 특화 반례:

- 보고 문단 명칭은 비슷하지만 목적이 다른 답안을 구분한다.
- 핵심감사사항으로 다른 보고 요구를 대체한 답안과 반복 선정 항목의 중복 득점을 검증한다.
- 발문에서 요구한 개수와 해당 selection·constraints가 일치하는지 물음별로 확인한다. 데이터에 해당 조건이 없으면 무조건 새 규칙을 추가하지 않는다.
- 여러 criterion이 한 문장에 표현되는 정답과 동일 사실의 반복 답안을 구분한다.

검증 명령: 공통 계획의 관련 테스트 명령과 `npm run typecheck`, `npm run questions:v3:validate`. 새 답안 사례 실행 결과는 기존 단위 테스트 결과와 따로 기록한다. 완료 조건은 총점뿐 아니라 criterion 판정·인용·부분점수·결과 귀속까지 기대와 일치하거나 불일치가 이슈로 기록되는 것이다.
