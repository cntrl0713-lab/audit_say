# 주제 17 — 내부회계관리제도

[전체 계획으로](../question-content-review-plan.md) · 상태: 계획 작성 완료 / 검토 미착수

## 목표와 대상

4세트·8개 물음·24개 criterion을 전수 검토한다. 문제 상황, 모든 발문·정답·채점기준·출처, 오탈자·어색한 표현 및 실제 채점·화면 동작을 포함한다. 2027년 대비이며 **2026년 시행 기준과 동일하다는 가정으로 시작하고 공식 확인된 변경만 반영**한다.

현재 데이터의 기준 태그: KGA 1100. 이 태그는 검토 출발점이며 현행성·완전성을 보증하지 않는다.

## 이 주제의 중점 검토

- 2026년 시행 대상·규모·상장 여부·연결 또는 개별 범위·유예 조건을 공식 근거로 확인한다.
- 감사와 검토, 경영진 평가와 감사인 평가, 통합감사의 목적을 구분한다.
- 미비점 분류·보고 상대방·운영실태보고서 관련 요구를 확인한다.
- 문제 제목·상황·물음·모범답안의 용어, 조사·호응, 띄어쓰기, 부정어와 수식 범위를 함께 교정한다. 세트 간 유사 발문도 대조한다.
- 연계 주제: [05](05.md), [06](06.md), [07](07.md), [15](15.md), [16](16.md). 적용 조건·전문용어·배점 계약의 모순 또는 중복을 확인한다.

## A — 적용 기준과 출처 대조

- 목표: 모든 물음과 criterion을 적용되는 기준·문단에 연결한다.
- 범위: 아래 원출처, 정본의 이 주제 source_refs·requirements·criteria, 공통 기준대장.
- 절차: 2026년 시행 판본과 인용 앞뒤 문맥 확인 → 2027년 공식 변경 여부 표시 → 낡은 근거·누락 조건·예외 기록.
- 동반 확인: 기준 변경 시 영향을 받는 발문·정답·criterion·태그·공개 설명을 함께 표시한다.
- 완료: 8개 물음·24개 criterion의 근거 확인 결과 또는 미확정 사유가 모두 기록된다.

## B — 문제·물음과 문장 검토

- 목표: 수험생 관점에서 답할 내용이 분명하고 문장이 자연스럽다.
- 범위: 이 주제 제목·공통 사실·전 물음·모범답안·화면 표시.
- 절차: 정답을 가리고 요구사항 추출 → 필요한 사실·주체·조건·시점·개수·순서 확인 → 정답 대조 → 오탈자·조사·번역투·장문·용어 표기 교정.
- 검증: 수정 전후 문장을 나란히 두고 의미·정답 범위가 유지되는지 확인한다. 앞뒤 물음의 정답 노출 및 답안 의존성도 확인한다.
- 완료: 모든 문장에 이상 없음 또는 구체적인 수정 문안이 있고, 각 수정의 의미 변경 여부가 표시된다.

## C — 정답·채점기준·코드 검증

- 목표: 발문 요구와 모범답안·criterion·실제 득점이 일치한다.
- 범위: 정본의 이 주제 항목, 공통 계획 C1의 채점 경로, 해당 주제의 평가 답안.
- 절차: 양방향 요구사항 연결 → 기대판정 독립 작성 → 모의 응답으로 코드 검증 → 실제 설정 모델 평가 → 불일치 원인 분류.
- 기본 사례: 물음마다 완전 정답 / 의미가 같은 표현·경미한 오탈자 / 핵심 누락 / 반대 의미·조건 교체 / 빈 답안. 이 주제는 최소 40개 물음-답안 조합이며 criterion별 정답·실패 및 허용된 partial 경계를 추가한다.
- 빈 답안의 모델 무호출, 물음 간 인용 격리, 점수 합산·상한·보안 처리는 코드에서 검증한다.
- 실제 모델의 답안 인용과 criterion 판정, 코드 보정 후 판정·점수를 따로 기록한다. 불일치·불안정 사례는 동일 설정으로 최소 3회 재측정한다.

주제 특화 반례:

- 적용 대상의 경계값·연도·회사 조건만 바꾼 답안에서 판단이 구분되는지 검증한다.
- 미비점의 심각도나 보고 주체를 바꾼 답안과 용어 표기 변형 답안을 대조한다.
- 발문에서 요구한 개수와 해당 selection·constraints가 일치하는지 물음별로 확인한다. 데이터에 해당 조건이 없으면 무조건 새 규칙을 추가하지 않는다.
- 여러 criterion이 한 문장에 표현되는 정답과 동일 사실의 반복 답안을 구분한다.

검증 명령: 공통 계획의 관련 테스트 명령과 `npm run typecheck`, `npm run questions:v3:validate`. 새 답안 사례 실행 결과는 기존 단위 테스트 결과와 따로 기록한다. 완료 조건은 총점뿐 아니라 criterion 판정·인용·부분점수·결과 귀속까지 기대와 일치하거나 불일치가 이슈로 기록되는 것이다.

## D — 화면·연계 주제·결과 확인

- 목표: 전 물음이 올바르게 표시·전송·채점되고 검토 결과가 누락 없이 남는다.
- 범위: app/quiz/QuizClient.tsx, app/actions.ts 및 공통 계획의 연동 경로, 이 주제 전 세트.
- 절차: 각 세트를 데스크톱·모바일 폭에서 확인 → 답안 슬롯과 물음 ID·문구·줄바꿈·결과 대조 → 연계 주제의 중복·모순 확인 → 우선순위별 수정안 정리.
- 결과 경로: `docs/reports/question-review-2027/17.md` 및 `17.json`. 아직 생성하지 않은 실행 산출물이다.
- 수정이 필요하면 표현·도메인 계약·공통 코드를 구분한다. 공통 코드 수정은 이 주제에 가두지 않고 영향을 받는 모든 주제를 연결하고 재검증한다.
