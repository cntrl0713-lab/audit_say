# Luna·물음별 ±1점 허용 기준의 전수검증 재개

이 문서는 API 잔액 소진으로 중단한 현재 작업을 이어가기 위한 요구서다. [현재 진행 보고서](../reports/문항-전수검증-재개-진행-2026-09-12.md)를 함께 읽는다. 이전 handoff-001과 resume-001~004의 입력·원시 응답·판정은 당시 증거로 보존한다.

## 확정 범위

- 사용자 승인 범위는 신규 49세트와 기존 수정 70세트, 총 119세트·280물음·1,113 criterion의 필수 전수검증 후 운영 DB 반영이다. 앱 배포까지 자동 확대하지 않는다.
- 의미검수와 채점은 **gpt-5.6-luna**다. 사용자 허락 없이 모델을 상향하지 않는다.
- 사용자가 확정한 **물음당 ±1점 이내**의 채점 편차를 적용한다. 원 기대·실제 점수·엄격 일치 여부와 모든 반복 관측을 보존하고 별도 수락으로 표시한다. 문항·모범답안·출처의 결함과 전송·응답·근거·보안·증거 저장 오류는 점수 편차로 수락하지 않는다.
- 실제 모델 호출 흐름은 모든 단계 합계 최대 3개다. 큰 입력을 사용하는 의미검수는 단일 흐름에서 429가 재발했으므로 속도 제한으로 단정하지 않는다. 현재 확정 원인은 `credit_balance_exhausted / insufficient_quota`이며 사용자에게 충전 후 알림을 요청한 상태다. 잔액 복구를 알리기 전에는 추가 호출·반복 진단을 하지 않는다.

## 이어갈 순서와 담당 범위

### A: 미완료 의미검수

`quota-stop-01/README.md`와 `pending-manifest.json`의 현재 코드·은행·출처·계획 해시를 확인하고, 새 경로에서 기존 `validation-worker-v3.mjs`의 semantic 단계로 이어간다. 별도 신호가 없으면 큰 의미검수 입력은 한 흐름으로 진행한다. 비통과는 별도 목록으로 모으고 실행 오류는 다음 CLI를 멈춘다. API 실행 중 공통 코드·은행·원 계획을 수정하지 않는다.

### B: 통과한 의미검수의 실제 생성 채점과 작성자 QA

`D/b/r4-grading-wave-01/README.md`의 명령을 사용한다. 현재 선택은 원 의미검수 pass 12세트이며 생성 345 assertion·작성자 QA 329개를 준비했다. 두 단계 dry-run만 완료했고 실제 호출은 0이다. 원 manifest/run/세트 summary/request/receipt를 `semantic_provenance`로 검증하므로 완료된 의미검수를 다시 호출하지 않는다.

생성 채점 다음 작성자 QA를 단일 흐름으로 수행한다. QA 출력은 `cpa_uploader/drafts/delegated-authoring-2026-09-11/validation-resumes/resume-2026-09-12-v4/grading-wave-01/author-qa-b`의 새 경로를 쓴다. 허용 편차를 없애려 추가 진단을 반복하지 않는다. 내장 반복이 실행되면 전체 관측을 보존한다. 이후 새 의미검수 pass를 추가할 때도 완료 집합을 제외한 새 wave와 출력으로 연결한다.

### C: 학습 단위 실측과 출처 후속 대조

`D/b/learning-unit-smoke-v6/manifest.json`과 `D/b/run-learning-unit-smoke-v6.ts`를 사용한다. 249개 빈 답안·정적 검사는 완료했고 비빈 모범답안 실제 실행은 0이다. 원 smoke 입력 816개를 확인하고 `resume-2026-09-12-v4/learning-smoke-a`, `learning-smoke-b`, `learning-smoke-c`의 미사용 출력에서 worker를 순차 실행한다. 모든 단계 합계 최대 3개 호출 흐름을 지킨다.

출처 관련 4개 비통과는 점수 허용과 별도로 처리한다. 다음 계획은 **비활성 후속안**이며 기존 receipt를 pass로 바꾸지 않는다.

## 총괄이 처리할 수락·수정·DB 경계

정식 편차 수락 구현안은 `D/b/grading-tolerance-study-v1/implementation-v2/proposed.patch`다. 기존 4개 파일과 신규 adapter 1개를 바꾸며, 현재는 생산 코드 미적용이다. 원 v1/v2 스냅샷·88개 fixture·복제 타입/lint·적용 사전검사는 보존돼 있다. 기존 strict API, 원 receipt·matched·점수, 사람이 실제로 확인하는 절차를 유지한다.

패치 적용과 공통 지침 갱신은 API가 모두 중지된 경계에서 진행한다. 이전 바이트를 보존하고 새 실행·수락 도구 신원을 만든 뒤 관련 기존 strict 회귀와 새 adapter·CLI·장부·컴파일 검사를 수행한다. 코드가 바뀐 뒤 옛 worker 잠금의 해시만 고치거나 오류를 무시하여 계속하지 않는다. 실제 요청·모델·스키마·내용·출처·계획·채점기까지 동일한 기존 증거의 재사용은 명시적인 영향·계보 검사로 판단한다.

생성 사례의 target 기대표는 전체 물음 기대점수가 아니다. 별도 수락 근거는 답안 전체·모든 criterion과 직접 근거를 확인하여 정규화한다. 기대 범위가 필요한 경우 각 물음의 모든 관측에서 최악 편차가 1점 이하여야 한다. 실제 점수에 맞춰 범위를 좁히거나 테스트 fixture를 실제 출처 검토로 사용하지 않는다. 현 adapter가 지원하지 않는 별도 진단·복구 trace는 지원 계약을 구현하거나 미완료로 남긴다.

재사용할 정책의 지침 초안은 `D/grading-tolerance-policy-proposal-v1/README.md`에 있다. AGENTS.md·스킬에는 모델·허용폭을 사용자가 지정한 배치에 적용하는 절차를 반영하며, Luna/1점을 보편 기본값으로 고정하지 않는다. 현재 동결된 AGENTS.md·스킬은 아직 추가 변경하지 않았다.

전수 의미검수·실제 생성 채점·작성자 QA 6,040개·학습 단위 249개 및 불일치 후속이 준비되면 `D/c/r4-execution-v1/content-review-catalog-v1/review.html`을 현재 내용과 다시 대조해 사람 확인용 자료로 사용한다. 자료 생성이나 이전 DB 작업 승인을 사람이 모든 정답을 읽은 증거로 기록하지 않는다. 필요한 실제 내용 확인을 갖춘 후 기존 70세트는 재검수 승급, 신규 49세트는 신규 승급 계약을 적용한다. 정본·게시·운영 DB 반영 조건을 충족하기 전에는 상태만 먼저 올리지 않는다.
