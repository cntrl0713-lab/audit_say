# 주제 01–03 검토에 따른 수정 결정

작성: 2026-09-08. 근거: [01 보고서](../reports/question-review-2027/01.md), [02 보고서](../reports/question-review-2027/02.md), [03 보고서](../reports/question-review-2027/03.md) 및 현재 코드·정본 대조.

이 문서는 수정 방향을 결정한 문서다. 제품 코드와 문제은행에 아직 적용하지 않았다. 기존 보고서의 실측은 당시 계약의 기록으로 보존한다. 이번 사용자 정책과 충돌하는 기존 수정 제안은 이 문서를 따른다.

## 1. 확정 정책과 수정 범위

| 항목 | 결정 | 결정 근거 |
| --- | --- | --- |
| 열거 답안 | **대상 항목을 모두 작성하는 문제로 통일**. 일부 선택·앞 N개 제한·최고 N개 선택을 사용하지 않음 | 사용자 확정 |
| 배점 | **정수 단위**. 현재 각 criterion 1점 구조를 유지하고 충족한 criterion을 합산. 한 항목 누락으로 물음 전체를 0점 처리하지 않음 | 사용자 확정 + 현재 503개 criterion 전부 1점 확인 |
| 결론 표현 | 요구 조치에서 결론이 분명하면 인정. 명시적으로 반대 결론을 썼거나 결론이 불분명하면 인정하지 않음 | 앞선 사용자 확정 |
| 경험치 | **새 제출마다 얻은 점수 전액 가산**. 최고점 차액 방식이나 최초 풀이만 가산하는 방식은 채택하지 않음 | 사용자 확정 |
| 중복 요청 | 같은 제출의 통신 재시도·중복 클릭에는 한 번만 가산. 사용자가 새로 제출한 답안은 내용이 같아도 새 제출로 취급 | 확정 경험치 정책을 구현하기 위한 결정 |
| 적용 기준 | 2026년 시행 기준을 유지하고 2027년 동일 적용을 가정. 개정 220 시행일은 별도 메모 유지 | 기존 범위·검토 결과 유지 |
| 내용 수정 범위 | 01–03의 13세트·26물음. 열거 정책·공통 코드 변경은 전체 은행에 적용 | 사용자 정책에 따른 공통 영향 |

‘모두 쓰기’는 발문이 정한 범위의 모든 사항을 뜻한다. 기준서 전체의 모든 사항으로 무조건 범위를 넓히지 않는다. 명시된 네 가지 사항, 두 가지 수행능력 등의 범위는 보존한다. 문장 수·줄바꿈 수·criterion 수가 곧 항목 수라는 가정도 하지 않는다.

## 2. 열거형 수정은 항목 자르기 구현 대신 정책 단순화로 해결

### 데이터·코드 계약

- 전 물음의 채점은 `selection={type:'all',n:null}`로 통일한다.
- 답안을 자르지 않도록 `max_entries=null`, `overflow_policy='none'`으로 통일한다. 필요한 내용 개수는 발문에 남긴다.
- 나열 순서 자체에는 점수를 부여하지 않는다. `ordered=false`로 정리하되, 감사절차의 선후관계·보고 시점 등 **의미상의 순서**는 발문·criterion에 남겨 채점한다.
- v3의 `selection`·`constraints` 필드는 이번에는 유지한다. 생성 스키마와 검증기는 위 조합만 허용하고, 점수 코드는 모든 criterion을 합산한다. 필드 제거를 위한 별도 v4 마이그레이션은 만들지 않는다.
- 자유 서술 답안 전체를 모델과 인용 검증에 전달한다. 번호·줄바꿈 파서나 항목별 입력 배열은 만들 필요가 없다.
- 개수를 넘겨 썼다는 이유로 감점하지 않는다. 같은 사실을 반복해도 동일 criterion은 한 번만 득점한다. 정답과 함께 그 정답을 부정하는 내용을 쓴 경우에는 해당 명제의 모순을 평가한다. 무관한 문장 하나가 다른 정상 명제까지 0점으로 만들지 않게 한다.

### 실제 영향

현재 은행은 96세트·192물음·503criterion, 열거형 82개다. `max_entries`가 있는 물음은 83개, `ignore_after_limit`는 63개, `ordered=true`는 7개다. 서술형·판단형으로 분류돼 있지만 개수 제한이 있는 물음 5개도 포함해 정리한다. 분류명이 아니라 실제 요구를 확인한다.

`best_n`은 `pilot-11-003/sub1` 한 곳이다. ‘절차 중 다섯 가지’를 ‘**수행해야 할 절차를 해당되는 조건과 함께 모두 제시하시오**’로 바꾸고 현재 7개의 독립 채점요소를 모두 평가한다. 하위 절차를 분리한 7criterion을 기준서의 상위 항목 일곱 개라고 표현하지 않는다. 해당 재무보고체계의 조건, 필요시 추가 절차, 고의적 미공개의 조건을 유지한다. 주제11 전체의 내용 적합성을 승인하는 작업은 아니다.

`max_entries`가 있는 비열거형: `pilot-07-003/sub1`, `pilot-08-001/sub1`, `pilot-10-001/subq1`, `pilot-11-001/sub2`, `pilot-17-001/subq1`. 이 물음들도 답안 전체를 평가하되 기존 정의·판단 등의 요구를 삭제하지 않는다. 실제로 열거만 요구하는 오분류는 함께 바로잡는다.

| 사례 | 기존 계약 기대 | 이번 정책 기대 |
| --- | ---: | ---: |

## 3. 공통 채점 수정

### G1 — 동일 인용의 독립 명제 인정

`lib/questionV3.ts`의 `positiveByQuote` 승자 선택·나머지 감점 처리를 제거한다. 프롬프트의 ‘동일 quote 금지’도 바꾼다. **같은 문장이 서로 다른 명제를 충족하면 같은 인용을 허용한다.**

인용의 원문 실존·물음 간 격리는 계속 코드에서 확인한다. 같은 requirement ID라고 중복 명제로 처리하지 않는다. 하나의 requirement에 정의·시점·대상 등 여러 독립 criterion이 연결되어 있다. 동일 사실의 중복 배점은 정본의 명제 설계·검수에서 방지하고, 같은 criterion에 여러 판정이 반환되면 지금처럼 응답 오류로 거절한다.

새 기대값: 01의 정의+시점 2점, 02의 양/질 2점, 03의 책임 인정/이해 2점. 동일 사실 반복은 원래 한 criterion 점수만 받는다.

### G2 — 정상 명칭 나열의 보안 오탐 제거

프롬프트의 ‘단어 나열은 not_met’, ‘문장 없이 전문용어만 나열하면 salad’ 규칙을 수정한다. 발문이 명칭을 요구하면 명칭만으로 해당 criterion을 충족할 수 있다. 정의를 묻는 부분은 정의를 쓰지 않으면 득점하지 않는다.

`salad_detected`는 그 자체로 물음 전체를 0점으로 만드는 조건에서 제외한다. 무관하거나 의미를 구성하지 못한 단어 조합은 **criterion별 not_met**으로 판단한다. 채점 조작 지시를 의미하는 `injection_detected`와 혼동하지 않으며, 지시 삽입에 대한 코드의 감점 처리는 유지한다. 기존 응답 필드는 당장 없애지 않아 파서와 로그 형상 변경을 줄인다.

핵심 회귀: 02-001/sub2에서 감사기준·회계기준·윤리기준만 제시하면 정의는 0점, 세 명칭은 **3점**. 모델이 세 명칭을 met으로 판정하고 salad도 true로 반환하더라도 명칭 점수를 없애지 않는다. 무관한 키워드·순서 뒤섞인 비문·명시적 채점 조작은 별도 반례로 검증한다.

### G3 — 판단·근거·부분점수 계약

- 01-004/sub1은 조치가 분명히 함축하는 판단을 인정하도록 `claim`과 `critical_facts`를 정합화한다. 모호한 조치나 반대 결론까지 넓혀 인정하지 않는다.
- 발문에서 근거까지 요구하는 물음과 결론만 요구하는 물음을 구별한다. 물음마다 숨은 근거 요건을 없앤다.
- 현재 주제01–03의 1점 criterion에는 partial을 추가하지 않는다. 판단+근거를 한 criterion으로 유지하는 경우 둘 다 충족해야 1점이라는 계약을 명시한다. 서로 다른 criterion 일부만 충족한 점수는 정상적으로 합산한다.

## 6. 화면·제출·경험치 처리

### 화면과 채점 경계

1. 물음당 입력 한도를 **5,000자**로 통일한다. 공통 상수를 UI·action payload·grader에서 사용하고 화면에 한도를 표시한다.
2. 채점 결과를 받은 뒤 프로필 갱신이 실패해도 결과 화면을 유지한다. 갱신 실패는 별도 안내·재시도로 처리한다.
3. 결과에 물음별 보안 감점 사유와 인용 검증에 따른 감점 사유를 전달한다. 화면에는 코드가 정한 안전한 사유를 표시하고 내부 프롬프트·source_quote는 노출하지 않는다. 모델의 자유 형식 reason을 무조건 사용자에게 내보내지 않는다.
4. ‘criterion’은 ‘채점기준’으로, 기본 placeholder는 ‘물음에서 요구한 내용을 작성하세요.’로 교정한다. 공통 안내에는 모든 요구사항을 작성하고, 표현·문장 분리보다 내용 충족을 평가한다는 점을 적는다.
5. 빈 물음은 해당 물음0점으로 평가할 수 있게 하고, 전부 빈 답안은 모델 무호출·0점 처리한다. 미작성 물음이 있다는 이유로 다른 답안 제출까지 HTML `required`로 막지 않는다. 전부 빈 답안은 모델 키·호출 한도를 요구하지 않는 경로로 일치시킨다.
6. 설치된 Next.js 가이드를 읽은 뒤 action/클라이언트 코드를 수정한다. 단일 호출45초·3회 재시도와 라우트60초의 조합은 전체 요청 예산 안에 들어오도록 조정한다. 새 모델을 고정하여 해결하지 않는다.

### 새 제출과 같은 제출의 재시도

- 사용자의 새 제출에는 새로운 `submission_id`를 부여한다. 채점 중 중복 클릭·네트워크 재전송·상태 조회에는 같은 ID를 재사용한다.
- 서버는 사용자 ID+submission ID에 유일성을 보장하고 답안·세트·채점계약 버전의 fingerprint를 결합한다. 같은 ID로 다른 내용을 보내면 거절한다. **답안 내용이 같다는 이유만으로 새 제출을 중복 처리하지 않는다.**
- 인증·세트 존재·소속 물음 ID·입력 한도 검증을 먼저 수행한다. 새 유효 제출의 모델 호출 직전에 rate limit을 소비하고, 완료된 동일 제출을 다시 읽을 때에는 재채점·한도 소비·경험치 가산을 하지 않는다.
- 제출 상태와 채점 결과를 저장하고, 경험치 가산은 제출 단위의 유일한 적립 기록과 사용자 경험치 증가를 **DB 트랜잭션/RPC**으로 처리한다. 현재 `exp` 읽기→덮어쓰기는 동시 제출에서 갱신을 잃을 수 있으므로 원자적 증가로 교체한다.
- 채점 결과 저장과 경험치 적립 상태를 구별한다. 채점 결과가 확보됐으나 경험치 반영에 실패하면 결과를 보여주고 적립을 같은 제출 ID로 재시도한다. 성공으로 위장하거나 사용자가 새 답안을 제출하도록 유도하지 않는다. 서버 장애·결과 저장 실패 시 모델 호출까지 항상 딱 한 번이라는 보장은 별도 문제이며, 경험치 중복 방지와 구분한다.
- 기존 사용자 누적 경험치는 유지한다. 새 적립 기록을 과거 제출에 소급 생성하지 않는다. 0점은 경험치를 추가하지 않는다. 게스트의 비영구 진도 정책은 기존 동작을 유지한다.

현재 `app/actions.ts`는 `incrementProgress`의 false 반환을 확인하지 않고 성공을 돌려준다. 03 보고서의 ‘진도 저장 실패가 예외를 발생시킨다’는 서술과 달라 **현재 코드 확인 결과를 채택**한다. 이 차이는 보고서에서 가져온 별도 새 요구로 취급하지 않는다.

## 8. 검증 기준

- 각 변경된 물음: 완전 정답, 동의 표현, 부분 명제 누락, 반대 의미, 빈 답안 및 저장 모범답안. 01–03 전체 기본130개 물음-답안 조합을 새 계약으로 재측정한다.
- 기존01/02/03 평가 실행기는 서로 다른 캐시 방식을 쓰므로 새 데이터·코드·프롬프트·모델·정책 해시를 fingerprint에 넣는다. 과거 case ID가 같다는 이유로 옛 응답을 새 검증으로 재사용하지 않는다. 새 기대값을 현재 코드 출력에서 복사하지 않는다.
- 동일 문장의 독립 명제 모두 득점 / 동일 사실 반복은 해당criterion 한 번 / 무관한 항목 뒤의 정답도 득점 / 명시적 반대 문장은 해당 명제0점.
- 02-001/sub2 명칭만 작성=3점. 01-004/sub1의 분명한 조치 답안=2점. 02-005/sub2는 정의만1, 판단만1, 정의+잘못된 판단1, 모두맞음2. 02-004/sub2는 발문에 새로 명시한 판단 근거까지 평가한다.
- 03-004/sub2는 법규 예외와 문단19 예외를 서로 바꿔 쓴 반례, 예외를 부정한 반례, 정답 문안을 확인한다.
- 11-003/sub1 모두 충족=7점, 한 명제 누락=6점. 조건부 절차를 무조건 실시한다고 쓰는 답안은 별도 확인한다.
- 새 열거 정책은 전체82개 열거형의 발문·요구항목·criterion 대응을 대조한다. 나머지 주제의 공식 기준 전수 검토 완료를 뜻하지 않는다. 비열거형의 제한 필드83개 집계에 포함된5물음과 전체7개 ordered 항목도 확인한다.
- 실제 모델 불일치·불안정 사례는 같은 설정에서 총3회 이상 재측정한다. 총점뿐 아니라 각 criterion·인용·코드 보정 전후를 비교한다. 반복 통과를 확률적 모델의 영구 무오류 보장으로 표현하지 않는다.

- 2027년 시험 판본 지정은 별도 확인 항목으로 유지한다. [개정220 시행일 메모](../reports/question-review-2027/kga220-effective-date-note.md)를 보존한다. 코드 회귀검증 통과만으로 2027년 사용 적합을 자동 확정하지 않는다.

## 9. 이번 결정 작업의 검증 범위

세 보고서와 현재 정본·채점 경로·생성 스키마·공개 변환·진도 가산 코드를 대조했다. 정본을 파일에 쓰지 않고 메모리상으로만 변환하여 전체 501→504점, 주제01–03 합계 68→69점을 검산했다. 새 문서에 전체 ID로 기재한 6개 대상과 연결한 보고서들을 포함한 로컬 링크 77개가 존재함을 확인했다. 이번에는 실행 코드·문제은행을 변경하지 않았고, 모델 호출·제품 테스트는 새로 수행하지 않았다.
