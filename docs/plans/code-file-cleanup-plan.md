## 1. 목표와 정리 방향

현재 v3 서비스의 동작을 유지하면서 사용하지 않는 선언과 CSS, 현행 구현과 맞지 않는 문서를 정리한다. 파일 수를 줄이는 것보다 삭제 근거를 확인하고 유지보수 과정의 혼동을 줄이는 데 우선순위를 둔다.

조사 결과 v2 런타임·테스트의 대규모 정리는 이미 완료되어 있다. 따라서 이번 작업은 **소규모 미사용 코드 제거 → 미사용 스타일 제거 → 문서 현행화 → 조건부 작업 자료 관리** 순서가 적절하다. 추가로 제거할 수 있다고 확정된 대형 런타임 디렉터리나 패키지는 찾지 못했다.

Git 추적 파일은 170개이며, 이 중 `.ts`·`.tsx`·`.mjs` 파일은 43개다. 미추적 파일은 이 수에 포함하지 않았다. 파일 수와 용량 감소를 성과 목표로 미리 약속하지 않는다.

- v3 세트·세부 문항·criterion의 ID, 배점, 상태, 출처, 검수 이력을 유지한다.

이번 계획은 기능 삭제, 채점 정책 변경, DB 스키마 변경, 패키지 업그레이드, 폴더 전체 재설계를 포함하지 않는다.

## 4. 원자적 요구사항

- R1. 각 후보에 삭제·유지·보류·이력 보관 중 하나의 처분을 기록한다.
- R2. 삭제 전 import, 동적 import, 문자열 경로, npm 명령, 문서, 테스트 참조를 재확인한다.
- R3. Next.js 규약·스크립트 직접 실행·파일 시스템 로딩을 사용처로 인정한다.
- R4. 미추적 파일을 제거하려면 먼저 용도와 복원 가능한 보관 위치를 확정한다.
- R5. 미사용 선언 제거와 공통화·리팩터링을 같은 변경으로 묶지 않는다.
- R6. 데이터 정본과 생성 배포물을 서로 대체 가능한 중복 파일로 취급하지 않는다.
- R7. 원자료 경로를 바꾸면 JSON 출처·위키 링크·생성 스크립트까지 추적해야 한다. 첫 정리에서는 경로를 유지한다.
- R8. 변경 단위마다 정해진 검사를 완료하고 실패하면 다음 단위로 진행하지 않는다.
- R9. 기존 회귀 테스트의 보장 조건을 삭제하거나 약화하지 않는다.
- R10. 생성 파일·로컬 자료에 대한 ignore 규칙은 실제 경로로 좁혀 적용한다.
- R11. 신규 정적 분석 도구나 의존성은 기존 도구로 확인하지 못하는 구체적 필요가 있을 때만 도입한다.

| 이전 검색 실험의 CLI·설정 | 이전 검색 실험의 도구·설정 | 이미 제거됨. `references/`는 읽기용 기준서로 유지 |
| `data/회계감사_통합학습자료/`, `wiki/` | 출처 실존 검증·문제 생성·탐색에서 파일 시스템으로 참조. 위키에 수동 관리 문서도 포함 |
| 현재 5개 `.test.ts` 파일, `.githooks/pre-commit` | 채점·보안·배포·v2 재유입 회귀 및 커밋 검증을 담당 |
| `package-lock.json`, `next.config.ts`의 tracing 설정 | 의존성 재현성과 암호화 배포 파일 포함·평문 제외에 필요 |

직접 의존성은 앱·CLI·설정에서 사용 흔적이 확인되어 일괄 삭제를 제안하지 않는다. `react-dom`·타입 패키지·Tailwind/PostCSS처럼 프레임워크와 빌드가 사용하는 패키지는 일반 소스 import 검색만으로 판단할 수 없다. `server-only`도 실제 참조가 있다.

## 6. 가정, 미확정 사항, 도메인 위험

첫 코드·스타일·문서 정리에는 필수 질문이 없다. 현재 기능을 보존하고 미추적 자료를 그대로 둔다는 가정으로 진행할 수 있다. 다음 항목은 해당 선택 작업에 들어갈 때만 결론이 필요하다.

- RAG retriever는 중단한 실험으로 확정됐으며 새 OpenAI 전환 계획에서 삭제한다.
- `.hermes`의 draft가 모두 정본과 검수 장부에 반영되었는가? 동일 ID만으로 반영 완료를 추정하지 않는다.
- 디자인 참고 저장소와 여러 에이전트 도구를 계속 사용하는가? 결정 전에는 도구 진입점을 보존한다.
- 평문 authoring을 앞으로 Git에서 제외할 것인가? 현재 테스트와 생성 과정이 원본을 요구하므로 안전한 원본 공급·백업 체계를 먼저 설계해야 한다.

특히 다음 위험을 경계한다.

1. **원자료 손실:** 출처 경로를 이동하거나 평문 파일을 제거하면 타입 검사는 통과해도 출처 검증·문제 제작이 실패할 수 있다.
2. **채점 회귀:** 중복처럼 보이는 인용 검증·배점 상한·`best_n` 계산은 보장 조건이다. 정리 명목으로 합치지 않는다.
3. **권한 회귀:** 익명 사용자도 실제 인증 세션을 사용한다. 클라이언트 역할 표시와 서버 인증은 서로 대체할 수 없다.
4. **인증 Effect 회귀:** lint 경고만 보고 `resolveSessionUser`를 의존성 배열에 바로 넣으면 함수 재생성·재구독 문제가 생길 수 있다. 별도 동작 검증이 필요하다.
5. **서버 경계 회귀:** `supabaseAdmin.ts`의 조건부 `require('server-only')`를 import로 바꾸는 것은 단순 문법 청소가 아니다. Node 테스트 실행 환경과 번들 경계를 함께 검증해야 한다.
6. **생성물 오판:** 위키는 재생성 가능하더라도 수동 문서가 섞여 있다. public·암호화 JSON은 배포 시 필요하므로 캐시처럼 제거하면 안 된다.
7. **Git 정책 오판:** `.gitignore`를 추가해도 이미 추적 중인 authoring 파일이 자동으로 제외되지 않으며 과거 커밋도 바뀌지 않는다.
8. **기존 수정 손실:** 미추적 자료는 Git revert로 복구할 수 없다. 광범위한 `git clean`·`reset --hard`는 사용하지 않는다.

## 7. 영향 경계와 최소 구현 구조

| 경계 | 첫 정리의 변경 | 검증 포인트 |
| --- | --- | --- |
| UI | 랭킹 import, 미사용 CSS | 화면·로딩·포커스 상태 보존 |
| 서버 인증 모듈 | 호출되지 않는 helper·타입만 제거 | 실제 인증 및 관리자 검사 그대로 유지 |
| API / Server Actions | 구현 변경 없음 | 기존 권한·응답 계약 유지 |
| 도메인·직렬화 | 구현 변경 없음 | criterion·공개 데이터 계약 검증 유지 |
| 영속 데이터·DB | 변경 없음 | 정본·공개본·암호화본·장부 내용 유지 |
| 테스트 | 기존 검사 실행 | 테스트 삭제·완화 없음 |

신규 위치는 `docs/plans/`와 `docs/archive/`만 도입한다. `src/` 전환, `lib/` 재분류, `cpa_uploader/` 이름 변경은 하지 않는다. 변경하기 위해 공통 helper나 추상화 계층을 새로 만들 필요도 없다.

## 8. 순차 구현 단위

### Slice 1 — 작업 기준선과 복원 범위 확정

- **목표:** 기존 변경과 이번 정리를 구분할 수 있는 기준을 확보한다.
- **예상 파일 범위:** 작업 기록 문서만. 소스 변경 없음.
- **독립 이유:** 삭제에 앞서 데이터·검사 결과의 비교 기준이 필요하다.
- **필수 연동:** 시작 커밋·`git status`·대상 경로·중요 데이터 해시·lint 진단을 함께 기록한다. 미추적 파일은 첫 정리 제외 목록에 둔다.
- **검증:** 타입 검사, 기존 테스트, 문제은행 검증, 위키 검사, lint를 한 번씩 실행한다.
- **완료 조건:** 기존 실패와 신규 실패를 구분할 수 있고, 보존 대상 및 실제 변경 파일 목록이 정해져 있다.

### Slice 2 — 호출되지 않는 선언 제거

- **목표:** 컴파일러와 참조 검색으로 확인한 작은 선언만 제거한다.
- **예상 파일 범위:** `app/ranking/page.tsx`, `lib/supabaseServer.ts`, 설명 연동을 위한 `proxy.ts`, `supabase-rls.md`.
- **독립 이유:** UI·인증 구조를 바꾸지 않고 삭제 효과를 검증할 수 있다.
- **필수 연동:** `assertSelf` 제거 시 두 설명 참조도 갱신한다. `assertAuthenticated`·`assertAdmin` 호출부는 유지한다.
- **검증:** 일반 타입 검사, 추가 미사용 검사, `npm test`, 변경 파일 lint를 실행한다. 심볼 검색에서 현행 코드·설명의 참조가 사라졌는지 확인한다. 계획·아카이브에 남은 이름은 허용한다.
- **완료 조건:** TS6133 1개 해소, 기존 테스트 26개 통과, 새 lint 진단 0개, 인증 로직의 동작 변경 없음.
- **예상 규모:** 집중 작업 30~60분. 실제 변경 전 재조사 결과에 따라 조정한다.

### Slice 3 — 미사용 스타일 제거

- **목표:** 렌더링에서 사용하지 않는 CSS만 제거한다.
- **예상 파일 범위:** `app/globals.css` 한 파일.
- **독립 이유:** 화면 변화가 생기면 스타일 변경만 되돌릴 수 있다.
- **필수 연동:** animation 변수와 keyframes, hover 기본·상태 규칙은 함께 처리한다. accent 제거를 선택하면 theme 매핑과 설명도 함께 처리한다.
- **검증:** class 문자열·템플릿·inline style 참조를 재검색하고 빌드한다. 홈·퀴즈·커리큘럼·프로필·랭킹·관리자의 데스크톱/모바일 화면 및 버튼 hover·키보드 focus를 전후 비교한다.
- **완료 조건:** 제거한 스타일의 실제 사용처 없음, 빌드 통과, 화면·상태 비교 차이 없음. 미확인 토큰은 유지한다.
- **예상 규모:** 검증 포함 45~90분.

### Slice 4 — 현재 문서와 과거 이력 분리

- **목표:** 신규 개발자가 v2 설명을 현재 구현으로 오해하지 않게 한다.
- **예상 파일 범위:** 두 README, `tests/`의 Markdown 두 개, `grading-policy-rulings.md`, `docs/archive/`의 이동 대상, 실제 발견된 인바운드 링크.
- **독립 이유:** 런타임 변경 없이 문서의 정확성을 개선한다.
- **필수 연동:** 문서 이동·상대 링크·구현 경로·아카이브 표시를 함께 갱신한다. 현행 v3 진입점인 `questionV3.ts`, `questionV3Grading.ts`, `questionV3Store.ts`로 안내한다.
- **검증:** 현재 파일·스크립트와 문서 설명을 대조한다. 파일 이동 후 `npm test`와 위키 lint를 실행한다. 과거 정책·실측 기록이 보존되었는지 diff로 확인한다.
- **완료 조건:** `tests/`에 실행 테스트와 무관한 v2 계획·결과 문서가 남지 않고, README가 현행 기능·추적 정책·배포 구조를 정확히 설명한다.
- **예상 규모:** 60~120분.

### Slice 5 — 선택한 작업 자료·생성물의 관리 규칙 적용

- **목표:** 용도가 확정된 로컬 자료가 앞으로 불필요하게 추적·검사되지 않게 한다.
- **예상 파일 범위:** `.gitignore` 또는 개인용 `.git/info/exclude`, 처리하기로 정한 개별 경로만. 필요할 때만 ESLint ignore를 제한적으로 수정한다.
- **독립 이유:** 자료 소유·복원 문제와 런타임 정리를 분리한다. 미확정 항목이 있으면 이 단위의 해당 항목만 보류한다.
- **필수 연동:** 외부 보관을 선택하면 파일 목록·해시·복원 위치를 남긴다. `.hermes`는 정본 반영 여부를 확인한다. 생성 checkpoint·debug 파일의 ignore는 실제 생성 경로를 확인해 특정한다.
- **검증:** `git status`, `git check-ignore -v <확정한 경로>`, `git ls-files -- <보존 대상>`으로 의도한 범위를 확인한다. 검사 범위를 변경했다면 typecheck·lint·테스트를 재실행한다.
- **완료 조건:** 선택한 자료의 처분과 복원 방법이 기록되고, 미추적 작업·정본·도구 진입점이 우발적으로 사라지지 않는다. 근거가 없는 대상은 명시적으로 유지한다.
- **예상 규모:** 정책 적용 자체 30~60분. draft 내용 대조·미확정 결정 시간은 별도이며 일정에 포함하지 않는다.

Slice 1~4가 필수 첫 정리다. 순수 구현·검증은 반나절~하루를 작업 가정으로 삼되, 브라우저 계정 준비·빌드 환경 문제·보류 자료 조사는 별도로 본다. 큰 lint 개선이나 도메인 리팩터링이 필요해지면 작업 단위를 확장하지 말고 후속 계획으로 넘긴다.

## 9. 검증 절차와 전체 인수 체크리스트

### 9.1 실행 검사

아래 명령은 저장소 루트에서 실행한다. 각 결과를 별도로 확인하고 실패 시 원인을 분류한다.

```powershell
npm run typecheck -- --incremental false
node node_modules/typescript/bin/tsc --noEmit --incremental false --noUnusedLocals --noUnusedParameters
npm test
npm run questions:v3:validate
node cpa_uploader/wiki/scripts/lint-wiki.mjs
npm run lint
npm run build
git diff --check
git diff --stat
git status --short
```

문서만 바꾼 단위마다 빌드를 반복하지는 않는다. 코드·CSS 변경 후 필요한 검증을 완료하고, 마지막에는 이후 변경 내용에 맞는 검사만 보충한다. `npm run build`는 별도의 lint 검사를 대체하지 않는다.

`questions:v3:compile`, `generate_cpa_v3.ts`, `apply_cpa_v3_review.ts`, 승급 명령, 이전 검색 명령은 데이터를 쓰거나 외부 작업을 수행한다. 정리 검증 명목으로 실행하지 않는다. 위키도 lint만 실행하며, 재생성이 필요해진 경우 생성 diff를 별도로 검토한다.

### 9.2 기능 확인

| 시나리오 | 보존해야 할 관찰 결과 |
| --- | --- |
| 기존 로그인·회원가입·게스트 | 기존 성공·실패 UI와 세션 처리 유지 |
| 퀴즈·커리큘럼 열기 | 기존 공개 문제 수·배점·표시 유지 |
| 기존 채점 테스트 입력 | criterion 합산, 인용 검증, 주입 감지, `best_n` 결과 유지 |
| 일반 사용자·관리자 접근 | 기존 권한 범위 유지. 실제 권한 검사 호출 제거 없음 |
| 랭킹·프로필 | 로딩·오류 표시 및 역할·경험치 표시 유지 |
| 화면 크기·키보드 조작 | 반응형 배치·포커스 표시 유지 |

기존 26개 테스트가 로그인·실제 서버 액션 전체를 검증하는 것은 아니다. 화면·인증 smoke 확인은 사용 가능한 개발/테스트 계정에서 수행하고, 준비되지 않은 항목은 미검증으로 남긴다. 실제 채점으로 비용·경험치·DB 상태를 바꾸는 검사는 단순 정리의 기본 검사에 포함하지 않는다.

### 9.3 인수 조건

- [ ] 실행 전후 변경 파일이 합의된 정리 범위에 한정된다.
- [ ] 랭킹의 미사용 기본 import가 제거되고 추가 TypeScript 미사용 검사가 통과한다.
- [ ] `assertSelf`·`AuthenticatedSession` 제거 대상에 새 사용처가 없었으며 설명 참조도 정리됐다.
- [ ] 제거한 CSS의 소비자가 없고 화면 비교에서 의도하지 않은 차이가 없다.
- [ ] 기본 타입 검사와 기존 테스트 26개가 통과한다.
- [ ] 문제은행 검증 결과가 96세트·192개 물음·503개 criterion·총 501점으로 유지된다. 다른 정상 작업의 데이터 변경이 있으면 그 기준을 먼저 재확정한다.
- [ ] 정본·공개본·암호화본·승급 장부의 내용 및 해시가 이번 정리로 바뀌지 않는다.
- [ ] 위키 검사 오류·경고가 0개다.
- [ ] lint의 파일·규칙·원인별 신규 오류·경고가 0개다. 전체 통과 여부를 별도로 보고한다.
- [ ] 프로덕션 빌드가 통과하거나 환경 실패의 구체적 원인과 미검증 항목이 기록된다. 미실행을 통과로 보고하지 않는다.
- [ ] README의 기능·모델 설정·정본 추적 설명이 현행 코드와 일치한다.
- [ ] 과거 문서가 아카이브로 분리되고 정책·실측 이력이 보존된다.
- [ ] 미추적 자료와 에이전트 도구 설정은 유지되거나 선택한 보관·복원 절차가 완료됐다.
- [ ] Next.js 규약 파일, 기존 회귀 테스트, 잠금 파일, 서버·클라이언트 경계가 유지된다.
- [ ] `git diff --check`가 통과한다.

검증 실패 시 가장 최근의 정리 단위를 되돌린다. 구현할 때 각 단위를 별도 커밋으로 남기면 해당 커밋만 revert할 수 있다. 미커밋 상태에서는 자신이 변경한 부분만 복구하고, 기존 사용자 작업을 포함한 파일 전체를 무조건 restore하지 않는다. 외부로 보관한 미추적 자료는 기록한 위치·해시로 복원한다.

## 10. 후속 작업으로 미룰 항목

1. **기존 lint 오류·경고 해소:** SDK 응답의 `any`, Auth Effect 의존성, 테스트 인증 타입, `server-only` 로딩을 각각 별도 단위로 다룬다. 일괄 autofix나 전역 규칙 해제로 처리하지 않는다.
2. **평문 authoring 추적 정책 변경:** 현재 추적 사실과 문서의 불일치는 우선 문서로 바로잡는다. 원본 공급·백업·로컬 검증·CI·배포 절차가 마련되기 전 `git rm --cached`나 원본 삭제를 하지 않는다. Git 이력 재작성은 범위 밖이다.
3. **RAG 통합 또는 폐기:** 호출되지 않는 실험 모듈과 현재 CLI 파이프라인의 필요성을 따로 판단한다.
4. **여러 도구의 skill·workflow 통합:** 실행 도구별 탐색 경로와 Windows의 링크·동기화 방식이 확인된 뒤 결정한다.
5. **구조 리팩터링:** `questionV3.ts`의 파일 검증과 계산 로직 분리, 데이터 경로 공통화, 로딩 UI 통합, export 범위 축소는 미룬다.
6. **캐시·대용량 정리:** `.next`, `tsconfig.tsbuildinfo`, `node_modules`는 이미 생성물 또는 의존성이다. 디스크 부족·캐시 문제 같은 별도 목적이 있을 때 정리한다. `.env.local`과 문제 제작 draft는 캐시로 취급하지 않는다.
7. **DB·RLS·EXP 동시성·채점 정책 개선:** 기존 코드에서 개선 여지가 보여도 불필요한 파일 정리와 합치지 않는다.
8. **패키지 제거·업그레이드 및 분석 도구 도입:** 현재 확인된 삭제 대상 패키지가 없다. 후보를 만들기 위해 새 도구를 무조건 추가하지 않는다.
