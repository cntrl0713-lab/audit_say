# 프로젝트 테이블 cpa 접두어 전환

2026-09-08. 대상 Supabase 프로젝트는 로컬 앱 설정과 일치하는 `xvifzicrjmbfqaepcfpp`다.

## 이름과 범위

- `public.user_cpa` → `public.cpa_users`
- `public.firm_*` 26개 → `public.cpa_firm_*` (나머지 이름 유지)
- 기존 `cpa_questions_v2`, `cpa_review_notes`, `cpa_rate_limits`는 이름·데이터 유지. 현재 v3 문제 로더가 사용하지 않는 과거 문제 테이블도 삭제하지 않는다.
- 다른 앱의 `cta_*`, Supabase의 `auth`·`storage` 관리 객체는 제외한다.

전체 27개 대응은 [전환 마이그레이션](../supabase/migrations/20260908003002_cpa_table_prefix.sql)에 명시했다. 테이블 데이터를 복사하거나 삭제하지 않고 `ALTER TABLE RENAME`으로 변경한다. 외래키·정책·인덱스·트리거의 객체 연결과 물리 데이터는 유지한다. 기존 제약·시퀀스·정책의 이름은 테이블 이름 변경 범위에 포함하지 않는다.

## 기존 앱 호환

기존 테이블 이름에는 같은 데이터를 가리키는 `security_invoker=true` 뷰를 둔다. Supabase 기본 권한을 그대로 추가하지 않고 원래 테이블의 DML 권한만 복사하며 RLS는 원래 테이블의 정책으로 평가한다. 새 로컬 코드는 `cpa_*` 물리 테이블을 사용한다. 이전 배포본의 조회·회원가입·프로필 갱신은 호환 뷰를 사용할 수 있다.

`v_firm_*` 집계 뷰와 `replace_firm_annual_report` RPC 이름은 유지한다. RPC의 정적 SQL·동적 SQL 대상은 새 테이블로 바꾸되 기존 payload의 `firm_*` 키는 유지해 기존 수집기와 캐시의 계약·해시를 바꾸지 않는다. `verifyAnnualReports.ts`는 payload 키와 실제 DB 테이블 이름을 구분한다.

기존 마이그레이션은 다시 쓰지 않는다. 새 DB는 기존 스키마·회원 테이블을 만든 뒤 전환 마이그레이션까지 순서대로 적용한다. 기존 F004 전용 설치 도구는 새 테이블이 있는 DB에 과거 DDL을 재적용하지 않는다. 호환 뷰 제거는 이전 배포본·외부 수집기 사용이 끝난 뒤 별도 작업으로 진행한다.

PostgreSQL 동작 근거: [테이블 이름 변경](https://www.postgresql.org/docs/17/sql-altertable.html), [security_invoker와 갱신 가능한 뷰](https://www.postgresql.org/docs/current/sql-createview.html).

## 검증

- 격리 PostgreSQL: 27개 테이블의 OID·물리 파일 식별자·ACL·RLS·외래키·정책 유지, 기존/신규 이름의 회원 본인 조회·가입과 타인/권한 변경 차단.
- 기존 이름의 upsert, 신규 테이블을 쓰는 연간 RPC, 실패 시 원자적 롤백, 개인 명세의 anon/authenticated 비노출, 기존 집계 뷰, 마이그레이션 재실행·이름 충돌 롤백 확인.
- 운영 적용 전후에는 테이블 행 수와 카탈로그 정보를 읽어 대조한다. 운영 데이터를 테스트용으로 삽입하거나 수정하지 않는다.

## 운영 적용 결과

- Supabase 마이그레이션 `20260908003002 / cpa_table_prefix` 적용 성공. 로컬 파일 버전도 운영 이력과 일치시켰다.
- 물리 테이블 27개 이름 변경 완료. 변경 대상 434,324행 보존, 조회한 public 테이블46개의 행 수 전후 일치. 기존 `cpa_*`·타 프로젝트 `cta_*`의 객체와 데이터도 유지됐다.
- 테이블 OID·relfilenode·RLS·ACL, 외래키/제약, 정책, 연간 RPC 권한의 전후 일치 확인. 이전 `user_cpa`·`firm_*` 물리 테이블은 남지 않고 호환 뷰만 존재한다.
- 실제 PostgREST 읽기: 새/이전 회원 이름 모두3행, 회계법인 마스터 모두269행, 기존 연간 집계 뷰721행 조회. anon에서는 새/이전 회원과 이사 개인 명세·보수 모두0행, 공개 마스터269행 확인. 사용자 답안·개인 정보 원문은 출력하지 않았다.
- 타입 검사 통과, 전체 테스트139개 통과(전환·롤백 테스트 포함), wiki lint 오류0·경고0. 초기 전체 검사에서 수집기 mock의 과거 테이블명이 발견돼 현재 호출명으로 수정 후 통과했다. 동시에 진행 중이던 화면 편집의 일시적 타입 오류도 최종 검사에서는 해소된 상태다.
- 운영에서는 읽기 검증만 수행했고 시험용 데이터를 쓰지 않았다. Edge Function 목록 조회는 도구 scope 부족으로 확인하지 못했다. 이전 이름의 호환 뷰를 유지해 외부 호출의 이름을 보존했다.
- 운영 DB 이름 변경은 반영됐으며, 로컬 코드의 별도 서비스 배포는 이 작업에서 수행하지 않았다. 기존 배포본은 호환 뷰로 계속 접근할 수 있다.
