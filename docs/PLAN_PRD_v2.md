## 1. 프로젝트 개요

### 1.1 한 줄 정의

**audit_say**는 하나의 홈페이지에서 두 가지 공간을 제공한다.

1. **회계감사 채점 시스템** — 회계사 1·2차 수험생을 위한 감사론 답안 채점 서비스 (기존 기능 계승)
2. **회계법인 리서치 플랫폼** — 회계법인 취업준비생·리서처를 위한 감사 데이터 탐색·보고서·챗봇 서비스 (신규)

### 1.2 프로젝트 배경

기존 audit_say는 수험생을 위한 채점 시스템으로 시작했다.  
v2에서는 같은 도메인(회계감사)에서 다른 니즈(취업·리서치)를 가진 사용자를 위한 공간을 추가한다.  
두 서비스는 도메인을 공유하지만, 데이터 레이어와 기능은 완전히 분리한다.

### 1.3 기술 스택 (기존 계승)

- **Frontend**: Next.js (TypeScript)
- **Backend/DB**: Supabase (PostgreSQL + Auth + RLS)
- **AI**: 외부 AI API(공급자 미정)
- **디자인 시스템**: DESIGN.md 기반 (Cursor-inspired 크림 캔버스 `#f7f7f4`, 잉크 `#26251e`, Primary Orange `#f54e00`)
- **배포**: Vercel

### 1.4 새 폴더 구조

기존 레포에 새 폴더를 추가해 v2를 시작한다.

```
audit_say/
├── app/                        # 기존 채점 시스템
├── app/(firm)/                 # 신규: 회계법인 플랫폼 라우트 그룹
│   ├── firms/                  # 회계법인 탐색
│   ├── companies/              # 회사 탐색
│   ├── reports/                # 자동 보고서
│   ├── chat/                   # 챗봇
│   └── reviews/                # 평점 시스템
├── scripts/firm_collector/     # 데이터 수집 배치
└── docs/
    └── PLAN_PRD_v2.md          # 본 문서
```

## 2. 서비스 구조 — 두 공간

### 2.1 전체 홈페이지 구조

```
audit_say.com
│
├── / (홈)
│   ├── → 채점 시스템 진입 CTA
│   └── → 회계법인 리서치 진입 CTA
│
├── /grade         채점 시스템 (기존)
│
└── /firms         회계법인 리서치 플랫폼 (신규)
```

### 2.2 공간 A — 회계감사 채점 시스템 (기존 계승)

수험생이 자신의 감사론 답안을 제출하면 AI 기반으로 채점하고 피드백을 제공한다.  
기존 audit_say의 핵심 기능을 유지하며, v2에서는 UI/구조적 개편만 반영한다.

### 2.3 공간 B — 회계법인 리서치 플랫폼 (신규)

DART 공개 데이터를 회계법인 중심으로 재구조화하여  
탐색 → 자동 보고서 → 챗봇 → 평점 시스템을 순차적으로 제공한다.

## 4. 공간 B — 데이터 수집 설계

### 4.1 데이터 원천

DART는 회계법인을 "기타법인"으로 분류하며, 각 회계법인이 사업보고서를 DART에 제출한다.  
감사대상회사 관련 데이터는 OpenDART 구조화 API로, 회계법인 자체 인력·재무 지표는 해당 법인의 사업보고서 API로 수집한다.

### 4.2 1차 수집 범위

1차는 상장회사와 구조화 API 경로로 수집 가능한 법인을 우선 대상으로 한다.

#### A. 감사대상회사 관련 (OpenDART 구조화 API)

- 감사인 및 감사의견 (`list` API)
- 감사용역체결현황
- 회계감사인과의 비감사용역 계약체결현황
- 재무 주요계정 (매출, 영업이익, 당기순이익)

#### B. 회계법인 자체 운영지표 (사업보고서 API)

회계법인도 DART에 사업보고서를 제출하므로, 사업보고서 주요 정보 API로 다음을 수집한다.

- **임원 현황** → 이사 수(등기임원 기준)
- **직원 현황** → 직원 수, 평균 급여, 급여 총액
- **재무 주요계정** → 매출액(영업수익), 영업이익, 당기순이익

다음 항목은 사업보고서 내 표에서 파싱하거나 직접 추출 필요 (1차 선택 수집):

- 사업부문별 매출 내역 (회계감사/세무/경영자문/기타 구분)
- 사업부문별 인원 구성

#### C. API로 즉시 산출 가능한 파생 지표

| 지표 | 계산 방식 | 원천 |
|---|---|---|
| 임직원 1인당 매출액 | 영업수익 / 직원 수 | 직원 현황 + 재무 |
| 임직원 1인당 급여 | 급여 총액 / 직원 수 | 직원 현황 |
| 이사 수 대비 직원 비율 | 직원 수 / 이사 수 | 임원 현황 + 직원 현황 |
| 감사부문 매출 비중 | 감사부문 매출 / 영업수익 | 사업부문별 매출 (파싱 필요) |
| 부문별 인원 비중 | 각 부문 인원 / 직원 수 | 사업부문별 인원 (파싱 필요) |

> **참고**: "회계사 수" 기준 지표는 직원 현황에서 직접 구분되지 않을 수 있다.  
> "직원 수 기준 1인당 매출" 을 우선 지표로, 등록회계사 수는 가능한 경우 별도 파싱으로 보완한다.

### 4.3 2차 수집 범위

- 일반 비상장회사 감사보고서 원문 파싱
- 금융회사 재무 3지표 보완
- KAM 주제 분류 및 태깅
- 사업부문별 인원·매출 정밀 파싱

### 4.4 재무제표 수집 기준

- 연결재무제표(CFS) 우선
- 연결 없으면 별도재무제표(OFS) 대체
- `fs_div`, `fallback_yn` 으로 기록

### 4.5 수집 주기

- 사업보고서 기준 연 1회 배치
- 시작: 2025 사업연도 (2026년 접수분)
- 이후 매년 증분 방식으로 누적

## 5. 핵심 기능 요구사항

### 5.1 회계법인 탐색

**목적**: 특정 회계법인의 감사 포트폴리오와 운영 현황을 한눈에 제공한다.

특정 회계법인을 선택하면 다음을 바로 확인할 수 있어야 한다.

- 감사한 회사 목록 (상장/비상장, 시장, 업종, 매출 규모 기준 필터링)
- 감사의견 분포 (적정/한정/부적정/의견거절)
- KAM 개수 및 원문
- 감사용역·비감사용역 계약 현황
- 인력 현황 (직원 수, 이사 수, 1인당 매출액, 1인당 급여)
- 부문별 매출 비중 (수집 가능 시)
- 연도별 변화 추이

**우선순위**: Must

### 5.2 자동 보고서 생성

**목적**: 특정 회계법인 기준 구조화 보고서를 자동 생성한다.

보고서 구성:
1. 회계법인 개요
2. 고객사 포트폴리오 요약
3. 재무 규모 분포
4. 감사의견 및 KAM 특징
5. 의견변형 회사 목록
6. 용역 현황 요약
7. 인력·운영지표
8. 연도별 변화 분석

**우선순위**: Should

### 5.3 구독형 챗봇

**목적**: 특정 회계법인에 대한 자연어 질의응답을 제공한다.

예시 질문:
- "삼정회계법인이 감사한 코스피 제조업 회사는?"
- "한영회계법인의 최근 3년 고객사 수 변화는?"
- "안진회계법인이 감사한 회사 중 의견변형이 나온 곳은?"
- "삼일회계법인의 직원 1인당 매출액은?"

요구사항:
- 구독 사용자만 접근 가능
- 특정 법인 컨텍스트 설정 후 질문
- 플랫폼 내부 데이터 범위 내 답변 (환각 최소화)
- 답변에 근거 데이터 출처 표시
- 외부 AI API 단일 엔진
- 질문 이력 저장

**우선순위**: Should

### 5.4 회계법인 평점 시스템 ⭐ 신규

**목적**: 특정 회계법인에 근무했거나 근무 중인 회계사·직원이 익명으로 평점과 후기를 남길 수 있게 한다.

사용 대상:
- 현직 회계법인 근무자
- 전직 회계법인 근무자
- 취업준비생에게는 읽기만 허용

평점 항목 (초안, 변경 가능):
- 워라밸 (1-5점)
- 성장 기회 (1-5점)
- 급여 만족도 (1-5점)
- 조직문화 (1-5점)
- 업무 강도 (1-5점)
- 전반적 만족도 (1-5점)
- 텍스트 후기 (선택)
- 재직 기간 (입사연도~퇴사연도 또는 현재)
- 직급 (수습/스탭/시니어/매니저/이상)

익명성 정책:
- 닉네임 + 직급 + 재직기간만 표시
- 이메일/실명은 비공개
- 법인 인증 방법은 별도 정책 필요 (이메일 도메인 인증 우선 고려)

**우선순위**: Could (채점·탐색 이후)

## 6. DB 엔터티 관계 설계

### 6.1 핵심 설계 원칙

- 회사와 회계법인의 관계는 `engagement`를 경유해 연결
- `engagement` = 회계법인 1개 + 회사 1개 + 사업연도 1개
- 원천 데이터(공시)와 서비스 데이터(사용자 활동) 분리
- 회계법인 자체 운영지표는 별도 테이블로 관리
- 평점 시스템은 서비스 레이어에서 firm_id만 참조

### 6.2 데이터 도메인 — 공시 기반 (8개 테이블)

#### registered_firm
등록회계법인 마스터

| 필드 | 설명 |

| firm_id | PK |
| firm_name | 법인명 |
| registration_no | 등록번호 (UK) |
| tier | 가군/나군 |
| alias | 별칭 배열 (명칭 변형 대응) |
| status | 활성/폐업 |
| dart_corp_code | DART 기타법인 코드 |

## 10. 페르소나 및 사용자 스토리

### 페르소나 A — 회계법인 취업준비생

"특정 회계법인에 지원하기 전, 그 법인이 어떤 회사를 감사하고 어떤 특징이 있는지 빠르게 파악하고 싶다."

핵심 사용자 스토리:
- 회계법인 이름으로 검색하면 고객사 목록과 의견 분포를 3초 안에 볼 수 있어야 한다.
- 다른 회계법인과 인원·매출 규모를 비교할 수 있어야 한다.
- 현직자 평점과 후기를 읽고 분위기를 파악할 수 있어야 한다.

### 페르소나 B — 수험생 (기존)

"감사론 답안을 채점받고 부족한 부분에 대한 피드백을 받고 싶다."

핵심 사용자 스토리:
- 답안을 입력하면 항목별 점수와 피드백을 받을 수 있어야 한다.

### 페르소나 C — 리서처·영업 담당자

"업종별·시장별로 어떤 회계법인이 강한지 비교 분석하고 싶다."

핵심 사용자 스토리:
- 특정 업종 기준으로 회계법인별 고객사 수를 비교할 수 있어야 한다.
- 리포트로 저장해 공유할 수 있어야 한다.

### 페르소나 D — 현직/전직 회계사

"근무했던 법인에 대한 솔직한 후기를 남기고 싶다. 또는 다른 법인 후기를 참고하고 싶다."

핵심 사용자 스토리:
- 근무 법인을 선택하고 항목별 점수와 텍스트 후기를 익명으로 작성할 수 있어야 한다.
- 다른 법인의 항목별 평균 점수와 최근 후기를 열람할 수 있어야 한다.

## 11. 비기능 요구사항

### 성능
- 회계법인 상세 페이지 첫 로드: 3초 이내
- 리포트 생성: 10초 이내
- 챗봇 첫 답변: 10초 이내

### 신뢰성
- 배치 실패 시 재실행 가능
- 동일 사업연도 재수집 시 중복 방지
- 출처(접수번호, API 종류) 추적 가능

### 보안
- 배치 쓰기 권한은 service_role 전용
- 구독·챗봇·평점은 인증 사용자만
- 평점 익명성 보장 (실명·이메일 외부 노출 없음)

### 확장성
- 증분 수집으로 매년 연도 추가 가능
- 채점 시스템과 리서치 플랫폼은 라우트·DB 분리로 독립적 확장 가능

5. **무료 사용자 공개 범위**: 리포트·챗봇을 유료로 가릴 때, 어느 수준까지 미리보기 허용할지
