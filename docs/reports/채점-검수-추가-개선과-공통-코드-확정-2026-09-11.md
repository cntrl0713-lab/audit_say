## 추가 발견과 수정

| 발견 | 수정과 검증 |
| --- | --- |
| 성공한 모델 응답의 `onTrace` 기록 실패를 모델 오류로 잡아 다시 호출했다. | 기록 콜백을 모델 재시도 밖으로 분리했다. 판정·보안 단계의 기록 실패가 즉시 중단되고 추가 호출·점수 확정으로 이어지지 않는 회귀 테스트를 추가했다. 수정 전에는 이 반례가 실패했다. |
| 기록용 객체가 실제 판정·답안·점수와 공유되어 콜백의 편집이 결과에 영향을 줄 수 있었다. | `onTrace`·`onJudgment`·`onChunk`·`onRun`에 독립 스냅샷을 전달한다. 기록용 편집이 만점·실패 판정·답안·receipt를 바꾸지 못하는지 검사했다. |
| SDK의 실제 `APIConnectionError`는 메시지가 `Connection error.`라서 일시적 연결 장애로 분류되지 않았다. | SDK 오류 타입으로 연결·시간초과를 판별한다. 사용자 중단은 재시도하지 않고, HTTP 오류는 상태코드를 우선해 인증·잘못된 요청의 메시지에 network/timeout이 있어도 재시도하지 않는다. 실제 SDK 오류 클래스의 주입 회귀 검사로 확인했다. |
| 주입 응답으로 수행한 의미검수가 `model_reasoned`로만 기록되어 실제 채점만 추가하면 신규 수락될 수 있었다. | 의미검수 `execution.transport`와 사례 채점 `grading.transport`를 각각 기록·검증한다. 신규 모델 의미검수 수락에는 `execution.transport=model`을 요구한다. 누락·주입 응답을 차단하고 과거 기록의 읽기 호환은 유지했다. 중간 의미검수 로그에도 transport를 기록한다. |
| CLI가 기존 최종 출력 파일을 덮어써 과거 양식·receipt를 잃을 수 있었다. | 기존 `--output`을 모델 호출 전에 거절한다. 같은 출력으로 재실행해도 기존 바이트가 보존되는 실제 CLI 회귀 검사를 추가했다. |

잘못된 모델 응답·보안 미확정·실행 장애를 학생의 0점으로 바꾸지 않는다. 정상 사례의 보안 오탐은 기대 점수가 0이어도 불일치로 유지한다. 공격의 물음별 차단과 다른 물음 점수 보존, 과거 세트 전체 보안 플래그 계약은 유지했다.
