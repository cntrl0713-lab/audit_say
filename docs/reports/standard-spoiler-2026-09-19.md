# 기준서형 물음의 수정 사항·정답 암시 전수 검토 (2026-09-19)

사례형 지정 검토(r01~r11)에 이어 사용자는 “기준서형 물음에서도 수정할 사항과 스포일러요소를 확인하고 수정해줘”라고 요청했다. 현재 정본의 기준서형 물음 372개를 발문·모범답안·criterion·출처와 하나씩 대조하고, 고칠 물음은 게시 문항 수정 경로(세트당 correction 하나)로 고쳤다. 기계 판독 근거와 재현 명령은 [검토 배치](../../cpa_uploader/analysis/reviews/standard-spoiler-2026-09-19/README.md)에 있다. 이번에 정한 기준은 [기준서형 발문의 정답 암시 금지](../물음별-학습-단위와-분류-계약.md#기준서형-발문의-정답-암시-금지)로 계약·제작·검토 스킬·AGENTS.md에 반영했다.

## 채점 입력의 정비

발문만 고치면 채점 모델이 함께 읽는 criterion 명제·critical_facts·모범답안이 옛 발문을 가리키게 된다. 다음을 함께 고쳤다.

- 옛 발문의 문맥에 기댄 인정 문구: draft-12-560-freq01 q1(“이 발문 문맥에서는 ‘수정할 수 있어야 한다’도 …”), pilot-13-010 sub1(“발문·지문의 경영진주장 수준 위험 문맥”), pilot-17-003 sub2(“제시된 전제하에”).
- 판단형에서 서술형으로 바꾼 물음의 판단 문장: pilot-01-004 sub1(“적절하지 않다.”), pilot-12-005 sub2, pilot-12-008 sub1.
- 내용이 빈 명제: pilot-19-001 sub2 crit2(“확신의 수준을 서술함” → 제한적 확신).
- 인용 문단 표기: 검토 기록의 KGA 500 A64 → A65(특정 항목의 추출), KGA 260 A4 → 문단 4, KGA 501 문단 4·7에 A12~A14 추가.

이 경험을 [배점과 물음별 타당성](../물음별-학습-단위와-분류-계약.md#배점과-물음별-타당성)에 규칙으로 남겼다. 명제·critical_facts는 채점 모델이 글자 그대로 적용하므로 발문이 준 전제, 발문이 제외한 내용, 원문에 없는 한정어, 묻지 않는 설명 문장, 묻지 않는 기준서 번호를 요건처럼 적지 않고, 원문의 조건을 요건으로 두면 모범답안도 그것을 쓴다.

v1의 기대 점수 불일치 18건 중 위 표로 해소한 7건을 뺀 11건(부분정답 −1 일곱 건, 부분정답 +1 한 건, 오답 +1 세 건)은 원문에 있는 조건·한정어를 Luna가 엄격하게 요구하거나 비슷한 표현을 너그럽게 인정한 채점 일관성의 차이로 판정해 명제를 유지했다. 물음별 판단은 [검토 배치의 실측 절](../../cpa_uploader/analysis/reviews/standard-spoiler-2026-09-19/README.md#실측)에 있다.

## 바꾸지 않은 것

- 개수(“세 가지”), 적용 조건, 제외 범위, 범위를 정하는 데 필요한 대상 이름(예: pilot-08-004 sub1의 “원천, 내부통제 및 입수방식과 관련된” 일반화)은 명제의 방향·조건을 주지 않으므로 유지했다.
- 경영진주장의 명칭을 묻는 물음(std-points-20260914-44a4823e71a6 등)과 정의를 묻는 물음은 정의 물음의 발문이 명칭을 쓸 수밖에 없어 서로의 정답이 겹친다. 구조상 피할 수 없어 기록만 했다. “감사의견근거 단락”처럼 기준서 용어가 다른 물음의 명칭 정답과 같은 경우도 같다.
- 혼합 세트의 사례형 물음은 기준서형 검토 범위 밖이다. pilot-16-008 sub4와 pilot-18-005 sub4는 발문이 판단 축을 알려 주고, pilot-18-005·pilot-19-005의 사실관계는 실제 연도를 쓴다. 사용자 지정 사례 검토 때 다룬다.

## 운영 반영에서 고친 도구

- 평문 전송 요청(3.35MB)이 Supabase Management API의 크기 제한에 걸려 probe가 HTTP 413으로 거절됐다(읽기 전용, 쓰기 없음). 2026-09-14 전례를 따라 반영 도구에 압축 전송(`--transport compressed`, pgcrypto OpenPGP·zlib, 공개 상수 암호로 기밀성 없음)을 넣어 요청을 0.49MB로 줄였다. DB에서 푼 pack도 평문과 같은 payload 해시 guard를 통과해야 importer에 들어간다.
- verify는 조회 함수(`cpa_get_active_question_bank`, `cpa_get_learning_classifications`)를 읽기 전용 API 계정으로 불러 권한 오류가 났다. 이 함수들은 service_role만 실행할 수 있으므로 read only transaction 안에서 service_role로 부르게 고쳤다.
- 두 결함 모두 PGlite 테스트가 운영의 조건(요청 크기, 읽기 전용 계정의 함수 권한)을 흉내 내지 않아 놓쳤다. 압축 전송 경로와, 읽기 전용 요청을 함수 권한이 없는 역할로 실행하는 로컬 전송을 테스트에 넣었고, 고치기 전 verify 코드로는 새 테스트가 운영과 같은 오류로 실패함을 확인했다. 운영 기록은 `cpa_uploader/releases/20260919-standard-spoiler*/`에 있다.
