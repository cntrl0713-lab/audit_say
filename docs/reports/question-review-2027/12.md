## 화면·연계 주제와 남은 범위

실제 QuizClient·globals.css로 8세트×1440/390폭의 문제·결과 32화면을 확인했다. 문구·물음 ID·점수·답안 귀속·모범답안·줄바꿈·수평 넘침, 재풀이 초기화, 서비스 실패 시 답안 보존, 프로필 갱신 실패 시 결과 유지를 확인했다. 빈 답안의 HTML 제출 차단은 없고 입력 한도는 5,000자다. 초기에 재사용한 UI 검사 스크립트가 sub1 ID를 가정하여 001에서 시간 초과했으나 실제 subq1 ID를 사용하도록 검사 스크립트를 고쳐 전수 통과했다. 제품 UI 결함으로 분류하지 않는다.

실제 action에 격리 어댑터를 연결해 키 없는 빈 답안의 quota 우회, 다른 물음 ID·5,001자 거절, 5,000자 및 일부 빈 답안 허용을 확인했다. 인증·서버 action·DB를 실제 운영 환경까지 관통한 E2E는 아니다. 공통 제출 ID·경험치의 동시 가산/재시도 및 진행 저장 실패 처리는 기존 공통 이슈에 연결하며 이번 문항 교정으로 해결했다고 보고하지 않는다.

- 04 중요성과 12의 집계 제외 기준은 다르다. ‘중요하지 않음’을 ‘명백하게 사소함’으로 대체하지 않는다.
- 05의 경영진·지배기구 커뮤니케이션 및 법규 예외와 450의 대상별 요구를 구별했다.
- 11-002/sub1·11-004/sub1의 감사보고서일까지 사건 증거 접근방법과 560의 보고서일 후 인지 사실 대응을 구별했다.
- 15의 일반 의견변형 조합과 580.20의 특정 경영진책임 진술 미제공·신뢰 불가 조건을 구별했다. 570의 계속기업전제 부적합은 부적정의견, 적합하나 중요한 불확실성이 있으면 공시의 적절성 등에 따라 보고가 달라진다. 단순 사건 식별·평가기간 부족 자체만으로 의견을 확정하지 않는다.
- 16의 기타정보 수정 거절·강조사항과 재무제표 수정·후속사건을 혼동하지 않았다. 560.12의 한정된 추가 일자·강조/기타사항 예외는 007/sub2의 일반 날짜 질문과 분리했다.
- 002/sub1과007/sub1에는 세 절차의 중복이 있다. 전자는 각 1점, 후자는 일반 원칙 1점과 세 절차를 모두 충족하는 결합 1점이다. 결합 채점에서 계획 질문 하나가 빠지면 그 1점은 미득점이다. 005/sub1과006/sub2의 개별 식별·수정 요청도 중복 학습목표로 기록한다. 기존 ID 삭제나 내용 범위의 임의 축소로 숨기지 않았다.
- 수정 거절(450.9), 계속기업 보고 결과의 상세 조합(570.21–23), 서면진술 미제공의 두 의견거절 경우를 각각 열거하는 문제는 이번 16물음이 직접 요구하는 범위 밖이다. 기준·반례·연계 검토를 실제 출제 범위로 과장하지 않는다.

위키의 감사종결 설계 지침과 개인 `audit-question-review` 스킬의 주제12 안내를 보완했다. 스킬 UTF-8 검증은 통과했다. 위키 자동 생성 영역은 정본으로 갱신하고 수동 지침·원자료·기존 로그는 보존했다.

**검토 기록 완료와 2027년용 사용 적합은 별도다.** 최종 시험 판본과 운영 인증/DB E2E는 미확정·미실행이다. 다른 주제의 병행 수정 중 은행 전체 검사 실패를 주제12의 실패로 혼합하지 않으며, 최종 시점의 전체 검사 결과를 위 실행 집계에 그대로 기록한다.
