# 채점기 ID 제한 보고서와 관련 변경의 후속 검토 — 2026-09-11

[원보고서](채점기-id-오반환-결함-해결과-신규-세트-재검수.md)의 ID 제한 수정은 타당했다. 다만 검수 통과 조건과 오류 기록에 결함이 있었고, 교체 후 사례의 전건 일치를 이전 실패 전체의 해결로 해석하면 안 되는 문제가 있었다. 공통 채점·의미검수·승급 검증과 보고서에 연결된 9세트 변경을 검토했다. 작업 트리에 섞인 공통 계정·운영 배포 스크립트의 전수 검토는 이 범위에 포함하지 않았다.

## 발견과 수정

| 우선순위 | 발견 | 수정 |
| --- | --- | --- |
| 높음 | 물음별 보안 오탐으로 0점이 되었어도, 세트 전체 플래그만 확인해 누락/조건 경계 사례가 pass할 수 있었다. | 정상 검수 사례는 원시 판정의 물음별 보안 플래그까지 검사해 불일치로 처리한다. 기존 물음별 점수·DB 저장 범위는 유지한다. |
| 높음 | 테스트용 `injected_response`가 신규 검수 수락·승급에도 허용되었다. | 현재 검수를 새로 수락할 때 실제 모델 transport를 요구한다. 과거 기록 읽기에서는 당시 종류를 보존한다. 생산 코드에 mock 우회 옵션을 추가하지 않았다. |
| 중간 | 모델 호출과 JSON 파싱이 재시도 try 밖에 있어 503·빈 응답·잘못된 JSON은 첫 실패에 종료하고 trace를 남기지 않았다. | 호출·파싱·형식 검증을 같은 제한 재시도 안으로 넣었다. 일시적 전송/빈 응답/JSON 오류를 기록하고 최대 2회 요청한다. 인증·설정·거절·출력 한도 오류는 즉시 종료한다. 오류를 학생의 0점으로 바꾸지 않는다. |
| 중간 | 실제 사례 채점 도중 API 오류가 나면 앞서 완료한 실행도 최종 receipt에 쓰이지 못하고 유실되었다. | 성공·불일치·실패를 각 실행 직후 `.grading.jsonl`에 보존한다. 부분 기록은 완료 receipt로 취급하지 않으며 기존 로그를 덮어쓰지 않는다. |
| 중간 | 사례 교체로 원답안의 정상 표현·과대채점 반례가 현재 회귀 묶음에서 빠졌다. | 원자료와 전체 답안 문맥에서 원답안 4건을 다시 판단하고 교체답안과 함께 보존·실측했다. 사례 교체 후에도 유효한 원답안과 불완전 답안의 경계를 유지하도록 지침을 보완했다. |

ID는 스키마에서 해당 물음·criterion의 값으로 제한하고, 실제 응답의 중복·미등록·물음 간 이동·누락도 코드에서 검사한다. 잘못된 ID를 순서나 문구로 짐작하여 다른 명제에 붙이지 않는다. 기존 `incomplete_details.reason` 기록 추가는 출력 한도와 다른 실패를 구분하는 데 유효해 유지했다.

## 원보고서의 해석을 정정할 사항

- “전건 일치”와 “게시 준비”는 그 시점에 선택한 사례·코드·은행의 결과다. 원 사례를 더 명시적인 문구로 교체한 결과만으로 원답안의 오판이 해결되었다고 확정할 수 없다.
- 원보고서 끝부분에서 인정한 20회 비교·6~10회 반복의 임시 원자료는 이번 검토에서 확보하지 못했다. 해당 수치는 작성자의 당시 기록이며, 아래 새 실측을 과거 로그 복원이나 독립 재현으로 표시하지 않는다.
- Claude의 대리 검수는 AI가 수행한 의미 대조다. 실제 사람이 문항별로 확인했다는 증거로 해석하지 않는다. 기존 승급 장부를 임의 삭제하거나 운영 상태를 변경하지 않았다.
- `pilot-13-006/sub2/crit5`의 “입수할 수 있는 경우” 조건 명료화는 KGA 402.12(a), 발문의 조건 요구, 모범답안에 부합한다. `pilot-13-008`의 반대 사례를 명시적 부정으로 바꾼 것도 타당하다. 이번에 이 문항 내용을 다시 고치지는 않았다.
- `pilot-05-008`의 두 51회 검수 기록은 단위·사례·내용은 같으나 비교 은행 해시는 다르다. 동일 은행에서 두 번 검수했다고 확대하지 않는다.

## 새 실제 모델 검증

현재 `gradeQuestionSetV3`와 기본 설정 `gpt-5.6-luna`로 **33회 호출, 33회 기대 판정 일치**를 확인했다. 9세트의 전체 모범답안 9회와 다음 4쌍의 원답안·교체답안을 각각 3회씩 실행했다.

| --- | --- | --- |
| 05-008/sub2/crit11 | 앞 문장의 총 보수를 다음 문장의 보수 배분이 이어받음 | met 3/3 |

교체답안도 각 3회 일치했다. 13-006의 교체답안은 대상을 이용자기업 자체 통제로 바꾼 별도 반례이므로 contradicted로 확인했다. 9세트 모범답안은 모든 criterion이 met, 세트별 만점이었다. 판정/점수·원문 근거·ID·보안 플래그를 함께 검사했다.

이는 현재 정상 호출 경로의 표본 검사다. 9세트의 모든 기존 의미검수 사례 재실행, 나머지 은행 전수 모델 채점, 드문 오류의 영구 해결을 주장하지 않는다. 요청 프롬프트와 응답 스키마의 정상 경로는 이번 수정에서 바꾸지 않았다. 전송 장애·JSON 오류·승급 차단은 별도 주입 회귀 검사로 검증한다.
