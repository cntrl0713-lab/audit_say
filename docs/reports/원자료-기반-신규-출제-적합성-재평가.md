표의 상대 경로는 `cpa_uploader/` 기준이다. [새 출제 설계 안내](../../cpa_uploader/wiki/question-generation/source-authoring-design.md), [원자료 카탈로그](../../cpa_uploader/wiki/_meta/source-catalog.md), [실행 명령](../../cpa_uploader/README.md)에서 현재 사용법을 확인한다.

생성기는 공통 5지침과 해당 주제 지침, 사람이 작성한 ready 계획, 선택 원문·필수 참조·판본 정보를 입력한다. 계획과 원문 묶음은 draft 옆 sidecar로 저장하며 세트 ID·계획 해시·출처 묶음 해시로 연결한다. 체크포인트를 복원할 때도 현재 원문과 인용·위치·상태·계획 유형을 다시 대조한다. 미완성 계획이나 기존 결과 덮어쓰기는 거절한다.

의미 검수는 발문·모범답안·명제·핵심 조건·requirement 인용과 위치의 전체 필드, 실제 원문 인용, 적용 판본 가정, 기존 은행과 세트 내부의 의미 중복을 대상으로 한다. 원문 파일·문항·계획·출처 문맥·비교 은행의 해시를 검수 기록에 남긴다. 이 기록은 사람의 실제 검토 근거와 별개이며, 새 verified·재검수에는 둘 다 요구한다.

`questionReviewGrading.ts`는 모범답안·동의 표현·명제 누락·반대 의미·조건 경계의 사례와 빈 답안을 실제 `gradeQuestionSetV3`에 전달한다. 같은 답안은 합쳐 실행하되 각 criterion의 기대 판정을 모두 대조한다. 부분점수는 해당 criterion에 계약이 있을 때만 허용한다. 실행한 원시 판정과 인용·보안 보정 후 점수, 사례·채점 코드 해시를 기록하고, 승급 시 현재 코드로 점수를 재현한다. 채점 누락·기대값 불일치·점수 조작·새 승인 시 모델 설정 불일치는 거절한다. 기존 게시 기록의 모델명은 당시 이력으로 유지한다.

의미 검수만 끝낸 `grading.status=not_run`은 승급할 수 없다. 완료한 의미 검수에 `review_question_draft_v3.ts --review-input <의미검수.json> --grade-cases`로 채점 기록을 추가한다. 이 명령은 설정된 채점 모델을 호출한다. 이번 회귀 검증에서는 오프라인 응답을 주입해 실제 코드 경로를 실행했고, `transport=injected_response`로 외부 모델 실행과 구분했다.

### 실제 자료의 남은 경계

- 6,866개는 문단·페이지 단위 수다. 독립 학습목표 6,866개나 기준서 전체의 확보·출제 완료를 뜻하지 않는다. 263개 단위는 주제 미연결로 별도 표시한다.
- CLI의 기본 후보를 문단 범위로 준비했을 때 02·04·10·13·14·18·19는 파싱된 참조 연결을 충족했다. 01·03·05·06·11·15·16·17은 누락 문단 또는 범위가 지정되지 않은 교차참조를 표시했고, 07·08·09·12는 필수 문맥의 입력 예산을 초과했다. 이 결과를 숨기지 않으며, 다른 명시 문단을 선택하거나 원자료를 보충해야 한다. 19주제 모두에서 범위를 명시한 독립 문단으로 실행 경로를 검증했다.
- `completeness=complete`의 범위는 **파서가 인식한 참조 연결**이다. 의미상 충분성·예외의 완전한 탐지·공식 판본 승인까지 뜻하지 않는다. OCR 페이지 경계는 실제 발문·해설의 경계와 다를 수 있어 전후 페이지와 대조한다.
- 공식 전사와 학습자료의 권위를 구분한다. 2027년에 2026년 시행 기준을 동일 적용한다는 기존 가정은 보존하며 최종 시험 적용 공고 확인으로 바꾸지 않는다.
- 기존 96세트의 무해시 소급 장부는 역사 기록으로 읽기 호환한다. 그 장부만으로 과거·향후 내용 변경을 모두 탐지한다고 주장하지 않는다. 이번 작업에서 기존 문항의 의미 검수를 새로 수행하거나 소급 승인하지 않았다.

## 1. 높은 우선순위 — 원자료의 주제별 진입 링크가 누락되어 있다

통합 목차에는 기본이론 37행, 문제연습 57행, 기출문제 57행, 합계 **151개의 자료·페이지 연결**이 있다. 실제 생성된 concept는 **19개 모두 `원자료 탐색` 절이 비어 있다.**

원인은 [목차 파서](../../cpa_uploader/wiki/scripts/build-wiki.mjs:23)가 `- `로 바로 시작하는 행만 읽는 데 있다. [실제 목차](../../cpa_uploader/data/회계감사_통합학습자료/00_통합_목차.md:20)의 연결 행은 두 칸 들여쓴 `  - `로 시작한다. 따라서 링크를 생성하는 [후속 코드](../../cpa_uploader/wiki/scripts/build-wiki.mjs:99)에 빈 배열이 들어간다.

이 결과 [워크플로](../../cpa_uploader/wiki/question-generation/question-generation-workflow.md:21)가 안내하는 ‘concept의 원자료 탐색에서 기출·문제연습 확인’ 경로가 작동하지 않는다. 매니페스트나 통합 목차를 직접 열어 우회할 수 있지만, 주제별 파일과 페이지를 제공하려는 위키의 핵심 기능은 누락된 상태다.

실제 소재가 없는 것도 아니다. 예를 들어 [기출문제 주제별 해설의 원문 페이지166](../../cpa_uploader/data/회계감사_통합학습자료/04_기출문제/기출문제_주제별_해설.md:6907)에는 서비스조직의 서비스 이해와 보고서 이용에 관한 공통 사례·독립 발문·해설이 있다. 현재 은행에서 비어 있는 KGA402 범위의 출제 후보를 검토할 수 있는 자료다. 이 자료가 주제13 concept의 원자료 탐색으로 전달되지 않는다.

수정 기준: 151개 연결을 원자료에서 독립 집계하여 실제 생성 결과와 대조한다. 원자료 링크가 존재해야 하는 주제의 빈 절을 실패로 처리한다. 생성기를 다시 실행한 값과 일치한다는 검사만으로 대체하지 않는다.

## 2. 높은 우선순위 — 자동 출제의 근거 후보가 기존 문제은행에 묶여 있다

실제 `generateTopic` 요청을 외부 모델 없이 가로채 19주제의 `SOURCE_BUNDLE`을 확인했다.

| 구분 | 실제 입력 | 의미 |
| --- | ---: | --- |
| 주제01~05 | 학습자료 fallback 70개 | 공식 전사 연결 없이 키워드에 맞는 기준서 학습자료의 줄을 선택 |
| 주제06~19 | 공식 전사 인용 172개 | 172개 모두 기존 은행이 이미 참조한 인용에서 선택 |
| 전체 | 242개 | 원자료 전체나 미출제 요구사항 전체를 입력한 수치가 아님 |

[공식 출처 수집](../../cpa_uploader/generate_cpa_v3.ts:301)은 현재 은행의 해당 주제 `source_refs`를 출발점으로 삼는다. 그 인용이 실제 공식 전사 파일에 존재하는지 확인하는 점은 좋다. 그러나 파일에 있는 다른 요구사항이나 인접 예외를 새로운 후보로 읽지는 않는다. [후보 선택](../../cpa_uploader/generate_cpa_v3.ts:363)은 기준서·키워드 기준으로 최대14개를 선택하고, [생성 경로](../../cpa_uploader/generate_cpa_v3.ts:653)는 공식 후보가 하나라도 있으면 학습자료 후보를 병합하지 않는다.

**주제13의 실제 입력은 KGA610·620의 12개 인용이고 KGA402는 0개다.** 위키는 KGA402를 보강 대상으로 안내하지만 그 주제로 생성기를 실행해도 402 근거가 제공되지 않는다. 같은 조항에 대한 새로운 물음은 만들 수 있어도, 아직 은행에 연결되지 않은 조항으로 범위를 넓히는 데는 제한이 있다. 국내 직접적 보조 금지에 관한 610.5는 실제 입력에 포함되어 있으므로 이 조항이 탈락했다고 판정하지는 않았다.

또한 자동 생성기는 `03_문제연습`·`04_기출문제`를 읽는 경로가 없다. 기준서 학습자료와 기본이론용 수집 함수 및 기존 공식 인용을 사용한다. 원자료의 사례·발문·해설을 함께 이용한다는 수동 위키 흐름과 실제 자동 출제 입력은 다르다.

수정 기준: 출제 대상 학습목표 또는 원자료 구간을 먼저 선택하고, 해당 구간의 원문과 필요한 근거를 기존 은행 등록 여부와 독립적으로 수집한다. 기존 은행은 출처 후보의 유일한 목록보다 중복·기출 범위 대조에 활용하는 편이 목적에 맞다.

## 3. 높은 우선순위 — 열거사항과 조건·예외가 출제 입력에서 분리된다

공식 파일을 사용한다는 것과 필요한 문맥을 모두 입력했다는 것은 다르다. 예를 들어 [주제16 공식 전사](../../cpa_uploader/data/official/kga701-706-710-720-2025-review16.txt:81)에는 701.10이 존재하지만 실제 입력 묶음에는 없다. 같은 파일의 [720.18~19](../../cpa_uploader/data/official/kga701-706-710-720-2025-review16.txt:605)도 입력에 없다. 기존 문항의 한정된 발문에는 불필요할 수 있지만, 새 물음에서 범위를 확대할 때는 이런 인접 단계·후속 요구를 재수집해야 한다.

학습자료 fallback 수집은 [한 줄의 길이·키워드 기준](../../cpa_uploader/generate_cpa_v3.ts:404)으로 후보를 만든다. 원문의 문단 머리말, 하위 항목, 앞 문단의 적용 조건, 다른 문단의 예외를 하나의 검토 단위로 보장하는 구조가 아니다. 인용 개수 상한을 늘리는 것만으로 이 문제를 해결할 수는 없다.

실제 fallback 70개를 확인했을 때 **목록의 머리문장만 선택되고 후속 열거항목이 빠진 사례는 4개**였다.

| 주제·입력 위치 | 원자료의 구간 | 전달되지 않은 후속 항목 |
| --- | --- | --- |
| 02/src2 | 200.7 | 3개 과정 |
| 03/src3 | 210.10 | 계약조건 6개 |
| 04/src13 | 300.A22 | 초도감사 추가 고려사항 4개 |
| 05/src14 | 260.A43 | 제3자 제공 문서에 명시할 사항 3개 |

예를 들어 [210.10 학습자료](../../cpa_uploader/data/회계감사_통합학습자료/01_감사기준/02_감사의_기본원칙과_감사인책임.md:343)는 머리문장과 여섯 하위 항목을 함께 제공하지만 생성 입력에는 머리문장만 들어간다. 별도로 주제01의 220.A26 인용은 20~22 준수를 요구하면서 해당 본문은 입력하지 않는다. 이 다섯 의존관계 단절을 전체 의미 오류율로 일반화하지는 않았다.

공식 후보179개 중 최대14개 선택 규칙으로 입력에는172개가 남았다. 제외된 7개 레코드 중 하나는 다른 선택 인용과 겹치므로 실제 내용이 빠진 것은6개다. 주제09의505.12~13·14, 주제12의450.5·8·A2, 주제15의705.29가 해당한다. 어떤 새 발문을 선택하느냐에 따라 필요한 조건·예외를 다시 읽어야 한다. 현재 `[SOURCE_BUNDLE]` 외 내용을 정답 근거로 삼지 말라는 계약에서는 wiki 지침의 설명이나 문서 링크만으로 이 누락을 메울 수 없다.

## 4. 중간 우선순위 — 기준서에서 새 학습목표를 설계하는 흐름이 부족하다

위키의 [프롬프트 작업 순서](../../cpa_uploader/wiki/question-generation/llm-question-generation-prompt.md:48)는 ‘기존 문제 발문에서 요구사항 추출’을 전제로 한다. 기존 기출을 재구성하는 데 적합한 흐름이다. 반면 기준서로부터 처음 문제를 만들 때 필요한 ‘학습목표 선택 → 적용 조건·예외 정리 → 신규 발문 설계 → 답안 범위 → 채점 명제 → 직접 근거’의 제작 기록은 위키에 명확한 단계·서식으로 갖추어져 있지 않다. 외부 출제 스킬에 일부 원칙이 있어도 위키만 제공받은 저자에게 자동 전달되지는 않는다.

[요구사항 지도](../../cpa_uploader/wiki/_meta/requirement-coverage.md:17)도 4글자 문자열 유사도에 따른 탐색 후보다. KGA265·1200과 비KGA 범위의 미스캔을 솔직하게 표시하는 점은 좋지만, 모든 학습목표·조건·유형의 출제 여부를 기록한 대장은 아니다.

수정 기준: 각 제작 단위에 학습목표, 대상·시점·조건·예외, 요구할 답의 범위, 원문 위치·판본, 기존 문제와의 차이를 기록한다. 근거 묶음은 문단의 하위 항목과 연결된 예외·적용자료를 보존하고, 부족하면 범위 확대를 보류하거나 추가 원문을 요청하도록 한다.

## 5. 중간 우선순위 — 자동 검증으로 내용 적합성을 승인할 수 없다

현재 검증기는 정책 형상·정수 배점·인용 실존·연결 ID·동일 발문 중복을 확인한다. 그러나 정답이 근거에서 도출되는지, 발문이 요구한 것과 채점이 일치하는지, 조건·예외를 누락했는지를 자동 확인하지 않는다.

정본을 메모리에서만 복제하고 원래 `source_refs`와 `source_fidelity=exact`를 유지한 다음 다섯 반례를 만들었다. **모두 `validateQuestionSetV3({verifySourceQuotes:true})` 오류0·경고0, 전체 authoring 구조 검증 오류0이었다.**

| 반례 | 변경한 내용 | 결과 |
| --- | --- | --- |
| 반대 정답 | 01-001/sub2의 책임 불경감 명제를 반대로 변경 | 인용 실존 검증 통과 |
| 조건 누락 | 13-003/sub1의 허용 국가·활용 요건 충족 전제를 삭제 | 검증 통과 |
| 가짜 위치·판본 | 10-001/subq1의 source_span에 존재하지 않는 기준서·문단·시험 연도 기재 | 검증 통과 |
| 숨은 채점 요구 | 01-001/sub1의 발문은 명칭만 요구하도록 바꾸고 정의·대상 criterion 유지 | 검증 통과 |
| 의미 중복 | 10-001의 다른 물음에 같은 내용을 복제하고 발문 접두사만 변경 | 발문 중복 검사도 통과 |

근거는 [인용 존재 검사](../../lib/questionV3.ts:389), [requirement 검사](../../lib/questionV3.ts:465), [claim 존재 검사](../../lib/questionV3.ts:482), [문자열 중복 검사](../../cpa_uploader/questionDraftInventory.ts:14)다. `source_span`의 실제 문단·페이지·판본을 대조하는 검사는 없다. 이는 현재 게시된 문항이 다섯 결함을 실제 갖고 있다는 판정이 아니라, 그런 결함을 자동 구조 검증으로 차단할 수 없다는 재현이다.

생성 후처리도 주의가 필요하다. 실제 응답 스키마를 통과하는 합성 응답에 유효한 출처 ID와 가짜 인용·위치, 잘못된 claim을 넣고 로컬 callback으로 반환했다. [후처리](../../cpa_uploader/generate_cpa_v3.ts:582)는 인용을 허용된 공식 인용으로 바꾸고 `source_fidelity=exact`, `calculation_required=false`로 고정했다. 가짜 위치와 잘못된 claim은 남았지만 `generateTopic`은 재시도 없이 초안을 반환했다. 출처의 통제는 유용하지만 모델의 원래 오류 신호를 내용 교정 완료처럼 해석해서는 안 된다. 반환 상태는 `needs_review`였으며 자동 게시된 것은 아니다.

현재 [생성 테스트](../../tests/questionV3Generation.test.ts:27)는 근거 인용을 그대로 정답·claim에 넣는 합성 응답으로 실행 경로를 검사한다. 따라서 앞선 전체 테스트 통과는 구현과 계약의 검증 결과이며 실제 새 문항의 품질 실측 결과는 아니다.

수정 기준: 구조 검증과 별도로 문항별 ‘발문 요구 ↔ 정답 명제 ↔ criterion ↔ 근거·조건·예외’ 검토를 기록한다. 검토가 끝난 초안에 대해 모범답안·동의 표현·부분 누락·반대 의미·빈 답안의 기대값과 실제 채점을 대조한다. 의미 검토 단계는 사람 또는 별도 검토 모델로 도울 수 있지만, 출처 연결을 자동 교체한 사실만으로 승인하지 않는다.

## 현재 잘 갖추어진 부분

- 96세트·192물음·521criterion의 사실·발문·답안·조건·직접 근거를 조회할 수 있다.
- 주제별 지침은 기존 검토에서 중요한 조건·예외를 보존한다. 특히 주제18의 전체 열거 범위와 주제19의 업무 유형·법역 구분은 설계에 도움이 된다.
- 모두 작성·정수 배점·의미상 순서 보존 규칙이 실행 계약과 일치한다.
- 신규 ID·동일 발문 중복, draft 상태, 검수·게시·재검수 장부 경계는 갖추어져 있다.
- wiki가 공식 원문이나 시험 적용 확정을 대신하지 않는다는 원칙을 명시한다.

## 권장 수정 순서와 이번 검토 범위

1. 원자료 링크151개를 복구하고 원본 목차 기준의 누락 검사를 추가한다.
