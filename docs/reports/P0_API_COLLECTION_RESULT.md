# P0 API 수집 결과 — 2026-09-08

Git main을 origin/main의 b18eb0f로 fast-forward했고 기존 로컬 정리 작업을 보존했다. 이 작업의 변경 사항은 아직 커밋·푸시하지 않았다.

## 범위와 결과

삼성전자(00126380)를 먼저 프로브한 뒤 2024·2025 사업연도 전체를 조회하고, 식별 가능한 데이터를 Supabase에 적재했다. 모집단은 OpenDART corpCode.xml에서 종목코드가 있는 3,989개 회사다. 상장폐지 회사도 포함하므로 현재 상장사 3,989곳이라는 뜻은 아니다.

사용자 결정: API 데이터 우선, 감사대상회사의 감사·비감사 보수 및 임직원 정보 제외, 원문 파싱 제외, 식별 불가 건은 검토 목록에 보류.

|---|---:|---:|
| 전체 조회 회사 | 3,989 | 3,989 |
| 적재 회사 | 2,757 | 2,787 |

범주에는 중복이 있다. 한 회사의 일부 감사인은 식별되어 적재되고 다른 감사인은 보류될 수 있다. 공동감사 등으로 감사인 연결 수가 회사 수보다 많을 수도 있다. API 조회 데이터 없음은 공시 원문 부재를 증명하지 않는다. 재무 결측·외화 보류 회사도 식별된 감사인·의견은 적재했다.

## 프로브와 매핑 교정

- 감사의견 API의 당기·전기·전전기를 구분하여 당기만 선택하고 연결/별도 중복 행을 합쳤다. 의견이 상충하면 임의로 하나를 고르지 않는다.
- KAM·의견 등 선택 필드의 부재는 결측으로 보존했다. KAM 개수는 명시적인 연속 번호만 센다.
- 재무는 CFS 우선, 없으면 OFS를 사용한다. currency가 KRW가 아니면 원화 칸에 저장하지 않고 NULL·parse_failed로 남긴다.
- 종목코드만으로 상장 여부를 단정하지 않고 응답 corp_cls를 사용한다.
- 초기 삼성전자 프로브의 과거 감사인 오연결과 제외 대상 용역 데이터를 백업 후 정정했다. 초기 이름 정규화 중 생긴 세일원 오연결 1건도 백업 후 제거하여 보류했다.

## 회계법인 자체 정보

DART 전체 법인명과 고유번호가 유일하게 대조된 신규 법인 35곳을 반영하여 마스터는 63개 항목이다. 등록번호·군(tier)은 근거 없이 채우지 않았다. status=active는 수집 대상 상태이며 상장회사 감사인 등록 확인을 대신하지 않는다.

회계법인 자체 주요계정·직원·임원 API를 두 연도 모두 조회했다. 59곳은 세 API 모두 빈 응답으로 인력·재무 적재 0건이며, 4곳(대성삼경·성도이현·다산·동아송강)은 고유번호 확인을 보류했다. 인원이나 매출을 0으로 만들지 않았다. 소속 회계사 수·경력별 구성·입퇴사 현황은 현재 API 실데이터로 확보되지 않았으며 원문 파싱은 이번 작업에서 하지 않았다.

## 보류와 후속 작업

- 정인·선일 외에 대성·서원도 동명 다중 후보가 있어 추정 연결하지 않았다. 오타·감사반·감사인 칸의 잘못된 값도 보류했다.
- 2024년 두산에너빌리티: 당기 표시 없는 기수가 62·60·60으로 연속하지 않아 보류.
- 2024년 코다코: 같은 당기 감사인 의견이 한정/의견거절로 달라 보류.
- 2025년 원티드랩: 같은 당기 감사인 의견이 적정/한정으로 달라 보류.
- API 금융회사 재무 결측, 외화 환산 근거, 회계법인 자체 인력·재무, 등록번호·군은 후속 확인 대상이다.

[검토 목록](collection-review-queue.md)과 [기계 판독용 목록](collection-review-queue.json)에 회사·연도·감사인 원문·후보 고유번호를 남겼다. 보류는 사용자 승인에 따른 처리 완료 상태이며 해당 데이터의 식별 완료를 뜻하지 않는다.

## 검증과 재실행

- npm test: 84개 통과. npm run typecheck 및 수집기·관련 테스트 ESLint 통과.
- DB 연결 5,546건 전부를 저장된 API 응답에 현재 파서를 적용한 결과와 대조했다. 감사인·감사의견·KAM 수 및 재무 3지표·재무제표 구분·결측 상태 불일치 0건, 캐시 누락 0건.

- 이 검증은 API 응답과 적재 값의 일관성을 확인한다. 제출 자료 자체의 정확성이나 번호 없는 KAM 개수까지 검증한 것은 아니다.
- 프로브·재처리·누적 보고서를 구분했고 최종 processed는 DB 고유 연결 수다. [집계 JSON](collection-summary.json), [2024 최종](engagements-2024-final.json), [2025 최종](engagements-2025-final.json).
- 재개·캐시·오류 재처리 명령은 [수집기 README](../../scripts/firm_collector/README.md)를 따른다. 캐시는 인증키를 제외하여 gitignore 경로에 저장하며, 공시 정정 반영 시 새 기준일 캐시를 사용한다.
