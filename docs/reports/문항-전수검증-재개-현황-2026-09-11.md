## 과거 실제 실행과 현재 미완료 구분

과거 후보의 실제 결과는 당시 증거로 보존하며 현재 후보의 완료 건수에 더하지 않는다. 문항·출처·비교 은행·코드 결속이 달라진 receipt는 해시만 바꿔 재사용할 수 없다.

| 실행 | 확인된 상태 | 현재 후보에 대한 처리 |

| 초기 실행 v1·재개 v1 | 초기 실행에 의미검수 pass 6세트·65단위가 남아 있고 비통과·부분 로그도 존재. 전수 완료 아님 | 당시 경로 보존, 현재 통과 수로 합산 금지. v2와 중복 가능한 역사 실행 수 |
| 선행 `execution-canary-v2` | 3세트의 의미검수 35단위 pass | 이전 은행·출처의 결과. 현재 신규 수락 근거로 자동 전용 금지 |

## 남은 작업과 완료 조건

1. 현재 고정 입력으로 선행 3세트 30단위, 이후 116세트 1,363단위의 실제 의미검수. 모든 단위의 출처·사실·조건·예외·배점·중복 대조와 유효한 실제 모델 receipt가 필요하다.
2. 실제 의미검수가 만든 criterion별 사례의 정식 모델 채점, 작성자 QA 6,029개 모델 채점, 학습 단위 249개의 비어 있지 않은 모범답안 실측. 이 세 범위를 서로 대신하지 않는다.
3. fail/uncertain·실행 오류·점수 불일치 원인을 구분해 수정하고 영향 범위를 재검증한다. 유효한 원답안·반례·실패 로그를 보존한다.
4. 사용자가 실제 확인한 사람 검수 근거 확보. AI 대리 검토를 사람 확인으로 기록하지 않는다. 기존 70세트의 재검수와 신규 49세트의 승급 요건을 모두 충족한다.
5. 정본·공개본·암호화본·분류 카탈로그를 최종 상태로 생성·검사하고, 승인된 운영 DB 반영 및 실제 반환 결과 검증을 수행한다. 이번 인계에서는 모두 미실행이다.

사용자는 필수 전수검증 후 DB 반영을 승인했지만, 이번에는 실행을 다음 작업으로 미뤘다. 새 자동화나 백그라운드 검증을 시작하지 않는다. 재개 전에는 현재 지침과 파일 해시, 실제 운영 DB 상태를 다시 확인한다.
