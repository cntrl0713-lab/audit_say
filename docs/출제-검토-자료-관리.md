# 출제·검토 자료 관리

기존 JSON과 Git을 유지하며 자료의 역할에 따라 수정 위치를 정한다. 현재 상태는 정본과 연결 분석에서 조회하고, 과거 실행의 판단·증거는 당시 상태로 보존한다.

## 위치와 소유권

| 위치 | 관리하는 내용 | 수정 방법 |
| --- | --- | --- |
| `cpa_uploader/raw/` | wiki 기반 자료·제작/검증 출처의 원본·추출본·보존 사본과 수집 계보 | 원본 바이트를 보존하고 원래 경로·해시·판본을 매니페스트로 연결. 새 자료는 이곳에 먼저 보관 |
| `cpa_uploader/data/` | 현재 문제은행과 기존 출처 계약의 등록 입력 | 문항·출처 등록 절차로 갱신. 기존 원문 경로와 ID는 유지하며 raw 보존본에 연결 |
| `cpa_uploader/analysis/question-elements/` | 발문 추출, 원출제·재수록 연결, 보정 입력, 요소·빈도 결과 | 추출기·수동 보정 입력을 수정하고 JSON과 Markdown을 재생성 |
| `cpa_uploader/analysis/coverage/` | 재사용할 요구사항 관계와 현재 은행의 연결 결과 | 사람이 `links.json`의 관계를 확인하고, `registry.json`·`summary.md`·`topics/*.md`는 생성 |
| `cpa_uploader/analysis/reviews/` | 여러 문항·주제에 걸친 검토 장부, 사례, 실행 증거·당시 출처 | 실행별로 보존하고 후속 검토를 별도 기록. 과거 결과를 최신 결과로 덮어쓰지 않음 |
| `cpa_uploader/drafts/` | 개별 제작 배치의 문제·계획·패킷·QA·검수 receipt | 해당 배치 계약에 따라 관리. 정본 반영 여부와 검수 상태를 구분 |
| `docs/` | 사람이 읽는 정책·설계 결정·계획·보고 이력 | 수동 설명은 직접 수정. 생성된 문제지·보고 표는 해당 생성기에서 갱신 |
| `cpa_uploader/wiki/` | 현재 자료를 탐색하는 통합 안내와 조회 화면 | 수동 지침은 직접 수정하고 생성 현황은 입력에서 재생성 |

각 묶음의 README와 wiki `SCHEMA.md`가 수동 입력·생성 출력을 구분한다. 확장자는 소유권을 정하지 않는다. 예를 들어 `question-elements/frequency.md`, `deduplication.md`, `elements/*.md`는 분석 JSON과 함께 재생성하므로 현재 위치에 둔다.

## 원자료 수집

[raw 안내](../cpa_uploader/raw/README.md)에서 원자료와 검증 출처의 수집 매니페스트를 확인한다. 기존 자료는 인용·검수 receipt·분석 입력의 경로를 유지하면서 raw에 바이트가 동일한 보존본을 만든다. 원문, 추출 텍스트, 페이지 이미지, 등록 전사, wiki 입력의 시점 사본을 구분한다. 중복 바이트는 하나의 보존 파일에 여러 원래 경로를 연결할 수 있다.

새 원자료는 `raw/originals/<자료-판본>/`에 먼저 보존하고 수집 입력에 등록한다. 원 URL·판본·확인일·쪽수/문단·파일 해시·추출 방법은 실제 확인한 값만 기록한다. 기존 자료에 없는 취득일·출판사·판본을 수집 시각으로 대신 채우지 않는다. URL만 있거나 원본이 없는 자료는 미보관으로 표시한다. Git에서 제외하던 외부 원문과 공개하지 않는 학습 자료는 raw에서도 로컬 보존 범위를 유지한다.

출처 등록에 기존 `data/official/` 또는 학습자료 경로가 필요한 동안 그 입력을 유지하고 raw 원본과의 관계를 남긴다. raw를 카탈로그의 추가 원문 폴더로 무조건 재귀 탐색하여 같은 자료를 이중 등록하지 않는다. 현행 편집 정본·분석 수동 입력·생성기는 각 소유 위치에서 수정하며 raw의 시점 사본을 편집 정본으로 사용하지 않는다.

출처 보존의 완료는 수집 전후 바이트·해시·누락 검사로 확인한다. 문항·판본의 정확성 검수는 [공통 출처 검증 지침](../.agents/skills/audit-question-review/references/source-evidence.md)과 제작·검토 스킬을 따른다. 해시 일치를 내용 검수로 대신하지 않는다.

물음별 학습 유형·주제의 수동 분류와 당시 근거는 각 `analysis/reviews/` 검토 배치에서 관리한다. 최초 이관 입력은 `question-unit-migration-2026-09-11/`에 보존한다. `data/learning-question-classifications.json`은 `scripts/build-learning-unit-catalog.ts`로 컴파일하는 파일 모드용 산출물이므로 직접 고치지 않는다. 후속 분류는 `--review <새 검토 입력> --output <카탈로그>`로 생성한다. 이후 명시적 `--review`가 없으면 해당 카탈로그의 `review_file`을 사용하므로 과거 분류 입력을 덮어쓸 필요가 없다. `--check`는 선택한 입력과 산출물을 읽기 전용으로 대조한다. 원문 v3 세트와 학습 부모·단위의 차이, 새 분류 revision과 기존 DB 이관은 [물음별 학습 계약](물음별-학습-단위와-분류-계약.md)을 따른다.

## 요소·기준서·문항 연결

[연결 분석 안내](../cpa_uploader/analysis/coverage/README.md)의 `links.json` 입력 계약을 따른다. 기존 요소 ID, 공식 판본·문단 또는 출처 단위 ID, 세트·물음·criterion ID를 참조하고, 기준서 본문·모범답안·빈도를 연결 장부에 중복 작성하지 않는다. 출처 인용이나 실행 증거처럼 문항·검수 계약이 요구하는 사본은 유지한다.

- 사람이 확인한 직접 대응·상위 요구·인접 요구·제외 관계와 그 근거를 기록한다. 자동 인용 연결·단어 일치·같은 기준서 분류는 의미 검토의 후보 정보다.
- 추출 요소는 원래 발문의 요구이고, 기준서의 요구사항과 은행 criterion은 각각 별개 단위다. 같은 이름이라고 동일한 채점 범위로 합치지 않는다.
- 관계의 확인 상태와 입력 해시를 보존한다. 연결이 없다는 사실만으로 미출제를 확정하지 않고, 연결이 있다는 사실만으로 해당 요구를 충분히 출제했다고 확정하지 않는다.
- 과거 제작 장부에서 가져온 관계는 과거 근거와 검토 필요 상태로 구분한다. 가져오기나 자동 연결만으로 정식 의미검수·사람 승인 상태로 올리지 않는다.
- 학습 순서나 폴더 구조가 바뀌어도 기존 주제·요소·문항 ID를 재번호화하지 않는다.

## 수치와 상태 해석

| 항목 | 유지할 구분 |
| --- | --- |
| 빈도 | 기출 고유 물음, 확인된 모의고사, 연습·OX 수록 기록을 별도로 집계 |
| 중복 | 같은 원물음의 교재 재수록은 추가 출제로 세지 않음. 서로 다른 연도·실제 물음의 출제는 각각 보존 |
| 커버리지 | 인용·ID 연결 수와 사람이 확인한 요구사항 충족 범위를 구분 |
| 문항 상태 | 정본 수록, 검수 대기, 의미검수, 실제 채점, 사람 확인, 공개 여부를 구분 |

상위 주제 합계·요소별 횟수·문항 수를 합쳐 임의의 중요도 점수를 만들지 않는다. `needs_review` 문항이 정본에 들어가 있어도 검수 완료나 게시를 뜻하지 않는다.

## 현재값과 과거 기록

[출제·검토 현황](../cpa_uploader/wiki/_meta/authoring-dashboard.md)은 현재 입력에서 생성한 조회 화면이다. 생성 시점과 입력 해시를 확인하고, 입력이 달라지면 현재 현황을 재생성한다. 관계를 판단할 때 사용한 원문·은행·판본이 달라졌다면 영향을 받는 관계를 재검토한다. 자동 재집계 성공은 의미 검토의 승인이 아니다.

날짜별 검토에는 대상 ID, 당시 입력·코드·설정 해시, 실행 방법, 결과와 미실행 범위를 남긴다. 새 검토는 새 증거로 기록하고 이전 결과를 보존한다. 현재 해시와 다르다는 이유만으로 과거 결과를 오기라고 고치거나, 옛 해시를 최신 해시로 치환하지 않는다. 현재 재사용 가능성은 해당 검수·채점 계약으로 판정한다.

`docs/archive/과거-검토-증거/reports/question-review-2027/`의 Markdown 보고서는 당시 판단을 설명한다. 대응하는 JSON·채점 사례·출처 증거는 `cpa_uploader/analysis/reviews/question-review-2027/`에서 관리한다. 이동 전 경로가 과거 실행 기록 안에 남아 있으면 이동 기록과 함께 해석하고, 경로 이동만으로 원문 내용이나 실행 결과를 다시 쓰지 않는다.

## 변경 순서

1. 바뀌는 사실의 소유 파일을 찾는다. 원문·추출 보정·관계 판단·문항·설명 중 무엇이 바뀌는지 구분한다.
2. 수동 입력이나 해당 생성기를 수정한다. 과거 실행 증거는 보존하고 필요한 후속 기록을 만든다.
3. 변경한 묶음을 재생성하고 아래 검사로 현재 조회 결과의 일치를 확인한다. 발문 추출·문항·실제 채점 검증은 각 묶음의 별도 계약을 따른다.

```sh
npm run analysis:build
npm run analysis:check
npm run wiki:build
npm run wiki:check
```

폴더 정리는 참조 경로를 확인하며 묶음별로 진행한다. 생성기·입력·링크를 함께 갱신하고 이동 전후 바이트·해시를 대조한다. 자동 현황 검사 통과를 실제 모델 채점이나 기준서 내용 검수 완료로 보고하지 않는다.
